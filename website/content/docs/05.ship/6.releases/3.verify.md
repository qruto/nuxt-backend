Every release from `0.2.0` on is built in the open and signed on the way out: the release workflow checks out the tag, packs the tarball, writes a software bill of materials (SBOM) of what it installs, attests both, creates an immutable GitHub Release with all three, and publishes the same tarball to npm with provenance. Nobody holds a token that could publish it another way. Each step below checks one of those promises. (`0.1.0` was a throwaway test publish, built before any of this, and carries none of it.)

## Check npm's provenance

```bash
npm view nuxt-backend@0.2.0 dist
```

The `dist` block lists `attestations` beside `signatures`: npm's provenance statement, which names the repository, the workflow and the commit the tarball was built from. In an app that already installed it, `npm audit signatures` verifies the registry signatures and provenance of every installed package, this one included.

## Verify the tarball and its SBOM

The GitHub Release holds the tarball, its attestation bundle and the SBOM. Download them and verify each file against its attestation:

```bash
gh release download v0.2.0 --repo qruto/nuxt-backend --pattern 'nuxt-backend-*'
gh attestation verify nuxt-backend-0.2.0.tgz --repo qruto/nuxt-backend
gh attestation verify nuxt-backend-0.2.0.cdx.json --repo qruto/nuxt-backend
```

Both files are subjects of one attestation, signed by the release workflow's identity through Sigstore: a tarball or an SBOM changed by one byte fails. The bundle beside the tarball (`nuxt-backend-0.2.0.tgz.sigstore.json`) is the same attestation, for verifying without asking GitHub.

## Check the release itself

```bash
gh release verify v0.2.0 --repo qruto/nuxt-backend
```

The Release is immutable: once published, its tag and its assets cannot change, and GitHub attests it.

## Read the SBOM

`nuxt-backend-0.2.0.cdx.json` is a CycloneDX document of the package's production dependencies, with their versions and licenses: what an app installs with it, nothing of the website or the tests. Feed it to the scanner your organization uses, or read it for a license review.
