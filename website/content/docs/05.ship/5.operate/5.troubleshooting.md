Find your symptom below, or the log code you saw. Start with `npx nuxt-backend doctor`: most of what follows is a finding with a fix hint. Something broke in production? [Respond to incidents](/docs/ship/operate/runbooks) has the runbooks, and [Get help](/docs/ship/operate/help) says what to send when nothing here fits.

## `convex dev` can't resolve `@convex-dev/…/convex.config`

**Symptom:** the push fails resolving a component definition imported by `backend/convex.config.ts`.

**Cause:** pnpm's default isolated linker hides transitive packages, and Convex's bundler resolves the `@convex-dev/*` component definitions from your project root.

**Fix:** let them hoist, from `pnpm-workspace.yaml` (pnpm 11+ no longer reads such settings from `.npmrc`):

```yaml [pnpm-workspace.yaml]
publicHoistPattern:
  - '@convex-dev/*'
```

(or `nodeLinker: hoisted`), then reinstall.

## The sign-in code never arrives

**Symptom:** "request code" answers *"This app is in test mode and only emails test addresses, so this address can't receive mail here"* or *"This app can't send email yet"*, or succeeds but no email comes.

**Cause:** no email transport (`EMAIL_API_KEY` is unset), test mode, or no `EMAIL_FROM` in production. The package refuses a code it knows would not arrive ([Get email into inboxes](/docs/build/email/delivery/deliverability)), and logs `email.undeliverable` with the setting to change.

**Fix:**

- In development you don't need email. On a deployment whose `BACKEND_ENVIRONMENT` is `development`, every code prints where Convex's function logs go: the **`nuxt-backend dev` terminal**.
- Outside production, email runs in test mode: only Resend's test addresses (`delivered@resend.dev`, with any `+label`) receive mail. Sign in with one, and read the code in the [dev inbox](/docs/develop/dev-inbox).
- In production, `EMAIL_FROM` must be an address on a domain verified in Resend.
- The `doctor` findings `email-transport` and `deployment-email-api-key` tell you which case you are in.

## `nuxt build` or `generate` never exits

**Symptom:** the build finishes compiling, the prerender crawl starts, and the process hangs.

**Cause:** the crawler rendered a page that opens a live Convex WebSocket (`useQuery` subscriptions), which keeps the event loop alive. The module's own pages are never prerendered; this is one of the app's.

**Fix:** exclude the app's live pages from prerendering:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/app/**': { prerender: false },
  },
})
```

## `start_push 500` on `convex dev` / `deploy`

**Symptom:** the push fails with an opaque `start_push 500` while evaluating the definition bundle.

**Cause:** Convex discovers components by intercepting every `convex.config` import while bundling `convex.config.ts`, and current backends crash when such an import is reached through an **intermediate module** (a helper that imports component definitions for you) or when `app.use` runs in a loop.

**Fix:** keep the scaffolded shape: every component imported and mounted **in the root `convex.config.ts`**, one `app.use()` per component. Never wrap the definitions in a helper module. `nuxt-backend/app` deliberately exports only the env contract (`backendEnv`) for that reason.

## Sessions fail after changing `AUTH_SECRET` by hand

**Symptom:** after changing `AUTH_SECRET` with `convex env set`, sign-in loops, or the `/api/auth` proxy answers 5xx on token requests.

**Cause:** `AUTH_SECRET` signs sessions **and** encrypts the RS256 private keys stored in the backend component's `jwks` table. With a new secret the stored keys can no longer be decrypted, so no JWT can be signed; existing sessions are invalid regardless.

**Fix:** clear the stored keys so fresh ones are generated on the next request. In the Convex dashboard, open the `backend` component's data and delete the rows of the `jwks` table (or run a one-off mutation on `components.backend.adapter.deleteMany` with `{ model: 'jwks' }`). Every user signs in again. To change the secret with nobody signed out, run `npx nuxt-backend env rotate AUTH_SECRET` ([Rotate secrets](/docs/ship/security/secrets)) instead of setting it by hand.

## Pricing is empty although the catalog synced

**Symptom:** `useBilling().products` is `{}` / the pricing page shows nothing, but `billing sync` created the products.

**Cause:** `getConfiguredProducts` reads the reactive products table, which fills from `product.*` webhooks, and the webhook endpoint is created by the same sync run, *after* the products.

**Fix:** `billing sync` runs `billing:syncProducts` itself. If it reported the products as not loaded, the deployment lacked `BILLING_ACCESS_TOKEN`, or its `BACKEND_ENVIRONMENT` bills in another Polar environment than the one you synced. Fix that, then run `npx convex run billing:syncProducts` (add `--prod` for production). `billing.generated.ts` holds the sandbox ids and the production ids apart. Also check that `appConfig.backend.billing.plans[].key` matches the catalog keys.

## Credits don't update after a top-up / "Credit balance not synced yet"

**Cause:** `/billing/events` isn't receiving or verifying events (`BILLING_WEBHOOK_SECRET` unset → `503`, wrong secret → `403`, dashboard pointed at the wrong URL → nothing).

**Fix:** `doctor` (`billing-webhook-route`), then the delivery log in the DevTools Backend tab, whose outcome column names the failure. As a fallback, `useCredits().refresh()` runs `syncEntitlements` and pulls the balance directly.

## `useEmailStatus` stays at `sent` on a local deployment

**Cause:** Resend posts its delivery events to a public URL, and a local deployment has none, so no event reaches `/email/events`.

**Fix:** develop on a cloud dev deployment, or run a tunnel to the local one, and point Resend's webhook there with `EMAIL_WEBHOOK_SECRET` set. Then a send to `delivered@resend.dev` or `bounced@resend.dev` moves the status. The status moves only for an email sent with `EMAIL_API_KEY`: with no key, `send` returns `null`, so there is nothing to track ([Resend](/docs/services/resend#link-it)).

## Invitation links 404

**Cause:** the deployment emails a path other than `backend.pages.acceptInvitation`, where the Nuxt page mounts: its code predates the generated `paths.generated.ts`, or `backend/auth.ts` does not pass its `paths` to `setupAuth`.

**Fix:** run `npx nuxt-backend doctor --fix`, which rewrites the paths file, pass `paths` on as the scaffold does, and push the functions. `doctor`'s `page-paths` finding compares the deployment with `nuxt.config`. Also make sure `SITE_URL` is the app's origin, never the `.convex.site` URL: links are built from it.

## A composable returns `undefined` forever

**Symptom:** `useBilling` / `useCredits` / `useGifts` / `useFeatures` / `useEmailStatus` never load; or `useAuth` has no user.

**Cause:** the deployment lacks a function the composable binds to by name: a scaffolded file was renamed or its exports trimmed.

**Fix:** `doctor`'s `function-contract` finding lists the missing `module:export` names. Restore with `npx nuxt-backend init` (existing files untouched) and let `convex dev` push. If you renamed on purpose, pass `{ api }` to the composable.

## `/login` shows the Nuxt welcome page

**Cause:** `app/app.vue` is still the `create nuxt` starter, with `<NuxtWelcome />` and no `<NuxtPage />`. So the route resolves (the page guard even redirects there) but nothing renders it. The dev console says so: "app.vue still renders <NuxtWelcome /> and no <NuxtPage />".

**Fix:** replace `<NuxtWelcome />` with `<NuxtPage />`, or run `npx nuxt-backend init` while the file is untouched.

## `npm run dev` stops at "Preparing Convex functions" and Nuxt never starts

**Cause:** the `dev` script is `convex dev --start "nuxt dev"` (`nuxt-convex-module` writes it on `nuxt prepare` when `convex.devScript` is on). On a new deployment its first push fails on the missing `AUTH_SECRET` and `SITE_URL`, Convex starts Nuxt only after a successful push, and those values are provisioned from inside Nuxt.

**Fix:** `npx nuxt-backend doctor --fix` points the script at [`nuxt-backend dev`](/docs/reference/cli#dev), which provisions the env first. `doctor` reports the script as `dev-script`.

## `npx convex dev` says "add `convex` to your package.json dependencies"

**Cause:** `convex` is this package's peer dependency. A package manager installs it, but never writes it to your own `package.json`, and the Convex CLI reads that file before it runs.

**Fix:** `npm install convex` (or run `npx nuxt-backend init`, which adds the line when it is missing).

## `convex dev` says "A local backend is still running on port 3210"

**Cause:** an earlier run of `convex dev` itself (not through `nuxt-backend dev`) was stopped with SIGTERM (a plain `kill`, which is how coding agents and process managers stop a process), or any run was ended with `kill -9`. The Convex CLI exits on SIGTERM but leaves the local backend and the Nuxt server running, so the next run finds the port taken. `nuxt-backend dev`, the `dev` script `init` sets, passes SIGINT and SIGTERM on to Convex as SIGINT, so it shuts all three down either way.

**Fix:** stop what that run left behind, then run `dev` again. On macOS and Linux, list what listens on the default ports with `lsof -nP -iTCP:3210 -iTCP:3000 -sTCP:LISTEN`, then `kill <pid>` the `convex-local-backend` and the `node` process from that run; port 3000 may belong to another app. On Windows, end `convex-local-backend.exe` and the old `node` process in Task Manager. Stop a bare `convex dev` with Ctrl-C (SIGINT) or `kill -INT <pid>` next time: that shuts down all three.

## The built server answers 500: `Cannot find module '…/convex/dist/esm/index.js'`

**Cause:** Nuxt 4.6 changed how a production build resolves a module runtime's imports, and `nuxt-convex-module` before 0.11 let it inline the Convex client with an import that points outside `.output`. `nuxt build` succeeds and `nuxt dev` works; every request to the built server fails, on a Node server or in a Vercel function.

**Fix:** this package depends on `nuxt-convex-module` 0.11 or later, which avoids it. If a lockfile still holds 0.10, update it (`npm update nuxt-convex-module`). Adding `vite: { resolve: { dedupe: ['convex'] } }` to `nuxt.config.ts` fixes it too.

## Gated pages return `500 NUXT_PUBLIC_CONVEX_SITE_URL is not set` on the host

**Cause:** the production build has no backend URL. The page guard verifies the session on the server through the backend's HTTP-actions origin, and the underlying Convex module raises this (its own name for the variable) when that origin is unknown. Pages without the middleware still render, which is why the home page works and the account pages don't.

**Fix:** set `NUXT_PUBLIC_BACKEND_URL` on the host: the `.convex.site` origin is derived from a `*.convex.cloud` URL ([the env split](/docs/ship/deploy#the-env-split)). For a custom domain or a self-hosted backend, set `NUXT_PUBLIC_CONVEX_SITE_URL` too ([Self-host and add domains](/docs/ship/deploy/self-hosting)).

## Sign-in fails from `http://localhost:<port>`

**Cause:** `SITE_URL` is the only trusted browser origin, and it defaults to `http://localhost:3000` on dev deployments. Another port, or `127.0.0.1`, is a different origin. A deployment whose `BACKEND_ENVIRONMENT` is `development` trusts local origins on any port, so the deployment you sign in to runs in another environment.

**Fix:** run `npx nuxt-backend env push` against the dev deployment, which sets `BACKEND_ENVIRONMENT=development`, or set `SITE_URL` to the exact origin.

## Type errors on `#backend/*` before the first `convex dev`

The module ships fallback ambient types for `#backend/*` until `_generated/api` exists, and re-renders them the moment codegen appears. If types stay stale, restart the dev server after the first `convex dev` run.
