The deploy template puts a new app on Vercel before you clone it. It is the [starter](/docs/start/templates), deployed from the repository's `templates/starter` folder. One deploy creates the Git repository, the Vercel project and the Convex project together, and the app is live at its own URL. Start here when you want a public URL from day one. Start from the starter when you want to build on your machine first.

[Deploy with Vercel](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fqruto%2Fnuxt-backend%2Ftree%2Fmain%2Ftemplates%2Fstarter&project-name=nuxt-backend-app&repository-name=nuxt-backend-app&products=%5B%7B%22type%22%3A%22integration%22%2C%22integrationSlug%22%3A%22convex%22%2C%22productSlug%22%3A%22convex%22%2C%22protocol%22%3A%22storage%22%7D%5D)

## What the deploy does

1. **The repository.** Vercel copies the starter into your Git account and creates a project for it.
2. **The backend.** The deploy link adds Convex through the Vercel Marketplace. The integration creates a Convex project, in a Convex team of its own, and gives the Vercel project its deploy key. You sign in to Convex through Vercel, and copy no key by hand.
3. **The first build.** The starter's `vercel.json` sets the build command to [`npx nuxt-backend deploy --build`](/docs/reference/cli#deploy). It puts what the first push needs on the new production deployment, a generated `AUTH_SECRET` and the project's production URL as `SITE_URL`, then ships both halves as [Deploy to production](/docs/ship/deploy#one-command-on-any-host) describes: the backend first, then the app against it.

The first build leaves `BACKEND_ENVIRONMENT` unset, so every provider stays in its test mode: every capability that needs no account works, and the rest wait for their keys.

| Capability | After the first deploy |
|---|---|
| Auth | Sign in with a test address, such as `delivered+you@resend.dev`, once an email key is set, and read the code in Resend's list of sent emails. The [dev inbox](/docs/develop/dev-inbox) shows it in the app only on a demo: after `npx nuxt-backend deploy --sandbox`, with `EMAIL_DEV_INBOX=1` set on the deployment |
| Billing | Polar's sandbox, once you add a sandbox token |
| AI | The Convex AI Gateway on a paid Convex plan, or `AI_GATEWAY_API_KEY` |
| Data, jobs, flags | Running, on the new deployment |

## Then make it production

Clone the repository, install, sign in to Convex (`npx convex login`) and Vercel (`npx vercel link`), and run [one-command production](/docs/ship/deploy/one-command) from it:

```bash
npx nuxt-backend deploy
```

It links the production deployment the integration created, sets `BACKEND_ENVIRONMENT=production`, pushes production's env, syncs the catalog, registers the webhooks and writes the app's env into the same Vercel project. It ends with `doctor --prod`. Then walk [Prepare for launch](/docs/ship/checklist) for what no command can see. To keep the app a public demo instead, run `npx nuxt-backend deploy --sandbox` ([Deploy a demo or staging app](/docs/ship/deploy/staging)).
