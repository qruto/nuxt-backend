One command runs the whole app: Convex and Nuxt in one terminal, on a deployment that is yours alone. It provisions what a new deployment needs before anything starts, so the first run and every later one look the same.

- **What powers it natively:** `convex dev`, which pushes your functions on save and regenerates their types, and `nuxt dev`.
- **What the package adds:** `npx nuxt-backend dev`, which provisions the deployment's env first, sets `BACKEND_ENVIRONMENT`, and runs both in one process.

::steps{level="3"}

### Start it

```bash
npm run dev   # the dev script the install writes: nuxt-backend dev
```

`npx nuxt module add nuxt-backend` points the `dev` script at `nuxt-backend dev` when it installs the package, and `npx nuxt-backend init` does the same later. `npx nuxt-backend dev` runs it where the `dev` script is one of your own. Arguments after it go to `nuxt dev` (`npm run dev -- --port 3001`), and Ctrl-C stops Convex, Nuxt and a local backend together.

### Pick a deployment, once

The first run asks which deployment to use and writes the answer to `.env.local` as `CONVEX_DEPLOYMENT`. Every later run reuses it.

| Kind | `CONVEX_DEPLOYMENT` | Needs | Good for |
|---|---|---|---|
| Account-free local | `anonymous:…` | Nothing: **Start without an account**, or `npx nuxt-backend dev --anonymous` | Trying the package, agents and CI |
| Local | `local:…` | A Convex account | Working offline on a project of yours |
| Cloud dev | `dev:…` | A Convex account | Webhooks from Polar and Resend, the Convex AI Gateway on a paid plan, a team sharing one deployment |

`--anonymous` skips the question and starts on an account-free local deployment, the same way on macOS, Linux and Windows. It replaces setting `CONVEX_AGENT_MODE=anonymous` in the shell, which only works in POSIX shells. When `.env.local` already names a deployment, `dev` keeps it and says so: remove `CONVEX_DEPLOYMENT` from it to start an account-free one.

A local deployment runs only while `dev` runs, and providers cannot reach it from the internet. `npx convex login` turns an account-free deployment into one of your account's, and `npx convex dev --configure` points the app at another deployment.

### Change things

- **Backend code** in `backend/` is pushed on save, and `backend/_generated/` is regenerated, so `#backend/api` is typed at once.
- **A missing backend file** comes back with `npx nuxt-backend init`, which never touches a file that exists.
- **A value in `.env.local`** reaches the deployment with `npx nuxt-backend env push`, which never replaces a value already there (`--force` does).
- **The billing catalog** reaches Polar's sandbox with `npx nuxt-backend billing sync` ([Develop with real sandboxes](/docs/develop/sandboxes#billing-on-polars-sandbox)).

::

## Check it works

The dev console ends its start with one line, `backend preflight: …`, which counts the checks that pass and names the findings that do not. `npx nuxt-backend status` gives the state of each [capability](/docs/start/concepts/capabilities), and the [DevTools tab](/docs/develop/devtools) shows the same, live.

## What the first run provisions

Before Convex pushes anything, `dev` gives a new deployment the values it cannot start without, and never replaces one that is set:

- `AUTH_SECRET`, generated for this deployment;
- `SITE_URL`, set to `http://localhost:3000`;
- `BACKEND_ENVIRONMENT`, derived from `CONVEX_DEPLOYMENT`: `development` on every dev deployment.

`development` turns on what this page relies on. Sign-in codes print in the terminal running `dev`, email stays in test mode, billing uses Polar's sandbox, and auth trusts every local origin of your machine (another port, or a `https://*.localhost` name) as well as `SITE_URL`. None of it reaches a preview or production deployment ([Environments](/docs/start/concepts/environments#backend_environment)).

## Reach your machine from outside

Polar's sandbox and Resend post their webhooks to a public URL. On a cloud dev deployment that URL is the deployment's own, and it works as it is. A local deployment has none: run a tunnel to it, and pass the tunnel's URL to [`billing sync`](/docs/reference/cli#billing-sync) as `--webhook`, and to Resend's webhook settings.

## Why a dev command of its own

Convex starts the command it runs only after a push succeeds, and a new deployment's first push fails until `AUTH_SECRET` and `SITE_URL` are on it. Started that way, a new app waits forever. `nuxt-backend dev` provisions first and then hands over to the same `convex dev --start`. `doctor` reports the old script as [`dev-script`](/docs/reference/cli/diagnostics#dev-script), and `doctor --fix` rewrites it. Two terminals work too: `npx convex dev` in one and `nuxt dev` in the other, in either order.
