`npx nuxt-backend doctor` checks the project and its deployment, and every finding it prints names its fix. `npx nuxt-backend status` reads the same checks one [capability](/docs/start/concepts/capabilities) at a time.

::steps{level="3"}

### See what is wrong

```bash
npx nuxt-backend status
```

Each line is a capability, with its light, from live to failing. Under a capability that lacks something come the env names it misses and its most pressing finding, and the last line names the `doctor` run that shows every fix. Capabilities that are missing or in test mode are expected in development: only a failing one is an error.

### Read the findings of one capability

```bash
npx nuxt-backend doctor --only billing
```

`--only` runs the checks of the [capabilities](/docs/reference/capabilities) you name, comma-separated, and skips the rest, their deployment reads and provider calls included. Every finding has an id, a status (`pass`, `warn` or `fail`), a message and a fix, and its link, `https://nuxt-backend.dev/d/<id>`, opens its entry on [Diagnostics](/docs/reference/cli/diagnostics): what it checks, when it fails and how to fix it.

### Let doctor fix what it can

```bash
npx nuxt-backend doctor --fix
```

It restores a scaffold file that is gone (never one you changed), points a `convex dev --start "nuxt dev"` script at `nuxt-backend dev`, and runs [`env push`](/docs/reference/cli#env-push), which provisions what the dev deployment lacks and never replaces a value. What is left needs you: a provider key, a catalog, a decision.

::

## Check it works

Run `npx nuxt-backend doctor` again: it exits with `0` once no finding fails, warnings allowed.

## Gate CI and the launch on it

`--json` prints one document, `{ $schema, findings, summary }`, described by [its schema](https://nuxt-backend.dev/schemas/doctor.json), with stable ids and statuses, so a script reads it rather than the wording:

```bash
npx nuxt-backend doctor --json > doctor.json   # exit code 1 when a finding fails
```

`--prod` checks the production deployment instead, with the optional capabilities' designed degradations turned into failures, a few values read where a name alone says too little, and the live site probed at the origin its `SITE_URL` names. It needs a production `CONVEX_DEPLOY_KEY` and refuses a dev or preview one. [Prepare for launch](/docs/ship/checklist) runs it as the last gate:

```bash
CONVEX_DEPLOY_KEY=prod:… npx nuxt-backend doctor --prod
```

## The same checks elsewhere

- The dev server runs the project's half on every start and sums it up in one line, `backend preflight: …`.
- The [DevTools Backend tab](/docs/develop/devtools) shows the findings by capability, and its **Run doctor** key adds the deployment-side checks and copies the run as `doctor --json` prints it.
- A coding agent reads `doctor --json` and follows each fix line, as the [install guide](/docs/start/installation) has it do.
