The package ships its guidance for coding agents as one small core skill and a task skill per part of the app. An agent loads the core with every task, and the task skill a task needs, so neither crowds out the code it is working on. The table is generated from the skills registry, `src/guidance/skills.ts`.

## What each skill holds

- **The core**, `nuxt-backend`, holds the rules of an app built on the package: the neutral names, the scaffold contract and `backend/_generated`, the CLI and the env contract, and how to check the installed version. It also lists the names agents tend to guess that don't exist, from other stacks or from 0.1, each with the real one.
- **Its router** names the task skill for each feature, with the names that task reaches for.
- **Each task skill** lists its docs pages with the API each one uses, and the rules of its area. A how-to page belongs to exactly one skill, by its route.

Beside each `SKILL.md`, `references/` holds what an agent opens when a task needs it:

| File | In | Holds |
|---|---|---|
| `references/api.md` | Each task skill that owns names (all but `nuxt-backend-upgrade`) | Its composables, components, import paths, commands, `doctor` findings and env, each with the first sentence of its doc comment |
| `references/api.md` | The core | Every public name, plus the CLI flags, error codes, every `doctor` finding and the env |
| `references/upgrade.md` | `nuxt-backend-upgrade` | The names a release renamed, reshaped or removed, each linked to its section of [Upgrade to a new version](/docs/ship/releases/upgrade) |
| `references/surface.json`, `references/renames.json` | The core | The public names and the rename map as data, for a script or an agent that checks a name before writing it |
| `references/install.md` | The core | The install guide the [install prompt](/docs/start/installation#install) points at |

Every reference is generated from the code, so a name in a skill always exists in the version it ships with.

## Where they live

- **In the package**, at `node_modules/nuxt-backend/skills/`, for exactly the installed version.
- **In the project**, in `.agents/skills/`, where `init` copies them, linked from `.claude/skills/` in a project that uses Claude Code ([Agent files](/docs/develop/agents/agent-files)).
- **On this site**, under [`/.well-known/skills/`](/.well-known/skills/index.json), and linked from [`/llms.txt`](/llms.txt) beside the docs. The core is at [`/.well-known/skills/nuxt-backend/SKILL.md`](/.well-known/skills/nuxt-backend/SKILL.md).

## Install the skills on their own

To install the skills for your agent outside one app, use the [skills CLI](https://skills.sh), from this site or from the repository:

```bash
npx skills add https://nuxt-backend.dev --skill '*'
npx skills add qruto/nuxt-backend --skill nuxt-backend --skill nuxt-backend-billing
```

`--skill '*'` takes them all; name skills to take some. Both list exactly the skills in the table. The repository's own contributor skills are recorded in its `skills-lock.json`, which the skills CLI reads as installed, not published.

A copy from the repository follows its `main` branch, and one from the site follows what the site was built from. Either can be ahead of the version an app installed, so inside an app, prefer the copies `init` writes ([Keep them on your version](/docs/develop/agents#keep-them-on-your-version)).
