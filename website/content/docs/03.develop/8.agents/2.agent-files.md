`npx nuxt-backend init` writes three things for coding agents next to the scaffold, and the [starter template](/docs/start/templates) ships them. Each one points an agent at guidance and tools for the version the app installed, and none of them overwrites what you wrote yourself.

| File | What it holds | Read by |
|---|---|---|
| `AGENTS.md` | A `nuxt-backend` section: the installed version, where its skills are, the rules, the commands, the env and where the docs are | Codex, Cursor, Copilot and most agents; Claude Code through `@AGENTS.md` |
| `.mcp.json` | One server, the [developer MCP server](/docs/develop/agents/developer-mcp): `npx nuxt-backend mcp`, for your project's state, the docs and your providers' consoles, Convex's included | Claude Code, and any agent that reads the project's MCP servers |
| `.agents/skills/` | A copy of every skill the installed version ships, linked from `.claude/skills/` in a project that uses Claude Code | The skills CLI's layout, which most agents read |

## What `init` writes

- **`AGENTS.md`**: a short `nuxt-backend` section between `<!-- nuxt-backend-start -->` and `<!-- nuxt-backend-end -->` markers. It names the installed version, points at the skills in `node_modules`, the core first, and covers the rules, the commands, the env and where the docs are. The starter template ships it without a version, since it installs the latest.
  - A missing file is created.
  - An existing one without the markers gets the section appended, and nothing else changes.
  - Once the markers exist, `init` leaves the file alone. `init --force` replaces only what sits between them.
- **`.mcp.json`**: a `nuxt-backend` server that runs `npx nuxt-backend mcp`.
  - The server runs on `@modelcontextprotocol/sdk`, an optional peer. If your `package.json` doesn't list it, `init` adds it to `devDependencies`, and `npm install` links it.
  - A missing file is created.
  - An existing one gains the `nuxt-backend` server only when it has none, keeping its indentation and every other server.
  - A `convex` server an earlier version wrote stays, and `init` says you can remove it: the developer server passes Convex's tools through.
  - A file that is not valid JSON is left alone with a warning.
- **`.agents/skills/`**: a copy of every skill the installed version ships, where the skills CLI installs skills and most agents look for them. In a project that uses Claude Code (a `.claude/` folder or a `CLAUDE.md`), each skill is linked from `.claude/skills/` too, as the skills CLI links it.
  - A missing skill is copied.
  - A copy another version wrote, or one of a skill the installed version no longer ships, is left alone with a note: `init --agents`, or `init --force`, replaces it whole or removes it.
  - A skill the project's `skills-lock.json` lists came from the skills CLI, and `init` leaves it to that CLI, which restores and updates it.
  - Commit the copies or ignore them, as you do your other agent files.

What `init` writes in `.mcp.json`:

```json [.mcp.json]
{
  "mcpServers": {
    "nuxt-backend": {
      "command": "npx",
      "args": ["nuxt-backend", "mcp"]
    }
  }
}
```

Claude Code reads `CLAUDE.md` and follows `AGENTS.md` only when `CLAUDE.md` imports it. When your `CLAUDE.md` does not mention `AGENTS.md`, `init` says to add an `@AGENTS.md` line. It never edits that file.

A file whose markers don't pair up is left alone, by `init` and `init --agents` alike: fix the markers by hand. `init` says so and exits with `1`.

## Flags

| Flag | What it does to the agent files |
|---|---|
| none | Writes what is missing, as above, and leaves the rest |
| `--no-agents` | Writes none of them |
| `--agents` | Rewrites only these three, for the installed version: the section of `AGENTS.md` is replaced and the text around it stays, the `nuxt-backend` server in `.mcp.json` and the skill copies become the installed version's, the MCP SDK joins `devDependencies` when it is missing, and nothing else is scaffolded |
| `--force` | Overwrites the scaffold files too, and for the agent files replaces the section between its markers and the skill copies another version wrote, as `--agents` does |

Run `init --agents` after [`nuxt-backend upgrade`](/docs/reference/cli#upgrade), which reads the version the section names (its `next` lists `init --agents`). `init --json` lists, under `skills`, the ones it `installed`, `refreshed` and `removed`, and the `stale` ones it left. Every flag is in the [CLI reference](/docs/reference/cli#init).

## Checked by `doctor`

`doctor` reports an [`agent-files`](/docs/reference/cli/diagnostics#agent-files) warning while the section is missing or was written for another version, and while a skill copy differs from the installed version's or is one it no longer ships. Skills the project lacks don't warn: agents find every one in `node_modules`.

## Convex's own tooling

Inside `backend/`, the rules are Convex's. `npx convex ai-files install` writes Convex's guidelines for agents, which the developer server's Convex tools work alongside.
