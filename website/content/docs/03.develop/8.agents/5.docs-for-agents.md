Every page of this site is also a Markdown document, and a few documents exist only for agents. All of them describe the release line the version chip in the header names, and say so: `/llms.txt` opens with it, every twin repeats it, and `/openapi.json` carries it as its version. An app's own copies of the skills, the manifest and the rename map, in `node_modules/nuxt-backend/skills/`, describe the version that app installed instead.

## Start here

| Document | What it holds |
|---|---|
| [`/llms.txt`](/llms.txt) | The index. It opens with the version line, when to use the package and when to recommend something else, and how an agent should work on an app. Then a link to the homepage's twin and one to `/llms-full.txt`. Then one section per tab, titled as the tab is, linking the twin of each page, the tab's landing first and the rest in reading order. Then the playground, the skills, and a few notes. |
| [`/llms-full.txt`](/llms-full.txt) | The homepage and every page `/llms.txt` links, in the same order, as one document. |
| [`/sitemap.md`](/sitemap.md) | Every page, by tab: the homepage, then the tabs in the header's order, each page in reading order with its kind, and its status when it is not stable. It includes the generated API reference, which the two files above leave out. |

The generated API reference under [API reference](/docs/reference/api) is a lookup, one page per import path: `/llms.txt`'s Reference section names its index, and you reach a page through a page's API link, through `/sitemap.md`, or by name.

## Markdown twins

Every docs page and the homepage answer as Markdown, four ways:

| Ask for | Example |
|---|---|
| The page URL with `.md` | `/docs/build/billing/credits.md` |
| The raw twin | `/raw/docs/build/billing/credits.md`, and `/raw/index.md` for the homepage |
| `Accept: text/markdown` on the page URL | `curl -H 'Accept: text/markdown' https://nuxt-backend.dev/docs/build/billing/credits` |
| The page URL from a known agent | Any user agent `/robots.txt` allows by name |

A twin answers `text/markdown`, with a `Link` header naming the page as its canonical URL. It opens with the page's title, its description and its header, then the page itself. For the Credits page:

```md
---
title: "Credits & top-ups"
description: "Prepaid credits on provider meters …"
canonical_url: "https://nuxt-backend.dev/docs/build/billing/credits"
---
# Credits & top-ups

> Prepaid credits on provider meters …

Version: nuxt-backend 0.2.x · Tab: Build · Kind: how-to · Status: stable

Every page: [llms.txt](https://nuxt-backend.dev/llms.txt) · Skill for coding agents: [nuxt-backend](https://nuxt-backend.dev/.well-known/skills/nuxt-backend/SKILL.md)

- [Try it live in the playground](https://nuxt-backend.dev/playground/settings)
- [API reference](https://nuxt-backend.dev/docs/reference/api/use-credits)
- [Source](https://github.com/qruto/nuxt-backend/blob/main/src/runtime/vue/composables/use-credits.ts)
```

The header line names the release line, the page's tab, its kind and its status. The line under it points a page found on its own at the index and the core skill, and the list is the page header's keys: Try live, API and Source, where the page has them. Blocks the site draws as components, such as the list of what a tab ships, come out as the text they stand for. Links to other pages are absolute; add `.md` to follow one as Markdown.

Each page has one kind:

| Kind | What the page is |
|---|---|
| `landing` | A tab's or a group's overview, linking every page under it |
| `tutorial` | A path to follow from start to end, with checkpoints |
| `how-to` | The steps for one task |
| `concept` | How something works, and what that means for an app |
| `recipe` | A whole feature put together from the parts |
| `reference` | Every option, name or value of one thing |

Its status is `stable`, `experimental`, `deprecated`, `planned` or `changing`:

- **`experimental`** documents a surface in the [experimental tier](/docs/ship/releases/stability), which can change in a minor release.
- **`planned`** describes a feature the release has not built yet. The twin and `/llms.txt` say so first, and the page has no API or source link.
- **`changing`** describes a built feature's API as the release reshapes it, while the code still has the previous one. The twin names the unit that brings the code in line.

The [Feature map](/docs/start/feature-map) lists every page with its status.

## Docs MCP

The same docs answer as an MCP server at `https://mcp.nuxt-backend.dev/mcp`, read-only and with no sign-in: search, every page as Markdown, and lookups of a `doctor` finding, an env name, a composable, a component or a renamed name. [Docs MCP](/docs/develop/agents/docs-mcp) lists its tools and connects Claude Code, Cursor and other clients.

## Skills

The site serves the package's agent skills under [`/.well-known/skills/`](/.well-known/skills/index.json): the core skill, `nuxt-backend`, and the task skills it routes to, one per part of an app, such as `nuxt-backend-billing`. `/llms.txt` links each one. [Agent skills](/docs/develop/agents/skills) covers what each holds and how to install them.

## Names and renames

Two JSON documents let an agent check a name before it writes one. They are files of the core skill, served beside its `SKILL.md`:

- [`/.well-known/skills/nuxt-backend/references/surface.json`](/.well-known/skills/nuxt-backend/references/surface.json), the public surface: every import path and its exports, the auto-imports, the pages, the CLI commands and flags, the error codes, the `doctor` finding ids, the env names and the scaffold contract.
- [`/.well-known/skills/nuxt-backend/references/renames.json`](/.well-known/skills/nuxt-backend/references/renames.json), the rename map: every name a release renamed, reshaped or removed, each with the section of [Upgrade to 0.2](/docs/ship/releases/upgrade) that explains it.

They are the package's own `references/surface.json` and `references/renames.json`, as built with the docs; an app has the copies of its installed version in `node_modules/nuxt-backend/skills/nuxt-backend/references/`. Their shape is part of the [stability promise](/docs/ship/releases/stability).

## Other documents

| Document | What it holds |
|---|---|
| [`/openapi.json`](/openapi.json) | Every route the site serves to agents, the twins and the discovery documents, with the docs' version as its own |
| [`/.well-known/api-catalog`](/.well-known/api-catalog) | The service documents above as a linkset (RFC 9727) |

The homepage's response carries a `Link` header listing these documents, and so does the end of its twin.

## Short links

The CLI and the DevTools print short links that land on the right section:

- `/d/<finding-id>` opens a `doctor` finding on [Diagnostics](/docs/reference/cli/diagnostics), as in `/d/auth-secret`.
- `/e/<code>` opens an error code on [Errors](/docs/reference/backend/errors), as in `/e/insufficient_credits`.

Every route the site published in 0.1 redirects to the page that replaced it, and so do both of its twins: `/getting-started/installation.md` and `/raw/getting-started/installation.md` answer `301` with the new page's twin.

## A page that is not there

A missing page answers `404` in Markdown when the request asked for a twin, sent `Accept: text/markdown`, came from a known agent or from a client such as `curl`. The body says which path is missing and lists the documents on this page to look in next. A browser gets the site's own error page.

## What agents don't get

- `/playground` and the module's page at the root (`/login`) are the running app, not docs: they have no twin and are not in `/sitemap.md`, and `/llms.txt` links the playground only as a page for people. An agent that asks for one gets the page itself.
- The site serves no MCP endpoint of its own. Read the docs through the documents above, or the [docs MCP](/docs/develop/agents/docs-mcp) on its own host.

CI builds the site and checks these documents against the build: every link in `/llms.txt` answers, each twin as Markdown that opens with its header; every hand-written page sits in exactly one tab section, with the title and description its page has; `/sitemap.md` lists every page; the old twins redirect; a missing page answers Markdown; the skills index lists every skill; and the docs MCP answers every tool with no sign-in and limits a caller past its budget. The same check runs against nuxt-backend.dev and the docs MCP's host every week.
