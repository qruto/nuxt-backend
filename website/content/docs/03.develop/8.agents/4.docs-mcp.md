The docs answer as an MCP server, for the coding agent that builds your app. Everything a client needs is one URL:

```text
https://mcp.nuxt-backend.dev/mcp
```

Transport is streamable HTTP, and there is nothing to authorize: no sign-in, no key. Every tool only reads, and every answer describes the release line these docs describe, the one the version chip in the header names.

Inside a project, the [developer MCP server](/docs/develop/agents/developer-mcp) answers the same searches and pages beside your project's state, so an agent there needs only that one. Connect the docs MCP for an agent outside a project, or one that only reads.

## Claude Code

```bash
claude mcp add --transport http nuxt-backend-docs https://mcp.nuxt-backend.dev/mcp
```

Add `--scope project` to write it into the project's `.mcp.json`, so everyone who opens the project gets it. `claude mcp list` shows it connected.

## Cursor

In `.cursor/mcp.json` for one project, or `~/.cursor/mcp.json` for every project:

```json [.cursor/mcp.json]
{
  "mcpServers": {
    "nuxt-backend-docs": {
      "url": "https://mcp.nuxt-backend.dev/mcp"
    }
  }
}
```

## VS Code

In `.vscode/mcp.json`, for Copilot's agent mode:

```json [.vscode/mcp.json]
{
  "servers": {
    "nuxt-backend-docs": {
      "type": "http",
      "url": "https://mcp.nuxt-backend.dev/mcp"
    }
  }
}
```

## Claude.ai and Claude Desktop

Open **Settings → Connectors → Add custom connector**, name it, and paste the URL. There is no OAuth step: the tools appear as soon as it connects.

## Any MCP client

Anything that speaks MCP over streamable HTTP works: point its HTTP transport at the URL, and send nothing else. The server is stateless:

- each request is a `POST` of one JSON-RPC message, answered with JSON rather than a stream; a batch answers `400`;
- it hands out no session, so `GET` and `DELETE` answer `405`;
- a call needs no `initialize` before it, though clients send one anyway.

```bash
curl -s https://mcp.nuxt-backend.dev/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get-diagnostic","arguments":{"id":"auth-secret"}}}'
```

Opened in a browser, the URL brings you to this page.

| `get-composable` | `name` | A composable or auto-imported helper: its tab, tier, summary and API page. |
| `get-component` | `name` | A component: what it is, its contract, its props and its accessibility. |
| `get-upgrade-guide` | `name` (optional) | The rename map: what an old name became, and the Upgrade section that explains it. |

`list-pages` and `get-page` are Docus's own docs tools, answering as Docus ships them, with their inputs bounded; `get-page` returns the same Markdown as the page's [twin](/docs/develop/agents/docs-for-agents#markdown-twins). The lookups answer from the same registries the reference pages are generated from, so a lookup says what its page says: [Diagnostics](/docs/reference/cli/diagnostics), [Environment variables](/docs/reference/configuration/environment-variables), [Composables](/docs/reference/nuxt/composables), the [component pages](/docs/reference/components), and the rename map of [Upgrade to 0.2](/docs/ship/releases/upgrade). A name a lookup doesn't have comes back as an error that lists the closest names it does.

The docs host serves an MCP server card of its own, `https://mcp.nuxt-backend.dev/.well-known/mcp/server-card.json`, which describes this server and lists the same tools.

## Limits

- **Rate:** 120 requests a minute per IP, in a window that opens with a request and runs a minute. A tool call is one request, and so are `initialize` and `tools/list`. After the first request of a window, each answer carries `x-ratelimit-limit`, `x-ratelimit-remaining` and `x-ratelimit-reset`, the last as a timestamp in milliseconds, and a request past the budget answers `429` until then. The limiter spends nothing on the request that opens an IP's first window, so that one window admits 121.
- **At the edge:** on nuxt-backend.dev, the Vercel Firewall also counts the docs MCP per IP, at the docs host's `/mcp` and at the site's `/api/docs-mcp` alike, with the same budget in fixed one-minute windows, across every server instance: past it, a request answers `429` with `retry-after` ([Deploy to Vercel](/docs/ship/deploy/vercel#rate-limit-at-the-edge)).
- **Size:** a request is one JSON-RPC message of 16 KiB at most, and every argument is bounded: a name, a path or a query is at most 200 characters.
- **Read-only:** no tool changes anything, and none takes anything but the name or words you pass it. The rate limit counts requests per IP for the window and keeps nothing else.

The site serves the same server at `/api/docs-mcp`, and the docs host answers from that route. The site's docs assistant reads the docs through that route too, in-process, under each visitor's own budget.

CI builds the site and calls every tool against the build, and checks that a caller past the budget gets `429` while another does not. The same check calls the live host every week.
