The package ships no MCP endpoint for your users' agents. The previews of `main` before `0.2.0` served one at `/mcp`: an agent such as Claude signed in as one of your users through OAuth, and called your app's tools with the scopes that person approved. That serves an app other software builds on, so it moves to a later release with the other service-app features. It returns there on Better Auth 1.7's own MCP plugin, with connected agents people can review and revoke ([Roadmap](/docs/start/roadmap#service-app-features)).

The agents that build your app are not affected: the skills, the agent files, the docs MCP and the developer MCP server are all in the package ([Build with agents](/docs/develop/agents)).

## What left with it

The endpoint and everything that only served it are gone:

| Left out | What it was |
|---|---|
| `/mcp` and `/mcp/exchange` | The endpoint, and the route that traded an agent's OAuth token for a Convex token |
| The agent-tool entry point | The built-in tools, and the helpers that wrote your own |
| The consent screen, its composable and its page | Where a person approved an agent's scopes |
| The `mcp` module option | The endpoint's route and server metadata |
| `scope` on `ai.meteredAction` and `ai.stream` | The scope an agent's token needed to spend credits |
| The `agents` capability and its `doctor` findings | `mcp-challenge`, `agent-discovery` and the consent and login path checks |

The [Upgrade page as `0.2.1` published it](https://github.com/qruto/nuxt-backend/blob/v0.2.1/website/content/docs/05.ship/6.releases/4.upgrade.md#the-mcp-endpoint-for-your-users-agents-waits-for-the-next-release) says what to do with each name in an app that used it. The coding-agent findings, `agent-files` and `agent-docs`, stay: they check the files and the docs that guide the agent that builds your app.

## What this means for you

- **A person's spend is always their own.** No function the package ships accepts an agent's token, so every credit is spent by a person in your app.
- **Your own integration is still yours to build.** A Nuxt server route or a Convex HTTP action can serve an MCP server of your own, with the auth you choose. The package does not check it for you until the endpoint returns.
- **Coding agents keep their tools.** For the agent that builds your app, use the [developer MCP server](/docs/develop/agents/developer-mcp) and the [docs MCP](/docs/develop/agents/docs-mcp).
