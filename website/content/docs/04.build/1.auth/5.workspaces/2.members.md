A workspace's owner and admins decide who belongs to it and in which role. `useWorkspace()` lists the active workspace's members and changes them, so a team page of your own takes a few lines. People join by [invitation](/docs/build/auth/workspaces/invitations), and leave when they choose or when an owner or admin removes them.

Better Auth's organization plugin keeps the members and checks who may change them. The package adds the actions on `useWorkspace()`, the recent sign-in they take, and a removal that locks the person out on their next call.

## Build a team page

```vue [app/pages/team.vue]
<script setup lang="ts">
definePageMeta({ auth: true })

const { members, role, updateMemberRole, removeMember, error } = useWorkspace()
const { withReauthentication } = useReauthentication()
const manages = computed(() => role.value === 'owner' || role.value === 'admin')
</script>

<template>
  <ul>
    <li v-for="member in members" :key="member.id">
      {{ member.user.name }} · {{ member.role }}
      <template v-if="manages && member.role !== 'owner'">
        <button type="button" @click="withReauthentication(() => updateMemberRole(member.id, 'admin'))">Make {{ member.user.name }} an admin</button>
        <button type="button" @click="withReauthentication(() => removeMember(member.id))">Remove {{ member.user.name }}</button>
      </template>
    </li>
  </ul>
  <p v-if="error" role="alert">{{ error.message }}</p>
</template>
```

Each member carries `id`, `role`, `createdAt` and `user` (`id`, `name`, `email`, `image`).

| Action of `useWorkspace()` | Who | Does |
|---|---|---|
| `members` | every member | The active workspace's members, live. |
| `updateMemberRole(memberId, role)` | owner, admin | Gives a member another built-in role: `owner`, `admin` or `member`. |
| `removeMember(memberId)` | owner, admin | Takes a member out of the workspace. |
| `leave(workspaceId?)` | every member | Leaves a workspace, the active one by default. |

## What each change does

- **Changing a role and removing a member take a [recent sign-in](/docs/build/auth/access/step-up).** Wrap the call in `withReauthentication`, as above.
- **A removal is immediate.** The `workspace` tier reads membership fresh on every call, so a removed member's next call is refused, and their active workspace is cleared.
- **A workspace always keeps an owner.** Better Auth refuses a change that would leave it without one, so the last owner can neither leave nor lose the role.
- **An administrator's visit** can read the members and change nothing.
- **Every change is recorded** on the [activity trail](/docs/build/auth/admin/audit-log) the workspace's owners and admins read on `/settings`.

A role is never a seat: members are free, and nothing counts them for billing. The owner and admins manage the workspace's plan and credits ([Give people roles](/docs/build/auth/access/roles#workspace-roles)).

## What waits for the next release

Roles an owner defines, moving ownership to another member, billing as a permission inside roles, and shareable links into a workspace are features of service apps. They arrive with the next release ([Roadmap](/docs/start/roadmap#service-app-features)).
