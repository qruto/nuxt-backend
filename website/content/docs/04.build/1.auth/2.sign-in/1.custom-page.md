Your sign-in page is the first screen of your brand most people see. Put an app page at `/login` and it replaces the module's: the module detects it, skips its own and logs the override. To serve sign-in at another path, also set [`pages.login`](/docs/reference/configuration/module-options), so guarded pages send signed-out visitors there.

Better Auth ships no sign-in UI. The package ships `<AuthForm>` and the `useLoginFlow()` step machine under it, and lets you take over as much as you need, one rung of the [customization ladder](/docs/build/ui/customize) at a time:

| Rung | What you change | Where |
|---|---|---|
| Mount | Nothing: `/login` is there | [Sign users in](/docs/build/auth/sign-in#use-the-ready-made-page) |
| Tokens | Colors, radius, type, through `--bk-*` on `:root` and the `data-auth` hooks | [Restyle with tokens](/docs/build/ui/customize/tokens) |
| Labels | Every word, in every language | [Change copy and labels](/docs/build/ui/customize/labels) |
| Slots | One region of the form | [below](#restyle-authform-through-its-slots) |
| Swap a part | One part everywhere, such as `AuthFormCode` | [below](#swap-one-part) |
| Composables | Every element, on `useLoginFlow()` and its bindings | [below](#write-your-own-markup-on-useloginflow) |
| Eject | A copy of the source you own | [below](#eject-the-form) |

The playground's own [/login](/login) stops at slots. To drop the package's CSS entirely, see the [Customization ladder](/docs/build/ui/customize).

## Restyle `<AuthForm>` through its slots

Each slot receives the whole flow, the object `useLoginFlow()` returns, as its props. The props are refs, so read `.value` inside a slot.

| Slot | Replaces |
|---|---|
| `header` | The logo and the title. |
| `choose` | The first step: the passkey button and "Continue with email", with the last method marked "Last used". |
| `request-code` | The email field. Keep `autocomplete="username webauthn"` on it, where the browser offers saved passkeys. |
| `verify-code` | The code field. |
| `passkey-offer` | The offer to save a passkey after a code, and the passkey a recovery requires. |
| `age`, `recover`, `undeliverable`, `waitlisted`, `invite-code` | The `0.2.0` steps of [Sign users in](/docs/build/auth/sign-in#the-steps). |
| `error` | Why the last step failed. It renders only while `error` is set. |
| `footer` | Below everything. |

```vue [app/pages/login.vue]
<script setup lang="ts">
definePageMeta({ layout: false })

function done() {
  return navigateTo(resolveAuthRedirect(useRoute().query.redirect, '/strips'))
}
</script>

<template>
  <main class="sign-in">
    <AuthForm @success="done">
      <template #header>
        <img src="/logo.svg" alt="Panels">
      </template>
      <template #error="{ error, retryAfter }">
        <p role="alert">
          {{ error.value?.message }}
          <span v-if="retryAfter.value">Try again in {{ retryAfter.value }} seconds.</span>
        </p>
      </template>
    </AuthForm>
  </main>
</template>
```

`<AuthForm>` emits three events. `success` fires once the person is signed in and has saved or skipped a passkey. `step` fires on every step change, and `error` carries the message of a failed step.

## Swap one part

Every region of `<AuthForm>` is a registered part. An app component with the same name, in `app/components/`, replaces it everywhere the form renders, the packaged `/login` and the "Confirm it's you" dialog included.

| Part | Renders |
|---|---|
| `AuthFormHeader` | The logo and the title. |
| `AuthFormChoose` | The first step's buttons. |
| `AuthFormEmail` | The email field and its button. |
| `AuthFormCode` | The code field and its button. |
| `AuthFormPasskey` | The passkey button and its "Last used" badge. |
| `AuthFormPasskeyOffer` | The offer to save a passkey after a code sign-in. |
| `AuthFormError` | The failure message. |

A part receives the flow as props, the same object a slot gets, and its bindings carry the accessibility attributes:

```vue [app/components/AuthFormCode.vue]
<script setup lang="ts">
import type { UseLoginFlowReturn } from 'nuxt-backend'

const props = defineProps<{ flow: UseLoginFlowReturn }>()
</script>

<template>
  <label class="code">
    Code from your email
    <input v-bind="props.flow.bind.codeInput" class="code-input">
  </label>
</template>
```

`doctor` lists every app component that shares a name with a part, so you know which ones you swapped ([Swap a part](/docs/build/ui/customize/parts)).

## Write your own markup on `useLoginFlow()`

`useLoginFlow()` holds the steps, the fields, `isPending` and `error`. [Sign users in](/docs/build/auth/sign-in#drive-the-flow-from-your-own-page) has a complete page and every field it returns. A page of your own has four things to keep.

### Send the person back

A guarded page puts the page the person wanted in `?redirect=`. Never navigate to it as given. `resolveAuthRedirect` (auto-imported) keeps it when it is a path of this site, and returns your fallback otherwise:

```ts [app/pages/login.vue]
const flow = useLoginFlow({
  onSuccess: () => navigateTo(resolveAuthRedirect(useRoute().query.redirect, '/strips')),
})
```

The module's own page falls back to [`redirects.afterSignIn`](/docs/reference/configuration/module-options). Read it from `useRuntimeConfig().public.backend.redirects.afterSignIn` to keep one setting for both.

### Render every step

The flow can land on any step of [the step table](/docs/build/auth/sign-in#the-steps), so give each one markup, `0.2.0`'s `undeliverable`, `waitlisted` and `invite-code` included. A failed step stays where it is, with the reason in `error`. Show `error.message`, and branch on `error.code` where a failure needs its own words:

```vue [app/pages/login.vue]
<template>
  <p v-if="error?.code === 'rate_limited' && retryAfter">Too many tries. Wait {{ retryAfter }} seconds.</p>
  <p v-else-if="error" role="alert">{{ error.message }}</p>
</template>
```

After a code, the flow stops at `passkey-offer`. It calls `onSuccess` only once the person saves a passkey (`addPasskey()`) or declines (`skipPasskey()`). Render that step, or call `skipPasskey()` yourself. In `0.2.0` the flow skips the offer on its own in a browser without a passkey provider, and after a recovery `passkeyRequired` hides "Not now" ([The passkey offer](/docs/build/auth/sign-in#the-passkey-offer)).

### Keep passkey autofill

`useLoginFlow({ autofill: true })` offers saved passkeys in the email field's autofill, and `preferLastMethod: true` opens the page on the way this browser last signed in. The flow asks the browser only when the email field's `autocomplete` ends in `webauthn`:

```vue [app/pages/login.vue]
<template>
  <input v-model="email" type="email" autocomplete="username webauthn">
</template>
```

Mark the button of `lastMethod` (`'passkey'` or `'email-otp'`) "Last used". [Passkey autofill](/docs/build/auth/sign-in#passkey-autofill) has a complete page and what the person sees.

### Leave when already signed in

A person who is already signed in and opens the page should move on. Watch `isSignedIn` from `useAuth()`, and send them on from the `choose` and `request-code` steps only. During a code sign-in the person is signed in before the passkey offer, and leaving then would skip it. A passkey picked from autofill signs in on `request-code` and calls `onSuccess` too, so send the person on once, whichever comes first.

## Eject the form

When slots and parts aren't enough, copy the source into your app and own it.

```bash
npx nuxt-backend eject AuthForm
```

It writes `app/components/AuthForm.vue` and its CSS, stamped with the package version. Your copy wins, as a swapped part does. `npx nuxt-backend upgrade` later shows what changed in the package's version since the stamp, so you can carry fixes over by hand ([Eject a part, page or email](/docs/build/ui/customize/eject)).

## Verify

1. Sign out, open a page guarded with `definePageMeta({ auth: true })`, and check you land on your page with `?redirect=` set.
2. Sign in with a code: the page offers a passkey, then returns you to the guarded page.
3. Open the page with `?redirect=https://example.com`. After sign-in you land on your fallback, not on another site.
4. Sign out after a passkey sign-in and open the page again. The passkey button is marked "Last used", and the email field offers the passkey.

## If it fails

- **The module's page still renders.** Your page must sit at the exact path `pages.login` resolves to (`/login` by default). The dev server logs `App page at /login overrides the built-in login page` when it does.
- **The email field offers no passkey.** Its `autocomplete` does not end in `webauthn`, the flow was made without `autofill: true`, or the browser has no conditional mediation. The passkey button still works there.
- **A step shows nothing.** The page has no markup for it. Render every step of the table, or keep `<AuthForm>` and fill only the slots you change.
