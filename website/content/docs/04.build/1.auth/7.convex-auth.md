Better Auth is the package's auth, and stays the default: every page, the page guard, workspaces, billing, AI credits and the account features run on its accounts. An app that wants [Convex Auth](https://docs.convex.dev/auth/convex-auth) instead can switch to it, for sign-in only. The package then runs nuxt-convex-module's own Convex Auth integration and turns off what Better Auth carries, rather than rebuilding it on Convex Auth. It is experimental ([Stability](/docs/ship/releases/stability)).

## Turn it on

```bash
pnpm add @convex-dev/auth
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    auth: 'convex-auth',
  },
})
```

The base module then gets `betterAuth: false` and `convexAuth: { loginPath }`, its Polar integration off, and the package's sign-in path as the page its `convex-auth` middleware redirects to (`backend.pages.login`, `/login` by default). Without `@convex-dev/auth` installed, the base module says so at startup.

## Set up the backend

Follow [Convex Auth's setup](https://docs.convex.dev/auth/convex-auth): its component in `backend/convex.config.ts`, an `auth.ts` with the sign-in methods you want, and the keys `npx @convex-dev/auth` sets on the deployment. `@convex-dev/auth` signs people in with emailed magic links, OAuth providers (Google, Apple, GitHub, Discord), passkeys and passwords.

Then wire the Nuxt side as nuxt-convex-module's [Convex Auth guide](https://nuxt-convex-module.dev/components/convex-auth) shows. For an app that renders on the server, that is one file, `server/convex-auth.ts`, whose `setupConvexAuthNuxt` lists the functions that start a session. Its sign-in composables (`useSendEmailMagicLink`, `useSignInWithGithub`, `useSignInWithUsernamePasskey`, …), `useAuthActions` and `<ConvexAuthProvider>` stay registered in this mode: the package hides the base module's brand-named surface in a Better Auth app, but not that one.

## Guard a page

The package's page guard, `definePageMeta({ auth })`, reads the Better Auth session, so it is not registered. Use the base module's middleware:

```vue [app/pages/studio.vue]
<script setup lang="ts">
definePageMeta({ middleware: 'convex-auth' })
</script>
```

In a backend function, read the account with `getAuthUserId(ctx)` from `@convex-dev/auth/server`. The package's tiers (`authed`, `workspace`, `admin`) are written for Better Auth's accounts: leave them out in this mode.

## What is off

| Off in this mode | Why |
|---|---|
| The ready-made pages (`/login`, `/profile`, `/security`, `/settings`, `/pricing`, `/admin`, …) | Each reads the Better Auth session. Write your own sign-in page with the base module's composables. |
| The page guard and its 403 page | It reads the Better Auth session. |
| `useAuth()` and the Nitro `backendAuth(event)` | Both are the Better Auth session. `useAuthActions()` and `setupConvexAuthNuxt` stand in. |
| Workspaces, roles, the admin console and impersonation | They are Better Auth's organization and admin plugins. |
| Billing, gifts and AI credits | They belong to a Better Auth account and its workspace. |
| The account features: export, deletion, sessions, sign-in alerts, consents | They run on Better Auth's account and session tables. |
| The startup preflight of `AUTH_SECRET` and `SITE_URL` | They are Better Auth's. Startup says once which mode runs instead. |

`npx nuxt-backend doctor` reports the mode as [`auth-provider`](/docs/reference/cli/diagnostics#auth-provider), and says that its checks of `AUTH_SECRET`, the sign-in pages and the features above do not apply.
