Every Convex function you export can be called by anyone who reaches your deployment. So declare each one at the tier it needs. `backend/functions.ts` calls `createFunctions` once and exports one builder per tier, and each builder checks the caller before your handler runs. A function's access is part of how you write it, and a forgotten check can't hide in a handler.

## Create the tiers

The scaffold writes `backend/functions.ts`:

```ts [backend/functions.ts]
import { createFunctions } from 'nuxt-backend/functions'
import { billing } from './billing'
import { rateLimiter } from './rateLimiter'
import { components } from './_generated/api'
import { action, mutation, query } from './_generated/server'

export const { authed, workspace, admin, withRole, withFeature, setUserRole } = createFunctions(
  { query, mutation, action },
  { components, billing, rateLimiter },
)
```

Each tier is a drop-in `{ query, mutation, action }`. Write your functions with it instead of `_generated/server`:

```ts [backend/strips.ts]
import { v } from 'convex/values'
import { authed, workspace } from './functions'

export const mine = authed.query({
  args: {},
  handler: async ctx => ctx.db.query('strips')
    .withIndex('authorId', q => q.eq('authorId', ctx.user.id))
    .take(50),
})

export const create = workspace.mutation({
  args: { title: v.string() },
  handler: async (ctx, { title }) =>
    ctx.db.insert('strips', { title, authorId: ctx.user.id, workspaceId: ctx.workspace.id }),
})
```

## The tiers

| Tier | Lets in | Adds to `ctx` |
|---|---|---|
| `authed` | A signed-in person who is not banned. Queries read the token. Mutations and actions read the account fresh, so a ban lands on the next write. | `ctx.user` |
| `workspace` | A member of the active workspace, read fresh on every call, so a removed member is refused at once. | `ctx.user`, `ctx.workspace` (`{ id, slug, name, role }`) |
| `admin` | An app-wide administrator, the role read fresh on every call. Its writes refuse an administrator's visit to another account, and take a [recent sign-in](/docs/build/auth/access/step-up). | `ctx.user` |
| `withRole(role)` | A person with an app-wide role of yours, such as `withRole('editor')`. | `ctx.user` |
| `withFeature(key)` | A `workspace` member whose plan includes the feature. Others are refused `feature_required`, with the plans that include it ([Gate features by plan](/docs/build/billing/subscriptions/feature-gating#enforce-it-on-the-server)). | `ctx.user`, `ctx.workspace` |

`ctx.user` holds `id`, `email`, `name` and `role`, and `signInMethod`: how the person signed in to this session, `'passkey'` or `'email-otp'`. It is the session's own method, so a code used in another browser never changes it. It is `null` while an administrator visits the account. A refusal is a [catalog error](/docs/reference/backend/errors) the page reads with `getBackendError`: `unauthenticated` when signed out, `forbidden` with a reason otherwise, `no_workspace` without an active workspace.

`setUserRole` is an internal mutation, never callable from a browser. It makes your first administrator ([Run the admin console](/docs/build/auth/admin#make-the-first-administrator)).

## Its options

| Option | What it does |
|---|---|
| `components` | Your generated `components`: the tiers read the `backend` component's tables. |
| `billing` | Your `setupBilling` instance. It enables `withFeature`. |
| `rateLimiter`, `limits` | Your `setupRateLimiter` instance, and a limit name per tier: `{ authed: 'write' }` spends the `write` limit, keyed by user, on every mutation and action of the tier. Declare `write` in `backend/rateLimiter.ts` ([Tune rate limits](/docs/ship/security/rate-limits)). |
| `adminRoles` | The roles the `admin` tier lets in. Default `['admin']`. |

To keep [aggregate](/docs/build/data/read-write/aggregates) triggers running on every write, pass your `withTriggers`-wrapped `mutation` in place of the generated one.

## Ask more of one function

Two options sit beside `args` and `handler` in a function's definition:

- **`recentSignIn`**: `true` takes a sign-in from the last ten minutes, a number takes one from that many seconds. The `admin` tier's writes take it by default, and `recentSignIn: false` lifts it for a routine one ([Require a recent sign-in](/docs/build/auth/access/step-up#ask-in-your-own-functions)).
- **`impersonation: 'refused'`**: refuses an administrator's visit to the account (`forbidden`, reason `impersonating`). Use it where a person's money or access is at stake ([Impersonation](/docs/build/auth/admin/impersonation)).

```ts [backend/strips.ts]
import { v } from 'convex/values'
import { workspace } from './functions'

export const publish = workspace.mutation({
  recentSignIn: true,
  impersonation: 'refused',
  args: { stripId: v.id('strips') },
  handler: async (ctx, { stripId }) => {
    await ctx.db.patch('strips', stripId, { publishedAt: Date.now() })
  },
})
```

## Which one to reach for

- **Data a person owns:** `authed`, and filter by `ctx.user.id`.
- **Data a workspace owns:** `workspace`, and filter by `ctx.workspace.id` ([Scope tables to a workspace](/docs/build/data/read-write/workspace-scoped)).
- **A step that needs a passkey sign-in:** check `ctx.user.signInMethod === 'passkey'` in the handler, and refuse any other session with a `forbidden` reason of your own.
- **A step only a workspace's owner may take:** `workspace`, then check `ctx.workspace.role` in the handler and `throw backendError('forbidden', { reason: 'role' })`.
- **Operations on other people's accounts, or anything that moves money or mails typed addresses:** `admin`.
- **A role of your own across the app:** `withRole('editor')`.
- **A function a plan's feature unlocks:** `withFeature('hd-export')`.

A function nobody outside the deployment should call is an `internalQuery`, `internalMutation` or `internalAction` instead. The scaffold sends its emails that way.

## What happens when…

| Refused with | When |
|---|---|
| [`unauthenticated`](/docs/reference/backend/errors#unauthenticated) | Nobody is signed in. |
| [`forbidden`](/docs/reference/backend/errors#forbidden), reason `banned` | The account is banned. Writes read it fresh, so a ban lands on the next one. |
| `forbidden`, reason `role` | The caller lacks the tier's role: `admin`, or the one `withRole` names. |
| `forbidden`, reason `impersonating` | An administrator's visit calls an `admin` write, or a function with `impersonation: 'refused'`. |
| [`no_workspace`](/docs/reference/backend/errors#no_workspace) | A `workspace` or `withFeature` function, called without an active workspace the caller belongs to. |
| [`feature_required`](/docs/reference/backend/errors#feature_required) | A `withFeature` function, and the workspace's plan lacks the feature. `data.plans` lists those that have it. |
| [`reauthentication_required`](/docs/reference/backend/errors#reauthentication_required) | A `recentSignIn` function, with an older sign-in. |
| [`rate_limited`](/docs/reference/backend/errors#rate_limited) | The tier's `limits` entry ran out for this caller. |

The page reads each one with `getBackendError` ([Handle errors](/docs/build/data/read-write/errors)).

## Test it

`asUser` signs a test in as a fresh account with its own workspace ([Test backend functions](/docs/develop/testing/functions)):

```ts [backend/strips.test.ts]
import { asUser, defineBackendTestApp } from 'nuxt-backend/test'
import { expect, test } from 'vitest'
import { api } from './_generated/api'
import schema from './schema'

const testApp = defineBackendTestApp(schema, import.meta.glob('./**/*.ts'))

test('a strip belongs to the caller\'s workspace', async () => {
  const t = testApp()
  const ada = await asUser(t)
  await ada.mutation(api.strips.create, { title: 'Monday' })
  await expect(t.mutation(api.strips.create, { title: 'Anonymous' })).rejects.toThrow()
})
```
