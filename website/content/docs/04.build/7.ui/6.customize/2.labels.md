Module options own the *wiring*: where the pages mount and where they send a person once done. `appConfig.backend` owns the *content*: the plan catalog's copy, the brand and every label. It is reactive, reloads with HMR, and is typed, so your editor completes every key.

```ts [app.config.ts]
export default defineAppConfig({
  backend: {
    billing: {
      // Each `key` is a key of your billing catalog. Names, prices, trials and
      // credits always come live from billing, so the page cannot drift.
      plans: [
        { key: 'starter', blurb: 'For trying things out.' },
        { key: 'pro', blurb: 'For products finding their feet.', features: ['Priority support'], highlight: true },
      ],
      packs: [
        { key: 'credits100' },
        { key: 'credits500', blurb: 'For a busy month.' },
      ],
    },
    brand: { name: 'Panels', logo: '/logo.svg' },
    labels: {
      auth: { title: 'Welcome back', sendCode: 'Send me a code' },
      pricing: { subscribe: 'Get started', topUp: 'Add credits' },
      errors: { rate_limited: 'Slow down a little, then try again.' },
    },
  },
})
```

## Where a label comes from

Every word a packaged component or page renders is a label: a message in a group, under a key. Each key resolves on its own, and the first source that has it wins:

1. the component's `labels` prop;
2. `appConfig.backend.labels.<group>.<key>`;
3. the `backend.<group>.<key>` message of `@nuxtjs/i18n` in the active locale ([Translate the UI](/docs/build/ui/customize/translation));
4. the package's English default.

So an override stays partial: set one key, and the rest of the group keeps its defaults and its translations. App config holds one language, so an app that translates puts its copy in its messages instead, where each locale has its own.

The `labels` prop changes one placement only:

```vue
<AuthForm :labels="{ sendCode: 'Get my code', emailCode: 'Use an email code' }" />
```

## Messages

A label is a vue-i18n message, so it moves into an app's messages unchanged:

- `{name}` fills in a value: `auth.sent` is `'We sent a code to {email}.'`;
- `|` separates plural forms, and `count` picks one: `usage.units` is `'{count} credit | {count} credits'`;
- some params are nodes, not text: in `invitation.invited`, `{inviter}` and `{workspace}` render as `<strong>`, wherever the message puts them.

The syntax is that much of vue-i18n's and no more: `{name}` written without spaces, and `|` between forms. Linked messages (`@:key`) and literals (`{'…'}`) are not read in app config or the `labels` prop.

A missing param stays as written, so a typo shows up instead of vanishing, and in development an override that leaves out a param its English message fills (`'Upgrade to'` where the message is `'Upgrade to {plan}'`) is named in the console. An empty message renders nothing: `history.title` and `usage.title` are empty, so those components show no heading until you set one.

## The groups

One group per packaged component. Its page reads the same group, and the page's heading and document title is the group's `title`. [Labels](/docs/reference/configuration/labels) lists every key of every group with its English default, its params and its plural forms.

| Group | Renders | Notes |
|---|---|---|
| `auth` | `<AuthForm>` and `/login` | `title`, or `titleBrand` (`'Sign in to {brand}'`) once `brand.name` is set |
| `profile` | `<ProfileSettings>` and `/profile` | the email change's steps and hints; `roles.<role>` |
| `security` | `<SecuritySettings>` and `/security` | `renameNamed`, `removeNamed` and `revokeNamed` are the row buttons' accessible names, each starting with the visible label it names; `device`, `browser` and `deviceTypes.<type>` word a session's device and a passkey's kind |
| `account` | `<AccountData>`, on `/security` | the export and the deletion |
| `reauthenticate` | `<ReauthenticateDialog>` | the "Confirm it's you" dialog a sensitive action opens |
| `invitation` | `<AcceptInvitation>` and `/accept-invitation` | `roles.<role>` |
| `pricing` | `<PricingTable>` and `/pricing` | `trial.day`, `trial.week`, `trial.month` and `trial.year` |
| `settings` | `<WorkspaceSettings>` and `/settings` | |
| `history` | `<BillingHistory>` | `statuses.<status>` |
| `usage` | `<UsageHistory>` | |
| `audit` | `<AuditLog>` | one sentence per event kind under `events`, who acted under `actors` |
| `admin` | `<AdminUsers>`, `<AdminWorkspaces>` and `/admin` | the tab names under `tabs`, app-wide roles under `roles`, a workspace's under `workspaceRoles`, the Flags and System tabs under `flags` and `system` |
| `impersonation` | The `impersonation` notice of `<BackendNotices>` | whose account an administrator is acting as, and when the visit ends |
| `maintenance` | The `maintenance` notice of `<BackendNotices>` | the default sentence, which an administrator's own message replaces |
| `announcement` | The `announcement` notice of `<BackendNotices>` | its name, a link's default words and the **Dismiss** button; the announcement itself is the administrator's words |
| `credits` | The `low-credits` notice of `<BackendNotices>` | `low` takes `{balance}`, which is also its count |
| `upgrade` | `<UpgradePrompt>` | `availableOn` takes `{plans}`, the plans' names joined in the active locale's words; `upgrade` takes `{plan}` |
| `quota` | `<Gate quota>` (experimental) | `reached` takes `{used}`, `{limit}` and `{quota}`, the quota's name; `notIncluded` takes `{quota}`; `availableOn` and `upgrade` as in `upgrade` |
| `gift` | The `gift` notice of `<BackendNotices>` | |
| `access` | `<AccessDenied>` | `message`, `messageWorkspace` and `messageBanned` follow the rule the page guard refused |
| `connection` | `<ConnectionStatus>`, on every page | `pending` takes the waiting changes as `{count}` |
| `errors` | every component's failure message | by error code; `<code>_<reason>` for one reason, `invalid_input_<field>` for one field |
| `email` | the emails the package sends | not in app config: emails render on the backend ([Send email in each reader's language](/docs/build/email/templates/languages)) |

A refusal is worded by its reason, then its field, then its code, first from your own sources (props, app config, your locale's messages) and only then from the package's English: a locale that words only `errors.forbidden` shows that sentence for every reason, rather than English for the reasons the package words.

With 0.2.0, the `agents` group leaves with the consent screen, the gate and the notices region keep the `quota`, `impersonation`, `maintenance`, `credits` and `gift` groups, and the components that arrive bring groups of their own ([Show app-wide notices](/docs/build/ui/notices)).

A status, a role or a kind the server names without a label of its own (an app's custom role, say) shows as it came. The keys and their params are stable ([Stability](/docs/ship/releases/stability)); the English wording is not, so pin a sentence by overriding its key.

## The full shape

Every key `appConfig.backend` takes. [App config](/docs/reference/configuration/app-config) lists the same keys with their types and defaults.

::field-group
  :::field{name="billing.plans" type="PricingPlan[]"}
  The plan cards `<PricingTable>` shows, in order, and their copy: `key` (the catalog key, required), `blurb`, `features` (display only, since grants come from billing; by default the names of the plan's feature benefits), `highlight`. Names, prices, trials and credits come live from `getPricing`. Empty: every plan on sale, in catalog order.
  :::

  :::field{name="billing.packs" type="CreditPack[]"}
  The credit packs `<PricingTable>` and `<WorkspaceSettings>` show, in order: `key`, `blurb`. Empty: every pack on sale.
  :::

  :::field{name="billing.contact" type="PricingContact"}
  A card after the plans for what you sell in person: `name`, `blurb`, `features`, `href` (a page or a `mailto:` address) and `label` (default: the `pricing.contact` label). None by default. See [Customize the pricing page](/docs/build/billing/pricing-page#a-contact-card).
  :::

  :::field{name="billing.lowCreditsThreshold" type="number" default="10"}
  The balance under which the low-credits notice of `<BackendNotices>` appears: one number for the whole app; its `threshold` prop overrides it per placement.
  :::

  :::field{name="consent.purposes" type="StoragePurpose[]" default="[]"}
  The purposes of optional storage the app uses: `preferences` (the last-sign-in-method cookie behind **Last used**, and a dismissed upgrade prompt kept past the tab), `replay` (session replay in error monitoring, which listing it turns on) and `analytics`. `<ConsentPrompt>` asks about them once per browser, each off until allowed. Empty: the app uses only strictly necessary storage, and the consent manager stays off. See [Ask before optional storage](/docs/build/auth/accounts/consents#ask-before-optional-storage).
  :::

  :::field{name="monitoring.feedback" type="boolean" default="false"}
  Show the error-reporting service's feedback widget: a **Report a problem** button whose report reaches the monitoring service, asking for no name, address or screenshot. Needs the SDK and a DSN. See [What the preset does](/docs/ship/operate/monitoring#what-the-preset-does).
  :::

  :::field{name="legal.company" type="string"}
  Your legal entity's name, which the packaged privacy, terms and accessibility pages name as the controller of your users' data ([Legal pages](/docs/ship/compliance/privacy#legal-pages)).
  :::

  :::field{name="legal.address" type="string"}
  Its postal address, on the privacy page.
  :::

  :::field{name="legal.contact" type="string"}
  Where people send privacy requests and report an accessibility barrier: an email address or a URL.
  :::

  :::field{name="legal.dpo" type="string"}
  Your data protection officer's contact, on the privacy page. Leave it out when you need none.
  :::

  :::field{name="legal.host" type="LegalHost"}
  The host your app runs on, when it is not Vercel: `{ name, location, agreement }`. The privacy and subprocessor pages list it in place of Vercel's row.
  :::

  :::field{name="brand.name" type="string"}
  Product name in shipped copy: the sign-in heading becomes the `auth.titleBrand` label ("Sign in to {brand}") unless `labels.auth.title` sets it outright.
  :::

  :::field{name="brand.logo" type="string"}
  Logo URL. `<AuthForm>` renders it above its heading (`[data-auth='logo']`).
  :::

  :::field{name="brand.address" type="string"}
  The sender's postal address, in the footer of every email under a topic and every announcement. The module writes the brand to `backend/brand.generated.ts`, so the emails read the same name, logo and address ([Write the brand once](/docs/build/email/templates/theme#write-the-brand-once)).
  :::

  :::field{name="labels.auth" type="LabelOverrides<BackendLabels['auth']>"}
  The sign-in form and page.
  :::

  :::field{name="labels.profile" type="LabelOverrides<BackendLabels['profile']>"}
  `<ProfileSettings>` and the profile page.
  :::

  :::field{name="labels.security" type="LabelOverrides<BackendLabels['security']>"}
  `<SecuritySettings>` and the security page.
  :::

  :::field{name="labels.account" type="LabelOverrides<BackendLabels['account']>"}
  `<AccountData>`: the account's export and its deletion, on the security page.
  :::

  :::field{name="labels.reauthenticate" type="LabelOverrides<BackendLabels['reauthenticate']>"}

  :::

  :::field{name="labels.invitation" type="LabelOverrides<BackendLabels['invitation']>"}

  :::field{name="labels.pricing" type="LabelOverrides<BackendLabels['pricing']>"}

## Use the labels in your own components

A page you rebuild from the composables can keep the package's copy, with its overrides and translations, through the auto-imported `useLabels(group)`:

```vue [app/pages/sign-in.vue]
<script setup lang="ts">
const flow = useLoginFlow()
const { t, errorMessage } = useLabels('auth')
</script>

<template>
  <form @submit.prevent="flow.isPending.value || flow.sendCode()">
    <label>{{ t('email') }} <input v-model="flow.email.value" type="email"></label>
    <button :aria-disabled="flow.isPending.value || undefined">
      {{ flow.isPending.value ? t('sending') : t('sendCode') }}
    </button>
    <p v-if="flow.error.value" role="alert">{{ errorMessage(flow.error.value) }}</p>
  </form>
</template>
```

`t(key, params)` fills a label in; `rich(key, params)` returns it as render-function children, with a node wherever a param is one; `errorMessage(error)` words a failure through the `errors` group; `locale` is the active `@nuxtjs/i18n` locale, for dates and numbers. Read `appConfig.backend` itself with `useBackendConfig()`, and link to a packaged page with `useBackendPagePath('pricing')`.
