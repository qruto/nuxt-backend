Give every plan card your own design, on `/pricing` and wherever else `<PricingTable>` renders, with one file. Every region of a packaged page or component is a registered part with a name, such as `PricingPlanCard` or `AuthFormCode`. Nuxt already lets an app component shadow a module's component of the same name; the package builds its pages from parts by name, so your component replaces the part everywhere, and receives the same props the packaged one did.

## Swap a part

Create a component in `app/components/` with the part's name. This one replaces each plan card of `<PricingTable>`:

```vue [app/components/PricingPlanCard.vue]
<script setup lang="ts">
import type { PricingPlanCardProps } from '#backend/parts'

const { pricing, plan } = defineProps<PricingPlanCardProps>()
const { t } = useLabels('pricing')
</script>

<template>
  <article v-bind="pricing.bind.planCard(plan)" class="plan">
    <h3>{{ plan.name }}</h3>
    <p class="price">{{ plan.price }}</p>
    <ul>
      <li v-for="feature in plan.features" :key="feature">{{ feature }}</li>
    </ul>
    <button v-bind="pricing.bind.planAction(plan)">{{ t('subscribe') }}</button>
  </article>
</template>
```

A part receives the same props as the packaged one: the parent's headless composable (`pricing`, the `usePricing()` state) and the item it renders (`plan`). The bindings come from that composable, the same attribute and handler bags the packaged part spreads on its own elements. `pricing.bind.planCard(plan)` names the card's group, and `pricing.bind.planAction(plan)` carries the click handler, the `aria-disabled` while a checkout opens and the description that names the plan, so the button stays accessible without a line of ARIA from you. `PricingPlanCardProps` comes from `#backend/parts`, which types every part. The packaged part's stylesheet stops loading once yours takes its name, so your component brings its own styles, and the tokens still reach it.

Run `npx nuxt-backend doctor`: its name-collision finding lists every part you swapped, so a component that shadows one by accident does not go unnoticed.

## Show it in a page

Nothing to change: `/pricing` and every `<PricingTable>` in your pages now render your card. To use your card in one placement only, give it another name and fill the `plan` [slot](/docs/build/ui/customize/slots) there instead.

| Some parts | Part of | Region |
|---|---|---|
| `AuthFormCode`, `AuthFormPasskey` | `<AuthForm>` | The code step, the passkey button |
| `PricingPlanCard`, `PricingPeriodSwitch` | `<PricingTable>` | A plan card, the monthly and yearly switch |
| `AdminUsersTable` | `<AdminUsers>` | The accounts table |

[Parts](/docs/reference/components/parts) lists every part with its props, slots and the pages that use it.

## Replace a page

Every packaged page mounts, and three ways change one: move it, put a page of yours at its path, or turn it off. The module keeps mounting the pages you did not touch.

### Move a page

The [`pages` module option](/docs/build/ui/pages#move-a-page) gives a page another path:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    pages: {
      pricing: '/plans',      // the packaged pricing page, at /plans
      login: '/auth/sign-in', // and the sign-in page; every page guard follows it
    },
  },
})
```

Each path is declared once, there: the auth route, the guards and the invitation emails read it. `pages.<key>: false` turns a page off, for a page you serve somewhere else or a feature you do not offer.

### Put your own page at its path

An app page at a packaged path replaces it: the module detects it, mounts nothing there and logs the override. To bring your own profile page, add `app/pages/profile.vue`. It can keep the packaged component and fill a slot, or render something else entirely.

The guard does not come with the path: the module puts it on its own page only. A page of yours in place of a private one declares it:

```vue [app/pages/profile.vue]
<script setup lang="ts">
definePageMeta({ auth: true })
</script>

<template>
  <main>
    <h1>Your profile</h1>
    <ProfileSettings />
  </main>
</template>
```

The private pages ask for a sign-in, and `/admin` for the `admin` role too: a page of yours there declares `definePageMeta({ auth: { role: 'admin' } })` ([Protect pages and routes](/docs/build/auth/access/pages)). Your page also leaves the packaged frame behind, so the `<main>` landmark, the heading and [`<BackendNotices>`](/docs/build/ui/notices) are your layout's. The route rules stay with the path, so a private path stays out of caches and search indexes ([Caches](/docs/build/ui/pages#caches)).

### Link to a page wherever it is

`useBackendPagePath(key)` reads a page's path, in the active locale when the app uses `@nuxtjs/i18n`, so a moved page never leaves a stale link:

```vue [app/components/PlansLink.vue]
<script setup lang="ts">
const pricing = useBackendPagePath('pricing')
</script>

<template>
  <NuxtLink :to="pricing">See the plans</NuxtLink>
</template>
```

### Build from composables

A page of your own can drop the packaged component and run on the composables it used, with their bindings ([Build on the composables](/docs/build/ui/customize/headless)):

| Page | Its component runs on |
|---|---|
| `/login` | `useLoginFlow` |
| `/pricing` | `usePricing`, `useBilling`, `useCredits`, `useCampaign` |
| `/settings` | `useWorkspace`, `useBilling`, `useCredits`, `useFeatures`, `useOrders`, `useUsage`, `useAuditLog` |
| `/profile` | `useAuth`, `useAccount`, `useEmailChange` |
| `/security` | `usePasskeys`, `useSessions`, `useReauthentication`, `useAccount`, `useAuditLog` |
| `/accept-invitation` | `useWorkspace` |
| `/admin` | `useAdmin`, `useFlagAdmin`, `useAuditLog` |

## What happens when…

| Situation | Result |
|---|---|
| Your component has a part's name but not its props | Nuxt renders it anyway; the type check on `#backend/parts` fails, and `doctor` names the collision |
| A part you swapped is removed or renamed in a release | Your component no longer renders there, and `doctor` stops listing it; the [Upgrade page](/docs/ship/releases/upgrade) and the rename map name what replaces it |
| A page of yours sits at a private path without a guard | A signed-out visitor sees it: declare `definePageMeta({ auth: … })` |
| `pages.login` is `false` and you serve no page there | Guards still redirect to that path: serve your own sign-in page there |

## Limits

- **One component per name.** A swapped part replaces it everywhere; for one placement, use a slot.
- **Your part's accessibility is yours.** Spread the `bind` bags, and keep what the region promised ([Accessibility](/docs/build/ui/accessibility#what-a-replacement-must-keep)).
- **Layers and modules.** A Nuxt layer or another module that registers a component with a part's name swaps it too; `doctor` names it.

## Test it

```ts [test/pricing-plan-card.test.ts]
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { createBackendMock, resetBackendMock } from 'nuxt-backend/test-utils'
import { afterEach, expect, it } from 'vitest'
import { PricingTable } from '#components'

afterEach(() => resetBackendMock())

it('renders our plan card on the packaged table', async () => {
  createBackendMock({
    queries: {
      'billing:getPricing': {
        plans: [{ key: 'pro', name: 'Pro', description: null, retired: false, features: [], featureKeys: [], prices: { month: { productId: 'prod_pro', amount: 900, currency: 'eur', monthly: 900 } } }],
        packs: [],
      },
    },
  })
  const table = await mountSuspended(PricingTable)
  expect(table.find('article.plan h3').text()).toBe('Pro')
})
```

[Test pages over a mock backend](/docs/develop/testing/pages) covers `createBackendMock`.
