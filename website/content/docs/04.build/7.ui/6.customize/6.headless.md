Write a sign-in form in your own markup, with your design system's inputs, and keep every behaviour of the packaged one: the steps, the refusals, the passkey prompt, the focus moves and the announcements. Every packaged component runs on a composable you can call yourself. Each returns its state, its actions and `bind`: attribute and handler bags you spread on your own elements, so the accessibility attributes come with them. The helpers the packaged components use for busy buttons, focus and live regions are exported from `#backend/a11y`.

## Bind a composable to your markup

`useLoginFlow()` is the sign-in step machine `<AuthForm>` runs on. Spread its bindings on your elements:

```vue [app/pages/login.vue]
<script setup lang="ts">
const flow = useLoginFlow()
const { t } = useLabels('auth')
</script>

<template>
  <main>
    <h1>{{ t('title') }}</h1>

    <form v-if="flow.step.value === 'choose' || flow.step.value === 'request-code'" @submit.prevent="flow.sendCode()">
      <label>
        {{ t('email') }}
        <input v-model="flow.email.value" v-bind="flow.bind.emailInput">
      </label>
      <button v-bind="flow.bind.submit">{{ t('sendCode') }}</button>
      <button v-bind="flow.bind.passkeyButton">{{ t('passkeySignIn') }}</button>
    </form>

    <form v-else-if="flow.step.value === 'verify-code'" @submit.prevent="flow.verifyCode()">
      <label>
        {{ t('code') }}
        <input v-model="flow.otp.value" v-bind="flow.bind.codeInput">
      </label>
      <button v-bind="flow.bind.submit">{{ t('verify') }}</button>
    </form>

    <section v-else-if="flow.step.value === 'passkey-offer'">
      <p>{{ t('passkeyOffer') }}</p>
      <button type="button" @click="flow.addPasskey()">{{ t('addPasskey') }}</button>
      <button type="button" @click="flow.skipPasskey()">{{ t('skip') }}</button>
    </section>

    <p v-bind="flow.bind.status" />
  </main>
</template>
```

What the bindings carry:

| Binding | Spread on | Carries |
|---|---|---|
| `bind.emailInput` | The email `<input>` | `type`, `autocomplete="username webauthn"` for passkey autofill, `aria-invalid` and `aria-describedby` when refused |
| `bind.codeInput` | The code `<input>` | `inputmode="numeric"`, `autocomplete="one-time-code"`, the refusal's description, and focus when the step opens |
| `bind.submit` | The step's submit button | `type="submit"`, and `aria-disabled` while a step runs, so focus stays on it |
| `bind.passkeyButton` | The passkey button | The click handler, `aria-disabled` while the browser's prompt is open, and the "Last used" mark as its description |
| `bind.back` | The button that returns to the previous step | `type="button"`, the click handler, and focus on the field it returns to |
| `bind.status` | An empty element | A polite live region that announces a sent code, and an alert for a failure |

Your page sits at `/login`, so it replaces the packaged sign-in page ([Swap a part](/docs/build/ui/customize/parts#replace-a-page)). Labels and translations still apply through `useLabels`.

## Show a plan list on your own cards

`usePricing()` gives the plans from your live catalog, and `bind.planCard(plan)` names the card's group after the plan, so a row of the same buttons reads apart:

```vue [app/pages/pricing.vue]
<script setup lang="ts">
const pricing = usePricing()
const billing = useBilling()
</script>

<template>
  <main>
    <h1>Plans</h1>
    <div v-for="plan in pricing.plans.value" :key="plan.key" v-bind="pricing.bind.planCard(plan)">
      <h2>{{ plan.name }}</h2>
      <button v-bind="pricing.bind.planAction(plan)">Subscribe</button>
    </div>
  </main>
</template>
```

`bind.planAction(plan)` opens checkout, or changes the plan for a subscriber, keeps focus while it opens, and hides the button from a member who manages no billing: the server would refuse them anyway.

The other pricing bindings follow the same shape:

| Binding | Spread on | Carries |
|---|---|---|
| `bind.periodSwitch` | The monthly and yearly toggle | `role="switch"`, `aria-checked` on yearly, and the click handler |
| `bind.planCard(plan)` | One plan's container | `role="group"`, named by the plan |
| `bind.planAction(plan)` | The plan's button | The checkout or plan-change handler, `aria-disabled` while it opens |
| `bind.packCard(pack)` | One credit pack's container | `role="group"`, named by the pack |

## Use the accessibility helpers

For your own components, the same helpers the packaged ones use come from `#backend/a11y`:

```vue [app/components/RenameStrip.vue]
<script setup lang="ts">
import { useActionState, useFocusReturn, useLiveRegion } from '#backend/a11y'
import { api } from '#backend/api'

const props = defineProps<{ id: string }>()
const rename = useMutation(api.strips.rename)
const title = ref('')
const action = useActionState(() => rename({ id: props.id, title: title.value }), { busy: 'Saving…' })
const live = useLiveRegion()
const focus = useFocusReturn()

async function save() {
  await action.run()
  live.announce(action.error.value ? action.error.value.message : 'Title saved.', { alert: !!action.error.value })
  focus.restore()
}
</script>

<template>
  <input v-model="title" aria-label="Strip title">
  <button v-bind="action.bind" @click="save">{{ action.pending.value ? 'Saving…' : 'Save title' }}</button>
  <p v-bind="live.bind" />
</template>
```

| Helper | Does |
|---|---|
| `useActionState(fn, { busy })` | Runs an action once at a time; `bind` keeps the button focusable with `aria-disabled` and says what it waits for; `pending` and `error` as refs |
| `useFocusReturn()` | Remembers the element that had focus, and `restore()` returns it there, after a dialog closes or a row is removed |
| `useLiveRegion()` | A region that stays mounted; `announce(text, { alert })` speaks a polite status or an alert |

## Use it beside any UI library

The package depends on no UI library and brings no theme bridge. Put your library's components in your markup and spread the bindings on them: most kits pass unknown attributes through to their root element. Two habits of component kits work against accessibility:

- **Do not use a kit's `loading` or `disabled` prop for a busy button.** A disabled button drops focus to the page. Spread `bind.submit` or `action.bind` instead, which keep it focusable with `aria-disabled`.
- **Keep words in the button.** An icon-only button needs an accessible name that starts with the words a person would say to press it.

To keep the packaged pages and your kit in one look, set the `--bk-*` tokens from your kit's variables ([Restyle with tokens](/docs/build/ui/customize/tokens)), or load no package CSS with `css: false`.

## What happens when…

The refusals are the composables' own, read with [`getBackendError`](/docs/build/data/read-write/errors): a wrong or expired code is [`invalid_input`](/docs/reference/backend/errors#invalid_input) on `otp`, too many tries is [`rate_limited`](/docs/reference/backend/errors#rate_limited) with `flow.retryAfter` as a countdown, and a passkey-only account asked for a code is [`forbidden`](/docs/reference/backend/errors#forbidden). The bindings put each refusal on its field and in the live region; your markup only has to render them.

## Limits

- **No separate unstyled kit.** The package ships styled components and headless composables, not a third tier of unstyled primitives. `css: false` drops the styles and keeps the packaged markup; the [Customization ladder](/docs/build/ui/customize#why-it-works-this-way) explains why.
- **Your markup, your duty.** A binding you leave out takes its guarantee with it. Keep what each region promised ([Accessibility](/docs/build/ui/accessibility#what-a-replacement-must-keep)).
- **Composables, not pages.** A page of yours at a private path declares its own guard ([Protect pages and routes](/docs/build/auth/access/pages)).

## Test it

Run an axe check on your page in your end-to-end suite, in both colour schemes, and walk it with the keyboard: Tab reaches every control, a busy button keeps focus, and a wrong code is announced.
