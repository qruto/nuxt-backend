Show the "New strip" button to members whose plan includes illustrated strips, and an upgrade offer to everyone else. `<Gate>` renders its content only when the person passes every check you name, and its `#fallback` slot otherwise. It never shows the content while the checks load, and never shows the fallback before it knows. The function behind the content checks the same rule on the server: the gate decides what a page shows, never what a person may do. Vue and Nuxt have no notion of roles or plans; the package reads them from the session and the billing state, live, and gives each check a server half.

## Gate a region

```vue [app/pages/strips/index.vue]
<script setup lang="ts">
definePageMeta({ auth: true })
</script>

<template>
  <main>
    <h1>Strips</h1>
    <Gate feature="illustrations">
      <NuxtLink to="/strips/new">New strip</NuxtLink>
      <template #fallback>
        <UpgradePrompt feature="illustrations" />
      </template>
    </Gate>
    <!-- No fallback: with no room left, it names the plans that allow more. -->
    <Gate quota="strips">
      <NuxtLink to="/strips/import">Import a strip</NuxtLink>
    </Gate>
  </main>
</template>
```

Every prop you set is a check, and every check must pass, so one fallback answers them all. Give a feature and a quota a gate each when each needs its own offer, as above. Naming any check also asks for a sign-in, so a signed-out visitor gets the fallback.

| Prop | Type | Passes when |
|---|---|---|
| `signed-in` | `boolean` | A signed-in account that is not banned |
| `role` | `string \| string[]` | The account has one of these app-wide roles, such as `admin` |
| `workspace` | `boolean \| string \| string[]` | `true`: the session has an active workspace. A role or a list (`'owner'`, `['owner', 'admin']`): the person holds one of them there |
| `feature` | `string \| string[]` | The active workspace's plan grants one of these features |
| `quota` | `string` | The plan has room for `amount` more of this quota |
| `amount` | `number` | How many the content needs room for, with `quota`. `1` by default |

## Slots

| Slot | Renders | Receives |
|---|---|---|
| default | Every check passed | `workspace` with `workspace`; `limit`, `used` and `remaining` with `quota` |
| `fallback` | A check failed | With `quota`: the plans that allow more and the link to the first |
| `placeholder` | The checks are loading, on the server render and until the page has hydrated | Nothing |
| `error` | The plan's features or quotas could not be read | `{ error }`, as `{ code, data, message }` |

The server render shows the `placeholder`, never the content, so gated content is not in the HTML a crawler or a slow connection sees first. Without a `fallback`, a failed check renders nothing, except `quota`: it says how many are used of how many, names the plans that allow more, and links to the first. A member who manages no billing reads who to ask instead of a link. Its words are the `quota` [labels](/docs/build/ui/customize/labels#the-groups).

## Enforce the same rule on the server

The gate reads the session and the plan in the browser, where anyone can change what runs. Each check has a server half, and the function behind the content uses it:

| `<Gate>` prop | The function behind it | The page guard |
|---|---|---|
| `signed-in` | Any tier: `authed` and up | `definePageMeta({ auth: true })` |
| `role` | `admin` or `withRole(role)` | `auth: { role }` |
| `workspace` | `workspace`, then `ctx.workspace.role` for a role | `auth: { workspace }` |
| `feature` | `withFeature(key)` | `auth: { feature }` |
| `quota` | `billing.requireQuota`, which refuses with `quota_exceeded` | none: a quota changes while the page is open |

[Protect backend functions](/docs/build/auth/access/functions) covers the tiers, and [Protect pages](/docs/build/auth/access/pages) the guard.

## What it guarantees

It renders exactly one slot, so each state is as accessible as what you put in it. Loading is the `placeholder`, or nothing. With `quota`, the packaged refusal is a polite status whose one stop is a real link, and a failed read is an alert. [Accessibility](/docs/build/ui/accessibility) has what a slot of yours keeps.

## What happens when…

| Situation | Result |
|---|---|
| The plan changes while the page is open | The gate follows at once, in every open tab |
| The person signs out | Every gate shows its fallback |
| The features or quotas cannot be read | The `error` slot, or nothing |
| Someone edits the page in the browser to show gated content | The function behind it refuses: [`feature_required`](/docs/reference/backend/errors#feature_required), [`quota_exceeded`](/docs/reference/backend/errors#quota_exceeded) or [`forbidden`](/docs/reference/backend/errors#forbidden) |

## Limits

- **Display only.** Every check needs its server half; the gate alone protects nothing.
- **Built-in workspace roles.** Custom permissions wait for a later release ([Roadmap](/docs/start/roadmap)).

## Test it

```ts [test/new-strip.test.ts]
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { createBackendMock, resetBackendMock } from 'nuxt-backend/test-utils'
import { afterEach, expect, it } from 'vitest'
import StripsPage from '~/pages/strips/index.vue'

afterEach(() => resetBackendMock())

it('offers an upgrade to a plan without the feature', async () => {
  createBackendMock({ user: { name: 'Ada' } })
  const page = await mountSuspended(StripsPage)
  expect(page.find('[data-upgrade]').exists()).toBe(true)
})
```
