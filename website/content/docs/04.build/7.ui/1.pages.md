Install the module and these pages exist, with no files of yours. Each is a thin wrapper around a packaged component, built from named [parts](/docs/build/ui/customize/parts), at a path its `pages` key sets, with the route rules a private page needs. Every page mounts unless you turn its key off: turn `pricing` off in an app that sells nothing.

| Key | Route | What it is | Who can open it | Built on |
|---|---|---|---|---|
| `login` | `/login` | Sign-in with a passkey or an emailed code, then the offer to add a passkey | everyone | `<AuthForm>` · `useLoginFlow` |
| `pricing` | `/pricing` | The plans and credit packs, rendered on the server from the live catalog | everyone | `<PricingTable>` · `usePricing`, `useBilling`, `useCredits` |
| `settings` | `/settings` | The workspaces, members and invitations, the plan, credits, charges and invoices, usage, and the workspace's activity | signed in | `<WorkspaceSettings>` · `useWorkspace`, `<BillingHistory>`, `<UsageHistory>`, `<AuditLog>` |
| `profile` | `/profile` | The name, the email address, the language emails are written in, and an Email section for topics and channels | signed in | `<ProfileSettings>` · `useAccount`, `useEmailChange`, `useEmailPreferences` |
| `unsubscribe` | `/unsubscribe` | The email topics a person gets, from the one-click link every marketing email carries, and a double opt-in's confirmation ([Let people choose their emails](/docs/build/email/preferences)) | everyone with the signed link | the package's unsubscribe page · `getEmailLink`, `unsubscribeByLink`, `confirmEmailTopic` |
| `security` | `/security` | Passkeys, sessions, the account's data export and deletion, and its recent activity | signed in | `<SecuritySettings>` · `usePasskeys`, `useSessions`, `<AccountData>`, `<AuditLog>` |

| `waitlist` | `/waitlist` | A person's place in the queue, from the signed link in their confirmation ([Run a waitlist](/docs/build/growth/launch/waitlist)) | everyone with the signed link | the place of `<WaitlistForm>` · `useWaitlist` |

A signed-out visitor to a private page goes to the `login` path, with the original destination as `?redirect=`, so sign-in returns them where they were headed. The admin console is a [hidden page](/docs/build/auth/access/pages#hide-a-page-from-everyone-else): anyone without the `admin` role, signed in or not, gets the 404 of a page that does not exist. A 403 from a page of yours is rendered by [`<AccessDenied>`](/docs/build/auth/access/pages#the-403-page) in the module's error page when the app has no `error.vue`.

## The frame

Each page sits inside one shared frame:

- **`<main>`**, with `data-backend-page` naming the page, then the `h1` and the document title, both from the component's [label group](/docs/build/ui/customize/labels#the-groups), so every page follows your copy and [translations](/docs/build/ui/customize/translation). The page also sets `<html lang>` to the active locale.
- **A notices region** before `<main>`, with [`<BackendNotices>`](/docs/build/ui/notices). It renders only when a notice applies.
- **A status region** closing `<main>`, with [`<ConnectionStatus>`](/docs/build/data/read-write#tell-people-the-connection-dropped): an empty live region while the connection is up.

Inside a layout with [`<AppShell>`](/docs/build/ui/app-shell), a page is a `<div>` with its `h1`: the shell owns the header, the notices, the consent dialog, the connection status and the one main landmark, so nothing shows twice. A copy of a page that a router module mounts again, such as `/fr/profile` under `@nuxtjs/i18n`, carries the same route rules as the page it copies.

## Move a page

Give its key a path in the [`pages` module option](/docs/reference/configuration/module-options). Each path is declared once, there: the auth route, the guards and the invitation emails read it.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    pages: {
      pricing: '/plans',     // the packaged pricing page, at /plans
      settings: '/account',  // the packaged settings page, at /account
    },
  },
})
```

The path you give `login` is also where every page guard sends a signed-out visitor. To change part of a page, [swap a part](/docs/build/ui/customize/parts); to replace it, put an app page at its path ([Replace a page](/docs/build/ui/customize/parts#replace-a-page)).

## Turn a page off

`false` mounts nothing at that key's path:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    pages: {
      pricing: false, // pricing lives on the marketing site
      profile: false, // the profile lives on the app's own settings page
    },
  },
})
```

Links the package renders to a page that is off (`useBackendPagePath('pricing')`) read `null`, and the packaged components hide them. `login: false` keeps the path guards redirect to, so serve your own sign-in page there.

## Search engines

The private pages redirect a signed-out visitor to sign-in, so the module keeps them out of search indexes, sitemaps and caches (see [Caches](#caches)). It adds a route rule at each one's path, and the public pages get `prerender: false` alone, since no page is prerendered:

```ts
routeRules: {
  '/settings': {
    prerender: false,
    robots: false,
    sitemap: false,
    cache: false,
    swr: false,
    isr: false,
    headers: { 'cache-control': 'private, no-store' },
  },
  // …the same for /profile, /security, /accept-invitation, /welcome and /admin
  '/account/keep': { prerender: false, robots: false, sitemap: false, cache: false, swr: false, isr: false, headers: { 'cache-control': 'private, no-store' } },
  // Public, and each reads a token from its link: out of indexes, not out of caches.
  '/login': { prerender: false, robots: false },
  '/invite': { prerender: false, robots: false },
  '/waitlist': { prerender: false, robots: false },
  '/pricing': { prerender: false },
}
```

[`@nuxtjs/robots`](https://nuxtseo.com/docs/robots/getting-started/introduction) answers `robots: false` with a `noindex, nofollow` header and meta tag, and [`@nuxtjs/sitemap`](https://nuxtseo.com/docs/sitemap/getting-started/introduction) leaves the URL out; both come with `@nuxtjs/seo`. Without those modules the rules do nothing, so each private page also says it itself: every page `definePageMeta({ auth })` guards, the package's and yours, and everything below one (the admin console's tabs) carries `<meta name="robots" content="noindex, nofollow">`. `/login`, the access-link page and the unsubscribe page, which read a code or a signed token from their address, get `noindex` too. `/pricing` stays indexable.

The rules follow the path, so an app page that shadows one of these gets them too. With `@nuxtjs/robots` installed the module leaves the meta tag to it, so the rule you set for a path decides. Without it, a page of yours that should be indexed says so after the fact with `useSeoMeta({ robots: 'index, follow' })`, which runs after the tag and wins. The guard does not follow the path: a page of yours in place of a private one declares `definePageMeta({ auth: true })`. A rule you set for the same path wins key by key: `routeRules: { '/security': { robots: true } }` indexes that page again.

## Caches

A signed-in render carries the session's token: the server renders the page with it, and it rides in the page's payload to the browser. So the private pages turn off each cache a route rule can turn on (`cache`, `swr`, and the hosting platform's `isr`) and answer `cache-control: private, no-store`.

That holds at each page's exact path. Route rules match paths case-insensitively since Nuxt 4.6.2, as the router matches pages, unless your app sets routing to case-sensitive (checked on 2026-10-25). A localized copy of a page (`/fr/settings`) is another path, which the module covers with the same rules. When a wildcard `swr`, `isr` or `cache` rule covers a private page, the module warns at startup.

Your own pages with `auth` rules get the same rules at their paths, and the same warning: [Protect pages and routes](/docs/build/auth/access/pages#where-the-rules-are-checked).

Scope cache rules to the public pages they are meant for, never the whole app:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/': { swr: 3600 },
    '/blog/**': { swr: 3600 },
  },
})
```

## Arriving in 0.2.0

These pages join the set with the features they belong to. Each mounts like the others, inside the same frame, with a private or a public page's route rules, and each key takes a path or `false`.

| Key | Route | What it is | Who can open it | Unit |
|---|---|---|---|---|
| `report` | `/report` | The public notice form for illegal content and intimate-image removal ([Moderate user content](/docs/ship/compliance/moderation)) | everyone | SAFETY |

The legal pages above are drafts marked "not legal advice": have them reviewed, or turn them off and serve your own. The sign-in page gains steps of its own: an invite code in an early-access or invite-only phase, and the waitlist for a new address. The admin console gains Access, Waitlist, Queue, Reports, Analytics, Growth and Costs tabs, and tabs of your own through `adminTab` in page meta ([Run the admin console](/docs/build/auth/admin)).
