- **You get:** a fixed price per job, refused at the door when the balance is short, charged when it starts and refunded when it fails; and what each job cost you, per customer, in Polar.
- **Powered by:** Polar's credit meters, usage events and Cost Insights.
- **The package adds:** a hold that lasts as long as the job waits, the charge as the job's first durable step, the refund, idempotency keys on both, and a cost event per job.

A job is priced up front, in credits, like a product: 5 credits a panel, whatever its model calls cost. The queue holds the credits the moment the job joins the line, so someone who cannot afford it hears so before they wait. It charges them when the job starts, and refunds them if the job fails. A hold, or reservation, takes credits from the balance without charging them yet. A metered action reserves for a few minutes at most. A job can wait in line for an hour, so its hold lasts as long as the job waits.

## Price a job

`meter` and `cost` on `jobs.define` set the price:

```ts [backend/strips.ts]
export const render = jobs.define({
  meter: 'credits',
  cost: ({ panels }) => panels * 5,
  args: { stripId: v.id('strips'), idea: v.string(), panels: v.number() },
  handler: async (job, args) => {
    // …
  },
})
```

- **`meter`** is a sum meter from your catalog. A refund is a negative usage event, which a count meter cannot take, so a count meter throws where the job is defined.
- **`cost`** is a number, or `(args) => number` read once when the job joins. It must be a finite number above zero.
- **`meter: false`** makes the job free: no hold and no usage event, only the line. Its `cost`, `1` when you set none, still counts against a tier's budget.

A job's price is fixed. Its model calls are not metered one by one: the queue charges what you priced, not what the gateway reported. What each job cost you reaches Polar beside the charge ([Report what each job cost you](#report-what-each-job-cost-you)), so you can check the price stays above it.

## When credits move

| The job | Its credits | At the billing provider |
|---|---|---|
| Joins the line | Held: the balance drops at once | Nothing yet |
| Is refused at the door | Never held, and never counted against the tier's budget | Nothing |
| Starts | Charged | A usage event on the meter, for the member who started it |
| Finishes | Stay charged | |
| Is canceled before it starts | The hold is released, and its cost goes back to the budget window | Nothing |
| Is canceled while it runs | Stay charged: the steps it finished were real work | |
| Fails or stalls | Refunded, and its cost goes back to the budget window | A negative usage event that gives them back |

The hold is a reservation on the cached balance, as a [metered action's](/docs/build/billing/credits/spending#reserve-run-settle) is, kept for as long as the job waits. Two jobs that join at the same moment can never hold the same credits. Too few credits refuses the job with `insufficient_credits`, carrying `balance` and `need`, before anything joins the line. A tier's daily budget, when it has one, is checked before the hold, and counts the same `cost` ([Cap what an owner spends per day](/docs/build/ai/jobs/priority#cap-what-an-owner-spends-per-day)).

The charge is the job's first durable step. If the billing provider cannot record it, the job fails with nothing spent, and the hold is released. The charge and the refund carry the job's hold id as their idempotency key, so a step that runs again after a timeout never bills or refunds twice.

## Show the balance

`useCredits` reads the balance live, and it already counts the hold: a queued strip's credits are gone from the balance the moment it joins. A refund shows up when the billing provider confirms it, a few seconds after the job fails.

```vue [app/pages/strips/new.vue]
<script setup lang="ts">
import { api } from '#backend/api'

const credits = useCredits({ meter: 'credits' })
const create = useMutation(api.strips.create)
const idea = ref('')

async function start() {
  try {
    const stripId = await create({ idea: idea.value, panels: 4 })
    await navigateTo(`/strips/${stripId}`)
  }
  catch (error) {
    if (getBackendError(error)?.code === 'insufficient_credits') await navigateTo('/pricing')
  }
}
</script>

<template>
  <p>{{ credits.balance.value ?? '…' }} credits. A four-panel strip costs 20.</p>
  <input v-model="idea" placeholder="A fox who wants to fly">
  <button @click="start">
    Draw the strip
  </button>
</template>
```

[Out of credits](/docs/build/billing/credits#out-of-credits) shows how to offer the pack that covers what a refused job needed.

## What a failed job costs you

A refund gives the person back their credits, not your bill. The gateway still bills every model call a failed job made before it failed, and every step it retried. That is the price of promising your users that a failed job costs them nothing. Keep it small by failing early: check the input in your mutation before `jobs.enqueue`, and throw a catalog error from a step for what a retry cannot fix ([Which errors fail a job](/docs/build/ai/jobs/model-limits#which-errors-fail-a-job)).

## Report what each job cost you

When a job ends, done or failed, the package sends one more event to Polar: a child of the job's charge, carrying Polar's Cost Insights fields. It never carries the prompt or the result:

| Field | What it holds |
|---|---|
| `_cost` | What the job's model calls cost, in US cents, at sub-cent precision, as the gateway reported them |
| `_llm` | The vendor and model of the job's calls, and their input, output and cached tokens |

Polar's Costs dashboard then shows cost per customer, gross margin and cashflow next to your revenue, with no table of yours. A failed job's cost is reported too, although its credits were refunded, because you paid for its calls. The event carries the member who started the job, so Polar can show the cost per member of a workspace. A call through your own provider key reports no cost, and its event carries tokens only. See Polar's [Cost Insights](https://polar.sh/docs/features/cost-insights/introduction) (checked on 2026-10-25).
