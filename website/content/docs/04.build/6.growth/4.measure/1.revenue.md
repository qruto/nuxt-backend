See how the business is doing, from the source. The admin console's **Analytics** tab opens on the **Revenue** view, which reads the billing provider's own metrics when an administrator opens it. The package keeps no copy of revenue, so there is nothing to reconcile.

**What Polar does natively** (checked on 2026-10-25, [Get metrics](https://polar.sh/docs/api-reference/2027-01/metrics/get-metrics)): it computes recurring revenue, active, new, renewed and churned subscriptions, churn rate, checkouts and their conversion, lifetime value, and cancellations per reason. With [Cost Insights](https://polar.sh/docs/features/cost-insights/introduction), it adds costs, cost per user and gross margin.

**What the package adds:** the view in the console, kept to administrators, drawn with the package's parts, and fed with AI costs from the job queue.

## What it shows

- **Revenue**: monthly and annual recurring revenue, and revenue over the period you pick.
- **Subscriptions**: new, renewed and churned, per day, week or month, and the churn rate.
- **Cancellations per reason**: how many left for each of the eight reasons the [cancel flow](/docs/build/growth/engage/cancel-flow) asks about, and how many save offers were accepted.
- **Checkouts**: started, completed, and the conversion between them.
- **Usage per meter**: what each metered feature consumed, the credits AI actions spend included.
- **Costs and margin**: cost per user and gross margin, once costs reach Polar.

Pick the last 30, 90 or 365 days, per day, week or month (a new window takes the interval that suits it), and **Refresh** to read again. Each chart follows your [theme tokens](/docs/build/ui/customize/tokens) like the rest of the console: a bar per period in the text colour, churn on `--bk-error`.

## Show it

The tab appears once `backend/billing.ts` re-exports `getRevenue` from `billing.api`, as the scaffold does:

```ts [backend/billing.ts]
export const {
  // …the other billing functions
  getRevenue,
} = billing.api
```

`getRevenue({ since, until, interval })` is an action: `since` and `until` are epoch milliseconds, read as whole UTC days (`until` defaults to now), and `interval` is `day` (the default), `week` or `month`. A window covers at most 366 days. It answers a `RevenueReport`:

| Field | What it holds |
|---|---|
| `totals` | Each metric over the window: `monthlyRecurringRevenue`, `annualRecurringRevenue`, `revenue`, `netRevenue`, `activeSubscriptions`, `newSubscriptions`, `renewedSubscriptions`, `churnedSubscriptions`, `canceledSubscriptions`, `churnRate`, `checkouts`, `succeededCheckouts`, `checkoutsConversion`, `lifetimeValue`, `costs`, `costPerUser`, `grossMargin` and `grossMarginPercentage`. Money is in cents, a rate a fraction, and `null` where Polar has no value. |
| `periods` | The same metrics per period, each with its start (`at`), oldest first. |
| `cancellations` | `reasons`: cancellations per reason. `saveOffers`: the offers the cancel flow made in the window, and how many were accepted. |
| `meters` | Each catalog meter's `total` and its quantity per period. |

Only the save offers are counted in your deployment, from the cancel flow's own records. Everything else is one call to Polar's metrics and one per meter to its meter quantities.

## Report AI costs

Polar's Cost Insights reads a `_cost` property on the usage events it ingests. Every credit spend is already a usage event ([Spend credits in your functions](/docs/build/billing/credits/spending)). The job queue adds each job's AI cost to its event, so Panels' cost per strip shows next to its revenue without code of yours ([Charge for a queued job](/docs/build/ai/jobs/credits)). The admin Costs tab shows what every AI call cost per person, jobs included.

## Who may read it

Administrators only, with the role read fresh on every call ([Run the admin console](/docs/build/auth/admin)). An administrator visiting someone's account reads nothing. The billing access token needs Polar's `metrics:read` scope, which `npx nuxt-backend doctor --only analytics` checks.

## In development

The view reads the sandbox organization your development deployment bills on, so it shows the purchases you made with test cards ([Develop on real sandboxes](/docs/develop/sandboxes)).

## What happens when…

| Situation | Result |
|---|---|
| A non-administrator calls it | Refused as `forbidden`, reason `admin_only` ([Errors](/docs/reference/backend/errors#forbidden)) |
| An administrator visiting someone's account calls it | Refused as `forbidden`, reason `impersonating` |
| No `BILLING_ACCESS_TOKEN` is set | Refused as `unavailable`, reason `not_configured` |
| A window longer than 366 days, or one that ends before it starts | Refused as `invalid_input` (`since` or `until`) |
| The token lacks `metrics:read` | Refused as `unavailable`, and `doctor` names the missing scope ([`analytics-metrics`](/docs/reference/cli/diagnostics#analytics-metrics)) |
| Polar is unreachable | Refused as `unavailable`. The rest of the console keeps working. |

## Limits

- **Read live, not stored.** Each visit calls Polar's metrics API, so a long period takes a moment to load.
- **Polar's definitions.** Recurring revenue, churn and lifetime value are Polar's numbers, computed its way.
- **Costs only when reported.** Margin reads as revenue alone until usage events carry a cost.

## Test it

Open the console as an administrator on a development deployment after a test checkout with `4242 4242 4242 4242`, and check that the new subscription shows.
