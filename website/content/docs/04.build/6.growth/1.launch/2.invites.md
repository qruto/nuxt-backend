While your app is closed, a new address needs a ticket to sign up ([Launch in phases](/docs/build/growth/launch)). Administrators hand tickets out in the admin console's **Access** tab, three ways: an invite code to share, an access link for a cohort, or an invitation by address. The tab also shows the current phase and moves it on.

- **Natively:** neither Better Auth nor the email provider has invite codes. Better Auth's workspace invitations admit one address into one workspace, not into the app (checked on 2026-10-25).
- **The package adds:** invite codes and access links as hashed tokens in the `backend` component, checked inside Better Auth's sign-up hooks, a redemption ledger per label, and invitations by address that send no email unless you ask.

## Invite codes

An invite code is short enough to read out or type: `7KQ2M-XW9PA`. A person types it on the sign-in page's `invite-code` step, after their sign-in code.

Administrators create codes in the Access tab, each with:

- **a label**, such as `friends-of-the-team`, which names its cohort in the trail and in [growth funnels](/docs/build/growth/measure);
- **a number of uses**: 1 for a personal code, more for one you post in a community;
- **an expiry**, optional.

The tab shows each code once, when it is made. The database keeps only a hash, so neither a backup nor a log can give the code out again. Codes are read without case and without the dash, and look-alike characters count as one: `O` reads as `0`, `I` and `L` as `1`.

From your own code, `access.invites.create` makes one and returns it, once, like the tab:

```ts [backend/invites.ts]
import { v } from 'convex/values'
import { admin } from './functions'
import { access } from './access'

// One code for an illustrators' meetup: 30 uses, valid for two weeks.
export const createMeetupCode = admin.mutation({
  args: { label: v.string() },
  handler: (ctx, { label }) =>
    access.invites.create(ctx, { label, maxUses: 30, expiresAt: Date.now() + 14 * 24 * 60 * 60 * 1000 }),
})
```

## Access links

An access link admits a cohort without anyone typing a code: everyone who signs up through the link from one launch post. Administrators create links in the Access tab, each with a label, a number of uses and an expiry, all three required. Revoking a link closes it at once.

The link opens `/invite`, a page the module mounts, with the token in the fragment: `https://panels.example/invite#<token>`. Browsers never send a fragment to a server, so the token stays out of your host's logs. The page:

1. strips the token from the address;
2. checks it through a rate-limited call, so an expired or used-up link says so before anyone signs in, and keeps a valid one for the tab;
3. sends the person to the sign-in page, which hands the token over with the code check.

The account's creation checks the token again and counts the use. Logs and events name the link by its label, never its token.

## Show it in a page

`useInvite()` redeems a code or a link on a page of your own:

```vue [app/pages/join.vue]
<script setup lang="ts">
const { check, status, isPending, error } = useInvite()
const code = ref('')
</script>

<template>
  <form @submit.prevent="check(code)">
    <label for="invite-code">Invite code</label>
    <input id="invite-code" v-model="code" autocomplete="off" spellcheck="false" placeholder="7KQ2M-XW9PA">
    <button type="submit" :aria-disabled="isPending || undefined">Check my code</button>
  </form>
  <NuxtLink v-if="status === 'valid'" to="/login">Continue to sign in</NuxtLink>
  <p v-else-if="error" role="alert">{{ error.message }}</p>
</template>
```

`check(codeOrToken)` checks it and keeps a valid one for the tab, so the next code check carries it. `status` is `valid`, `expired`, `used-up`, `revoked` or `unknown`. With no argument, `check()` reads an access link's fragment from the address. It also returns `isKept` and `forget()`.

`checkInvite` is a mutation, so its rate limit can count: `inviteCheck` per signed-in caller, `inviteCheckGlobal` across the deployment.

## Invite people by address

"Invite by address" takes a pasted list or a CSV, up to 500 addresses at a time, and an optional label such as `beta-1`. Each address gets a ticket that expires after 30 days unused.

- **No email unless you ask.** Sending an invitation to people who didn't ask for one is direct marketing in most places. So the tab adds the tickets silently by default, and you announce through a broadcast to people who opted in ([Guardrails on growth features](/docs/start/concepts/principles#guardrails-on-growth-features)).
- **"Email them"** sends each person a plain "You're invited" email in the layout, with who you are, a link to your privacy policy (`backend.pages.privacy`) and the sign-in link (`backend.pages.login`), both from `paths`; the sign-in link holds no token and no address. It carries the one-click unsubscribe such an email needs, follows the weekly cap and quiet hours, and goes at about a hundred an hour, one wave after another, so a wave never crowds out sign-in codes. The emails go from an action of their own, by the invitations' ids. It needs the email instance and the action re-exported:

  ```ts [backend/access.ts]
  export const access = setupAccess(components, { audit, email, paths })
  export const { emailInvitations } = access.api
  ```

  The words are the `email.accessInvitation` labels. An invitation used, expired or revoked before its email goes gets none, and an email that cannot go leaves the invitation standing (`access.invitation_unsent`).
- **Cleaned first.** Existing accounts, suppressed addresses and reserved domains (`example.com`, `.test`, `.invalid`, `localhost`) are skipped.
- **Revoke** deletes an unused ticket. A used one is an account: ban it like any other ([Run the admin console](/docs/build/auth/admin#what-an-administrator-may-do)).

From your own code, `access.admit(ctx, { emails, label })` adds the same tickets, with no email. `useAccessAdmin().admit(emails, label, { email: true })` is the tab's "Email them".

## Who invited whom

Each ticket remembers how it was given: a code and its label, a link, an address an administrator invited, or a workspace invitation. The Users tab shows it on each account ("Signed up with"), the activity trail records it as `access.ticket_used`, and the [growth funnels](/docs/build/growth/measure) count sign-ups per label.

## What happens when…

- **A code is unknown, expired, used up or revoked:** `useInvite().check` reads it as that `status`, and the `invite-code` step asks again. Neither is an error.
- **Someone guesses codes:** the check is rate-limited per signed-in caller and across the deployment, and the code check that carries a code per address, then refused as [`rate_limited`](/docs/reference/backend/errors#rate_limited). A code has 50 bits, so guessing one is out of reach anyway.
- **The last use of a code is taken in the same moment by two people:** the account creations run in one transaction each, so one gets it and the other meets the `invite-code` step.
- **An administrator changes a code while visiting another account:** the write is refused as [`forbidden`](/docs/reference/backend/errors#forbidden) with reason `impersonating`.
- **A pasted list holds a malformed address:** that row is skipped and reported, and the rest are admitted.

## Limits

- **500 addresses per paste.**
- **A code shows once.** Lost codes are revoked and made again: the hash can't be read back.
- **No user-made codes.** Only administrators and your server code create invite codes. For person-to-person sharing, use [referrals](/docs/build/growth/offers/referrals).

## Test it

A code an administrator makes checks as valid until its uses run out:

```ts [backend/invites.test.ts]
import { asUser, defineBackendTestApp } from 'nuxt-backend/test'
import { expect, test } from 'vitest'
import { api } from './_generated/api'
import schema from './schema'

const testApp = defineBackendTestApp(schema, import.meta.glob('./**/*.ts'))

test('a new meetup code checks as valid', async () => {
  const t = testApp()
  const admin = await asUser(t, { role: 'admin' })
  const code = await admin.mutation(api.invites.createMeetupCode, { label: 'meetup' })
  expect(await t.mutation(api.access.checkInvite, { code })).toMatchObject({ status: 'valid' })
})
```
