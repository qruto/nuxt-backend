Fetch a city's forecast once a day, not on every page view. An action that calls a model, geocodes an address or fetches exchange rates costs time and often money, and is often called again with the same arguments. The official [`@convex-dev/action-cache`](https://www.convex.dev/components/action-cache) component keeps its results: the first call runs the action and stores what it returns, and every call with the same arguments gets the stored result until it expires.

## Cache a forecast

```bash
npm install @convex-dev/action-cache
```

::code-tree{defaultValue="backend/weather.ts"}

```ts [backend/convex.config.ts]
import actionCache from '@convex-dev/action-cache/convex.config'

// …after the package's components
app.use(actionCache)
```

```ts [backend/weather.ts]
import { ActionCache } from '@convex-dev/action-cache'
import { v } from 'convex/values'
import { components, internal } from './_generated/api'
import { internalAction } from './_generated/server'
import { authed } from './functions'

type Forecast = { high: number, low: number }

export const forecastFor = internalAction({
  args: { city: v.string() },
  handler: async (_ctx, { city }): Promise<Forecast> => {
    const response = await fetch(`https://api.example.com/forecast?city=${encodeURIComponent(city)}`)
    return await response.json() as Forecast
  },
})

const forecasts = new ActionCache(components.actionCache, {
  action: internal.weather.forecastFor,
  name: 'forecast:v1',
  ttl: 86_400_000,
})

export const forecast = authed.action({
  args: { city: v.string() },
  handler: (ctx, { city }): Promise<Forecast> => forecasts.fetch(ctx, { city }),
})
```

::

| Option | This recipe | Effect |
|---|---|---|
| `action` | `internal.weather.forecastFor` | The action whose results are kept. It runs on a miss, with the arguments `fetch` got |
| `name` | `'forecast:v1'` | Part of every key; the action's name when you leave it out. Change it when the action starts returning something else, so no old result is served |
| `ttl` | `86_400_000`, a day | How long a result is served, in milliseconds. Without it, results stay until you remove them |

One mount holds every cache your app defines, each told apart by its `name`.

## How a fetch answers

`fetch(ctx, args)` runs in an action, since a miss runs one. On a hit it returns the stored result without calling the action. On a miss, or once the stored result has expired, it runs the action, stores what it returns and returns that. Two callers that miss at the same moment both run the action, and one result is kept. A failed action stores nothing.

The arguments are the key, whole. Every caller who passes the same ones gets the same result, so a result that belongs to one person needs that person among the arguments: pass their id to the cached action, even when it only reads it to find their data.

## Expiry and invalidation

An expired result is never served. The component deletes expired results when it reads them and in a purge it runs once a day.

| Call | Effect |
|---|---|
| `fetch(ctx, args, { force: true })` | Runs the action now and replaces the stored result. Call it from a cron to refresh a result before anyone misses |
| `remove(ctx, args)` | Forgets the result for these arguments. Call it from the mutation that changes what the action reads |
| `removeAllForName(ctx)` | Forgets every result of this cache, a batch at a time |

A result keyed by a person's id is that person's data. Where you erase their data, `remove` each result cached under their id, or give a cache of personal results a `ttl` short enough that the daily purge erases them in time.
