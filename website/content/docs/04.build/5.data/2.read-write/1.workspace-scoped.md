A Panels workspace keeps its strips to its members: the author's personal workspace, or one a small team shares. Convex has no notion of tenants, so every query decides what it reads. The package's `workspace` tier checks the caller's membership, fresh on every call, and hands you the active workspace; three habits do the rest. Write its id on every row, read through an index on it, and check a row's workspace before you touch it by its id.

## Before you start

- A table with a `workspaceId: v.string()` field and an index on it, as in [Your data](/docs/build/data/your-data#define-a-table).
- The `workspace` tier from `backend/functions.ts` ([Protect backend functions](/docs/build/auth/access/functions)).

## Write and list the active workspace's rows

```ts [backend/strips.ts]
import { v } from 'convex/values'
import { workspace } from './functions'

export const create = workspace.mutation({
  args: { title: v.string() },
  handler: (ctx, { title }) => ctx.db.insert('strips', {
    workspaceId: ctx.workspace.id,
    authorId: ctx.user.id,
    title,
  }),
})

export const list = workspace.query({
  args: {},
  handler: ctx => ctx.db.query('strips')
    .withIndex('by_workspaceId', q => q.eq('workspaceId', ctx.workspace.id))
    .order('desc')
    .take(50),
})
```

Never take the workspace from the arguments: a member of one workspace could pass another's id. `ctx.workspace` is the session's active workspace, and a person switches it with `useWorkspace()` ([Workspaces](/docs/build/auth/workspaces)). Every query on the page follows the switch.

## Check a row you reach by its id

A function that takes a row's id checks the row's `workspaceId` before it reads or writes it. Refuse with the same error whether the row is missing or belongs to another workspace, so the answer says nothing about other workspaces:

```ts [backend/strips.ts]
import { backendError } from 'nuxt-backend/functions'

export const rename = workspace.mutation({
  args: { id: v.id('strips'), title: v.string() },
  handler: async (ctx, { id, title }) => {
    const strip = await ctx.db.get('strips', id)
    if (strip?.workspaceId !== ctx.workspace.id) {
      throw backendError('forbidden', { reason: 'other_workspace' })
    }
    await ctx.db.patch('strips', id, { title })
  },
})
```

## Let only some members write

`ctx.workspace.role` is the caller's role in the active workspace: `owner`, `admin` or `member`. Read it where a write is for some members only, such as removing another member's strip:

```ts [backend/strips.ts]
export const remove = workspace.mutation({
  args: { id: v.id('strips') },
  handler: async (ctx, { id }) => {
    const strip = await ctx.db.get('strips', id)
    if (strip?.workspaceId !== ctx.workspace.id) throw backendError('forbidden', { reason: 'other_workspace' })
    const mine = strip.authorId === ctx.user.id
    if (!mine && ctx.workspace.role === 'member') throw backendError('forbidden', { reason: 'role' })
    await ctx.db.delete('strips', id)
  },
})
```

The page guard and `<Gate workspace>` show a page or a region only inside a workspace; the function's check is the one that holds. [Workspaces](/docs/build/auth/workspaces) lists what each built-in role may do with the workspace itself.

## When a workspace or an account goes

Your rows stay until your code deletes them. Delete a workspace's rows from a source in `backend/account.ts`, which an account's erasure runs for the workspaces that go with it: the personal one, and any it was the only member of. A row in a workspace that stays keeps its `authorId`. Clear or reassign that field in the same source when it names the person. [Export and erase account data](/docs/build/auth/accounts/data) shows the source's two functions.

## Show it in a page

The list follows the active workspace. When a person switches with `useWorkspace()`, the query re-runs for the new one:

```vue [app/pages/strips/index.vue]
<script setup lang="ts">
import { api } from '#backend/api'

definePageMeta({ auth: { workspace: true } })

const strips = useQuery(api.strips.list, {})
const { current } = useWorkspace()
</script>

<template>
  <main>
    <h1>{{ current?.name }}: strips</h1>
    <p v-if="strips === undefined" role="status">Loading strips…</p>
    <ul v-else>
      <li v-for="strip in strips" :key="strip._id">{{ strip.title }}</li>
    </ul>
  </main>
</template>
```

## What happens when…

| Situation | Refusal |
|---|---|
| The caller is signed out | [`unauthenticated`](/docs/reference/backend/errors#unauthenticated) |
| The session has no active workspace | [`no_workspace`](/docs/reference/backend/errors#no_workspace) |
| The caller left the workspace, or was removed, while the page was open | [`forbidden`](/docs/reference/backend/errors#forbidden) on the next call |
| The row belongs to another workspace, or is gone | `forbidden`, reason `other_workspace`, from your own check |

## Limits

- **Keep the index.** An index that starts with `workspaceId` keeps a read as small as the workspace, whatever the table's size.
- **A person's own settings** belong to the account, not a workspace: store them by `ctx.user.id` and read them in the `authed` tier.
- **Internal functions, jobs and migrations** have no active workspace and see every row. Keep cross-workspace work there, and check who may start it.
- **Built-in roles only.** Custom workspace roles wait for a later release ([Roadmap](/docs/start/roadmap)).

## Test it

```ts [backend/strips.test.ts]
import { asUser, defineBackendTestApp } from 'nuxt-backend/test'
import { expect, test } from 'vitest'
import { api } from './_generated/api'
import schema from './schema'

const testApp = defineBackendTestApp(schema, import.meta.glob('./**/*.ts'))

test('each workspace reads only its own strips', async () => {
  const t = testApp()
  const ada = await asUser(t)
  const grace = await asUser(t)
  const id = await ada.mutation(api.strips.create, { title: 'Monday' })
  expect(await grace.query(api.strips.list, {})).toEqual([])
  await expect(grace.mutation(api.strips.rename, { id, title: 'Mine now' }))
    .rejects.toMatchObject({ data: { code: 'forbidden' } })
})
```
