A room is whatever the app names: a document, a page, a workspace. While a page is open and visible, each person on it sends a heartbeat, and everyone in the room sees who else is there as people come and go, without a message per heartbeat. Convex's [presence component](https://www.convex.dev/components/presence) keeps the rooms. The package puts them behind the backend's sign-in: a heartbeat counts the signed-in account, never an id the browser names, and the room can refuse an account. `useRoomPresence` runs it from a page. It is experimental ([Stability](/docs/ship/releases/stability)).

## Install and mount the component

```bash
pnpm add @convex-dev/presence
```

```ts [backend/convex.config.ts]
import presence from '@convex-dev/presence/convex.config'

// …the scaffold's mounts
app.use(presence)
```

`npx nuxt-backend doctor` reports the mount missing once a backend file imports `setupPresence`, and `--fix` adds it.

## Export the presence functions

```ts [backend/presence.ts]
import { setupPresence } from 'nuxt-backend/presence'
import { components } from './_generated/api'

export const { list, heartbeat, disconnect } = setupPresence(components)
```

Every signed-in account may join every room by default. Name who may join with `canJoin`, which runs on each heartbeat with the room, the account and its identity claims; a refusal answers `forbidden` with reason `presence_room`:

```ts [backend/presence.ts]
export const { list, heartbeat, disconnect } = setupPresence(components, {
  // A workspace's room lets in the members of that workspace only.
  canJoin: ({ roomId, claims }) => !roomId.startsWith('workspace:') || roomId === `workspace:${claims.activeOrganizationId}`,
})
```

`list` answers by the room token a heartbeat handed back, and to a signed-in caller only, so only someone the room let in reads who else is in it. A token stays valid after `canJoin` stops letting its holder in: to shut someone out at once, call `presence.removeRoomUser` from the setup's `presence` client in a mutation of your own. Each person comes with their name and picture, when the account has them. A room lists at most 50 people (`limit`, up to 200). An administrator acting as someone else sends no heartbeat (`forbidden`, reason `impersonating`): the room never shows the account they visit as present.

## Show who is here on a page

```vue [pages/docs/[id].vue]
<script setup lang="ts">
const route = useRoute()
const { members, others } = useRoomPresence(() => `doc:${route.params.id}`)
</script>

<template>
  <p v-if="others.length">
    {{ others.map(person => person.name ?? 'Someone').join(', ') }} also here
  </p>
  <FacePile :presence-state="members ?? []" />
</template>
```

`members` is everyone in the room, the signed-in person first, and `undefined` while it loads; `others` is who else is online now. Signed out, the composable sends nothing and lists nobody; it joins once someone signs in, and leaves when they sign out. A tab that is hidden leaves the room and joins again when it shows; one that closes leaves at once. `<FacePile>` is the base module's avatar row, registered once `@convex-dev/presence` is installed.

| Option | Default | |
|---|---|---|
| `interval` | `10000` | Milliseconds between heartbeats. Someone who leaves without a word drops off after two and a half of them. The server holds it between one second and five minutes. |
| `api` | `api.presence` | The functions to call, when they live elsewhere. |

## Rooms of your own

`setupPresence(…).presence` is the component's own client, for the app's functions: `listRoom` to read a room from a query, `removeRoomUser` and `removeRoom` to clear one. These check no sign-in: call them from functions that do.
