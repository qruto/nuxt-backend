A Panels author uploads a reference photo for a strip, and your app keeps it only when it is an image you accept, under your limits, with its location data removed. Convex file storage holds the bytes and hands out upload URLs. The package adds the checks: the size, the type read from the bytes, EXIF and GPS stripping, file and byte quotas, an owner record, and one mutation that stores the file and your row together.

## Set up storage

Create `backend/storage.ts` once, with the limits every upload must meet:

```ts [backend/storage.ts]
import { setupStorage } from 'nuxt-backend/storage'
import { billing } from './billing'
import { components } from './_generated/api'

export const storage = setupStorage(components, {
  maxSize: 8 * 1024 * 1024,
  accept: ['image/png', 'image/jpeg', 'image/webp'],
  stripMetadata: true,
  quota: { files: 'photos', bytes: 'storageBytes' },
  billing,
})

// The functions useUpload, <UploadField> and <StorageImage> call.
export const { generateUploadUrl, getFileUrl } = storage.api
```

| Option | Default | Effect |
|---|---|---|
| `maxSize` | `10 * 1024 * 1024`, 10 MB | The largest file kept, in bytes |
| `accept` | `['image/png', 'image/jpeg', 'image/webp']` | The types kept, as read from the file's first bytes. Leave out SVG and HTML: both can carry script |
| `stripMetadata` | `true` | Removes EXIF, XMP, IPTC and GPS data from JPEG, PNG and WebP images before they are kept. A photo taken sideways keeps its orientation alone, so it still shows upright |
| `quota.files` | none | A number, or a quota key of your [billing catalog](/docs/build/billing/subscriptions/quotas): how many files the billing entity may keep |
| `quota.bytes` | none | The same for the total bytes kept. Each file counts its size after stripping. A catalog key shows the files and bytes kept in `useFeatures().quotas` and `billing.getQuota`, beside anything your own mutations claim under the same key |
| `billing` | none | Your `billing` instance, which a quota key needs: it reads the limit from the billing entity's plan, and the files are counted against that entity |
| `rateLimiter` | the package's own | Your `rateLimiter`, whose `upload` limit bounds upload URLs ([rate limits](/docs/ship/security/rate-limits)) |

`generateUploadUrl` answers signed-in accounts only, at a per-account rate beside the package's other [rate limits](/docs/ship/security/rate-limits). `getFileUrl` returns a file's URL to its owner and to members of its workspace, and `null` to anyone else.

## Store a photo in one mutation

For a photo, send the bytes to your own mutation. `storage.store` checks them, strips the metadata, stores the file and records its owner, in the same transaction as your row. A refused file leaves nothing behind: no row, no bytes, nothing to sweep. `storage.store` is for files people upload; an image a model generates goes through `ctx.storeImage` in the job step instead ([Label AI-generated content](/docs/build/ai/provenance#label-a-result)).

```ts [backend/strips.ts]
import { backendError } from 'nuxt-backend/functions'
import { v } from 'convex/values'
import { workspace } from './functions'
import { storage } from './storage'

export const addPhoto = workspace.mutation({
  args: { id: v.id('strips'), photo: v.bytes() },
  handler: async (ctx, { id, photo }) => {
    const strip = await ctx.db.get('strips', id)
    if (strip?.workspaceId !== ctx.workspace.id) throw backendError('forbidden', { reason: 'other_workspace' })
    const { storageId } = await storage.store(ctx, photo, { userId: ctx.user.id, workspaceId: ctx.workspace.id })
    await storage.release(ctx, strip.photoId) // the photo it replaces, if any
    await ctx.db.patch('strips', id, { photoId: storageId })
  },
})
```

```vue [app/components/PhotoPicker.vue]
<script setup lang="ts">
import { api } from '#backend/api'

import type { Id } from '#backend/dataModel'

const props = defineProps<{ stripId: Id<'strips'> }>()
const addPhoto = useMutation(api.strips.addPhoto)
const busy = ref(false)
const refusal = ref<string | null>(null)

async function onPick(event: Event) {
  const file = (event.target as HTMLInputElement).files?.[0]
  if (!file) return
  busy.value = true
  refusal.value = null
  try {
    await addPhoto({ id: props.stripId, photo: await file.arrayBuffer() })
  }
  catch (failure) {
    refusal.value = getBackendError(failure)?.message ?? 'Could not keep that photo. Try another one.'
  }
  finally {
    busy.value = false
  }
}
</script>

<template>
  <label>
    Reference photo
    <input type="file" accept="image/png,image/jpeg,image/webp" :aria-disabled="busy || undefined" @change="onPick">
  </label>
  <p v-if="busy" role="status">Checking the photo…</p>
  <p v-if="refusal" role="alert">{{ refusal }}</p>
</template>
```

`store(ctx, bytes, owner)` returns `{ storageId, size, contentType }`. It works in a mutation because Convex 1.48 lets `ctx.storage` store a file there. A Convex function argument holds up to 16 MiB (checked on 2026-10-25), so this path suits photos and documents. Send anything larger through an upload URL.

Each file has one owner record:

| Owner | Who may read the file | What deletes it |
|---|---|---|
| `{ userId }` | The account that uploaded it | `release`, or the account's erasure |
| `{ userId, workspaceId }` | Every member of that workspace | `release`, or the workspace's deletion. It stays when the uploader leaves |

Store the id as `v.string()`: the file lives in the `backend` component's storage, so it is not an id of your schema.

## Upload a large file with an upload URL

The browser can also send the bytes straight to Convex storage, with progress and cancel. The base module's `useUpload` asks for an upload URL, sends the file and resolves with a storage id. Your mutation then claims it:

```ts [backend/strips.ts]
export const attachFile = workspace.mutation({
  args: { id: v.id('strips'), fileId: v.string() },
  handler: async (ctx, { id, fileId }) => {
    const strip = await ctx.db.get('strips', id)
    if (strip?.workspaceId !== ctx.workspace.id) throw backendError('forbidden', { reason: 'other_workspace' })
    await storage.claim(ctx, fileId, { userId: ctx.user.id, workspaceId: ctx.workspace.id })
    await ctx.db.patch('strips', id, { attachmentId: fileId })
  },
})
```

```vue [app/components/AttachmentPicker.vue]
<script setup lang="ts">
import { api } from '#backend/api'

import type { Id } from '#backend/dataModel'

const props = defineProps<{ stripId: Id<'strips'> }>()
const attachFile = useMutation(api.strips.attachFile)
const { upload, isUploading, progress, error, cancel } = useUpload(api.storage.generateUploadUrl)
const refusal = ref<string | null>(null)

async function onPick(event: Event) {
  const file = (event.target as HTMLInputElement).files?.[0]
  const fileId = file ? await upload(file) : null
  if (!fileId) return
  refusal.value = null
  try {
    await attachFile({ id: props.stripId, fileId })
  }
  catch (failure) {
    refusal.value = getBackendError(failure)?.message ?? 'Could not keep that file. Try another one.'
  }
}
</script>

<template>
  <input type="file" :aria-disabled="isUploading || undefined" @change="onPick">
  <progress v-if="isUploading" :value="progress" />
  <button v-if="isUploading" type="button" @click="cancel">Cancel upload</button>
  <p v-if="error || refusal" role="alert">{{ error?.message ?? refusal }}</p>
</template>
```

`claim(ctx, storageId, owner)` checks the stored size and the quotas at once, and refuses a file that is gone or already claimed. A mutation cannot read a file's bytes, so the type check and the metadata stripping run next, in the component, before the file's URL is served. Until then `getFileUrl` reads `null`. A file whose bytes are not a type you accept is deleted, and its URL stays `null`.

An upload nobody will claim, one the person dropped or one your own check refused, can go at once with `storage.discard(ctx, fileId)`, from a mutation or an action. It deletes only an unclaimed upload: a kept file, anyone's, stays as it is, and so does an id with no file. It answers whether bytes went, `false` on a second call, so calling it twice is safe. The sweep deletes an unclaimed upload after a day anyway ([Keep storage clean](/docs/build/data/files/cleanup#what-the-sweep-deletes)).

An upload URL takes a file of any size for an hour, and the upload must finish within two minutes (checked on 2026-10-25). The size check happens once the file has arrived, so the per-account rate on upload URLs is what bounds abuse. For many files at once, the base module's `useUploadQueue(api.storage.generateUploadUrl)` uploads with bounded concurrency; claim each id as it lands.

## Place the ready-made field

`<UploadField>` is the upload URL flow as a labelled field: a file picker reached by keyboard or click, drag and drop as a second path, progress, cancel and a live region. Give it a `claim` function. It calls it once the upload lands, ties a refusal to the field, and sets `v-model` only when the claim went through:

```vue [app/components/AttachmentField.vue]
<script setup lang="ts">
import { api } from '#backend/api'

import type { Id } from '#backend/dataModel'

const props = defineProps<{ stripId: Id<'strips'> }>()
const attachFile = useMutation(api.strips.attachFile)
const fileId = ref<string | null>(null)
</script>

<template>
  <UploadField
    v-model="fileId"
    accept="image/png,image/jpeg,image/webp"
    :claim="id => attachFile({ id: props.stripId, fileId: id })"
  />
</template>
```

Its words come from the `upload` label group, and it keeps the [component contract](/docs/reference/components#the-component-contract): `data-upload` hooks, a `data-state` for each step, and a live region for progress and refusals. [Upload and contact forms](/docs/reference/components/forms) lists its props, slots and parts.

## What the checks do

| Check | One-mutation store | Upload URL and claim |
|---|---|---|
| Size against `maxSize` | Before anything is stored | At claim, on the stored size |
| Type against `accept` | Read from the bytes, before storing | Read from the bytes after the claim; a mismatch deletes the file |
| EXIF, XMP and GPS removed | Before storing | After the claim, before the URL is served |
| `quota.files` and `quota.bytes` | Before storing | At claim |
| Owner record | In your transaction | In your transaction |

The type comes from the file's signature (its magic bytes), never from the name or the type the browser declared. Convex keeps only the declared type, so this check is what the package adds. A wildcard in `accept` (`image/*`) never admits SVG or HTML: name `image/svg+xml` to keep SVG files. Every kept upload is stored again under its sniffed type, so no URL serves a file with the type its uploader declared. Stripping rewrites the image's container without re-encoding the pixels, so quality is unchanged; the size counted against `quota.bytes` is the size after stripping. A JPEG ends at its first image: an appended preview or gain map, with EXIF of its own, goes too. HEIC, HEIF, AVIF and TIFF keep EXIF the stripper can't remove, so while `stripMetadata` is on a wildcard never admits them, and naming one in `accept` throws; pass `stripMetadata: false` to keep them as they are.

## What happens when…

| Situation | Refusal |
|---|---|
| The file is too large, of a type you did not accept, gone, or already claimed | [`invalid_input`](/docs/reference/backend/errors#invalid_input) on the `file` field, reason `too_large`, `unsupported_type`, `upload_gone` or `upload_claimed` |
| A quota has no room left | [`quota_exceeded`](/docs/reference/backend/errors#quota_exceeded), with the plans that allow more |
| A signed-out caller asks for an upload URL | [`unauthenticated`](/docs/reference/backend/errors#unauthenticated) |
| Upload URLs are asked for too fast | [`rate_limited`](/docs/reference/backend/errors#rate_limited), with `retryAfter` |

A refusal rolls back your whole mutation, so your row never points at a file that was not kept. [Handle errors](/docs/build/data/read-write/errors) shows how a page reads each one.

## Limits

- **Native gaps.** Convex stores the declared type without reading the bytes, sets no size limit on an upload URL, and serves any file URL to whoever holds it. The package covers the first two; [expiring private URLs](/docs/build/data/files/images#serve-a-private-file-for-a-while) cover the third.
- **What stripping covers.** JPEG, PNG and WebP. Other types are kept as they arrived, so leave them out of `accept` when location data matters.
- **Not a content check.** What an image shows is content safety: [Keep content safe](/docs/build/ai/content-safety).
- **`release` checks no owner.** Pass it an id read from your own row, never one from a client's arguments. `discard` may take a client's id: it never deletes a kept file.
- **Cost.** Stored bytes and bandwidth count against your Convex plan: [Convex](/docs/services/convex#costs-and-limits).

## Test it

```ts [backend/strips.test.ts]
import { asUser, defineBackendTestApp } from 'nuxt-backend/test'
import { expect, test } from 'vitest'
import { api } from './_generated/api'
import schema from './schema'

const testApp = defineBackendTestApp(schema, import.meta.glob('./**/*.ts'))

test('refuses a file that is not an image', async () => {
  const author = await asUser(testApp())
  const id = await author.mutation(api.strips.create, { title: 'Monday' })
  const text = new TextEncoder().encode('not an image').buffer
  await expect(author.mutation(api.strips.addPhoto, { id, photo: text }))
    .rejects.toMatchObject({ data: { code: 'invalid_input', field: 'file' } })
})
```
