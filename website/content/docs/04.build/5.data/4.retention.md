Every row you keep is a row you protect, export and erase. Convex gives you crons and the scheduler, but no time-to-live on a table. `defineRetention` turns one rule into an internal mutation that deletes a table's rows once they pass an age, a batch per transaction, until none is left; a cron in `backend/crons.ts` starts it. The package's own tables need no rule from you: its component prunes them every hour.

## Define a rule

```ts [backend/retention.ts]
import { defineRetention } from 'nuxt-backend/functions'
import { DAY } from 'nuxt-backend/rate-limit'
import { internalMutation } from './_generated/server'
import { storage } from './storage'

// Drafts nobody touched in 30 days, with their photos.
export const pruneDrafts = defineRetention(internalMutation, {
  fn: 'retention:pruneDrafts',
  table: 'strips',
  index: 'by_status_and_updatedAt',
  match: { status: 'draft' },
  ttl: 30 * DAY,
  batch: 100,
  onDelete: (ctx, strip) => storage.release(ctx, strip.photoId),
})

// Failed strips stay 14 days for a retry.
export const pruneFailedStrips = defineRetention(internalMutation, {
  fn: 'retention:pruneFailedStrips',
  table: 'strips',
  index: 'by_status_and_updatedAt',
  match: { status: 'failed' },
  ttl: 14 * DAY,
  batch: 50,
  onDelete: async (ctx, strip) => {
    await storage.release(ctx, strip.photoId)
    await storage.revokeShareLink(ctx, 'strips', strip._id)
  },
})
```

| Option | Default | Effect |
|---|---|---|
| `fn` | (required) | The rule's own function path, as `npx convex run` takes it. A batch that leaves rows behind schedules it again |
| `table` | (required) | The table to prune. Its rows are typed from your schema |
| `index` | (required) | The index to read through, named by its fields as Convex's guidelines ask (`by_status_and_updatedAt`): the rule reads the field names from the name. The field after any `match` fields holds the time, such as `updatedAt`; `by_creation_time` uses `_creationTime` |
| `match` | none | Equal values for the index's leading fields, in the index's order, such as `{ status: 'failed' }` |
| `ttl` | (required) | How old a row may get, in milliseconds, on the index's time field. `0` deletes a row once that time has passed, for an `expiresAt` field |
| `batch` | `100` | Rows per transaction. Lower it for large rows or a heavy `onDelete` |
| `onDelete` | none | Runs before each row is deleted, in the same transaction |

Pass the builder your other writes use. When an [aggregate](/docs/build/data/read-write/aggregates) counts the table, that is the trigger-wrapped `internalMutation`, so a pruned row leaves the count too.

The mutation takes an optional `{ now }` and returns `{ deleted, more }`. Pass `now` in a test to move the clock without fake timers, or run a pass by hand: `npx convex run retention:pruneDrafts`.

## Schedule it

```ts [backend/crons.ts]
import { cronJobs } from 'convex/server'
import { internal } from './_generated/api'

const crons = cronJobs()

crons.cron('prune drafts', '10 3 * * *', internal.retention.pruneDrafts, {})
crons.cron('prune failed strips', '20 3 * * *', internal.retention.pruneFailedStrips, {})

export default crons
```

Times are UTC. Pick a minute other than `0`, so your passes do not start with everyone else's. [Schedule jobs](/docs/build/data/jobs/scheduled#your-own-jobs) covers `crons.ts`.

## How a pass runs

1. **A cron starts it.** The pass fixes its cutoff, the current time minus `ttl`, so it always ends.
2. **Each batch** reads up to `batch` rows older than the cutoff through your index and deletes them, in one transaction.
3. **A batch that leaves rows behind schedules the next one** at once, through the rule's own `fn`, with the same cutoff. A batch that takes the last rows ends the pass.
4. **`onDelete` runs first** for each row, in the same transaction, for what the row points at: a file, a count.

Convex [scheduling](https://docs.convex.dev/scheduling/scheduled-functions) runs each batch; the package writes the loop.

## Store a token's hash, not the token

A token you store as is works for anyone who can read the table: a backup, an export, an administrator's query. Store its SHA-256 hash, compare hashes, and hand the token out once. Three helpers from `nuxt-backend/functions` run in the default Convex runtime, Node and the browser:

| Helper | Returns |
|---|---|
| `randomToken(bytes?)` | 32 random bytes by default, as 43 URL-safe characters. `bytes` is a whole number from 16 to 1024; anything else throws a `TypeError` |
| `sha256Hex(text)` | The text's SHA-256, as lowercase hex |
| `normalizeEmail(address)` | The address trimmed and lowercased, the form to store and compare it in |

```ts [backend/reviewLinks.ts]
import { backendError, randomToken, sha256Hex } from 'nuxt-backend/functions'
import { DAY } from 'nuxt-backend/rate-limit'
import { v } from 'convex/values'
import { authed } from './functions'

// A link that lets a friend review one strip for a week.
export const create = authed.mutation({
  args: { stripId: v.id('strips') },
  handler: async (ctx, { stripId }) => {
    const strip = await ctx.db.get('strips', stripId)
    if (strip?.authorId !== ctx.user.id) throw backendError('forbidden', { reason: 'not_owner' })
    const token = randomToken()
    const tokenHash = await sha256Hex(token)
    await ctx.db.insert('reviewLinks', { stripId, tokenHash, expiresAt: Date.now() + 7 * DAY })
    return token // shown once: only its hash stays
  },
})
```

Look a link up by `await sha256Hex(token)` through an index on `tokenHash`, and prune expired ones with a rule on `by_expiresAt` and `ttl: 0`. A link to a whole row that its owner turns on and off is a [share link](/docs/build/data/files/share-links), which does all of this for you.

## What happens when…

| Situation | Result |
|---|---|
| A batch throws, in `onDelete` or the delete | The batch rolls back, the pass ends, and the log has `retention.batch_failed` with the table and the row |
| The next pass starts | It retries from the same oldest rows, so a row whose `onDelete` keeps throwing holds the rule up until you fix it |
| The index's time field is missing on a row | The row sorts first and is deleted on the first pass: give old rows the field before you add the rule |
| The rule is malformed: an `fn` with no module, a negative `ttl`, a `batch` below 1, or an `index` whose name does not start with the `match` fields | The module throws a `TypeError` as it loads, so the deploy fails and the message names the index it expected |

## Limits

- **Your tables only.** The component prunes its own tables on its own windows ([Limits and retention](/docs/reference/backend/limits)); a rule never reaches them.
- **Function calls.** Each batch is one mutation call on your Convex plan. A larger `batch` makes fewer calls, within Convex's per-transaction read and write limits.
- **Not legal retention.** How long you may keep personal data is a legal question: [Privacy, GDPR and cookies](/docs/ship/compliance/privacy). Not legal advice.

## Test it

```ts [backend/retention.test.ts]
import { defineBackendTestApp } from 'nuxt-backend/test'
import { DAY } from 'nuxt-backend/rate-limit'
import { expect, test } from 'vitest'
import { internal } from './_generated/api'
import schema from './schema'

const testApp = defineBackendTestApp(schema, import.meta.glob('./**/*.ts'))

test('prunes drafts past 30 days', async () => {
  const t = testApp()
  await t.run(ctx => ctx.db.insert('strips', { workspaceId: 'w', authorId: 'u', title: 'Old', status: 'draft', updatedAt: 0 }))
  const result = await t.mutation(internal.retention.pruneDrafts, { now: 31 * DAY })
  expect(result).toEqual({ deleted: 1, more: false })
})
```
