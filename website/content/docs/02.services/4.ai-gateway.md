An AI gateway reaches every model provider through one account and reports what each call cost. The AI features call models by `provider/model` id through one of two gateways. Set a spend cap before anything else.

| You need | Time | Cost to start |
|---|---|---|
| A paid Convex plan, or a Vercel account for a gateway key | 5 minutes | Each call at the provider's price. No free tier on the Convex route |

## What it powers

| Capability | What the gateway gives | Build pages |
|---|---|---|
| `ai` | Model calls and streams by `provider/model` id, with the cost of each | [Choose a model](/docs/build/ai/models), [Stream a response](/docs/build/ai/streaming) |
| `ai`, `billing` | The cost each metered action settles in credits | [Meter an AI action](/docs/build/ai/metered-actions) |
| `jobs` | The calls each generation job makes | [Run generation jobs](/docs/build/ai/jobs) |

The package picks the route on every deployment, in this order:

1. **The Convex AI Gateway**, on Convex Cloud with a paid plan and `@convex-dev/ai-sdk-provider` installed. Convex holds the provider credentials: there is no key to create, store or rotate.
2. **The Vercel AI Gateway**, with the deployment's `AI_GATEWAY_API_KEY`. It answers where the Convex one cannot: a free plan, an account-free local deployment, a self-hosted backend.
3. **A refusal**, `unavailable` with reason `not_configured`, when neither answers.

[Where a model id goes](/docs/build/ai/models#where-a-model-id-goes) has the detail.

## Create the account

**The Convex AI Gateway:**

::steps{level="3"}

### Move the Convex team to a paid plan

In the [Convex dashboard](https://dashboard.convex.dev), open the team's billing page and choose Starter (pay as you go) or Professional ([Convex](/docs/services/convex#costs-and-limits)). The free plan answers `AiGatewayDisabled`.

### Install the providers

```bash
npm install ai @convex-dev/ai-sdk-provider
```

### Set the team's spending limit

On the same billing page, set a spending limit. At the limit, calls are refused until it resets or rises, and the key route is never tried instead.

::

**The Vercel AI Gateway:**

::steps{level="3"}

### Sign up for Vercel

At [vercel.com/signup](https://vercel.com/signup). The gateway works with any host: the key is all it needs.

### Create a key

Open **AI Gateway**, **API Keys**, **Create key**. A key never expires, but Vercel deactivates it when the member who created it leaves the team.

### Set a budget on the key

Open **AI Gateway**, **Budgets**, and set a monthly budget for the key. The CLI does the same:

```bash
vercel ai-gateway budgets set api-key <key-name> --limit 50 --refresh-period monthly
```

::

**Who should own it.** The person who answers for spend owns the Convex team's billing, or the Vercel team that holds the key. Create a production key under a shared account rather than one person's, so it survives a departure.

## Sandbox and test mode

Neither gateway has a test mode: development calls the same models as production, at their real cost. What differs is who pays:

| `BACKEND_ENVIRONMENT` | Credits the call spends | What the gateway bills |
|---|---|---|
| `development`, `preview`, `sandbox` | Credits from Polar's sandbox | Real money, to your Convex or Vercel team |
| `production` | Your customers' credits | Real money, to your Convex or Vercel team |

Point development at a small model, such as a `-mini` one, and set its own budget. Tests never call a model: `nuxt-backend/test` runs your functions on `convex-test` ([Test backend functions](/docs/develop/testing/functions)).

## Keys and environment

| Variable | Where to find it | Dev | Prod | Secret |
|---|---|---|---|---|
| `AI_GATEWAY_API_KEY` | Vercel: **AI Gateway**, **API Keys** | Only where the Convex AI Gateway does not answer | Only where the Convex AI Gateway does not answer | Yes |

The Convex AI Gateway needs no variable. `AI_GATEWAY_API_KEY` is the gateway's own name, read as it is, and lives on the Convex deployment. Vercel's keyless sign-in through `VERCEL_OIDC_TOKEN` never reaches the backend: model calls run in Convex actions, on Convex's servers.

## Link it

::steps{level="3"}

### Name a model

```ts [backend/ai.ts]
import { setupAi } from 'nuxt-backend/ai'
import { components } from './_generated/api'
import { billing } from './billing'
import { rateLimiter } from './rateLimiter'

export const ai = setupAi(components, { billing, rateLimiter, model: 'openai/gpt-5-mini' })
```

### Push the key, if you use one

```bash [.env.local]
AI_GATEWAY_API_KEY=your_ai_gateway_api_key
```

```bash
npx nuxt-backend env push
```

::

```bash
npx nuxt-backend doctor --only ai
```

| Finding | What it checks |
|---|---|
| [`deployment-ai-gateway-api-key`](/docs/reference/cli/diagnostics#deployment-ai-gateway-api-key) | Every `provider/model` id your backend names has a route on this deployment. It warns when none does, and fails under `--prod` |
| [`ai-stream-route`](/docs/reference/cli/diagnostics#ai-stream-route) | The deployment serves `/ai/stream` once `setupAi` is deployed |

## Go to production

::steps{level="3"}

### Cap the deployment's spend

On the Convex route, add a warning on production's own spend:

```bash
npx convex deployment usage-limits set --prod --metric aiGatewayCostDollars --window day --type warning --limit 50
```

A `--type disable` limit pauses the whole deployment, every function included. To stop AI alone, use the [`pause_ai` kill switch](/docs/ship/operate/flags).

### Set production's key, if you use one

```bash
npx convex env set --prod AI_GATEWAY_API_KEY
```

Give production a key and a budget of its own, never the development key.

### Check it

```bash
npx nuxt-backend doctor --prod
```

::

## Costs and limits

Checked on 2026-10-25, the spend caps again on 2026-10-27:

| | Convex AI Gateway | Vercel AI Gateway |
|---|---|---|
| Price | The same rates as OpenRouter, on your Convex invoice ([Usage and billing](https://docs.convex.dev/ai-gateway/usage-and-billing)) | The provider's list price, with no markup ([Pricing](https://vercel.com/docs/ai-gateway/pricing)) |
| Free use | None: paid Convex plans only | A monthly free credit on some models, until you buy credits |
| Spend cap | The team's spending limit, and a per-deployment usage limit | Budgets per team, project, key or member, reset daily, weekly or monthly at 00:00 UTC. Past one, calls get `402`. Budgets are soft caps |
| Rate limits | The providers' own | None of its own on paid credits; lower limits on the free credit |
| Modalities | Text and embeddings; image, video and speech in alpha | See its [model list](https://vercel.com/ai-gateway/models) |

- **Budgets cap the team, not your users.** Neither gateway limits what one person of yours spends. The package does that with credits, rate limits and, for queued jobs, a per-tier budget ([Budgets and costs](/docs/build/ai/models#budgets-and-costs), [Cap what an owner spends per day](/docs/build/ai/jobs/priority#cap-what-an-owner-spends-per-day)).
- **A failed run** releases its credit reservation, even when the gateway billed the calls it made before failing.
- **Vercel credits** you buy expire after a year. Auto top-up is off until you turn it on.

### Per-user limits and gateway-wide stops

Checked on 2026-10-27. These facts decide what the [job queue](/docs/build/ai/jobs/priority#why-the-package-does-this-not-the-gateway) does itself:

- **No limit per app user or workspace.** Convex documents daily and monthly dollar limits per deployment, and a monthly spending limit per team ([Usage and billing](https://docs.convex.dev/ai-gateway/usage-and-billing)). Vercel's budgets scope to a team, a project, an API key or a team member, and its `quotaEntityId` tag has no documented budget ([Budgets](https://vercel.com/docs/ai-gateway/observability-and-spend/budgets)).
- **A limit stops everyone in its scope.** A Convex usage limit at its disable threshold disables the whole deployment for the rest of its window, sign-in and billing webhooks included. It comes back when the window resets, daily ones at 00:00 UTC, or when the limit is raised ([Usage limits](https://docs.convex.dev/production/usage-limits)). A Vercel budget answers `402`, type `quota_for_entity_exceeded`, to every request in its scope until it resets or is raised. The AI SDK can surface that as `GatewayInternalServerError`.
- **Caps are soft and late.** A Vercel budget is checked at the start of each request, so the request that crosses it still completes, and spend shows about 20 seconds later.
- **Dollars arrive after the call.** Convex chat completions return tokens and no dollar cost. Vercel reports a call's cost once it ran.
- **No capacity to divide.** The Convex gateway documents no rate or concurrency limit. Vercel sets none of its own on paid credits, and lower per-model limits on the free credit, without numbers. Convex's Workpool advises at most about 20 jobs running across all pools on the free plan, and 100 on Pro.
- **`Retry-After` is not always there.** Convex documents forwarding it on chat completions ([API](https://docs.convex.dev/ai-gateway/api)), and the Vercel AI Gateway sends `retry-after` on some `429`s.
- **Canceling does not always stop the cost.** Convex says canceling a video request does not cancel its generation or cost, and that a lost answer to an async video job may still be charged.

## Data and compliance

- **What it holds:** each prompt and response passes through the gateway to the model provider. The package stores neither, unless your code does.
- **Convex route:** Convex processes the calls under its [DPA](https://www.convex.dev/legal/dpa), and lists OpenRouter among its [subprocessors](https://www.convex.dev/legal/subprocessors) for routing. Region pinning is not documented as of 2026-10-25.
- **Vercel route:** Vercel processes the calls under its [DPA](https://vercel.com/legal/dpa). Since 2026-07-27 it can pin inference to the EU: pass `providerOptions: { gateway: { inferenceRegion: { scope: 'zone', geoRegion: 'eu' } } }` in the call. A model with no EU provider fails with `400` rather than leave the region, and EU rates run about 10% higher ([Regional inference](https://vercel.com/docs/ai-gateway/security-and-compliance/regional-inference)).
- **Providers:** each model provider has its own retention and training terms. Read them before you send personal data, and name the providers you use in your privacy policy.

Generated content may need a visible label in the EU ([Disclose AI-generated content](/docs/ship/compliance/ai-transparency)). This is not legal advice.
