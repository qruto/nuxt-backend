Vercel hosts the Nuxt app. Any host that runs Nuxt works; Vercel is the one the package is built and checked on first, and on it bot protection, error reports and edge rate limits take what the platform gives.

| You need | Time | Cost to start |
|---|---|---|
| A Vercel account and the app in a Git repository | 10 minutes | Free for a personal project. A commercial app needs Pro, $20 a month |

## What it powers

| Capability | What Vercel gives | Pages |
|---|---|---|
| `hosting` | The Nuxt server, previews per branch, the CDN and custom domains | [Deploy to production](/docs/ship/deploy), [Set up preview environments](/docs/ship/deploy/previews) |
| `protection` | BotID, an invisible bot check before a sign-in code is sent | [Bot protection](/docs/services/bot-protection) |
| `protection` | Firewall rate limits, counted at the edge | [Deploy to Vercel](/docs/ship/deploy/vercel#rate-limit-at-the-edge) |
| `analytics` | Web Analytics and Speed Insights, without cookies | [Deploy to Vercel](/docs/ship/deploy/vercel#count-visits-without-cookies) |
| `monitoring` | Sentry's integration, which sets the source-map names | [Sentry](/docs/services/sentry) |

The backend never runs on Vercel: it runs on Convex. [Deploy to Vercel](/docs/ship/deploy/vercel) has what an app gets there, part by part.

## Create the account

::steps{level="3"}

### Sign up

At [vercel.com/signup](https://vercel.com/signup), with the Git provider that holds your app. Hobby, the free plan, is for personal, non-commercial use: an app that takes payments or pays a developer needs Pro ([Fair use](https://vercel.com/docs/limits/fair-use-guidelines#commercial-usage)).

### Import the project

**Add New**, **Project**, then pick the repository. Vercel detects Nuxt and needs no configuration for it.

### Set the build command

In **Settings**, **Build and Deployment**, override the build command so the backend deploys first:

```bash
npx convex deploy --cmd 'npm run build' --cmd-url-env-var-name NUXT_PUBLIC_BACKEND_URL
```

### Pick the function region

New projects run their functions in `iad1` (Washington, D.C.). Move them next to your Convex deployment in **Settings**, **Functions**: `fra1` or `dub1` for a deployment in Ireland. Every request the Nuxt server makes to the backend crosses that distance.

::

**Who should own it.** Create the project in a team, not a personal account. The team's owner pays the bill and holds the production env. Members deploy; viewer seats are free.

## Sandbox and test mode

Vercel's environments map to the deployments of your backend:

| Vercel environment | Its deploy key | `BACKEND_ENVIRONMENT` |
|---|---|---|
| Production | The production deploy key | `production`, or `sandbox` for a [demo or staging app](/docs/ship/deploy/staging) |
| Preview | A preview deploy key: each branch gets a backend of its own | `preview` |
| Development | None: `npx nuxt-backend dev` runs locally | `development` |

Turn on Vercel Authentication for previews, on every plan, so only your team opens them. An end-to-end run against a preview passes the **Protection Bypass for Automation** secret in the `x-vercel-protection-bypass` header ([Deployment protection](https://vercel.com/docs/deployment-protection)).

## Keys and environment

Set these in **Settings**, **Environment Variables**, each for its environment. Mark the secret ones as **Secret**: Vercel never shows them again.

| Variable | Where to find it | Preview | Production | Secret |
|---|---|---|---|---|
| `CONVEX_DEPLOY_KEY` | Convex: the project's preview deploy key, or the production deployment's deploy key ([Convex](/docs/services/convex#keys-and-environment)) | The preview key | The production key | Yes |
| `NUXT_PUBLIC_BACKEND_URL` | Written by the build command | Written | Written | No |
| `PROTECTION_PROOF_SECRET` | Generate it: `openssl rand -base64 32`. The same value as the deployment's | Optional | Production's own ([Bot protection](/docs/services/bot-protection)) | Yes |
| `MONITORING_DSN` | Sentry: **Project Settings**, **Client Keys (DSN)** ([Sentry](/docs/services/sentry)) | Optional | Yes | No |

Leave **Enable access to System Environment Variables** on: the package reads `VERCEL` and `VERCEL_ENV` to know it runs on Vercel.

## Link it

::steps{level="3"}

### Link the folder to the project

```bash
npx vercel link
```

### Write the app's env into the project

```bash
npx nuxt-backend deploy
```

`deploy` arrives with `0.2.0`. It writes the env the Nuxt app needs into the project's production environment through your own Vercel login, and stores no token. Until then, set each variable above by hand, or with `vercel env add <name> production`.

### Push a branch

A push to a branch builds a preview with a backend of its own; a push to the production branch deploys both halves.

::

## Check it

```bash
npx nuxt-backend doctor --only hosting
```

Under `--prod`, `doctor` probes the live site at production's `SITE_URL`:

| Finding | What it checks |
|---|---|
| [`site-https`](/docs/reference/cli/diagnostics#site-https) | The site answers over HTTPS, with HSTS |
| [`site-csp`](/docs/reference/cli/diagnostics#site-csp) | The security headers carry a content security policy |
| [`site-backend-url`](/docs/reference/cli/diagnostics#site-backend-url) | The served app talks to the production deployment |
| [`agent-docs`](/docs/reference/cli/diagnostics#agent-docs) | The site serves its docs for agents, where the app declares them |

## Go to production

::steps{level="3"}

### Move to pro before you charge anyone

Hobby's terms exclude commercial use.

### Add the domain

**Settings**, **Domains**, then add `app.example.com` and the DNS records Vercel shows. Set the same origin as `SITE_URL` on the Convex deployment ([Self-host and add domains](/docs/ship/deploy/self-hosting)).

### Deploy and check

```bash
npx nuxt-backend doctor --prod
```

::

[Deploy to Vercel](/docs/ship/deploy/vercel#check-the-dashboard) lists the dashboard settings to check once per project: Analytics, the Firewall rules, OIDC and the AI Gateway budget.

## Costs and limits

Checked on 2026-10-25 against [Vercel's plans](https://vercel.com/docs/plans/pro-plan):

| | Hobby | Pro |
|---|---|---|
| Price | $0, personal and non-commercial only | $20 a month, with one deploying seat and $20 of usage credit |
| Extra seats | None | $20 a month per member; viewers free |
| Function regions | One | Several |
| Firewall rate-limit rules | 1 per project, 1M allowed requests included | 40 per project, $0.50 per 1M allowed requests in `iad1` |
| BotID | Basic check | Basic check, plus Deep Analysis at $1 per 1,000 checks |
| Password-protected previews | No | $20 a month per project |

Pro warns you once spend reaches $200 by default. Set a spend limit in the team's billing settings before launch.

## Data and compliance

- **What it holds:** request logs, the env you set, build output, and Web Analytics counts, which use no cookies.
- **Region:** functions run where you pick; logs and the account live in the US. Vercel may transfer data worldwide under its DPA.
- **Role:** Vercel processes data on your behalf. Its [DPA](https://vercel.com/legal/dpa) is part of the agreement you accept at sign-up, and its subprocessors are on its [trust center](https://security.vercel.com). It holds SOC 2 Type 2 and ISO 27001, and is certified under the EU-US Data Privacy Framework ([Compliance](https://vercel.com/docs/security/compliance)).

Name Vercel in your privacy policy as your host ([Privacy, GDPR and cookies](/docs/ship/compliance/privacy)). This is not legal advice.
