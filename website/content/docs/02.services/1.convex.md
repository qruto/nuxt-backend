Convex runs your database, your functions and the packaged `backend` component. It is the one service every app needs.

| You need | Time | Cost to start |
|---|---|---|
| A Convex account, or none for a local deployment | 5 minutes | Free: the free plan covers development |

## What it powers

| Capability | What Convex gives | Build pages |
|---|---|---|
| `data` | The database with realtime queries, full-text search and file storage | [Query and update data](/docs/build/data/read-write), [Files](/docs/build/data/files) |
| `jobs` | The scheduler, crons, and the workflow and workpool components | [Background work](/docs/build/data/jobs) |
| `auth` | The functions Better Auth runs in, inside the `backend` component | [Auth setup](/docs/build/auth/setup) |
| `ai` | The Convex AI Gateway, on a paid plan | [AI gateway](/docs/services/ai-gateway) |

Every other capability keeps its state in the same deployment, so one Convex backup holds the whole app ([Back up, restore and roll back](/docs/ship/operate/backup)).

## Create the account

::steps{level="3"}

### Start without an account, if you like

`npx nuxt-backend dev --anonymous`, arriving in `0.2.0`, runs a local deployment on your machine with no account, on every OS. Everything but the AI Gateway works there. Link it to an account later with `npx convex login`.

### Sign up

Open [dashboard.convex.dev](https://dashboard.convex.dev) and sign in with GitHub or Google. Convex creates a team for you.

### Pick the region before the first project

In the team's settings, set the default region: US East (Virginia), EU West (Ireland), Canada Central or Asia Pacific (Sydney). A deployment keeps the region it was created in. Read [Data and compliance](#data-and-compliance) before you choose.

### Create the project

Run `npx nuxt-backend dev` in your app. The first run asks you to log in, creates the project and your dev deployment, and writes `CONVEX_DEPLOYMENT` to `.env.local`. Each developer who runs it gets a dev deployment of their own in the same project.

::

**Who should own it.** Create the project in a team, not a personal account, and invite each developer to the team. The person who answers for production keeps the production deploy key. The team's plan pays for every deployment in it.

## Sandbox and test mode

Convex has no test mode: a deployment is real wherever it runs. The kind of deployment keeps development apart, and `env push` sets `BACKEND_ENVIRONMENT` from it:

| Deployment | `CONVEX_DEPLOYMENT` | `BACKEND_ENVIRONMENT` | Used for |
|---|---|---|---|
| Local or account-free | `local:…`, `anonymous:…` | `development` | Your machine. Provider webhooks need a tunnel to reach it |
| Cloud dev | `dev:…` | `development` | One per developer, with a public URL providers can reach |
| Preview | `preview:…` | `preview` | One per branch, deleted after 5 days (14 on Professional) |
| Production | `prod:…` | `production` | The live app. Set `sandbox` on purpose for a [demo or staging app](/docs/ship/deploy/staging) |

[Environments and deployments](/docs/start/concepts/environments#backend_environment) has what each value turns on.

## Keys and environment

| Variable | Where to find it | Dev | Prod | Secret |
|---|---|---|---|---|
| `CONVEX_DEPLOYMENT` | Written to `.env.local` by the first `npx nuxt-backend dev`. The platform's own name: read it, never author it | `dev:<slug>` | `prod:<slug>` on the host, optional | No |
| `NUXT_PUBLIC_BACKEND_URL` | Derived from `CONVEX_DEPLOYMENT`. The production build gets it from `convex deploy` | Derived | `https://<slug>.convex.cloud` | No |
| `CONVEX_DEPLOY_KEY` | The production deployment's **Settings**, **Deploy keys**. Preview deploy keys sit in the project's settings | Not used | In the host's build env | Yes |
| `AUTH_SECRET` | Generate it: `openssl rand -base64 32` | Provisioned for you | 32 random bytes of production's own | Yes |
| `SITE_URL` | The origin your app answers on | Provisioned for you | `https://app.example.com` | No |
| `BACKEND_ENVIRONMENT` | Set by `env push` from the deployment's kind | `development` | `production`, or `sandbox` for a demo | No |

A self-hosted backend uses the platform's `CONVEX_SELF_HOSTED_URL` and `CONVEX_SELF_HOSTED_ADMIN_KEY` instead of a deploy key ([Self-host and add domains](/docs/ship/deploy/self-hosting)).

## Link it

::steps{level="3"}

### Provision the dev deployment

`npx nuxt-backend dev` pushes `backend/` on every save, and provisions the dev deployment's `AUTH_SECRET`, `SITE_URL` and `BACKEND_ENVIRONMENT`.

### Forward what you add to `.env.local`

```bash
npx nuxt-backend env push
```

It forwards the package's names from `.env.local` to the dev deployment, and generates the web push key pair ([`env push`](/docs/reference/cli#env-push)).

### Give new preview deployments a starting env

In the project's **Settings**, set default environment variables for preview deployments, `AUTH_SECRET` at least. Defaults apply only to deployments created after you set them ([Set up preview environments](/docs/ship/deploy/previews)).

::

## Check it

```bash
npx nuxt-backend doctor --only data
```

| Finding | What it checks |
|---|---|
| [`deployment-env`](/docs/reference/cli/diagnostics#deployment-env) | The CLI can read the deployment's env |
| [`backend-site-url`](/docs/reference/cli/diagnostics#backend-site-url) | The app finds the deployment's HTTP origin |
| [`env-defaults`](/docs/reference/cli/diagnostics#env-defaults) | A new preview deployment starts with the env its first push needs |
| [`convex-config`](/docs/reference/cli/diagnostics#convex-config) | `backend/convex.config.ts` mounts the `backend` component |
| [`deployment-backend-environment`](/docs/reference/cli/diagnostics#deployment-backend-environment) | The deployment holds `BACKEND_ENVIRONMENT`, and under `--prod` that it says `production` |

## Go to production

::steps{level="3"}

### Generate the production deploy key

Open the production deployment's settings in the dashboard and generate a deploy key. Put it in the host's env as `CONVEX_DEPLOY_KEY`, and export it in your shell for the commands below.

### Set production's own values

```bash
openssl rand -base64 32 | npx convex env set --prod AUTH_SECRET
printf %s https://app.example.com | npx convex env set --prod SITE_URL
npx nuxt-backend env push --prod
```

`--prod` sets `BACKEND_ENVIRONMENT=production` and never copies a secret from `.env.local`.

### Deploy and check

```bash
npx nuxt-backend deploy
npx nuxt-backend doctor --prod
```

`deploy` arrives with `0.2.0`. Until then, the host's build command runs `npx convex deploy --cmd 'npm run build' --cmd-url-env-var-name NUXT_PUBLIC_BACKEND_URL` ([Deploy to production](/docs/ship/deploy)).

::

## Costs and limits

Checked on 2026-10-25 against [Convex pricing](https://www.convex.dev/pricing) and [limits](https://docs.convex.dev/production/state/limits):

| | Free and Starter | Professional |
|---|---|---|
| Price | $0. Free stops at its limits; Starter bills usage past them | $25 per developer a month |
| Function calls | 1M a month | 25M a month |
| Database storage | 0.5 GB | 50 GB |
| File storage | 1 GB | 100 GB |
| Data egress | 1 GB | 50 GB |
| Action compute | 20 GB-hours | 250 GB-hours |
| Concurrent queries and mutations | 16 | 256 |
| Concurrent actions | 64 | 512 |

- **Paid plans only:** the AI Gateway (Starter and Professional). On Professional: log streams, exception reporting, periodic backups and custom domains.
- **Regions:** usage outside the US costs 1.3 times as much. The included amounts are shared across regions.
- **Function limits:** a query or mutation runs at most 1 second of your code, and a document holds at most 1 MiB.
- **On the Free plan,** writes past the storage limit fail. Watch the usage page before launch, or move to Starter.

## Data and compliance

- **What it holds:** everything your app stores: accounts, sessions, workspaces, billing state, email logs, files and your own tables.
- **Region:** a deployment stays in the region you chose, and its storage providers are located there. Moving to another region means a new deployment and a [restored backup](/docs/ship/operate/backup).
- **Role:** Convex processes data on your behalf. Its [DPA](https://www.convex.dev/legal/dpa) includes the standard contractual clauses, and it lists its [subprocessors](https://www.convex.dev/legal/subprocessors).
- **Certifications:** SOC 2 Type 2, and HIPAA with a BAA on Professional. Data is encrypted at rest with AES-256 ([Convex security](https://www.convex.dev/security)).

Name Convex in your privacy policy as a processor ([Privacy, GDPR and cookies](/docs/ship/compliance/privacy)). This is not legal advice.
