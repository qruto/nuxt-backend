The module mounts `/security` (module option `pages.security`) behind the `auth` middleware. It renders `<SecuritySettings>`, built entirely on `useAuth`, `usePasskeys` and `useSessions`, in three sections you can pick with `sections`: `passkeys`, `sessions` and `danger`.

```vue
<template>
  <SecuritySettings :sections="['passkeys', 'sessions']" />
</template>
```

## Passkeys

`usePasskeys()` lists the person's passkeys and adds, renames and removes them:

```ts
const { passkeys, add, rename, remove, isLoading, error } = usePasskeys()
await add()                        // runs the browser's passkey ceremony
await rename(passkeyId, 'Laptop')
await remove(passkeyId)
```

## Signed-in devices

`useSessions()` is a live list of the person's unexpired sessions, latest expiry first, with `current` marking this browser. `revoke(id)` signs one out, `revokeOthers()` every other one, and `describeUserAgent(userAgent)` turns a session's user agent into a label such as `Chrome · macOS`. It reads `listSessions` and calls `revokeSession`, which `backend/auth.ts` re-exports from `setupAuth`, and works for sessions of any age.

## Deletion

Every address is verified by the code that signs the person in, so there is nothing left to verify here. The `danger` section deletes the account: the person confirms by email first, and `setupAuth`'s `onUserDeleted` hook runs once the account is gone. Destructive actions ask through the `confirm` prop first (`window.confirm` by default).

## Its props, events and slots

`<SecuritySettings>` takes `sections` and `confirm`, emits `passkey-added`, `passkey-removed(id)`, `session-revoked(id)`, `sessions-revoked`, `delete-requested`, `signed-out` and `error(message)`, and has the slots `passkeys`, `passkey`, `sessions`, `session`, `danger` and `footer`. Its copy comes from `appConfig.backend.labels.security`.
