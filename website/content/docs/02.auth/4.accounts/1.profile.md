The module mounts `/profile` (module option `pages.profile`) behind the `auth` middleware. It renders `<ProfileSettings>`: the person's identity (initials, verification, role and workspace), their display name, and a change of email.

```vue
<template>
  <ProfileSettings @name-saved="name => toast(`Saved as ${name}`)" />
</template>
```

## The display name and avatar

`useAuth().updateUser({ name?, image? })` changes them from the browser. From the server, and for agents, `updateProfile` (re-exported from `backend/auth.ts`) takes `{ name }` and nothing else: an email change never goes through it.

## A new email address

`useAuth().changeEmail(newEmail, callbackURL?)` starts the confirmed flow. For a verified account, the current address receives a confirmation link; following it sends a verification link to the new address, and the account moves once that one is followed too. An unverified account gets the verification link at the new address straight away. `<ProfileSettings>` runs it for you; `callbackPath` sets where the link returns to (the current path by default), and `validateEmail` gates the new address before anything is sent.

## Its props, events and slots

`<ProfileSettings>` takes `validateEmail`, `callbackPath` and `showIdentity` (`true`), emits `name-saved(name)`, `email-change-requested(email)` and `error(message)`, and has the slots `identity`, `name`, `email` and `footer`, each receiving the name and email state with `saveName` and `requestEmailChange`. Its copy comes from `appConfig.backend.labels.profile`: see [Change copy and labels](/docs/ui/customize/labels).
