`useBilling()` opens the provider's hosted checkout and customer portal, and runs every plan change from the browser. The entity it acts for resolves on the server, the active workspace by default.

```vue
<script setup lang="ts">
const { products, checkout, portal, changePlan, cancel } = useBilling()

// Subscribe (opens checkout in a new tab; `redirect: true` for same-tab)
await checkout(products.value!.pro!.id, { trialInterval: 'day', trialIntervalCount: 7 })

// Manage payment methods, invoices, the subscription
await portal({ returnUrl: window.location.href })

// Upgrade / downgrade the active subscription
await changePlan(products.value!.ultra!.id, { proration: 'invoice' })

// Cancel at the end of the paid period (the default) — `atPeriodEnd: false`
// revokes on the spot, with no refund implied either way.
await cancel({ atPeriodEnd: true, reason: 'too_expensive' })
</script>
```

The rest of the lifecycle sits on the same composable: `uncancel()` undoes a scheduled cancellation, `pause({ resumesAt })` pauses at the end of the period, and `resume()` restarts a paused subscription immediately. Each takes an optional `subscriptionId` — needed only with `setupBilling({ multipleSubscriptions: true })`, when one entity can hold several at once (the ids are on `billing.subscriptions`).

`checkout(productIds, options)` accepts `subscriptionId`, `metadata`, `trialInterval` / `trialIntervalCount`, `locale`, `successUrl` (defaults to the current URL), `redirect`, and the checkout-form options `prefill`, `customFields`, `requireBillingAddress`, `allowDiscountCodes` and `discountId`. Discount codes are typed into the provider's own checkout: see [Offer discounts](/docs/billing/subscriptions/discounts). After checkout returns, the `subscription.*` / `order.paid` webhooks refresh the cache — or call `syncEntitlements` (`useCredits().refresh()`) to pull immediately.

## Without code

`<BillingCheckoutLink>` and `<BillingPortalLink>` render the same two actions as links: `<BillingCheckoutLink :product-ids="[productId]">` and `<BillingPortalLink>`. They are the neutral names of the base module's `<CheckoutLink>` and `<CustomerPortalLink>`, which stay registered too.
