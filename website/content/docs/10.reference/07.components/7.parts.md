A part is one region of a packaged component or page, registered as a component under its own name. An app component with the same name, in `app/components/`, replaces it everywhere, packaged pages included. [Swap a part](/docs/build/ui/customize/parts) shows how; this page lists every part.

## How a part is shaped

- **Its name** says the component it belongs to: `AuthFormCode` is a region of `<AuthForm>`, `AccountExport` of `<AccountData>`. A minor release may add a part, never rename one ([Stability](/docs/ship/releases/stability)).
- **It receives** the state its parent already holds, as props: the parent's headless composable (`flow` for the sign-in parts, `pricing` for the pricing parts) and the item it renders, such as one `plan`. `#backend/parts` types each part's props under the part's name, such as `PricingPlanCardProps` for `PricingPlanCard`. It emits nothing: it calls the composable's actions.
- **Its bindings** come from the same composable, such as `flow.bind.codeInput` and `flow.bind.submit`. They carry the accessibility attributes and handlers, so a part you write stays accessible ([Build on the composables](/docs/build/ui/customize/headless)).
- **Its hook** is the `data-*` attribute on its root, the same in the packaged part and the one you write, so styles and tests that target it keep working.

A part you swap in replaces the packaged one in every component and page that renders it. To change it in one place only, fill a [slot](/docs/build/ui/customize/slots) instead.

## Every part

### Sign-in: `<AuthForm>`

| Part | Region | Receives | Hook |
|---|---|---|---|
| `AuthFormHeader` | The logo and the title | `flow` | `data-auth="logo"`, `data-auth="title"` |
| `AuthFormChoose` | The first step: the ways to sign in, in the order `preferLastMethod` gives them | `flow` | `data-auth="step-choose"` |
| `AuthFormPasskey` | The passkey button and the "Last used" badge, inside the first step | `flow` | `data-auth="passkey"` |
| `AuthFormEmail` | The email field and the button that sends a code | `flow` | `data-auth="step-request-code"` |
| `AuthFormCode` | The code field and the button that verifies it | `flow` | `data-auth="step-verify-code"` |
| `AuthFormRecover` | "Lost your passkey?": the address and the recovery code of a passkey-only account | `flow` | `data-auth="step-recover"` |
| `AuthFormWaitlisted` | A new address in early access with no ticket: its place on the waitlist, and the way to an invite code | `flow` | `data-auth="step-waitlisted"` |
| `AuthFormInviteCode` | The invite code field, while the app is invite only or early access | `flow` | `data-auth="step-invite-code"` |
| `AuthFormAge` | The question "How old are you?", asked once of a new address when the app sets a minimum age | `flow` | `data-auth="step-age"` |
| `AuthFormUndeliverable` | An address the email provider stopped delivering to: no code was sent, the same words for every address, and a way back to try another | `flow` | `data-auth="step-undeliverable"` |
| `AuthFormPasskeyOffer` | The offer to save a passkey after a code sign-in, and the passkey a recovery requires, with the new recovery code | `flow` | `data-auth="step-add-passkey"` |
| `AuthFormAgreement` | The line that links every required consent, under the steps that can create an account | `flow` | `data-auth="agreement"` |
| `AuthFormError` | The failure message of the current step, with the wait after a rate limit | `flow` | `data-auth="error"` |

### Waitlist: `<WaitlistForm>`

| Part | Region | Receives | Hook |
|---|---|---|---|
| `WaitlistJoin` | The first step: the address, your questions, the launch-news box (unticked) and the friend the visitor came through | `waitlist` | `data-waitlist="join"` |
| `WaitlistCode` | The sign-in code that proves the address, and the way back | `waitlist` | `data-waitlist="verify"` |
| `WaitlistPlace` | The place in line, the honest words about admission, and Leave; the `/waitlist` page renders it too | `waitlist` | `data-waitlist="place"` |
| `WaitlistShare` | Inside `WaitlistPlace`: the share link, its copy button and the friends who joined through it | `waitlist` | `data-waitlist="share"` |

The `waitlist` a part receives is `useWaitlist()`, with the form's own `join` and `verify`: a part of yours calls them, and `<WaitlistForm>` still emits `joined`, `signed-in` and `error`.

### First run: `<OnboardingFlow>`

| Part | Region | Receives | Hook |
|---|---|---|---|
| `OnboardingProfile` | The first step: the person's name and an optional picture, saved to the account | `onboarding` | `data-onboarding="profile"` |
| `OnboardingWorkspace` | The workspace: rename the one the account starts with, or join a workspace the person was invited to | `onboarding` | `data-onboarding="workspace"` |
| `OnboardingTeammates` | Inviting people to the workspace by email, one after another | `onboarding` | `data-onboarding="teammates"` |
| `OnboardingPlan` | The pricing table and a way to decide later; shown only when the catalog sells a plan | `onboarding` | `data-onboarding="plan"` |

## Swap one

An `AuthFormCode.vue` in your app replaces the code step in `<AuthForm>`, on the packaged sign-in page too:

```vue [app/components/AuthFormCode.vue]
<script setup lang="ts">
import type { AuthFormCodeProps } from '#backend/parts'

const { flow } = defineProps<AuthFormCodeProps>()
</script>

<template>
  <form data-auth="step-verify-code" @submit.prevent="flow.verifyCode()">
    <label>
      Your six-digit code
      <input v-model="flow.otp.value" v-bind="flow.bind.codeInput">
    </label>
    <button v-bind="flow.bind.submit">
      Sign in
    </button>
  </form>
</template>
```

`npx nuxt-backend eject AuthFormCode` writes the packaged source to the same file instead, with its CSS and a version stamp, for when you want to start from it ([`eject`](/docs/reference/cli#eject)).
