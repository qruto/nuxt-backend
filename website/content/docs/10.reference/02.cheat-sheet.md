Every name the package gives you, on one page, so you find the right one without opening each tab. The first half lists the `0.2.0` surface by area, with the unit that brings each name the code does not have yet. The second half is generated from the code as it stands. Each name links to the page that explains it, and a coding agent reads the Markdown twin of this page as its lookup.

The **Unit** column names the build step of the release that brings the name: it builds a new name, or renames or reshapes a built one. A blank cell means the name is built and stays as it is. The [Feature map](/docs/start/feature-map) lists every unit with what it builds.

## Module options and page rules

The `backend` key in `nuxt.config.ts` takes six options: `url`, `authRoute`, `pages` (a path moves a page, `false` turns it off), `redirects`, `devtools` and `css` (`false` loads no package CSS) ([Module options](/docs/reference/configuration/module-options)). A page guards itself with `definePageMeta({ auth: true })`, or with an `auth` object of these rules (SIMPLIFY):

| Rule | Lets the page render when | Unit |
|---|---|---|
| `role` | The signed-in account has this app-wide role | |
| `workspace` | `true`: the session has an active workspace. A role or a list of roles: the caller holds one of them in it | SIMPLIFY |
| `feature` | The workspace's plan includes this feature | SIMPLIFY |
| `hidden` | Set to `true`: a refusal answers 404 instead of the access-denied page | |
