Every name the package gives you, on one page, so you find the right one without opening each tab. Each name links to the page that explains it, and a coding agent reads the Markdown twin of this page as its lookup. The composables, setup helpers, commands, variables and error codes are generated from the registries; the components and the module options follow them.

Every composable and component is auto-imported in your app, and every composable follows the [composable conventions](/docs/reference/nuxt/conventions). Your `backend/` files call each setup helper once: `setupX(components, options)` wires an integration and returns `{ ...helpers, api }` (except `setupRateLimiter`, which returns the `RateLimiter` itself), and `defineX(...)` declares data.

## Other imports

Beside the setup helpers, `nuxt-backend/functions` exports `backendError`, `getBackendError`, `BACKEND_ERRORS`, `verifyHuman` and the token helpers `sha256Hex`, `randomToken` and `normalizeEmail`; `nuxt-backend/app` exports `backendEnv`, the env contract `convex.config.ts` passes to `defineApp`; `nuxt-backend/rate-limit` exports `DEFAULT_LIMITS`; and `nuxt-backend/monitoring` exports `reportError` and `checkIn` ([Package entrypoints](/docs/reference/entrypoints)). In `server/`, `backendAuth` is auto-imported ([Server utilities](/docs/reference/nuxt/server-utilities)).

`BACKEND_ENVIRONMENT` takes `development`, `preview`, `sandbox` or `production`. [Environment variables](/docs/reference/configuration/environment-variables) has each variable.

## Module options and page rules

The `backend` key in `nuxt.config.ts` takes six options: `url`, `authRoute`, `pages` (a path moves a page, `false` turns it off), `redirects`, `devtools` and `css` (`false` loads no package CSS) ([Module options](/docs/reference/configuration/module-options)). A page guards itself with `definePageMeta({ auth: true })`, or with an `auth` object of these rules:

| Rule | Lets the page render when |
|---|---|
| `role` | The signed-in account has this app-wide role |
| `workspace` | `true`: the session has an active workspace. A role or a list of roles: the caller holds one of them in it |
| `feature` | The workspace's plan includes this feature |
| `hidden` | Set to `true`: a refusal answers 404 instead of the access-denied page |
