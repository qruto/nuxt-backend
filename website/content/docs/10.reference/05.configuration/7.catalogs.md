`backend/billing.catalog.ts` declares what the app sells: meters, plans, credit packs and feature benefits, once, with `defineBillingCatalog`. `npx nuxt-backend billing sync` pushes it to the billing provider and writes the provider's ids to `backend/billing.generated.ts`. [Define and sync your catalog](/docs/build/billing/catalog) walks through it; this page lists the fields, generated from the catalog's types.

```ts [backend/billing.catalog.ts]
import { defineBillingCatalog } from 'nuxt-backend/billing'

export default defineBillingCatalog({
  meters: { credits: {} },
  plans: {
    pro: { name: 'Pro', prices: { month: 2900, year: 29000 }, credits: { meter: 'credits', units: 500 } },
  },
  packs: {
    credits500: { name: '500 credits', price: 2000, credits: { meter: 'credits', units: 500 } },
  },
})
```

## The catalog

### `BillingCatalog`

| Field | Type | Required | What it is |
|---|---|---|---|
| `currency` | `string` | no | ISO 4217 currency every single-currency `price` is created in, lowercase (`'usd'`, `'eur'`), and the one a visitor pays in when the catalog does not price their own. |
| `meters` | `Record<string, CatalogMeter>` | no |  |
| `plans` | `Record<string, CatalogPlan>` | no |  |
| `packs` | `Record<string, CatalogPack>` | no |  |
| `features` | `Record<string, CatalogFeature>` | no |  |
| `quotas` | `Record<string, CatalogQuota>` | no | The quotas plans set, keyed by what `billing.requireQuota`, `useFeatures().quota()` and `<Gate quota>` name them by. |
| `customFields` | `Record<string, CatalogCustomField>` | no | Checkout fields plans and packs can collect, keyed by catalog key. |
| `discounts` | `Record<string, CatalogDiscount>` | no | Promotions: the provider's own discounts, declared here and kept in line by `billing sync`, keyed by what checkout names them by (`billing.checkout(ctx, { discount: 'launch' })`). |

### `CatalogMeter`

A usage meter, keyed by the event name spends use (`spendCredits({ meter })`).

| Field | Type | Required | What it is |
|---|---|---|---|
| `aggregation` | `'sum' \| 'count'` | no | How events aggregate: `'sum'` (default) sums `property` across events — multi-credit spends in one event; `'count'` counts events (1 credit per event, not refundable). |
| `property` | `string` | no | The metadata property summed by `'sum'` meters. |
| `eventName` | `string` | no | Event name the meter filters on. |

### `CatalogPlan`

A subscription plan: one recurring product per priced interval.

| Field | Type | Required | What it is |
|---|---|---|---|
| `name` | `string` | yes |  |
| `description` | `string` | no |  |
| `prices` | `CatalogPlanPrices \| CatalogCurrencyPrices` | yes | Price in cents per interval: `{ month: 2900, year: 29000 }`, in the catalog's `BillingCatalog.currency`; or per currency, `{ usd: { month: 2900 }, eur: { month: 2700 } }`. |
| `credits` | `CatalogPlanCreditGrant` | no | Credits included with the plan, granted every cycle (see `CatalogPlanCreditGrant`). |
| `features` | `string[]` | no | Feature-benefit keys (from `BillingCatalog.features`) this plan grants. |
| `trial` | `CatalogTrial` | no | Free trial before the first charge, on every interval. |
| `meterCycle` | `'month'` | no | Run the plan's meters on a monthly cycle on every price: a yearly price then charges once a year while its credits are granted, and its usage invoiced, every month (the provider's meter cycle). |
| `usage` | `CatalogUsagePrice[]` | no | Metered prices charged on top of the fixed price (pay-as-you-go overage), every cycle. |
| `gift` | `CatalogPlanGift` | no | Make the plan giftable as a pass, for these lengths: someone buys it once and a workspace on the free plan holds it for that long, with no card and no renewal. |
| `taxBehavior` | `CatalogTaxBehavior` | no | Tax treatment of the price. |
| `customFields` | `string[]` | no | Checkout field keys (from `BillingCatalog.customFields`) to collect. |
| `retired` | `boolean` | no | Retire the plan: `billing sync` archives its products, so nobody new can check out or switch to it, while everyone subscribed keeps it, renews on it and can switch away. |
| `quotas` | `Record<string, number \| 'unlimited'>` | no | How many of each quota (keys from `BillingCatalog.quotas`) the plan allows: a whole number, or `'unlimited'`. |

### `CatalogPack`

A one-time credit pack.

| Field | Type | Required | What it is |
|---|---|---|---|
| `name` | `string` | yes |  |
| `description` | `string` | no |  |
| `price` | `number \| CatalogPackPrices` | yes | Price in cents, in the catalog's `BillingCatalog.currency`; or per currency, `{ usd: 2000, eur: 1800 }`. |
| `credits` | `CatalogCreditGrant` | yes | Credits granted once at purchase. |
| `taxBehavior` | `CatalogTaxBehavior` | no | Tax treatment of the price. |
| `customFields` | `string[]` | no | Checkout field keys (from `BillingCatalog.customFields`) to collect. |

### `CatalogCreditGrant`

A credit grant a plan or pack carries (a provider meter-credit benefit).

| Field | Type | Required | What it is |
|---|---|---|---|
| `meter` | `string` | yes | The catalog meter key the credits land on. |
| `units` | `number` | yes | Units granted (per cycle for plans, once for packs). |
| `rollover` | `boolean` | no | Carry unused credits into the next cycle. |

### `CatalogUsagePrice`

A metered price billed on top of the plan's fixed price — pay-as-you-go overage, charged at the end of each cycle for what the meter recorded.

| Field | Type | Required | What it is |
|---|---|---|---|
| `meter` | `string` | yes | The catalog meter key this price bills. |
| `unitAmount` | `number \| string` | yes | Price per unit in cents. |
| `cap` | `number` | no | Never charge more than this many cents per cycle, however much is used. |

### `CatalogFeature`

A feature benefit, gated by its key: in a function with `billing.requireFeature(ctx, key)` or the `withFeature(key)` tier, in the UI with `useFeatures().has(key)` and `<Gate feature>`.

| Field | Type | Required | What it is |
|---|---|---|---|
| `description` | `string` | yes |  |

### `CatalogQuota`

A quota: how many of a thing a billing entity may hold at once — projects, boards, sites — counted where the thing is made and given back where it is removed.

| Field | Type | Required | What it is |
|---|---|---|---|
| `description` | `string` | yes | What it counts, as a sentence names it: `'projects'`, `'team boards'`. |

### `CatalogCustomField`

A field the checkout collects and stores on the order/subscription — the answers ride along to the provider dashboard and the webhook payloads.

| Field | Type | Required | What it is |
|---|---|---|---|
| `type` | `'text' \| 'number' \| 'checkbox' \| 'date' \| 'select'` | yes | Input type. |
| `name` | `string` | no | Label shown at checkout. |
| `slug` | `string` | no | Key the answer is stored under. |
| `required` | `boolean` | no | Checkout refuses to submit without an answer. |
| `options` | `Array<{ value: string, label: string }>` | no | Choices for `type: 'select'`. |

## The generated map

`billing.generated.ts` exports `catalog`, one id map per billing environment: `sandbox` and `production`. `billing sync` rewrites it, so never edit it by hand. Earlier previews also wrote a `simulated` map for the billing simulator, which is gone. Each map:

<!-- generated:catalog-ids (pnpm docs:lookups, from src/convex/integrations/billing/types/records.ts) -->

| Field | Type | Required | What it is |
|---|---|---|---|
| `products` | `Record<string, string>` | no | Product key → provider product id: packs by their catalog key, a plan's monthly price by the plan's key and its yearly one as `<plan>:year`. |
| `plans` | `Record<string, Partial<Record<CatalogInterval, string>>>` | no | Plan key → its product per priced interval, retired plans included. |
| `retired` | `string[]` | no | The keys of retired plans: archived at the provider, never sold again. |
| `packs` | `string[]` | no | The catalog keys of `products` that are credit packs: what a gift may buy. |
| `gifts` | `Record<string, string>` | no | Pack key → the provider id of its private gift product: the same prices, no benefits, bought by a purchaser for someone else. |
| `passes` | `Record<string, CatalogPassIds>` | no | Plan key → its gift as a plan pass: the private purchase product per length in months (`months`, keyed `'3'`) and the one free pass product that carries the plan's benefits (`pass`). |
| `meters` | `Record<string, CreditMeterConfig>` | no | Catalog key → credit meter config. |
| `quotas` | `Record<string, string>` | no | Quota key → what it counts, as the catalog's `description` says it: each one is reported by `getFeatures` (as `useFeatures().quota()` reads it), granted or not. |
| `free` | `string` | no | The free plan's key (`plans` holds its product): every billing entity starts on it, and returns to it when a paid plan ends. |
| `currency` | `string` | no | The currency a visitor pays in when the catalog does not price theirs, lower-case ISO 4217: written for a catalog that prices more than one. |
| `discounts` | `Record<string, BillingCatalogDiscount>` | no | Discount key → the discount and its terms. |
