`appConfig.backend` holds content: the plan cards the pricing table renders, the brand, and the words every packaged component shows. Module options hold the wiring. This page lists each key with its type, its default and what it changes. A component reads a value from its prop first, then from here, then from the package default. The keys are generated from `BACKEND_APP_CONFIG_KEYS`, which STABILITY.md freezes.

```ts [app.config.ts]
export default defineAppConfig({
  backend: {
    billing: { plans: [{ key: 'pro', credits: 200 }], lowCreditsThreshold: 20 },
    brand: { name: 'Acme' },
    labels: { auth: { title: 'Welcome back' } },
  },
})
```

## What changes

The keys stay in `0.2.0`, two groups join them, and what reads them changes:

- **`billing.lowCreditsThreshold`** sets when the low-credits notice of [`<BackendNotices>`](/docs/reference/components/shell#backendnotices) appears, in place of the old low-credits banner (SIMPLIFY).
- **Each new component adds its own `labels.<group>`** ([Labels](/docs/reference/configuration/labels#what-changes)).
- **`legal`** is new: `company`, `address`, `contact` and `dpo` fill the packaged privacy, terms, subprocessor and accessibility pages, each marked "not legal advice" ([Legal pages](/docs/ship/compliance/privacy#legal-pages)).
- **`monitoring.feedback`** is new: it turns on the error-reporting service's feedback widget, and `consent.purposes: ['replay']` its session replay, after consent ([What the preset does](/docs/ship/operate/monitoring#what-the-preset-does)).
- **`brand`** names the app on its pages. The branded email theme, with colours, fonts and blocks, is set on the backend, in `setupEmail({ brand, theme })` ([Brand your emails](/docs/build/email/templates/theme)).
