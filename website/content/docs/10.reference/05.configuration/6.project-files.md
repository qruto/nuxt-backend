`npx nuxt-backend init` writes these files into the Convex functions directory (`backend/` unless `convex.json` names another) when they are missing. This page lists each one with who owns it and what it exports, so you know which file to edit and which exports must stay. Once written, a file is yours: nothing overwrites it without `--force`, and `doctor --fix` only restores a file that is gone. The composables and the packaged components call some exports by name, so `doctor` reports a deployment that lacks one as [`function-contract`](/docs/reference/cli/diagnostics#function-contract).

## The scaffold

In `0.2.0` the scaffold writes only the files the package calls into:

```text
backend/
├─ convex.config.ts      mounts the backend component, declares the env
├─ auth.config.ts        trusts the backend's tokens
├─ auth.ts               setupAuth
├─ http.ts               registerBackendRoutes
├─ functions.ts          createFunctions, once: every access tier
├─ billing.catalog.ts    defineBillingCatalog
├─ billing.generated.ts  written by billing sync
├─ billing.ts            setupBilling
├─ email.ts              setupEmail
├─ rateLimiter.ts        setupRateLimiter
├─ audit.ts              setupAudit
├─ account.ts            setupAccount
├─ admin.ts              setupAdmin
├─ flags.ts              setupFlags and defineFlags
├─ ai.ts                 setupAi
└─ workflows.ts          setupWorkflows
```

`backend/functions.ts` calls `createFunctions` once and exports every tier, so no other file builds a second set:

```ts [backend/functions.ts]
import { createFunctions } from 'nuxt-backend/functions'
import { billing } from './billing'
import { rateLimiter } from './rateLimiter'
import { components } from './_generated/api'
import { action, mutation, query } from './_generated/server'

export const { authed, workspace, admin, withRole, withFeature, setUserRole }
  = createFunctions(
    { query, mutation, action },
    { components, billing, rateLimiter },
  )
```

## Files you add

A feature you use gets a file of yours, named as below. The composables read `api.<file>` by default, and each one takes an `api` option to point at another file:

| File | Calls | Read by | Unit |
|---|---|---|---|
| `backend/access.ts` | `setupAccess` | `useAccessPhase`, `useInvite`, `useAccessAdmin`, the admin console's Access tab | |
| `backend/waitlist.ts` | `setupWaitlist` | `useWaitlist`, `<WaitlistForm>`, the Waitlist tab | |
| `backend/notifications.ts` | `setupNotifications` | `useNotifications`, `usePushSubscription`, `<NotificationInbox>` | PREFS |
| `backend/activation.ts` | `defineActivation`, passed to `setupAudit({ checklist })` in `backend/audit.ts` | `useActivation`, `<ActivationChecklist>` | |

| `backend/storage.ts` | `setupStorage` | The base module's `useUpload`, with `api.storage.generateUploadUrl`; `useShareLink`; `<UploadField>` | FILES |
| `backend/referrals.ts` | `setupReferrals` | `useReferrals`, `<ReferralCard>`, the `/r/:code` page and the admin console's Referrals tab | |
| `backend/ai.ts` | `setupAi` | `useChat` | AI |
| `backend/jobs.ts` | `defineJobQueue`, importing `ai` from `backend/ai.ts` | `useJob` | JOBS |
| `backend/retention.ts` | `defineRetention`, one per table you prune | Nothing in the app | RETAIN |
| `backend/crons.ts`, `backend/migrations.ts`, `backend/search.ts` | `@convex-dev/crons`, `@convex-dev/migrations` and `defineSearch`, when you use them | Your own pages | |

## What changes

- **The empty files go (SIMPLIFY).** The scaffold no longer writes `aggregates.ts`, `search.ts`, `crons.ts` or `migrations.ts`. You add one when you use what it sets up, importing the Convex component directly.
- **Fewer mounts (SIMPLIFY).** `convex.config.ts` mounts `backend` and the components its setup helpers use: `persistentTextStreaming`, `polar`, `rateLimiter`, `shardedCounter` (plan quotas), `workflow` and `workpool`. It stops mounting `actionCache`, `aggregate` and `migrations`, which an app mounts when it uses them ([How it works](/docs/start/concepts/how-it-works#the-scaffolded-convexconfigts)).
- **The demo functions go (SIMPLIFY).** `email.ts` drops `sendAsAdmin`, `createSegment`, `addContact`, `createBroadcast` and `sendBroadcast`, `billing.ts` drops `createDiscount`, and `ai.ts` drops the streamed echo (`startEcho`, `echoBody`) and keeps one metered action, `transform`, which the Quickstart's button calls. Each dropped one becomes a recipe in its tab.
- **One `createFunctions` (SIMPLIFY).** `functions.ts` exports `authed`, `workspace`, `admin`, `withRole`, `withFeature` and `setUserRole`. `withFeature` moves here from `billing.ts`, and `authorization` and `functionOptions` go.
- **One MCP server.** `init` writes one server into `.mcp.json`, `nuxt-backend mcp`, which passes Convex's tools through with the rest.
- **`.env.example` groups by purpose:** Backend, Email, Billing, AI, Protection, Monitoring, then the platform's names ([Environment variables](/docs/reference/configuration/environment-variables#app-variables)).
