## Options

The `backend` options are optional. The module reads `url` and `siteUrl` from explicit module options first, then from this package's own environment variables, then derives both from the deployment slug the platform CLI writes to `.env.local` — so in practice neither is set by hand.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    url: 'https://your-deployment.convex.cloud',
    siteUrl: 'https://your-deployment.convex.site',
    authRoute: '/api/auth',
  },
})
```

::field-group
  :::field{name="url" type="string"}
  Backend deployment URL (the `.convex.cloud` origin). Falls back to `NUXT_PUBLIC_BACKEND_URL`, then to the URL derived from the deployment slug.
  :::

  :::field{name="siteUrl" type="string"}
  Backend site URL — the HTTP-routes origin the auth proxy, the AI stream, and the agent exchange talk to. Falls back to `NUXT_PUBLIC_BACKEND_SITE_URL`, then to the derived value.
  :::

  :::field{name="authRoute" type="string" defaultValue="'/api/auth'"}
  Path of the same-origin Better Auth proxy. If you change it, keep `createAuthOptions` and the Convex auth config on the same path.
  :::

  :::field{name="scaffold" type="'auto' | false" defaultValue="'auto'"}
  Auto-scaffold missing Convex backend files on dev startup. Set `false` when you scaffold explicitly with `npx nuxt-backend init`.
  :::

  :::field{name="pages" type="ModulePagesOptions | false" defaultValue="all pages on"}
  The ready-made pages — `login`, `pricing`, `settings`, `profile`, `security`, `acceptInvitation` — all mounted by default. Per key: `true` (default path), a string (custom path), or `false` (bring your own); `false` disables the whole set. An app page at the same path always wins. See [Default Pages](/docs/ui/pages).
  :::

  :::field{name="css" type="boolean" defaultValue="true"}
  Auto-add the neutral `nuxt-backend/ui.css` stylesheet covering every shipped component and page. Set `false` to style the `data-*` hooks yourself. See [Theming](/docs/ui/customize).
  :::

  :::field{name="loginPath" type="string" defaultValue="the resolved pages.login path"}
  Where the `auth` middleware sends signed-out visitors. Set it when you disable the built-in login page and serve your own route.
  :::

  :::field{name="autoEnv" type="boolean" defaultValue="true"}
  On dev startup, provision the dev deployment's environment once (the `env push` engine: `AUTH_SECRET`, `SITE_URL`, the dev-only OTP log flag). Never touches a non-dev deployment. See the [CLI](/docs/reference/cli).
  :::

  :::field{name="mcp" type="ModuleMcpOptions" defaultValue="'/mcp'"}
  The OAuth-protected agent surface: the route, the server metadata, sessions and the Convex functions the built-in tools call. See [MCP server](/docs/agents/mcp).
  :::

  :::field{name="devtools" type="boolean" defaultValue="true"}
  The Backend tab in Nuxt DevTools (dev only). See [DevTools](/docs/start/develop/devtools).
  :::
::

Auth is always enabled by the module.

## Runtime config

The module publishes one key under `runtimeConfig.public.backend`, typed through `@nuxt/schema`:

- `runtimeConfig.public.backend.pages` — the resolved mount path per page key (`login`, `pricing`, `settings`, `profile`, `security`, `acceptInvitation`), `''` when a page is disabled. The shipped components cross-link through it; yours can too.

The deployment URLs are not on `backend`: the module forwards `url` and `siteUrl` to the underlying Convex integration, which exposes them as `runtimeConfig.public.convex.url`, `runtimeConfig.public.convex.siteUrl` and, server-side, `runtimeConfig.convex.siteUrl`.

## The interface

```ts
import nuxtBackendModule, { type ModuleOptions } from 'nuxt-backend'

interface ModuleOptions {
  url?: string                        // the deployment's client URL (`.convex.cloud`); defaults to
                                      // NUXT_PUBLIC_BACKEND_URL, else the URL derived from the
                                      // CONVEX_DEPLOYMENT slug the platform CLI writes to .env.local
  siteUrl?: string                    // the HTTP-routes origin (`.convex.site`) the auth proxy, /ai/stream and
                                      // the agent exchange talk to; defaults to NUXT_PUBLIC_BACKEND_SITE_URL
                                      // (or NUXT_PUBLIC_CONVEX_SITE_URL), else the derived value, else the
                                      // `.site` twin of `url` (or NUXT_PUBLIC_BACKEND_URL / NUXT_PUBLIC_CONVEX_URL)
  authRoute?: string                  // default '/api/auth'
  scaffold?: 'auto' | false           // default 'auto' — auto-scaffold backend files on dev startup
  pages?: ModulePagesOptions | false  // the ready-made pages, all on by default (see below)
  loginPath?: string                  // where the `auth` middleware redirects signed-out visitors;
                                      // defaults to the resolved `pages.login` path — set it when
                                      // you disable the built-in login page and serve your own route
  css?: boolean                       // default true — auto-add the neutral `nuxt-backend/ui.css`
  autoEnv?: boolean                   // default true — on dev startup, provision the dev deployment env
                                      // (the `env push` engine, once per deployment; never non-dev)
  mcp?: ModuleMcpOptions              // the OAuth-protected agent surface at '/mcp'
                                      // (experimental; see STABILITY.md). The module sets
                                      // `nitro.experimental.asyncContext` so tool handlers
                                      // can read the current request
  devtools?: boolean                  // default true — the Backend tab in Nuxt DevTools (dev only)
}

interface ModuleMcpOptions {
  route?: string                       // default '/mcp'
  name?: string                        // server name / description / instructions
  description?: string                 //   forwarded to the MCP toolkit
  instructions?: string
  sessions?: boolean | {               // stateful transport sessions, default off
    enabled?: boolean
    maxDuration?: number               // ms of inactivity before a session is dropped;
                                       //   toolkit default 1_800_000 (30 minutes)
    maxSessions?: number               // concurrent sessions — beyond it the endpoint answers 503;
                                       //   toolkit default 1000
  }
  functions?: Partial<Record<BackendMcpFunctionKey, string>>
                                       // override the Convex functions the built-in tools call
                                       // ('module:export' refs) when the scaffolded files were renamed
}

interface ModulePagesOptions {
  login?: boolean | string             // default '/login' (public) — also the auth middleware's redirect target
  pricing?: boolean | string           // default '/pricing' (public)
  settings?: boolean | string          // default '/settings' (auth)
  profile?: boolean | string           // default '/profile' (auth)
  security?: boolean | string          // default '/security' (auth)
  acceptInvitation?: boolean | string  // default '/accept-invitation' (auth)
}
```

`url` and `siteUrl` are forwarded to the base module as *defaults*, so an
explicit `convex.url` / `convex.siteUrl` in `nuxt.config` still wins over
them. `mcp.route`, `name`, `description`, `instructions` and `sessions` are
forwarded to `@nuxtjs/mcp-toolkit` the same way — an app's own top-level
`mcp` config wins; `functions` is read by this package (see
[MCP server](/docs/agents/mcp)).

Per page key: `true` mounts at the default path, a string mounts at a custom
path, `false` skips it. **An app page at the same path always wins** — the
module detects it, skips its own, and logs the override; you never fight the
router to replace a built-in page.

The module also augments runtime config and app config:

- `PublicRuntimeConfig.backend.pages` — the resolved path per page key
  (`''` when disabled), which is how the shipped components cross-link
  (settings → pricing, pricing → login).
- That is the only key the module publishes under `backend`; the
  deployment URLs stay on the base module's
  `PublicRuntimeConfig.convex.{ url, siteUrl }`, which is where the runtime
  reads them from (`useAiStream()` builds its endpoint off `convex.siteUrl`).
- `AppConfig.backend` — the [content layer](/docs/ui/customize#_2-appconfig-content):
  plan catalog, labels, brand

## Provided vs. intentionally app-owned

`nuxt-backend` is an all-in-one integration: it ships working pages and a
neutral stylesheet out of the box, while keeping every one of them replaceable
without ejecting.

| Capability (Nuxt Kit / mechanism) | In `nuxt-backend` |
|---|---|
| Module options · `defineNuxtModule({ configKey })` | ✅ `backend.url`, `siteUrl`, `authRoute`, `scaffold`, `pages`, `loginPath`, `css`, `autoEnv`, `mcp`, `devtools` |
| Runtime config · `options.runtimeConfig` | ✅ public + private `backend` keys (incl. resolved page paths) |
| App config · `options.appConfig` | ✅ `appConfig.backend` content layer (plans, labels, brand) |
| App plugins · `addPlugin` | ✅ client + server plugins, injects `$convex` |
| Auto-imported composables · `addImports` | ✅ data + auth + SaaS composables (`useBilling`, `usePasskeys`, …) |
| Auto-imported components · `addComponent` | ✅ `<AuthForm>`, `<PricingTable>`, `<WorkspaceSettings>`, `<ProfileSettings>`, `<SecuritySettings>`, `<RoleBoundary>`, `<FeatureBoundary>`, `<AcceptInvitation>`, `<GiftClaimBanner>`, … |
| Route middleware · `addRouteMiddleware` | ✅ `auth` (opt-in, non-global) |
| Server routes · `addServerHandler` | ✅ auth proxy at `authRoute/**`; the OAuth-gated MCP endpoint at `mcp.route` (+ its `/.well-known` discovery documents) |
| Server auto-imports · `addServerImports` | ✅ `fetchQuery`, `preloadQuery`, `backendAuth`, `useBackendMcp`, … |
| Import aliases · `options.alias` (+ `nitro.alias`) | ✅ `#backend`, `#backend/api`, `#backend/server`, `#backend/dataModel`, `#backend/_generated` |
| Type augmentation · `declare module` | ✅ runtime config + app config + generated declarations |
| Package entrypoints · `exports` map | ✅ module, server helpers (`nuxt-backend/billing`, `/email`, `/auth`, …), the component (`/convex.config`, `/_generated/component`), stylesheets (`/ui.css`, `/*.css`) |
| Scaffolded files on disk | ✅ first-run backend wiring |
| Pages / routes · `extendPages` | ✅ the full default-page set (`pages`), each opt-out and app-shadowable |
| Global CSS · `options.css` | ✅ the neutral `ui.css` (`css: false` to opt out) |
| DevTools · `devtools:customTabs`, `extendServerRpc` | ✅ the Backend tab with its own RPC, and an activity log on the Vue DevTools timeline (`devtools: false` to opt out) |
| Layouts · `addLayout` | — app-owned |
| Route rules · `extendRouteRules` | ✅ `robots: false` + `sitemap: false` on the private default pages it mounts ([search engines](/docs/ui/pages#search-engines)); a rule you set for the same path wins |
| Global route middleware · `addRouteMiddleware({ global: true })` | — app-owned (auth is opt-in per page) |
| Nitro plugins · `addServerPlugin` | — not used |
| Bundler plugins · `addVitePlugin` / `extendViteConfig` | — not used |
| Nuxt layer · `extends` | — not shipped as a layer |

::note
Everything the module mounts is progressively replaceable — the
[customization ladder](/docs/ui/pages): override `--bk-*` CSS tokens,
edit `appConfig.backend` content, fill component slots, or shadow a route with
your own page built on the same composables. No eject step exists because none
is needed.
::
