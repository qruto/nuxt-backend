The `backend` key in `nuxt.config.ts` takes six options in `0.2.0`. Five have defaults and the sixth, `url`, is derived, so most apps set none. This page lists each option with its default, the paths file that carries them to the backend, the options the release removes and what replaces them, the runtime config the module publishes, and the `ModuleOptions` interface.

## Options

Every option is optional. The deployment's URL is found in this order, so in practice you set it nowhere:

1. `url`, here.
2. `NUXT_PUBLIC_BACKEND_URL` in the env.
3. Derived from `CONVEX_DEPLOYMENT`, which the Convex CLI writes to `.env.local`.

The module hands the result to the base module as a default, so the base module's own `convex.url`, or `NUXT_PUBLIC_CONVEX_URL`, wins when you set one.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    pages: { login: '/sign-in', pricing: false },
    redirects: { afterSignIn: '/app' },
  },
})
```

::field-group
  :::field{name="url" type="string"}
  The deployment's URL (the `.convex.cloud` origin), found in the order above. The HTTP-routes origin (`.convex.site`) the auth proxy and the AI stream talk to is derived from it. A custom domain in front of the HTTP routes goes in `NUXT_PUBLIC_CONVEX_SITE_URL`, the base module's own variable.
  :::

  :::field{name="authRoute" type="string" defaultValue="'/api/auth'"}
  The path of the same-origin auth proxy, and of the auth routes behind it. This is the one place it is written: the backend's auth routes and the Convex auth config read it from the [paths file](#the-paths-file) ([Auth setup](/docs/build/auth/setup#auth-route-and-options)).
  :::

  :::field{name="pages" type="ModulePagesOptions" defaultValue="every page at its default path"}
  Where the ready-made pages mount. Every page is on at its default path; give a key a path to move it, or `false` to turn it off. A signed-out visitor to a guarded page goes to `pages.login`. To replace a page, put an app page at its path: an app page always wins. A value that is neither a path nor `false` stops the build. Each path is declared here once: the guards read it from the runtime config, and the emails that link to a page read it from the [paths file](#the-paths-file). See [Packaged pages](/docs/build/ui/pages).
  :::

  :::field{name="redirects" type="ModuleRedirectsOptions" defaultValue="{ afterSignIn: '/' }"}
  Where the ready-made pages send a person once they are done. `afterSignIn` is where the sign-in page sends someone whose `?redirect=` names no page of this site: a path, such as `/app`. See [When the session ends](/docs/build/auth/access/pages#when-the-session-ends).
  :::

  :::field{name="devtools" type="boolean" defaultValue="true"}
  The Backend tab in Nuxt DevTools, in development only. See [DevTools](/docs/develop/devtools).
  :::

  :::field{name="css" type="boolean" defaultValue="true"}
  The package's stylesheets. On, the module loads the tokens and the styles of each detected capability's components, inside `@layer nuxt-backend`, so any rule of yours wins. `false` loads no package CSS at all: the components render their markup, `data-*` hooks and accessibility attributes, unstyled. See [Customize the UI](/docs/build/ui/customize).
  :::
::

Auth is always on, and so is every [capability](/docs/start/concepts/capabilities): a capability lights up when its env or catalog exists, never through an option.

### Removed options

`0.2.0` removes four options. Each one stops the build with an error that names it and what replaces it:

| Option | Replaced by |
|---|---|
| `siteUrl` | Derived from `url`, the `.convex.site` twin of the `.convex.cloud` origin. A self-hosted backend or a custom domain sets `NUXT_PUBLIC_CONVEX_SITE_URL`, the base module's own variable |
| `autoEnv` | [`npx nuxt-backend dev`](/docs/reference/cli#dev), which provisions a new dev deployment's env once, and [`env push`](/docs/reference/cli#env-push) |
| `scaffold` | [`npx nuxt-backend init`](/docs/reference/cli#init), and `dev`, which scaffolds an app with no functions directory |
| `mcp` | Nothing in `0.2.0`: the end-user MCP endpoint waits for the next release ([Roadmap](/docs/start/roadmap)) |

`loginPath`, removed earlier in 0.2, stops the build the same way: it is `pages.login` now. Two settings an earlier 0.2 preview removed are back: `css: false`, and `false` on a page key. A page key set to `true` still stops the build, since every page is on unless you turn it off.

### Page keys

`pages` takes one key per ready-made page. A key left out keeps its default path:

| Key | Default path | Access | Unit |
|---|---|---|---|
| `login` | `/login` | Public | |
| `pricing` | `/pricing` | Public | |
| `settings` | `/settings` | Signed in | |
| `profile` | `/profile` | Signed in | |
| `security` | `/security` | Signed in | |
| `acceptInvitation` | `/accept-invitation` | Signed in | |
| `keepAccount` | `/account/keep` | Public, never indexed: keeps an account whose deletion is scheduled, by the link in its email | GRACE |
| `admin` | `/admin` | The `admin` role | |
| `invite` | `/invite` | Public, never indexed: redeems an access link or an invite code | ACCESS |
| `waitlist` | `/waitlist` | Public, never indexed: a place on the waitlist, by its signed status link | |
| `gifts` | `/gifts` | Signed in: gifts sent and received | |
| `unsubscribe` | `/unsubscribe` | Public, never indexed: unsubscribing from an email topic by its signed link | PREFS |
| `welcome` | `/welcome` | Signed in: the onboarding steps | |
| `report` | `/report` | Public: the notice form for reporting content | SAFETY |
| `privacy` | `/legal/privacy` | Public: the privacy policy, filled from `appConfig.backend.legal` | |
| `terms` | `/legal/terms` | Public: the terms of service | |
| `subprocessors` | `/legal/subprocessors` | Public: the generated subprocessor list | |
| `accessibility` | `/legal/accessibility` | Public: the accessibility statement | |

Every private page, and every public one that reads a token from its link, is kept out of search indexes, sitemaps and caches at its path. A page whose capability is not set up yet, such as `/gifts` before billing has a token, still mounts and says what it needs. `false` on a key turns its page off: nothing mounts at its path, and the components that link to it hide the link.

## The paths file

The backend needs some of these paths too: the auth routes are served under `authRoute`, and its emails link to pages. You still write each path once, here. On every `nuxt prepare`, `dev` and `build`, the module writes the ones the backend needs to `paths.generated.ts` in the functions directory, and rewrites the file only when `nuxt.config` moves one. No env var is involved, and the paths deploy with the code that reads them:

```ts [backend/paths.generated.ts]
/* Generated by nuxt-backend from nuxt.config (`backend.authRoute`, `backend.pages`) — do not edit. */
// The Nuxt module rewrites this file whenever nuxt.config moves a path, and the
// backend reads it: auth.config.ts, auth.ts, account.ts, email.ts, billing.ts, waitlist.ts and access.ts pass `paths` on. Commit it.
export const paths = {
  authRoute: '/api/auth',
  acceptInvitation: '/accept-invitation',
  keepAccount: '/account/keep',
  security: '/security',
  waitlist: '/waitlist',
  login: '/login',
  unsubscribe: '/unsubscribe',
  report: '/report',
  settings: '/settings',
  privacy: '/legal/privacy',
} as const
```

| Key | From | What reads it |
|---|---|---|
| `authRoute` | `authRoute` | The auth routes and the Convex auth config (`defineBackendAuthConfig`, `setupAuth`) |
| `acceptInvitation` | `pages.acceptInvitation` | The workspace invitation email (`setupAuth`) |
| `keepAccount` | `pages.keepAccount` | The "keep my account" link of a scheduled deletion (`setupAccount`) |
| `security` | `pages.security` | The email to a passkey-only account that its recovery code signed in (`setupAuth`) |
| `waitlist` | `pages.waitlist` | The waitlist confirmation's status link (`setupAuth`) |
| `login` | `pages.login` | The "You're in" email to a person admitted from the waitlist (`setupWaitlist`) |
| `unsubscribe` | `pages.unsubscribe` | The page a topic email's unsubscribe and confirmation links open, and an announcement broadcast's (`setupEmail`) |
| `report` | `pages.report` | The notice form a statement of reasons' appeal link opens (`setupAdmin`) |
| `settings` | `pages.settings` | The settings page the plan-pass and renewal emails link to (`setupBilling`) |
| `privacy` | `pages.privacy` | The privacy policy an access invitation email ("Email them") links to (`setupAccess`) |

The scaffold passes the file's `paths` on: `defineBackendAuthConfig({ paths })` in `auth.config.ts`, `setupAuth(components, query, { paths, … })` in `auth.ts` and `setupAccount(components, { paths, … })` in `account.ts`. A `waitlist.ts` passes them to `setupWaitlist(components, { paths, … })`. `npx nuxt-backend init` and `dev` write it with the default paths before the module first runs, so a new functions directory deploys. A page turned off with `false` keeps its default path in the file. Commit the file: a build that pushes functions without running Nuxt first deploys the paths it holds.

`npx nuxt-backend doctor` checks both ends. [`paths-file`](/docs/reference/cli/diagnostics#paths-file) warns when the file is missing or holds other paths than `nuxt.config`, and `doctor --fix` rewrites it. [`page-paths`](/docs/reference/cli/diagnostics#page-paths) fails when the deployment links to other paths, which happens when the deployed code predates the file or does not pass `paths` on.

## Runtime config

The module publishes three keys under `runtimeConfig.public.backend`, typed through `@nuxt/schema`:

- **`pages`**: the resolved mount path per page key, or `false` for a page turned off. The shipped components cross-link through it, and yours can too.
- **`authRoute`**: the same-origin auth route (`backend.authRoute`).
- **`redirects`**: `backend.redirects` with its default filled in, `{ afterSignIn }`.

The deployment URLs are not on `backend`: the module forwards `url` to the base module, which exposes it as `runtimeConfig.public.convex.url`, with the derived `runtimeConfig.public.convex.siteUrl` beside it.

## The interface

```ts
import nuxtBackendModule, { type ModuleOptions } from 'nuxt-backend'

interface ModuleOptions {
  url?: string                        // the deployment's URL (.convex.cloud);
                                      // else NUXT_PUBLIC_BACKEND_URL, else
                                      // derived from CONVEX_DEPLOYMENT
  authRoute?: string                  // default '/api/auth'
  pages?: ModulePagesOptions          // where the ready-made pages mount
  redirects?: ModuleRedirectsOptions  // where they send a person when done
  devtools?: boolean                  // default true: the Backend tab
  css?: boolean                       // default true; false loads no package CSS
}

interface ModuleRedirectsOptions {
  afterSignIn?: string  // default '/': when ?redirect= names no page here
}

// A path moves the page; false turns it off.
type PagePath = string | false

interface ModulePagesOptions {
  login?: PagePath             // default '/login'
  pricing?: PagePath           // default '/pricing'
  settings?: PagePath          // default '/settings'
  profile?: PagePath           // default '/profile'
  security?: PagePath          // default '/security'
  acceptInvitation?: PagePath  // default '/accept-invitation'; invitation
                               // emails link to it (the paths file)
  keepAccount?: PagePath       // default '/account/keep' (GRACE)
  admin?: PagePath             // default '/admin'
  invite?: PagePath            // default '/invite' (ACCESS)
  waitlist?: PagePath          // default '/waitlist'
  gifts?: PagePath             // default '/gifts'
  unsubscribe?: PagePath       // default '/unsubscribe' (PREFS)
  welcome?: PagePath           // default '/welcome'
  report?: PagePath            // default '/report' (SAFETY)
  privacy?: PagePath           // default '/legal/privacy'
  terms?: PagePath             // default '/legal/terms'
  subprocessors?: PagePath     // default '/legal/subprocessors'
  accessibility?: PagePath     // default '/legal/accessibility'
}
```

The interface in the code declares no `siteUrl`, `autoEnv` or `scaffold`, and the module stops the build on one.

`url` is forwarded to the base module as a default, so an explicit `convex.url` in `nuxt.config` still wins over it.

Per page key, a path moves the page there, `false` turns it off, and a key left out keeps its default path. **An app page at the same path always wins**: the module detects it, skips its own and logs the override, so you never fight the router to replace a built-in page.

The module also augments the runtime config and the app config:

- **`PublicRuntimeConfig.backend`**: `pages`, `authRoute` and `redirects`, as above.
- **`AppConfig.backend`**: the [content layer](/docs/build/ui/customize/labels), with the plan catalog, the labels and the brand ([App config](/docs/reference/configuration/app-config)).

## What the module adds to an app

`nuxt-backend` ships working pages and a neutral stylesheet, and keeps every one of them replaceable without ejecting:

| Capability (Nuxt Kit) | In `nuxt-backend` |
|---|---|
| Module options · `defineNuxtModule({ configKey })` | `backend.url`, `authRoute`, `pages`, `redirects`, `devtools`, `css` |
| Runtime config · `options.runtimeConfig` | Public `backend` keys, with the resolved page paths |
| App config · `options.appConfig` | The `appConfig.backend` content layer: plans, labels and brand |
| App plugins · `addPlugin` | Client and server plugins that inject `$convex`. A client plugin sends a person to sign in when the session ends on a guarded page (the `backend:session-ended` hook) |
| Auto-imported composables · `addImports` | The [composables](/docs/reference/nuxt/composables) |
| Auto-imported components · `addComponent` | The [components](/docs/reference/components) |
| Server routes · `addServerHandler` | The auth proxy at `authRoute/**`, and the health route |
| Server auto-imports · `addServerImports` | `backendAuth`, beside the base module's `fetchQuery` and `preloadQuery` |
| Import aliases · `options.alias` (and `nitro.alias`) | `#backend`, `#backend/api`, `#backend/server`, `#backend/dataModel`, `#backend/_generated` |
| Type augmentation · `declare module` | Runtime config, app config, page meta (`auth`) and generated declarations |
| Package entrypoints · `exports` map | The module, the setup helpers and the component ([Package entrypoints](/docs/reference/entrypoints)) |
| Pages · `extendPages` | The ready-made pages (`pages`), each movable and replaceable by a page of yours. None is prerendered, and private ones stay out of indexes and caches |
| Global CSS · `options.css` | The tokens on `:root` and the styles of each detected capability's components, inside `@layer nuxt-backend`, so any app rule wins. `css: false` adds none |
| DevTools · `devtools:customTabs`, `extendServerRpc` | The Backend tab with its own RPC, and an activity log on the Vue DevTools timeline (`devtools: false` turns both off) |
| Route rules · `extendRouteRules` | `prerender: false` at every page's path. At a private page's path, and at each of your pages with `auth` rules, also `robots: false`, `sitemap: false`, and caching off with `cache-control: private, no-store` ([search engines](/docs/build/ui/pages#search-engines), [caches](/docs/build/ui/pages#caches)). A rule you set for the same path wins, key by key |
| Global route middleware · `addRouteMiddleware({ global: true })` | `backend-access`, the [page guard](/docs/build/auth/access/pages): it acts only on a page with `definePageMeta({ auth })` rules |
| Error page · `app:resolve` | When neither the app nor a layer has an `error.vue`: a 403 shows `<AccessDenied>`, anything else Nuxt's own page |
| Layouts · `addLayout` | None: layouts are the app's |
| Nitro plugins, bundler plugins, `extends` | None |

`0.2.0` has no named `auth` route middleware: the page guard is the one way to protect a page (SIMPLIFY).

::note
Everything the module mounts is replaceable step by step, the [customization ladder](/docs/build/ui/customize): mount it as it is, restyle it with `--bk-*` tokens, change its labels, fill its slots, swap a part by name, build your own markup on the headless composables, or eject the source with `npx nuxt-backend eject`.
::
