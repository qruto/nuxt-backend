This page gives the signature of every composable the module auto-imports in app code, with no `import` needed. Use it when you need the exact members a composable returns. [Composable conventions](/docs/reference/nuxt/conventions) gives the shape they all share: an options object, `isLoading` for a read, `isPending` for an action, and `error` as `BackendError | null` (`{ code, data, message }`). Generic helpers in the signatures (`FunctionReference`, `FunctionArgs`, `FunctionReturnType`, `OptionalRestArgs`, `ConnectionState`, `Value`) come from `convex` and its subpaths. Wherever a signature says `FunctionReference<…>`, Convex's newer `FunctionReference_future<…>` is accepted too.

The [Cheat sheet](/docs/reference/cheat-sheet#composables) lists them all on one screen.

## At a glance

Every composable and helper the module auto-imports, in the order it registers them, with the tab that covers it and the first line of its doc comment. It is generated from `src/nuxt/registry.ts`.

## Auth and account

```ts
// The session, the role, impersonation and signing out, nothing else.
// isSignedIn and isLoading come from the session; isReady from the backend connection.
function useAuth(): {
  user: ComputedRef<BackendUser | null>  // with `banned`
  session: ComputedRef<BackendSession | null>
  role: ComputedRef<string>              // 'user' when signed out or unset
  hasRole: (role: string | string[]) => boolean
  isSignedIn: ComputedRef<boolean>
  isReady: ComputedRef<boolean>          // signed in, and the connection holds the token: gate signed-in reads on it
  isLoading: ComputedRef<boolean>        // the session is still resolving
  impersonating: ComputedRef<boolean>    // an administrator is visiting
  signOut: () => Promise<void>           // the app navigates after it
}

// The headless state machine behind <AuthForm>: choose → request-code →
// verify-code → passkey-offer (email OTP), choose → recover → passkey-offer
// (a passkey-only account's recovery code), or choose → signInWithPasskey.
// A step machine: its actions never reject; a failed step stays put.
function useLoginFlow(options?: {
  validateEmail?: (email: string) => boolean | string    // false = the default message, a string = your own
  onSuccess?: () => unknown | Promise<unknown>           // signed in and done (e.g. navigateTo)
  autofill?: boolean            // offer this browser's saved passkeys in the email field's autofill
  preferLastMethod?: boolean    // open on the step of the way this browser last signed in
}): {
  step: Ref<'choose' | 'request-code' | 'verify-code' | 'passkey-offer' | 'recover'
    | 'waitlisted' | 'invite-code' | 'age' | 'undeliverable'>
  lastMethod: ComputedRef<'passkey' | 'email-otp' | null>   // how this browser last signed in
  email: Ref<string>; otp: Ref<string>
  recoveryCode: Ref<string>           // typed on recover; the new code once recover() signed in
  inviteCode: Ref<string>             // typed on invite-code while the app is closed
  age: Ref<string>                    // typed on age, when the app sets a minimum age; never kept
  waitlist: Ref<{ position: number, total: number, token: string } | null>   // the place on waitlisted
  passkeyRequired: ComputedRef<boolean> // after a recovery: skipPasskey() does nothing
  isPending: ComputedRef<boolean>
  error: Ref<BackendError | null>     // why the last step failed; forbidden/banned for a banned account
  retryAfter: Ref<number | null>      // seconds to wait after a 429; null when unknown or no refusal
  emailValid: ComputedRef<boolean>
  signInWithPasskey: () => Promise<void>
  sendCode: () => Promise<void>       // → 'verify-code'
  verifyCode: () => Promise<void>     // signs in / signs up → 'passkey-offer', or done where no passkey can be saved
  redeemInviteCode: () => Promise<void>  // inviteCode and the code typed → 'passkey-offer'
  submitAge: () => Promise<void>      // the same code again, with the age → 'passkey-offer'
  addPasskey: () => Promise<void>     // → done
  skipPasskey: () => Promise<void>    // → done (not while passkeyRequired)
  recover: () => Promise<void>        // email + recoveryCode → 'passkey-offer', passkeyRequired
  goTo: (step: LoginStep) => void
  bind: LoginBindings                 // emailInput, codeInput, submit, passkeyButton, back, status
  reset: () => void
}

// The email change, by a code from each address. Like useLoginFlow, it never
// rejects: a failed step stays put with the reason in `error`.
function useEmailChange(options?: {
  validateEmail?: (email: string) => boolean | string    // gates the new address before any code is sent
  onChanged?: (newEmail: string) => unknown | Promise<unknown>
}): {
  step: Ref<'enter-email' | 'confirm-current' | 'verify-new' | 'done'>
  newEmail: Ref<string>; otp: Ref<string>
  isPending: ComputedRef<boolean>
  error: Ref<BackendError | null>
  retryAfter: Ref<number | null>      // seconds to wait after a 429
  emailValid: ComputedRef<boolean>    // validateEmail passes and it isn't the current address
  start: () => Promise<void>          // a code to the current address → 'confirm-current'
  confirmCurrent: () => Promise<void> // checks it, a code to the new address → 'verify-new'
  verifyNew: () => Promise<void>      // checks it, the account moves → 'done'
  reset: () => void
}

// Passkey management over the auth client. The list loads in the browser
// only (`undefined` during SSR); a load never rejects, the actions reject.
// A passkey-only account refuses sign-in codes and recovers through a
// recovery code; the WebAuthn Signal API keeps the browser's passkey list in step.
function usePasskeys(options?: { immediate?: boolean }): {   // immediate: load on mount, default true
  passkeys: ComputedRef<Passkey[] | undefined>
  isLoading: ComputedRef<boolean>                   // the list is loading
  isPending: ComputedRef<boolean>                   // add, rename or remove is running
  error: ComputedRef<BackendError | null>           // the last action's failure, else the last load's
  refresh: () => Promise<void>
  add: (options?: RegisterPasskeyOptions) => Promise<Passkey>
  rename: (id: string, name: string) => Promise<void>
  remove: (id: string) => Promise<void>   // the last passkey of a passkey-only account is refused
  capabilities: ComputedRef<PasskeyCapabilities | null>   // the browser's getClientCapabilities()
  passkeyOnly: ComputedRef<boolean>                 // the account refuses sign-in codes
  setPasskeyOnly: (on: boolean) => Promise<{ recoveryCode: string | null }>   // takes a recent sign-in; on resolves the recovery code
}

// Device sessions — a live list (any session age), revoke one, revoke the
// rest. Reads `listSessions` and calls `revokeSession` from backend/auth.ts.
// The list never throws; the actions reject with what the call threw and
// mirror it into `error`.
function useSessions(options?: { api?: SessionsApi }): {
  sessions: ComputedRef<SessionInfo[] | undefined>  // unexpired, latest expiry first; [] when signed out
  current: ComputedRef<SessionInfo | undefined>     // the session belonging to this browser
  isLoading: ComputedRef<boolean>
  isPending: ComputedRef<boolean>                   // an action is running
  error: ComputedRef<BackendError | null>           // the last action's failure, else the list's
  listError: ComputedRef<BackendError | null>       // the list's own failure, never an action's
  revoke: (id: string) => Promise<void>
  revokeOthers: () => Promise<void>
}

// SessionInfo: { id, userAgent, createdAt, updatedAt, expiresAt, current } — epoch ms

// <SecuritySettings>' Alerts without its markup: the latest sign-ins from a new
// device or with the recovery code, and signing that session out.
function useSignInAlerts(options?: { api?, labels? }): {
  alerts: ComputedRef<SignInAlert[] | undefined>   // newest first; [] signed out
  isLoading, isPending, error,
  device: (alert) => string,       // 'Firefox · macOS'
  date: (alert) => string,         // in the person's language
  sentence: (alert) => string,     // the alert as one sentence
  sessionOf: (alert) => SessionInfo | undefined,  // while its session is signed in
  canSignOut: (alert) => boolean,  // signed in, and not this browser
  signOut: (alert) => Promise<void>,  // rejects on failure, into error
  status, labels,
  bind,   // root, status, error (computed refs); alert(alert), signOut(alert) (functions)
}

// SignInAlert: { at, browser?, os?, recovery, sessionId? } — at in epoch ms

// Confirm it is the person before a sensitive action, by passkey or a code:
// the client half of requireRecentSignIn and of the routes that need it.
function useReauthentication(options?: {
  prompt?: boolean   // this component asks the person (as <ReauthenticateDialog> does)
}): {
  isRequired, step, email, otp, isPending, error, retryAfter,
  withPasskey, sendCode, verifyCode,
  back: () => void, cancel: () => void,
  reauthenticate: () => Promise<void>,   // rejects when they cancel
  withReauthentication: <T>(action: () => Promise<T>) => Promise<T>,
}

// The account itself: its profile, its export and its deletion.
function useAccount(options?: { api? }): {
  latestExport, exportsLeft, confirmation, isLoading, isPending, error,
  updateProfile: (fields: { name?, image?, locale? }) => Promise<void>,
  exportData: () => Promise<AccountExport>,
  deleteAccount: (confirmation: string) => Promise<void>,
  deletion,         // { requestedAt, deletesAt } | null | undefined, live
  cancelDeletion,   // () => Promise<boolean>
}
```

An administrator ends a visit with `useAdmin().stopImpersonating()`, which the impersonation notice of [`<BackendNotices>`](/docs/reference/components/shell#backendnotices) calls.

Beside the code and passkey steps, `useLoginFlow` has `undeliverable` when the email provider stopped delivering to the address after a bounce or a complaint (the same step for new and existing accounts), `waitlisted` when sign-ups are closed and the waitlist is open (`waitlist` holds the place the code check answered), `invite-code` when the launch phase asks for an invite code (`inviteCode` and `redeemInviteCode()`), `age` when the app sets a minimum age (`age` and `submitAge()`), and `passkey-offer` after a code sign-in, where `<AuthForm>` offers to save a passkey. A code only works in the browser that asked for it. Its `lastMethod`, `'passkey'` or `'email-otp'`, is the one place to read how this browser last signed in. `useAccount().deleteAccount` schedules the deletion after a grace period, which `deletion` and `cancelDeletion()` read and undo.

## Workspaces

```ts
// The state never throws; each action resolves with its data, or rejects
// and keeps the failure in `error`.
function useWorkspace(): {
  workspaces, current, member, role, members, invitations, isLoading,
  isPending,   // true while an action runs
  error,       // the last action's failure, else a failed read
  setActive: (workspaceId: string) => Promise<void>,
  create: (args: { name, slug, logo? }) => Promise<Workspace>,
  rename: (name: string, workspaceId?: string) => Promise<void>,   // owners and admins; the address stays
  invite: (args: { email, role?, workspaceId? }) => Promise<WorkspaceInvitation>,
  removeMember: (memberId: string) => Promise<void>,
  updateMemberRole: (memberId: string, role: 'owner' | 'admin' | 'member') => Promise<void>,
  leave: (workspaceId?: string) => Promise<void>,
  acceptInvitation: (invitationId: string, options?: { activate? }) => Promise<WorkspaceMember>,
  declineInvitation, cancelInvitation,   // (invitationId) => Promise<void>
  getInvitation: (invitationId: string) => Promise<InvitationDetails | null>,
  listReceivedInvitations: () => Promise<ReceivedInvitation[]>,
}
// Workspace: { id, slug, name, role }, the shape ctx.workspace has on the backend
```

```ts
  mode, state: ComputedRef<'ready' | 'pending' | 'sent' | 'error' | 'refused'>
  isPending, signedIn, reasons,
  isLoading,  // the session is still read: render a quick report once false; a press waits
  reason, details, url, name, email, goodFaith, signature,  // refs
  website,                                // the honeypot: leave it empty
  contactRequired, signatureRequired,     // what a notice requires now
  error, errorField, retryAfter, announcement, labels,
  noticePath, // the report page with ?table=&id=&url=, which it fills its form from
  send: () => Promise<boolean>,   // true once filed; never rejects
  reset: () => void,
  bind,   // root, reasons, details, urlInput, nameInput, emailInput, goodFaithInput, signatureInput,
          // honeypot (its hidden wrapper), honeypotInput, submit, status, errorText (computed refs);
          // reason(reason) (a function)
}

// <ContactForm> without its markup: a name and an address for a visitor, the
// message alone for a signed-in account, the bot check and a honeypot.
// Needs submitContactMessage re-exported from email.api in backend/email.ts.
function useContactForm(options?: {
  onSent?: () => void
  onError?: (error: BackendError) => void
  labels?, api?,
}): {
  state: ComputedRef<'ready' | 'pending' | 'sent' | 'error' | 'refused'>
  isPending, signedIn,
  name, email, message,   // Ref<string>: a visitor's name and address, and the message (10 to 2,000 characters)
  website,                // the honeypot: leave it empty
  count, error, errorField, retryAfter, announcement, labels,
  send: () => Promise<boolean>,   // true once the deployment stored it; never rejects
  reset: () => void,
  bind,   // root, nameInput, emailInput, messageInput, hint, honeypotInput, submit, status, errorText
}
```

## Headless bindings

The composables behind the packaged UI return `bind`, so your own markup gets the same behaviour and accessibility as the packaged parts. Each binding is attributes and handlers to spread with `v-bind`:

```vue [app/components/AuthFormCode.vue]
<script setup lang="ts">
const flow = useLoginFlow()
</script>

<template>
  <label>Code <input v-bind="flow.bind.codeInput"></label>
  <button v-bind="flow.bind.submit">Sign in</button>
  <button v-bind="flow.bind.passkeyButton">Use a passkey</button>
</template>
```

How a template reads a binding depends on its shape, and the table says which shape each one has. A computed ref is spread with its `.value`: a template unwraps only a top-level ref, never one nested in `bind` (`v-bind="form.bind.root.value"`). A plain object is spread as it is (`v-bind="flow.bind.submit"`). A function of an item returns a plain object for it (`v-bind="report.bind.reason('spam')"`).

The helpers the bindings are built on are exported from `#backend/a11y` for markup of your own:

- `useActionState(action)`: the busy, refused and failed states of an action, with `aria-busy` and `aria-disabled` set while it runs;
- `useFocusReturn()`: returns focus to the control that opened a dialog or a step;
- `useLiveRegion()`: announces a status or an error politely, or as an alert.
