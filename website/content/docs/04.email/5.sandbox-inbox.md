In test mode — the default, until `EMAIL_TEST_MODE=false` — the provider delivers only to its sandbox addresses (`delivered@resend.dev`, with any `+label`), and nobody can open those mailboxes. The component keeps a copy of every message sent to one for an hour, so a demo, a preview deployment or an end-to-end test can still finish an email-code sign-in. The copy is kept whether or not `EMAIL_API_KEY` is set, sign-in codes included, so such a deployment needs no email provider at all. Nothing is kept for a real address, and nothing at all once test mode is off — turning it off also hides what was kept before.

Publishing the inbox is opt-in: re-export its query next to `getEmailStatus`, and read it with `useSandboxInbox`.

```ts [backend/email.ts]
export const { getEmailStatus, getSandboxInbox } = email.api
```

```vue
<script setup lang="ts">
// A fresh label per visitor keeps one visitor's mail out of another's inbox.
const address = ref(`delivered+${crypto.randomUUID()}@resend.dev`)
const inbox = useSandboxInbox(address)
</script>

<template>
  <p v-if="inbox.code.value">Your sign-in code: {{ inbox.code.value }}</p>
</template>
```

`useSandboxInbox` returns the inbox newest first (`messages`), the newest message (`latest`), and the first six-digit code in it (`code`).

::note
The sandbox inbox is **experimental** (see [STABILITY.md](https://github.com/qruto/nuxt-backend/blob/main/STABILITY.md)): how long it keeps a message and the code it extracts may change in a minor release.
::

::warning
The query is public and unauthenticated — a visitor reads it before they are signed in — so **anyone who knows an address can read its mail and sign in as it**. Publish it only where every account is a throwaway sandbox one, generate unguessable labels, and never show one user's address to another.
::
