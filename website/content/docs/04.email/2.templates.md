Every email the package sends on your behalf comes from a template function that returns `{ to, subject, html?, text? }` — an `AuthEmailMessage`. The defaults are minimal, dependency-free HTML + text. An override receives the default it replaces, so it can keep the packaged body, and `setupAuth` returns the set in effect as `emailTemplates` for previews.

## The templates

| Key | Sent when | Data |
|---|---|---|
| `otp` | A one-time code: to sign in, to verify an address (`email-verification`, which also confirms the current address at the start of an email change), and for the new address of an email change (`change-email`) | `{ email, otp, type: 'sign-in' \| 'email-verification' \| 'forget-password' \| 'change-email' }` |
| `welcome` | Once, right after a user is created | `{ email, name }` |
| `deleteAccount` | Confirmation link for account deletion | `{ email, url }` |
| `invite` | Workspace invitation with an accept link | `{ email, url, inviterName, inviterEmail, organizationName, role }` |

The default `invite`, for reference — the shape every override follows:

```ts
invite: ({ email, url, inviterName, inviterEmail, organizationName, role }) => linkEmail(
  email,
  `Join ${organizationName}`,
  `${inviterName || inviterEmail} invited you to join ${organizationName} as ${role}.`,
  url,
  'Accept invitation',
)
```

## Overriding

Pass any subset as `emailTemplates` on `setupAuth` — the transport stays the component's, only the message changes. Each override gets the data and the default it replaces:

```ts [backend/auth.ts]
import { setupAuth } from 'nuxt-backend/auth'

export const { authComponent, createAuth, getAuthUser, /* … */ } = setupAuth(components, query, {
  rateLimiter,
  emailTemplates: {
    otp: ({ email, otp, type }) => ({
      to: email,
      subject: type === 'sign-in' ? `${otp} is your Acme sign-in code` : `Your Acme verification code`,
      text: `Your code: ${otp}. It expires in 5 minutes.`,
      html: renderOtpEmail({ otp }),   // your own renderer
    }),
    invite: (data, byDefault) => ({
      ...byDefault(data),    // keep the default body…
      subject: `${data.inviterName} wants you on ${data.organizationName}`,   // …change the subject
    }),
  },
})
```

Templates run inside the auth flow with the same data the defaults receive; render however you like (a string builder, `@vue-email`, `react-email` — anything returning HTML/text). The [advanced example](/docs/start/templates#example-advanced) overrides `otp` and `invite` this way.

### The welcome email

`welcome` goes out once, right after signup, on every app. Onboarding that follows it belongs in an [email sequence](/docs/email/engagement/sequences): the scaffold's `onSignup` sequence starts three days later. Restyle the welcome itself through `emailTemplates.welcome`.

### Taking over delivery

`setupAuth`'s `email` option replaces the transport for every auth email (`(ctx, message) => Promise<unknown>`); the workspace plugin's own `organization.sendInvitationEmail` replaces just the invitation. Both bypass the component's delivery tracking.

## The gift email

Gift notifications are billing's, restyled through `giftEmail` on `setupBilling` — data `{ recipientEmail, purchaserName, purchaserEmail, message, claimUrl, … }`. See [Gifts](/docs/billing/credits/gifts#the-notification-email).

## Previewing

`setupAuth` returns the templates in effect, overrides included, as `emailTemplates`: a plain object of functions, so a preview query is one call per template. The playground's email-templates page does exactly that:

```ts [backend/emailTemplates.ts]
import { emailTemplates } from './auth'   // re-exported from setupAuth

const preview = emailTemplates.otp({ email: 'you@example.com', otp: '482913', type: 'sign-in' })
// preview.subject, preview.html, preview.text
```
