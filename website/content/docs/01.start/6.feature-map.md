Everything the package gives an app, capability by capability, then what spans them: the pages and components, and the developer tools. Each row is a docs page, with what it gives you and its status, so you can tell what runs today from what `0.2.0` still builds. [Capabilities](/docs/start/concepts/capabilities) says what each capability is, the [Service map](/docs/services) what powers it, and the [Roadmap](/docs/start/roadmap) lists what waits for the next release.

## Statuses

| Status | Means |
|---|---|
| Available | Built, tested and running in the [playground](/docs/start/playground), under the `0.2.x` promise ([Stability](/docs/ship/releases/stability)). |
| Experimental | Built and running in the playground, but it may still change in a minor release ([the experimental tier](/docs/ship/releases/stability#the-experimental-tier)). |
| Changing | Built, and its page already shows the API as `0.2.0` reshapes it: renamed, simplified or moved. Until the named unit lands, the code has the previous names. |
| Planned | Arrives in `0.2.0` and is not built yet. Its page describes it as it will ship; the playground does not have it yet. |

A status in brackets names the unit of the release plan that builds the feature or brings its code to the page. When the unit lands, the row reads Available or Experimental.
