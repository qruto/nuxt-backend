Add the package to a Nuxt app with one command, then start it once. nuxt-backend is one Nuxt module: it goes in `modules`, never in `extends` ([Principles](/docs/start/concepts/principles#one-module-not-a-nuxt-layer)). For a new app, [create it from the starter](/docs/start/templates#starter) instead: the module is installed and the files are written.

## Before you start

- **Nuxt 4.6.2 or later**, not Nuxt 5 yet: the server code is written against `nuxt/server`, a 4.6 API ([Roadmap](/docs/start/roadmap#upstream-releases-the-package-holds-for)).
- **Node 24.11 or later**, the package's `engines` floor.
- No Convex account: the first run can create a local deployment, and [Run the dev loop](/docs/develop/dev-loop) says how to move to a cloud one. The [Service map](/docs/services) lists the accounts each later step asks for.

## Install

::tabs

:::tabs-item{label="Agent" icon="i-lucide-bot"}
Paste this prompt into Claude Code, Cursor, Codex or any agent that can run commands in your project:

```text
Install nuxt-backend, the all-in-one SaaS backend for Nuxt on Convex, in this project:
run `npx -y skills@1.7.0 add https://nuxt-backend.dev --skill nuxt-backend -y`,
then follow .agents/skills/nuxt-backend/references/install.md.
```

:agent-prompt-links

The agent installs the package's core [skill](/docs/develop/agents#the-agent-skills), then follows its install guide. The guide adds the package to an existing app (or creates one from the [starter](/docs/start/templates#starter)), starts it on a local deployment that needs no account, and checks that the app serves `/login`. It asks before it logs in to Convex or touches your accounts, and it never prints or replaces `AUTH_SECRET`. The skill stays in the project for later tasks, and the install adds the task skills of the installed version beside it.
:::

:::tabs-item{label="CLI" icon="i-lucide-terminal"}
```bash
npx nuxt module add nuxt-backend
```

`nuxt module add` installs the package, adds `'nuxt-backend'` to `modules`, then runs the module's install step. That step:

- installs `convex`, the one peer an app lists itself, since `npx convex dev` refuses to start until the app's own `package.json` names it (Nuxt brings `vue`; optional peers such as `ai` or `@sentry/nuxt` wait until a feature needs them);
- writes the backend files into `backend/` (or the functions folder `convex.json` names), never over a file that exists;
- writes `.env.example`, grouped by purpose;
- points the `dev` script at `nuxt-backend dev`;
- swaps `<NuxtWelcome />` for `<NuxtPage />` in an untouched `app/app.vue`, so the module's pages render;
- writes an `AGENTS.md` section, the agent skills and the one `nuxt-backend` entry in `.mcp.json` for the developer MCP server;
- asks the few questions it needs, such as whether to write the agent files, in the terminal.

`npx nuxt-backend init` runs the same setup again later, and restores a file that went missing. [`init`](/docs/reference/cli#init) lists every flag, and [Project files](/docs/reference/configuration/project-files) every file it writes.
:::

:::tabs-item{label="By hand" icon="i-lucide-hand"}
Install the two packages, then add the module:

```bash
npm install nuxt-backend convex
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
})
```

Then write the backend files with `npx nuxt-backend init --no-agents`, which never touches a file that exists. If you skip `init` entirely, make its two edits yourself: render `<NuxtPage />` in `app/app.vue` instead of `<NuxtWelcome />`, and point the `dev` script at `nuxt-backend dev`, which [Run the dev loop](/docs/develop/dev-loop) explains.

**An app on `nuxt-convex-module` already**: keep its entry in `modules` and its options. `nuxt-backend` installs and configures that module itself, and forces the few options it depends on ([nuxt-backend and nuxt-convex-module](/docs/start/concepts/nuxt-convex-module)). Your `convex/` folder stays where it is: the files go there beside yours, and an existing `convex.config.ts`, `http.ts`, `schema.ts` or `auth.config.ts` is kept, so merge the package's parts into them as [Auth setup](/docs/build/auth/setup) shows.
:::

::

## Start it

```bash
npm run dev
```

The first run sets up a dev deployment when none is configured: log in to Convex when it asks, or pick **Start without an account** for a local one. `npx nuxt-backend dev --anonymous` picks the local one without asking, on every OS. It writes `CONVEX_DEPLOYMENT` to `.env.local`, gives the deployment its `AUTH_SECRET`, `SITE_URL` and `BACKEND_ENVIRONMENT`, then runs Convex and Nuxt in this terminal. Nothing goes in `.env` by hand: the backend's URL derives from the deployment's name.

## Check it works

Open `/login` and sign in: with no email provider connected, the code prints in the terminal. `npx nuxt-backend doctor` checks the project and the deployment and names whatever is missing ([Diagnose your setup](/docs/develop/doctor)).

## Using strict pnpm

A flat `node_modules` (npm, Yarn, or pnpm with `nodeLinker: hoisted`) exposes the bundled Convex components to Convex's bundler. pnpm's default isolated layout hides them, so let them reach the project root from `pnpm-workspace.yaml` (pnpm 11 reads its settings there, not from `.npmrc`):

```yaml [pnpm-workspace.yaml]
publicHoistPattern:
  - '@convex-dev/*'
```

Without it, the first `convex dev` push fails to resolve the component definitions. The Nuxt side needs nothing: the module installs `nuxt-convex-module` and `nuxt-security` from its own dependencies. Apps made from the [templates](/docs/start/templates) carry this setting in a `.pnpmfile.mjs`.

pnpm 11 also refuses versions published less than a day ago (`minimumReleaseAge`) and stops an install until each dependency build script is approved or denied (`pnpm approve-builds`). `esbuild` comes in through Nuxt and works without its script, so denying it is safe. Both are pnpm's own supply-chain defaults.

## If it fails

| Symptom | Fix |
|---|---|
| `convex dev` can't resolve `@convex-dev/…/convex.config` | Hoist the components: [Using strict pnpm](#using-strict-pnpm). |
| `npx convex dev` says to add `convex` to your dependencies | Install `convex` in the app itself ([Troubleshooting](/docs/ship/operate/troubleshooting#npx-convex-dev-says-add-convex-to-your-packagejson-dependencies)). |
| `/login` shows the Nuxt welcome page | Render `<NuxtPage />` in `app/app.vue` ([Troubleshooting](/docs/ship/operate/troubleshooting#login-shows-the-nuxt-welcome-page)). |
| `npm run dev` stops at "Preparing Convex functions" | The `dev` script is `convex dev --start "nuxt dev"`: run `npx nuxt-backend doctor --fix` ([Troubleshooting](/docs/ship/operate/troubleshooting#npm-run-dev-stops-at-preparing-convex-functions-and-nuxt-never-starts)). |
| `nuxt module add` wrote no `backend/` folder | The install step runs only in an interactive terminal. Run `npx nuxt-backend init`. |
