Tell people when their strip is ready, in the app, by email and as a push, each a channel they choose, and let them share a finished strip by link.

| Part | You add | Accounts | Time |
|---|---|---|---|
| 5. Notify and share | A "strip ready" notification in the inbox, by email and as a push, the channels to choose, and share links with a public page | A Resend account | 20 min |

## Before you start

You need the app from [Part 4](/docs/start/tutorial/generate). This part adds a Resend account: sign up at [resend.com](https://resend.com) and create an API key. In development, Resend stays in test mode. It delivers only to its test addresses, such as `delivered@resend.dev`, and still sends real delivery events. Put the key and a sender in `.env.local`:

```bash [.env.local]
EMAIL_API_KEY=re_your_api_key
EMAIL_FROM="Panels <onboarding@resend.dev>"
```

Then push them:

```bash
npx nuxt-backend env push
```

[Resend](/docs/services/resend) covers the sending domain, the region and the separate subdomains for product and marketing mail you set up before launch.

### Brand the emails

Give Panels' emails its brand. The package's own emails, sign-in codes and receipts included, use the same layout. Change the `setupEmail` call in `backend/email.ts`; the logo is `public/email-logo.png`:

```ts [backend/email.ts]
export const email = setupEmail(components, {
  paths,
  brand: {
    name: 'Panels',
    logo: '/email-logo.png',
    address: 'Panels, 1 Example Street, 10115 Berlin, Germany',
  },
  theme: {

  },
  topics: {
    productNews: {
      name: 'Product news',
      description: 'New styles and features, about once a month.',
      subscribedByDefault: false,
    },
  },
  messages: {
    en: { backend: { notifications: { strip_ready: { title: 'Your strip is ready', body: 'Open it to read and share it.' } } } },
  },

```

Keep every export below the call as the starter wrote it: the preference center, the announcements, the suppressions and `send` all read them. The brand replaces the starter's `brand.generated.ts` import, which you can remove. `messages` holds the words of the "strip ready" notification, which the next step sends by email and as a push.

Now that `email.ts` declares its topics, create them at Resend, with the webhook subscription:

```bash

```

### Announce a finished strip

Notifications derive from backend events. Record one when a strip is ready, and the package turns it into a notification on every channel its kind allows and the author left on. Add the helper to `backend/strips.ts`, with its import:

```ts [backend/strips.ts]
import { audit } from './audit'
// …
async function announceReady(ctx: MutationCtx, strip: Doc<'strips'>) {
  await audit.recordBackendEvent(ctx, {
    type: 'app.strip_ready',
    subjectId: strip.authorId,
    entityId: strip.workspaceId,
    targetId: strip._id,
  })
}
```

Call it where Part 4 left a gap: after the last panel in `savePanel`, and after a canned strip's copy in `generate`. `savePanel` saves each panel once, so the strip is announced once:

```ts [backend/strips.ts]
    await ctx.db.patch('strips', stripId, { panels: [...strip.panels, { imageId, caption }], status: last ? 'ready' : 'queued' })
    if (last) await announceReady(ctx, strip)
// …
      await ctx.db.patch('strips', id, { panels: canned, cached: true, status: 'ready' })
      await announceReady(ctx, strip)
      return
```

Every event the package records about a person already reaches the inbox; an event of your own joins through `notify`, which says what it becomes and where it links. Add it to the starter's `setupNotifications` call in `backend/notifications.ts`:

```ts [backend/notifications.ts]
import { routes } from './routes'
// …
export const notifications = setupNotifications(components, {
  email,
  paths,
  notify: {
    'app.strip_ready': {
      channels: ['app', 'email', 'push'],
      link: event => routes.strip(event.targetId ?? ''),
    },
  },
})
// …
```

Keep `email`, `paths` and every export below the call as the starter wrote them. `backend/audit.ts` already passes `notifications` to `setupAudit`, so the event you recorded reaches it. Each channel is one the author can turn off:

- `app` puts it in the inbox, behind the bell.
- `email` sends it through the `email` instance, in Panels' brand, with the words from its `messages` and a button to the link. It is not transactional mail: the weekly cap and the quiet hours hold it as they hold every notification email.
- `push` sends a web push to each device that allowed it; `npx nuxt-backend env push` generates the `PUSH_PUBLIC_KEY` and `PUSH_PRIVATE_KEY` it needs.

In the app, a notification's words are labels, so they read in each person's language:

```ts [app/app.config.ts]
    labels: {
      notifications: {
        strip_ready: { title: 'Your strip is ready', body: 'Open it to read and share it.' },
      },
```

### Share a strip by link

A share link is a long random token in a URL. Anyone with it can read the strip, without an account, until the author turns the link off. Declare the strips table shareable in `backend/storage.ts`, in the gap Part 3 left, with its imports:

```ts [backend/storage.ts]
import { isDemo } from './demo'
import { routes } from './routes'
// …
storage.shareable('strips', {
  path: routes.share,
  canShare: (ctx, strip) => !isDemo() && strip.authorId === ctx.user.id && strip.status === 'ready',
})
```

The public demo shares nothing: a link there would publish whatever anyone drew.

The public page reads the strip by its token. `storage.resolveShareLink` returns `{ id, sharedBy, ogImageUrl }`, or `null` for a token that no longer works. Add the query to `backend/strips.ts`. It runs without a signed-in user, and returns only what the page shows:

```ts [backend/strips.ts]
export const shared = query({
  args: { token: v.string() },
  handler: async (ctx, { token }) => {
    const link = await storage.resolveShareLink(ctx, 'strips', token)
    const id = link && ctx.db.normalizeId('strips', link.id)
    const strip = id ? await ctx.db.get('strips', id) : null
    if (!strip || strip.status !== 'ready' || strip.hidden) return null
    const panels = await withUrls(ctx, strip.panels)
    return { idea: strip.idea, panels: panels.map(({ caption, url }) => ({ caption, url })) }
  },
})
```

`useShareLink` turns the link on and off from the strip's page. On the demo, the component says where to run Panels that shares:

```vue [app/components/ShareStrip.vue]
<script setup lang="ts">
import { api } from '#backend/api'

const props = defineProps<{ stripId: string }>()
const demo = useQuery(api.demo.status, {})
const { shared, url, enable, revoke, isPending, error } = useShareLink('strips', () => props.stripId)
</script>

<template>
  <section aria-labelledby="share-heading">
    <h2 id="share-heading">
      Share
    </h2>
    <p v-if="demo && !demo.sharing">
      Sharing is off on the public demo.
      <a :href="demo.templateUrl">Run Panels yourself</a> to share strips by a link.
    </p>
    <template v-else-if="demo">
      <p v-if="url">
        Anyone with this link can read the strip: <code>{{ url }}</code>
      </p>
      <div class="row">
        <button
          type="button"
          :aria-disabled="isPending || undefined"
          @click="isPending || enable()"
        >
          {{ shared ? 'Make a new link' : 'Turn on a link' }}
        </button>
        <button
          v-if="shared"
          type="button"
          :aria-disabled="isPending || undefined"
          @click="isPending || revoke()"
        >
          Turn the link off
        </button>
      </div>
      <p
        v-if="error"
        role="alert"
      >
        {{ error.message }}
      </p>
    </template>
  </section>
</template>
```

The page at the link reads the strip on the server, so the first HTML already holds it. It keeps itself out of search results, and the token out of the `Referer` header of every link it holds:

```vue [app/pages/s/[token].vue]
<script setup lang="ts">
import { api } from '#backend/api'

const route = useRoute()
const { data: strip } = await useAsyncQuery(api.strips.shared, { token: route.params.token as string })
useSeoMeta({ title: () => strip.value?.idea ?? 'Panels', robots: 'noindex', referrer: 'no-referrer' })
</script>

<template>
  <div class="page">
    <article v-if="strip">
      <h1>{{ strip.idea }}</h1>
      <figure
        v-for="panel in strip.panels"
        :key="panel.caption"
      >
        <img
          v-if="panel.url"
          :src="panel.url"
          :alt="panel.caption"
          width="480"
        >
        <figcaption>{{ panel.caption }}</figcaption>
      </figure>
      <AiLabel />
    </article>
    <p v-else>
      This link no longer works. Ask the author for a new one.
    </p>
  </div>
</template>
```

Show the `ShareStrip` component on the strip's page once the strip is ready. This is the finished page:

```vue [app/pages/strips/[id].vue]
<script setup lang="ts">
import { api } from '#backend/api'
import type { Id } from '#backend/dataModel'

definePageMeta({ auth: true })

const route = useRoute()
const id = computed(() => route.params.id as Id<'strips'>)
const strip = useQuery(api.strips.get, () => ({ id: id.value }))
const demo = useQuery(api.demo.status, {})
</script>

<template>
  <div
    v-if="strip"
    class="page"
  >
    <h1>{{ strip.idea }}</h1>
    <StripPhoto
      :strip-id="strip._id"
      :photo-id="strip.photoId"
    />
    <p
      v-if="demo?.demo && strip.ideaId"
      class="muted"
    >
      On the demo, this idea is copied from panels drawn once: a photo you add is not used.
    </p>
    <StripDrawing :strip="strip" />
    <ShareStrip
      v-if="strip.status === 'ready'"
      :strip-id="strip._id"
    />
    <ReportStrip :strip-id="strip._id" />
  </div>
  <div
    v-else-if="strip === null"
    class="page"
  >
    <p>This strip is not in your workspace.</p>
  </div>
</template>
```

On the demo, a strip from a canned idea is a copy of the panels drawn once, so the page says a photo plays no part in it.

**You should see** a link under a finished strip. Open it in a private window: the strip shows without a sign-in, with its label.

## Check your work

- `npx nuxt-backend inbox delivered+panels@resend.dev` lists "Your strip is ready", sent to `delivered+panels@resend.dev`. The DevTools Email tab renders it in Panels' colours.
- The bell in the header shows the notification, and opening it takes you to the strip.
- Press **Turn the link off**, then reload the private window. The page says the link no longer works.
