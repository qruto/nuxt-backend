Sell the credits a strip costs: a catalog in code, a sync to Polar's sandbox, the pricing page and a test purchase.

| Part | You add | Accounts | Time |
|---|---|---|---|
| 2. Sell credits | A credit meter, two packs and a plan, the pricing page, and the balance in the header | A Polar sandbox | 15 min |

## Before you start

You need the app from [Part 1](/docs/start/tutorial/sign-in), running with `npx nuxt-backend dev`. This part adds a Polar sandbox account: sign up at [sandbox.polar.sh](https://sandbox.polar.sh/start), create an organization, and create an organization access token in its settings. The sandbox is free and charges no card. [Polar](/docs/services/polar) covers the account, the token's scopes and what the sandbox does differently.

Credits are Polar's meters. Polar keeps every balance, grant and spend, and the package keeps a cache it can rebuild, so there is no ledger of yours to reconcile.

::steps{level="3"}
### Declare credits in the catalog

The catalog is your pricing as code. Replace the starter's with Panels' own: a `credits` meter, a free plan with a few credits a month, two packs, and a Studio plan whose `priority_queue` feature gives its strips a head start in Part 4.

```ts [backend/billing.catalog.ts]
import { defineBillingCatalog } from 'nuxt-backend/billing'

export default defineBillingCatalog({
  // Every price is created in US dollars, whatever the organization's default
  // currency: plans and packs then read alike on the pricing page.
  currency: 'usd',
  meters: { credits: {} },
  plans: {
    free: {
      name: 'Free',
      prices: { month: 0 },
      credits: { meter: 'credits', units: 30 },
    },
    studio: {
      name: 'Studio',
      prices: { month: 1200, year: 12000 },
      credits: { meter: 'credits', units: 400 },
      features: ['priority_queue'],
    },
  },
  packs: {
    credits100: { name: '100 credits', price: 500, credits: { meter: 'credits', units: 100 } },
    credits500: { name: '500 credits', price: 2000, credits: { meter: 'credits', units: 500 } },
  },
  features: {
    priority_queue: { description: 'Your strips start drawing first' },
  },
})
```

A strip will cost 30 credits, so the free plan draws one strip a month. Prices are in cents of `currency`. Without it, every price is created in your Polar organization's default currency, which may not be the one you priced in.

### Sync the catalog to the sandbox

Put the sandbox token in `.env.local`:

```bash [.env.local]
BILLING_ACCESS_TOKEN=your_sandbox_access_token
```

Push it to the deployment, then create the catalog in the sandbox:

```bash
npx nuxt-backend env push
npx nuxt-backend billing sync
```

`env push` forwards the token. The deployment's `BACKEND_ENVIRONMENT` is `development`, so billing calls Polar's sandbox, never live Polar. `billing sync` creates the meter, the plans and the packs, and writes their ids to `backend/billing.generated.ts`. Commit that file.

**You should see** `billing` turn from `missing` to `test` in `npx nuxt-backend status`.

### Buy credits with the test card

Open [localhost:3000/pricing](http://localhost:3000/pricing). The module mounts it, and `<PricingTable>` on it lists the plans and packs from the catalog. Press **Top up** on the **100 credits** card. Polar's sandbox checkout opens: pay with the card `4242 4242 4242 4242`, any future expiry and any CVC.

Back in the app, show the balance in the header, so people always know what a strip leaves them. Read it in the layout, and put it in the shell's `#actions` slot, for someone signed in: credits belong to a workspace, so a visitor has none.

```vue [app/layouts/default.vue]
<script setup lang="ts">
const pricing = useBackendPagePath('pricing')
const { isSignedIn } = useAuth()
const credits = useCredits({ meter: 'credits' })
</script>
<!-- … -->
    </template>
    <template #actions>
      <NuxtLink
        v-if="pricing && isSignedIn"
        :to="pricing"
      >
        {{ credits.balance.value ?? '…' }} credits
      </NuxtLink>
    </template>
    <slot />
  </AppShell>
</template>
```

`useCredits` reads the active workspace's balance, live: credits belong to the workspace. When it runs low, `<BackendNotices>` inside the shell shows a low-credits notice with a link to buy more. Set the threshold in app config:

```ts [app/app.config.ts]
export default defineAppConfig({
  backend: {
    billing: { lowCreditsThreshold: 30 },
// …
  },
})
```

**You should see** 130 credits in the header: the free plan's 30, plus the pack. Polar's webhooks cannot reach a deployment on your machine, so the return from checkout refreshes the balance.

## Check your work

- `npx nuxt-backend status` shows `billing` as `test`.
- The header reads 130 credits, and `/settings` shows the same balance in its billing section.
- Switch to another workspace. Its balance is its own: credits belong to the workspace that bought them.
