[`nuxt-convex-module`](https://github.com/qruto/nuxt-convex-module) is the base module under `nuxt-backend`: the generic Convex integration for Nuxt, with live queries and mutations, server rendering, the auth plumbing, DevTools and a Convex-aware content security policy. `nuxt-backend` installs and configures it as its own dependency, adds the twelve [capabilities](/docs/start/concepts/capabilities) on top, and puts one neutral name on each concept, so an app never needs both sets of names.

## What passes through unchanged

The base module's data composables and auth components keep their names and their guarantees, documented by the base module and listed in [Composables](/docs/reference/nuxt/composables):

- **Queries and mutations:** `useQuery`, `useQueries`, `useMutation`, `useAction`, `usePaginatedQuery`, `useAsyncQuery`, `useAsyncPaginatedQuery`.
- **Server rendering:** `usePreloadedQuery`, `usePreloadedAuthQuery`.
- **Files:** `useUpload`, `useUploadQueue`, `useStorageUrl`. nuxt-backend adds no upload composable of its own: you pass `useUpload` the package's `generateUploadUrl` ([Accept checked uploads](/docs/build/data/files/checked-uploads)).
- **Auth state:** `useConvexAuth`, and the `<Authenticated>`, `<Unauthenticated>` and `<AuthLoading>` boundaries.

## What is renamed

Every name of the base module that says the platform's or a provider's name is hidden, and the concept keeps one neutral name:

| The base module's | In an app with nuxt-backend |
|---|---|
| `useConvex` | `useBackendClient` |
| `useConvexConnectionState` | `useConnectionState` |
| `useBetterAuth` | `useAuth`, which reads the session and signs out, and `useLoginFlow`, the one way to sign in |
| `<ConvexImage>` | `<StorageImage>` |
| `<CheckoutLink>`, `<CustomerPortalLink>` | `<BillingCheckoutLink>`, `<BillingPortalLink>`, bound to this package's checkout and portal |
| The `convex-auth` route middleware | `definePageMeta({ auth })`, with no named middleware |
| `convexBetterAuthNuxt` (Nitro) | `backendAuth` |

The rest of the brand-named surface (`useConvexQuery`, `provideConvexAuth`, …) stays an explicit import from `nuxt-convex-module` for the rare app that needs it. In development, an old component name still renders its replacement and warns once with the new name.

## The options it sets

`nuxt-backend` passes its own configuration to the base module and sets four of its options:

- **`betterAuth`**: on, with this package's passwordless client (sign-in codes and passkeys). Your own `convex.betterAuth` object is spread over it, so a field you set wins.
- **`polar`**: on, for the billing integration, with the checkout and portal links bound to this package's billing functions. The other auth integrations stay off, so a second auth provider is never auto-detected.
- **`security`**: on, so every app gets the security headers and the content security policy, from `nuxt-security`, which this package installs. The policy is nonce-based, and a production build requires Trusted Types ([Content Security Policy](/docs/ship/security#content-security-policy)). `security: false` in `nuxt.config` still switches it off.
- **`devScript`**: off. The base module would rewrite the `dev` script to `convex dev --start "nuxt dev"`, which never starts Nuxt on a new deployment of this package ([Run the dev loop](/docs/develop/dev-loop#why-a-dev-command-of-its-own)).

Keep a `nuxt-convex-module` entry you already have in `modules`, with its options: they merge with these.

## Official integration parity

`nuxt-backend` ports the official Better Auth integration for Convex's React and Next clients to Vue and Nuxt, with each moving part given a Nuxt default:

| Official React/Next piece | Nuxt/Vue equivalent |
|---|---|
| Manual Better Auth component files | The packaged `nuxt-backend/convex.config`, mounted by the scaffolded `backend/convex.config.ts` |
| `auth.config.ts` with the Better Auth provider | `nuxt-backend/auth.config`, scaffolded as `backend/auth.config.ts` |
| `auth.ts` with `authComponent`, `createAuth` and the auth queries | The scaffolded `backend/auth.ts`, built on `setupAuth(...)` |
| A Better Auth client with `convexClient()` | The Vue Better Auth client the module creates, behind `useAuth()` and `useLoginFlow()` |
| `ConvexBetterAuthProvider` | A Nuxt client plugin, and the base module's `useConvexAuth()` |
| The Next route handler proxy | A Nuxt server proxy at `backend.authRoute` (`/api/auth` by default) |
| `convexBetterAuthNextJs()` | `backendAuth(event)` in Nuxt server handlers (`nuxt/server`) |
| `usePreloadedAuthQuery()` | `usePreloadedAuthQuery()`, for Vue hydration |

## What this means for you

- Read `nuxt-convex-module`'s docs for what passes through, and these for everything else: [Queries and mutations](/docs/build/data/read-write) shows both together.
- Moving an app that uses the base module alone: install this package, and the renames above are what changes in your code ([Installation](/docs/start/installation)).
- For the Convex bindings alone, without the capabilities, use `nuxt-convex-module` on its own.
