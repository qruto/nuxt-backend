Create a ready-made app with Nuxt's own `create nuxt` command. Each one is a standalone app of the published package, with plain version ranges and no lockfile, so what you get is exactly what installs from npm. All of them run against a Convex deployment of your own.

## Starter

The app to build on: a Nuxt app with the module installed and nothing else. Every file in `backend/` is byte-identical to what `npx nuxt-backend init` generates, and with zero custom backend code it has:

- passwordless sign-in (`<AuthForm>`, passkeys and sign-in codes);
- workspaces with emailed invitations (the module registers the `/accept-invitation` page);
- transactional, delivery-tracked email (sign-in codes, invitations, gift notifications);
- subscriptions, feature gating, prepaid credits and gifts, once `billing sync` creates the catalog.

```bash
npm create nuxt@latest my-app -- -t gh:qruto/nuxt-backend/templates/starter
```

`create nuxt` downloads the template, installs it with the package manager you pick, and offers to add more Nuxt modules. Then start it:

```bash
npm run dev
```

The first run sets up a Convex dev deployment (log in when asked, or start without an account), provisions its env, then runs Convex and Nuxt together. The `dev` script is [`nuxt-backend dev`](/docs/reference/cli#dev). Follow the [Quickstart](/docs/start/quickstart#sign-in-with-the-code-in-the-terminal) from the sign-in step: the code prints in the same terminal until you connect an email provider. The scaffolded `billing.catalog.ts` declares two plans and two credit packs, and `npx nuxt-backend billing sync` creates them in Polar's sandbox, as the Quickstart's [second checkpoint](/docs/start/quickstart#checkpoint-2-credits-bought-and-spent) shows.

`backend/_generated` is not part of the template: `npm run dev` writes it against the installed package on the first run, and until then `#backend/*` imports are typed `any`. With pnpm, the template's `.pnpmfile.mjs` answers the build-script question (none of its dependencies needs its script, so none runs) and hoists the component definitions Convex bundles, the same settings [Installation](/docs/start/installation#using-strict-pnpm) gives strict-pnpm users. [View the source](https://github.com/qruto/nuxt-backend/tree/main/templates/starter).

## Panels

Panels is the app the [tutorial](/docs/start/tutorial) builds: a comic-strip maker where people sign in with a code or a passkey, buy credits, add a photo, and turn an idea into a three-panel strip a model draws. They hear when it is ready, by email and in the app, and share it by a link. It is built only on the package's public APIs, and it is the code the [public demo](/docs/start/playground) runs in sandbox mode. Create it to read a finished app, or to run the demo on your own accounts:

```bash
npm create nuxt@latest my-panels -- -t gh:qruto/nuxt-backend/templates/panels
```

The `gh:` form downloads the template from the repository; it stays until `create nuxt` has a registry entry for `nuxt-backend/panels`. Then start it on a local deployment, with no Convex account:

```bash
cd my-panels
npx nuxt-backend dev --anonymous
```

Open `/login` and sign in: the code prints in the terminal until you connect an email provider. Each feature then waits for its service: credits for a Polar sandbox token and `npx nuxt-backend billing sync`, the strip-ready email for a Resend key and `npx nuxt-backend email sync`, drawing for the [AI gateway](/docs/services/ai-gateway). The [Service map](/docs/services) connects them in order, and `npx nuxt-backend doctor` says what is still missing. The template's README maps each file to the tutorial part that writes it. [View the source](https://github.com/qruto/nuxt-backend/tree/main/templates/panels).

## Example: advanced

Every customization point at once, created the same way:

```bash
npm create nuxt@latest my-app -- -t gh:qruto/nuxt-backend/examples/advanced
```

Start from the starter; each file in `advanced` changes exactly one thing from it:

| Customization | Where |
|---|---|
| A customized app definition: the `backendEnv` contract extended by an extra env var | `backend/convex.config.ts` |
| [Custom email templates](/docs/build/email/templates) (the sign-in code, the invitation and the [gift](/docs/build/growth/offers/gifts)) without replacing the transport | `backend/email.ts` → `templates` |
| A custom invitation path: emails link to `/join`, where the app's own page replaces the built-in one | `nuxt.config.ts` (`pages: { acceptInvitation: '/join' }`, carried to `backend/paths.generated.ts`), `app/pages/join.vue` |
| Explicit billing config instead of env-var defaults | `backend/billing.ts` (`accessToken`, `webhookSecret`) |
| A billing webhook hook: `order.paid` writes to an app table, after the built-in refresh and gift fulfilment | `backend/billing.ts` (`events`) + `backend/schema.ts` |
| Custom [webhook paths](/docs/ship/security/webhooks#custom-paths) (`/hooks/billing`, `/hooks/email`) | `backend/http.ts` |
| A hand-rolled signup workflow: `workflow.define` calls the component's email module directly, instead of `defineEmailSequence` | `backend/workflows.ts` |
| Gift claiming: `useGifts()`, with the claim notice in `<BackendNotices>` | `app/pages/app/index.vue` |

```ts [examples/advanced/nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  devtools: { enabled: true },
  css: ['~/assets/main.css'],
  telemetry: false,
  backend: {
    // The invitation page lives at /join, the one place the path is
    // written: the module carries it to backend/paths.generated.ts, which
    // invitation emails link from. The app's own page there replaces the
    // built-in one.
    pages: { acceptInvitation: '/join' },
  },
})
```

[View the source](https://github.com/qruto/nuxt-backend/tree/main/examples/advanced).

## Preview builds (pkg.pr.new)

Every pull request and every commit on `main` publishes a preview of the package through [pkg.pr.new](https://pkg.pr.new), so a fix can be tried before it is released:

```bash
# a specific PR
npm install https://pkg.pr.new/qruto/nuxt-backend@<pr-number>
# a specific commit
npm install https://pkg.pr.new/qruto/nuxt-backend@<commit-sha>
```

The install URL is posted by the pkg.pr.new bot on each PR, next to an **Open in StackBlitz** link that runs the starter with that build wired in. Preview builds carry the exact `exports` map of the release they precede, so the [import tree](/docs/reference/entrypoints) is the same.
