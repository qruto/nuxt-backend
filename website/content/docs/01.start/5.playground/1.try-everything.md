`pnpm try` runs the playground and these docs on your machine, on a local deployment, with every provider in its test mode: billing in Polar's sandbox, email to Resend's test addresses, models through the AI gateway. The playground is Panels, the comic-strip app the [tutorial](/docs/start/tutorial) builds, served under `/playground` with the package's ready-made pages beside it. The kit seeds a persona for each kind of account, with strips in each state a strip has, so you can check every page below as the person it is for. The tables are the review checklist: each row is a page, what to do there, who to sign in as, and what should happen.

## Start it

From a clone of the repository:

```bash [pnpm]
pnpm try
```

1. It reuses the website's local deployment (the one `website/.env.local` names) or provisions one with no account. It never touches a cloud deployment: `pnpm dev` keeps using the one the root `.env.local` names.
2. It pushes the deployment's env: `SITE_URL` set to the origin the app is served at, a generated `AUTH_SECRET`, and `BACKEND_ENVIRONMENT=development`, so any `https://*.localhost` origin of this machine signs in too and codes print in the terminal.
3. It forwards the sandbox keys in the root `.env.local`, a Polar sandbox token, a Resend key and an AI gateway key, and syncs the catalog to Polar's sandbox ([Develop on real sandboxes](/docs/develop/sandboxes)). Without them, billing, email and AI read `missing`, and their rows show empty states: with no gateway key nothing is drawn.
4. It serves the app at `https://nuxt-backend.localhost` through [portless](https://portless.sh), and the deployment's own URLs beside it (`https://api.nuxt-backend.localhost`, `https://site.nuxt-backend.localhost`), so a phone can reach them and no browser sees mixed content.
5. It runs `convex dev`, seeds the personas and their strips, queues Panels' canned ideas to be drawn when the root `.env.local` holds an AI gateway key (`AI_GATEWAY_API_KEY`), and starts the docs and the playground.

Ctrl-C stops everything it started. `pnpm try --name <name>` serves under another name, beside another checkout, and `PORTLESS=0 pnpm try` serves on `http://localhost:3000` with no proxy.

### On a phone

```bash [pnpm]
pnpm try --lan        # https://nuxt-backend.local, for devices on this network
pnpm try --tailscale  # this machine's tailnet name, with trusted certificates
```

Each origin gets its own `SITE_URL`, since auth trusts that one origin. A portless proxy that is already running keeps the mode it started in, and remembers LAN mode for its next start too: the kit serves at the origin portless reports, prints it, and sets `SITE_URL` to it. To switch between `pnpm try` and `pnpm try --lan`, stop the proxy first with `portless proxy stop`. On the LAN the phone must trust portless's certificate authority, or every page and every call fails with a certificate error: send the CA certificate at `~/.portless/ca.pem` to the phone (AirDrop it, or mail it to yourself), install it, then trust it. On iOS: **Settings → General → VPN & Device Management** installs the profile, and **Settings → General → About → Certificate Trust Settings** turns on full trust for it. On Android: **Settings → Security → Encryption & credentials → Install a certificate → CA certificate**. Passkeys on a real iPhone need a certificate the phone trusts without that step: use `--tailscale`, whose certificates come from a public authority (turn on HTTPS certificates for the tailnet first).

### Leave review notes

On any page of the playground or the docs, press **N** (or the **Note** key in the corner, then click an element) to write a note about the element under the pointer. Each note keeps the page, a selector for the element, the start of its text and the viewport, in `.review/notes.jsonl` at the repository root, which git ignores. The overlay and its endpoint exist only in `nuxt dev`: a production build carries neither.

```bash [pnpm]
pnpm try:notes                 # the notes as Markdown, by page
pnpm try:notes --out notes.md  # written to a file
```

### Start over

```bash [pnpm]
pnpm try:reset
```

It empties every table of the local deployment and seeds the personas and their strips again, beside a running `pnpm try` or on its own. It queues no canned idea: draw them from the admin console's Demo tab. Polar's sandbox keeps its customers and orders: archive them in its dashboard for a clean slate.

### The starter, as a new user gets it

```bash [pnpm]
pnpm try:starter
```

It packs the package, installs the tarball into a fresh copy of `templates/starter` in a temporary directory, and runs it at `https://starter.localhost` on a local deployment of its own. The copy's `.env.local` gets the sandbox keys of the root `.env.local`, and it prints the one command left: `npx nuxt-backend billing sync` in the copy, which creates the starter's catalog in the same Polar sandbox. The starter has no dev inbox page: sign in with a test address (`delivered+you@resend.dev`) and read the code in the terminal, or with `npx nuxt-backend inbox` in the copy. Then walk the [Quickstart](/docs/start/quickstart)'s two checkpoints on it: on `/app`, **Buy 500 credits** pays on Polar's sandbox checkout and **Spend 1 credit** runs the scaffold's metered action, so the balance reads 500, then 499. `npx nuxt-backend upgrade --dry-run` in the copy finds nothing to rewrite or repair in a starter of the installed version, and shows the package's data migrations waiting on its new deployment, which `npx nuxt-backend upgrade` runs.

An app made from a [template](/docs/start/templates) develops on the same sandboxes with `npx nuxt-backend dev`. A local deployment gets no webhooks from Polar or Resend, so the rows that wait on one (a renewal, a delivery status) need a cloud dev deployment or a tunnel.

## Personas

Each signs in with a sign-in code: type the address on the sign-in page, and the code prints in the `pnpm try` terminal, where a `development` deployment echoes every code. Every workspace starts on Panels' free plan, through the package's own start.

| Persona | Sign in with | What it has |
|---|---|---|
| Admin | `delivered+tryplaygroundadmin@resend.dev` | The app-wide admin role: the admin console with its Reports, Queue, Costs, Flags, Analytics and Demo tabs. The dev inbox never shows an administrator's mail. |
| Passkey-only admin | `delivered+trypasskeyonlyadmin@resend.dev` | An administrator who signs in with a passkey only, as the public demo requires of its admins. It has no passkey here, so nobody signs in as it: a code asked for it is never sent. |
| Owner on Studio | `delivered+tryworkspaceowner@resend.dev` | Owns the Acme workspace, on the free plan until you subscribe it to Studio (see below): 400 credits a month and the queue's head start. Its strip "Two pigeons open a café" is drawn, and its "Your strip is ready" notification waits unread. |
| Member | `delivered+tryworkspacemember@resend.dev` | A member of Acme: its plan, credits and strips, no billing or member management. Its strip "The office plant plots a takeover" reads `queued`. |
| Free user | `delivered+tryfreeplanpersona@resend.dev` | A personal workspace on the free plan, with 30 credits a month: one strip. Its drawn strip "A snail enters a marathon" has an open report from the owner. It is in the `ideaExamples` experiment, and answered "How did you hear about us?" with a podcast. |
| Gift purchaser | `delivered+trygiftpurchaser@resend.dev` | Buys a credit pack, then gives one to the gift recipient. |
| Gift recipient | `delivered+trygiftrecipient@resend.dev` | A credit pack gift waiting once the purchaser has paid for it, unclaimed. Reads German: the emails the package writes her are in German. |
| Leaving user | `delivered+tryleavingpersona@resend.dev` | A personal workspace and nothing else, there to be deleted. Seeding again (`pnpm try`) brings it back. |

The drawn strips' panels are three small fixture images (`scripts/try/fixtures/`), stored as a drawing job stores its images: the workspace's files, with a provenance record. The queued strip has no job behind it: only a signed-in member puts a metered job in line, so its page shows no place in line until you draw a strip of your own.

### Buy the paid states once

Polar's sandbox takes a payment at its checkout only, so the seeding pays for nobody. It says which purchase gives which persona its state, and you make each once, with the test card (`4242 4242 4242 4242`, any future expiry, any CVC):

| As | Buy | Gives |
|---|---|---|
| Owner on Studio | Subscribe Acme to Studio on `/playground/pricing` | The paid plan with its monthly credits and the `priority_queue` feature, for the owner and the member |
| Gift purchaser | Buy 100 credits on `/playground/pricing`, then give a pack to `delivered+trygiftrecipient@resend.dev` on `/playground/gifts` | The orders, their invoices and the gift the recipient finds waiting |

A local deployment gets no webhooks from Polar, so each return from checkout refreshes the state once. `pnpm try:reset` empties the deployment but not Polar's sandbox, so a second run finds the customers it keeps.
