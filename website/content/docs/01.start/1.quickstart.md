Two checkpoints take you from an empty folder to a signed-in app that sells and spends credits. The first needs no account: the app runs on a local deployment, and sign-in codes print in your terminal. The second adds a Polar sandbox account, so checkout runs on Polar's own test server.

| Checkpoint | Accounts | Time |
|---|---|---|
| [1. A signed-in app](#checkpoint-1-a-signed-in-app) | None | About 3 minutes |
| [2. Credits bought and spent](#checkpoint-2-credits-bought-and-spent) | A Polar sandbox account | About 5 minutes |
| [Next: email and webhooks](#next-email-and-webhooks) | A Resend account, and a Convex account for a cloud deployment | About 10 minutes |

You need Node 24.11 or later. Deploying is not part of the Quickstart: [Deploy](/docs/ship/deploy) takes it from here.

## Checkpoint 1: a signed-in app

::steps{level="3"}

### Create the app

::code-group
```bash [new app]
npm create nuxt@latest my-app -- -t gh:qruto/nuxt-backend/templates/starter
cd my-app
```

```bash [existing app]
npx nuxt module add nuxt-backend
```
::

The [starter](/docs/start/templates#starter) is a Nuxt app with the module installed and its backend files written. In an app you already have, `nuxt module add` is the whole install: the module's install step adds `convex`, writes the same files into `backend/`, points the `dev` script at `nuxt-backend dev` and swaps `<NuxtWelcome />` for `<NuxtPage />`. It asks a few questions in the terminal, and the defaults are fine for this page. [Installation](/docs/start/installation) covers strict pnpm, the install through a coding agent and the install by hand.

### Start it

```bash
npx nuxt-backend dev --anonymous
```

`npx nuxt-backend dev` runs Convex and Nuxt together, and the `dev` script runs the same command. `--anonymous` creates a local deployment that needs no account, on macOS, Linux and Windows alike. A plain `npm run dev` asks instead, and **Start without an account** is the same answer. The first run writes `CONVEX_DEPLOYMENT` to `.env.local`, then gives the deployment its `AUTH_SECRET`, a `SITE_URL` of `http://localhost:3000` and a `BACKEND_ENVIRONMENT` of `development`. Its last check reads `backend preflight: …`, and the email and billing findings in it are expected until you connect those services.

### Sign in with the code in the terminal

Open [localhost:3000/login](http://localhost:3000/login), type your email and ask for a code. No email provider is connected, and a `development` deployment logs every code, so it prints in the terminal running `dev`. Paste it, and you are signed in, with a personal workspace of your own.

::

**You should now see** your email and your workspace on `/app`, which the starter's home page opens. In an app you already have, open `/settings`, which the module mounts.

## Checkpoint 2: credits bought and spent

The starter's catalog, `backend/billing.catalog.ts`, declares two plans and two credit packs. This checkpoint creates them in Polar's sandbox, buys a pack with a test card and spends one credit.

::steps{level="3"}

### Connect Polar's sandbox

Sign up at [sandbox.polar.sh](https://sandbox.polar.sh/start), create an organization and an organization access token, and put the token in `.env.local`:

```bash [.env.local]
BILLING_ACCESS_TOKEN=your_sandbox_access_token
```

Then push it to the deployment and create the catalog in the sandbox:

```bash
npx nuxt-backend env push
npx nuxt-backend billing sync
```

`billing sync` creates the meter, the plans and the packs, and writes their ids to `backend/billing.generated.ts`. [`/pricing`](http://localhost:3000/pricing) lists them now.

### Buy a credit pack

On `/app`, press **Buy 500 credits**. Polar's sandbox checkout opens: pay with the card `4242 4242 4242 4242`, any future expiry and any CVC, then press **Pay**. Back on `/app`, the balance reads 500. The return from checkout refreshes it, since Polar's webhooks cannot reach a deployment on your machine.

### Spend a credit

Press **Spend 1 credit**. It calls `transform` from `backend/ai.ts`, a metered action: it reserves a credit, runs, then settles the spend with Polar, and the balance drops to 499. A run that fails releases its reservation and charges nothing.

::

**You should now see** 499 credits on `/app` and in the credits section of `/settings`.

In an app you already have, these two buttons are one page:

```vue [app/pages/credits.vue]
<script setup lang="ts">
import { api } from '#backend/api'

definePageMeta({ auth: true })

const { products } = useBilling()
const { balance, topUp } = useCredits({ meter: 'credits' })
const spend = useAction(api.ai.transform)
</script>

<template>
  <p>{{ balance ?? '…' }} credits</p>
  <button v-if="products?.credits500" @click="topUp(products.credits500.id)">
    Buy 500 credits
  </button>
  <button @click="spend({ prompt: 'hello' })">Spend 1 credit</button>
</template>
```

`definePageMeta({ auth: true })` sends a visitor who is not signed in to `/login` and back. `useCredits` reads the balance live, so the page updates the moment a purchase or a spend settles.

## Next: email and webhooks

Codes in the terminal and a refresh after checkout cover a first run. Two more steps make development behave like production. The [Service map](/docs/services) gives the order, and each service's page its keys:

- **Email.** Put a Resend key in `.env.local` as `EMAIL_API_KEY`, with `EMAIL_FROM`, and run `npx nuxt-backend env push` ([Resend](/docs/services/resend)). In development, mail goes only to Resend's test addresses: sign in as `delivered+you@resend.dev`, and read the code with `npx nuxt-backend inbox`.
- **Webhooks.** `npx convex login` links the deployment to your Convex account, and a cloud dev deployment has the public URL Polar and Resend post to ([Convex](/docs/services/convex)). Run `npx nuxt-backend billing sync` and `npx nuxt-backend email sync` again to register it.

[Develop on real sandboxes](/docs/develop/sandboxes) covers both, and the AI gateway for a real model call.

## First-run troubleshooting

| What you see | Why, and the fix |
|---|---|
| The Nuxt welcome page instead of the app | `app/app.vue` still renders `<NuxtWelcome />`. [Render `<NuxtPage />`](/docs/ship/operate/troubleshooting#login-shows-the-nuxt-welcome-page) instead. |
| `convex dev` can't resolve `@convex-dev/…` | Strict pnpm hides the components Convex bundles. [Hoist them](/docs/start/installation#using-strict-pnpm). |
| The CLI has no `dev` command, or the app looks nothing like these docs | `nuxt-backend: latest` installs `0.1.0`, a throwaway test publish, until `0.2.0` is out. Install the [preview build](/docs/start/templates#preview-builds-pkgprnew) over it: `npm install https://pkg.pr.new/qruto/nuxt-backend@main`. |
| "This app is in test mode and only emails test addresses, so this address can't receive mail here." | Email is connected and in test mode, which delivers only to Resend's test addresses. Sign in as `delivered+you@resend.dev`, and read the code in the terminal or with `npx nuxt-backend inbox`. |
| "This app can't send email yet." | The deployment has no email provider, and it is not a `development` one, so it does not log codes either. Run `npx nuxt-backend env push`, which sets `BACKEND_ENVIRONMENT` on a dev deployment. |
| `/pricing` is empty | The catalog never reached the deployment. With `dev` running, run `npx nuxt-backend billing sync`, then see [Pricing is empty](/docs/ship/operate/troubleshooting#pricing-is-empty-although-the-catalog-synced). |
| `billing sync` says the token is invalid | It is a production token. Polar's sandbox takes only a token created in the sandbox itself. |

Anything else: [Troubleshooting](/docs/ship/operate/troubleshooting) lists every message the package prints, and `npx nuxt-backend doctor` names what is missing ([Diagnose your setup](/docs/develop/doctor)).
