Everything a client needs is one URL:

```text
https://your-app.com/mcp
```

Transport is **HTTP** (streamable HTTP), and authorization is OAuth — the client discovers the flow from the `401` the endpoint answers with, registers itself, and sends the human off to sign in. No API key to issue, nothing to paste but the URL.

## Claude Code

```bash
claude mcp add --transport http nuxt-backend https://your-app.com/mcp
```

Then run `/mcp` inside Claude Code and pick the server to authenticate: a browser opens on your app's login page, you sign in and approve the scopes, and the tools appear. `claude mcp list` shows the server's connection state.

## claude.ai custom connector

In claude.ai, open **Settings → Connectors → Add custom connector**, give it a name, and paste `https://your-app.com/mcp`. Connecting starts the same OAuth flow in a popup. The URL must be publicly reachable over HTTPS — claude.ai runs the connection from Anthropic's servers, not from your machine.

## Any MCP-capable client

Anything that speaks MCP over HTTP with OAuth 2.1 works the same way. A client needs three things:

- HTTP transport (not stdio) pointed at `https://your-app.com/mcp`.
- Support for the `WWW-Authenticate` / protected-resource discovery handshake (RFC 9728) and the authorization-code flow.
- **Dynamic client registration** — nothing in the app pre-registers agents, unless you list them yourself in `setupAuth({ mcp: { trustedClients } })`.

::tip
For editors, `@nuxtjs/mcp-toolkit` adds two public conveniences next to the endpoint that the OAuth gate deliberately never challenges: `{route}/deeplink` (a one-click IDE install link) and `{route}/badge.svg`. When you start the dev server with Cursor or VS Code detected, it prints the install link in the terminal.
::

## Local development

A client on the **same machine** can use your dev URL directly (`http://localhost:3000/mcp`, or whatever your dev server prints).

A **remote** client — claude.ai's custom connectors above all — cannot reach `localhost`, so local dev needs a public tunnel. Working on this repository, the packaged script does it:

```bash
pnpm dev:nuxt-module:share   # portless nuxt-backend --ngrok nuxt dev … website
```

It runs the same dev server behind an ngrok tunnel and prints the public URL; append `/mcp` and hand that to the client.

::warning
Whatever tunnel you use, the OAuth flow only completes when the deployment's **`SITE_URL` matches the origin the browser is on**. It is the only trusted browser origin for auth, so set `SITE_URL` to the tunnel's origin while you test remote clients (`npx nuxt-backend env push` after editing `.env.local`, or set it on the deployment directly) — otherwise sign-in fails mid-flow. For clients on localhost, `AUTH_TRUST_LOCAL_ORIGINS=1` on a **dev** deployment trusts `http://localhost:*` and `http://127.0.0.1:*` instead.
::

## Troubleshooting a 401

Repeated `401`s with a `WWW-Authenticate` header are **the discovery handshake**, not an error — the client is meant to follow `resource_metadata` and come back with a token. Check the pieces in order:

```bash
# 1. Does the endpoint challenge correctly?
curl -i -X POST https://your-app.com/mcp \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
# → 401 + WWW-Authenticate: Bearer resource_metadata="…/.well-known/oauth-protected-resource"

# 2. Are both discovery documents served?
curl -s https://your-app.com/.well-known/oauth-protected-resource
curl -s https://your-app.com/.well-known/oauth-authorization-server
```

| What you see | What it means |
|---|---|
| `401` forever, client never opens a browser | The client doesn't implement OAuth with dynamic registration — it can't use this endpoint |
| `401` right after it worked | The agent's token was revoked, the account was banned or deleted, or `AUTH_SECRET` was rotated. Re-run the client's OAuth flow |
| `401` for a while after a change | Sessions are cached for the JWT's five-minute lifetime; revocations take effect within minutes |
| `503 Agent endpoint unavailable` | No backend site URL configured on the Nuxt side (`NUXT_PUBLIC_BACKEND_SITE_URL`) |
| `502 Agent token exchange failed` | `POST /mcp/exchange` isn't mounted (`registerBackendRoutes({ … mcp })`), the provider is off (`setupAuth({ mcp: false })`), or the deployment is unreachable |
| `429 Too many agent requests` | The `mcp` rate limit — 60 exchanges per minute per client + user |
| The second document returns `503` / `502` | The authorization-server metadata couldn't be fetched from the deployment — check the Convex site URL and that the deployment is up |
| Connects, but `tools/list` is empty | The agent has no consented scopes, every built-in tool is disabled (`tools.builtin`), or a browser-style `GET` reached the endpoint — tools are hidden without a session |
| Everything 404s | The surface is off (`backend: { mcp: false }`) or the route was moved (`backend.mcp.route`) |

::
