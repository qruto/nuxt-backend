Install the module and these routes exist — no files, no config:

| Route | Page | Access | Built on |
|---|---|---|---|
| `/login` | Passwordless sign-in (passkeys + email OTP) | public | `<AuthForm>` · `useLoginFlow` |
| `/pricing` | Plan cards + credit packs, live from billing | public | `<PricingTable>` · `useBilling`, `useCredits` |
| `/settings` | Workspaces, plan summary, credits | auth | `<WorkspaceSettings>` · `useOrganization` |
| `/profile` | Identity, display name, change email | auth | `<ProfileSettings>` · `useAuth` |
| `/security` | Verification, passkeys, sessions, deletion | auth | `<SecuritySettings>` · `usePasskeys`, `useSessions` |
| `/accept-invitation` | Workspace invitation accept links | auth | `<AcceptInvitation>` |

Each page is a thin wrapper around one auto-imported component, styled by the
neutral `ui.css` the module adds. The `/login` path doubles as the `auth`
middleware's redirect target, and the original destination rides along as
`?redirect=` so sign-in returns the visitor where they were headed.

Configure the set with the [`pages` module option](/api-reference/module-options):

```ts
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    pages: {
      pricing: '/plans',   // custom path
      profile: false,      // bring your own
    },
  },
})
```

## The customization ladder

Every rung keeps the packaged behavior — you only replace what you outgrow,
and there is nothing to eject.

### 1. Do nothing

The neutral stylesheet (`nuxt-backend/ui.css`) makes every page work and look
intentional out of the box. See it live in the playground's
[Vanilla section](/playground/vanilla/pricing).

### 2. CSS tokens

Every component reads the shared `--bk-*` custom properties. One override
re-themes everything at once:

```css
/* your app.css */
[data-auth], [data-pricing], [data-settings], [data-profile], [data-security] {
  --bk-accent: oklch(0.7 0.2 30);
  --bk-radius: 12px;
}
```

The full vocabulary is in the [theming reference](/api-reference/theming).
Prefer full control? Set `backend: { css: false }` and style the `data-*`
hooks from scratch.

### 3. `app.config` content

Copy and catalog live in `appConfig.backend` — reactive, HMR-friendly, typed:

```ts
// app.config.ts
export default defineAppConfig({
  backend: {
    billing: {
      plans: [
        { key: 'starter', credits: 50, blurb: 'For trying things out.' },
        { key: 'pro', credits: 200, features: ['premium'], highlight: true },
      ],
      packs: [{ key: 'credits100', credits: 100 }],
    },
    labels: { pricing: { subscribe: 'Get started' } },
  },
})
```

Plan `key`s match your `setupBilling` products map — names and prices always
resolve live from billing, so the catalog can't drift.

### 4. Slots

Create your own page at the same route (it wins automatically) and keep the
packaged component, replacing only the regions you care about — every slot
receives the full composable state:

```vue
<!-- app/pages/pricing.vue -->
<template>
  <PricingTable>
    <template #plan-action="{ plan, subscribe, pending }">
      <MyButton :loading="pending === plan.key" @click="subscribe(plan.key)">
        Start with {{ plan.product?.name }}
      </MyButton>
    </template>
  </PricingTable>
</template>
```

### 5. Composables

For a fully custom page, drop the component and build on the same composables
the packaged one uses — `useBilling()`, `useCredits()`, `useLoginFlow()`,
`usePasskeys()`, `useSessions()`, `useOrganization()`. The playground's own
[/login](/login) page is a worked example: full custom markup on
`useLoginFlow`, shadowing the module's login page.
