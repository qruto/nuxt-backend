## Prerequisites

- A [Convex](https://convex.dev) deployment (`npx convex dev` creates one).
- Node and a package manager. The bundled Convex components ship as dependencies of `nuxt-backend`, so this is the **only package you install**.

::steps{level="3"}

### Install the package

::code-group
```bash [nuxi]
npx nuxi@latest module add nuxt-backend
```

```bash [pnpm]
pnpm add nuxt-backend
```

```bash [npm]
npm install nuxt-backend
```

```bash [yarn]
yarn add nuxt-backend
```
::

::note{to="#using-strict-pnpm"}
The bundled components (`@convex-dev/aggregate`, `migrations`, `polar`, `rate-limiter`, `resend`, `workflow`, `better-auth`) come in transitively — you never add them to your own `package.json`. Strict pnpm needs one extra line; see the note below.
::

### Add the Nuxt module

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
})
```

### Configure environment variables

Create a `.env.local` in the app root. These are the only app variables auto-detected by the module:

```bash [.env.local]
NUXT_PUBLIC_CONVEX_URL=https://your-deployment.convex.cloud
NUXT_PUBLIC_CONVEX_SITE_URL=https://your-deployment.convex.site
```

#### Required environment

The Convex **deployment** needs all nine backend variables — set them via the CLI (or the [dashboard](https://dashboard.convex.dev)):

```bash
# auth
npx convex env set AUTH_SECRET "$(openssl rand -base64 32)"
npx convex env set SITE_URL https://nuxt-backend.localhost

# email (powered by Resend)
npx convex env set EMAIL_API_KEY re_...
npx convex env set EMAIL_FROM "Acme <hello@yourdomain.com>"
npx convex env set EMAIL_TEST_MODE true
npx convex env set EMAIL_WEBHOOK_SECRET whsec_...

# billing (powered by Polar)
npx convex env set BILLING_ACCESS_TOKEN ...
npx convex env set BILLING_WEBHOOK_SECRET ...
npx convex env set BILLING_ENVIRONMENT sandbox   # or production
```

So the required values split like this:

| Location | Variables |
|---|---|
| `.env.local` (Nuxt app) | `NUXT_PUBLIC_CONVEX_URL`, `NUXT_PUBLIC_CONVEX_SITE_URL` |
| Convex deployment | `AUTH_SECRET`, `SITE_URL`, `EMAIL_API_KEY`, `EMAIL_FROM`, `EMAIL_TEST_MODE`, `EMAIL_WEBHOOK_SECRET`, `BILLING_ACCESS_TOKEN`, `BILLING_WEBHOOK_SECRET`, `BILLING_ENVIRONMENT` |

::warning
Every deployment variable is **required** — a Convex deploy fails until all of them are set, so misconfiguration surfaces at push time instead of as silent no-ops in production. See the [configuration reference](/getting-started/configuration#convex-deployment-variables) for what each variable does.
::

### Start the app once to scaffold the backend

```bash
npm run dev
```

On first run the module creates the Convex files that mount the packaged components, register the webhook routes, and re-export each feature's functions. If a Convex functions directory already exists it is reused; otherwise `backend/` is created:

```text
your-project/
├── backend/
│   ├── convex.config.ts   # defineBackendApp() — mounts everything
│   ├── auth.config.ts
│   ├── auth.ts            # setupAuth — passwordless auth + workspaces
│   ├── http.ts            # registerBackendRoutes — auth + webhook routes
│   ├── functions.ts       # authorization + pre-authorized builders
│   ├── billing.ts         # setupBilling — subscriptions, credits, gifts
│   ├── email.ts           # setupEmail — transactional + marketing email
│   ├── rateLimiter.ts
│   ├── workflows.ts
│   ├── migrations.ts
│   ├── aggregates.ts
│   └── search.ts
└── convex.json
```

`convex.json` is only generated when the functions directory is non-standard (anything other than `convex/`).

### Start Convex

```bash
npx convex dev
```

Deploy with `npx convex deploy`.

::

## Optional: override module defaults

Most apps do not need a `backend` block. Add it only to override the env-based defaults or change the auth route:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    url: 'https://your-deployment.convex.cloud',
    siteUrl: 'https://your-deployment.convex.site',
    authRoute: '/api/auth',
  },
})
```

## Using strict pnpm

A flat `node_modules` (npm, yarn, or pnpm with `nodeLinker: hoisted`) exposes the bundled components automatically. pnpm's default isolated linker hides transitive deps, so let Convex's components reach the project root by adding to `.npmrc`:

```ini [.npmrc]
public-hoist-pattern[]=@convex-dev/*
```

(or set `node-linker=hoisted`). Without this, the `convex dev` push fails to resolve the component definitions.

::warning
The scaffolded `convex.config.ts` is a single `defineBackendApp()` call with no component imports — the package's `nuxt-backend/app` entrypoint imports the bundled `…/convex.config` modules itself (the all-in-one `backend` component plus the five upstream components), and Convex builds its component tree from those imports at **any** depth of the bundle graph. The `@convex-dev/*` packages still must be resolvable from your project root, hence the hoist pattern. You never add them to your own `package.json` — except `@convex-dev/resend` with a [local installation](/backend/local-installation) under pnpm.
::

## Upgrading from the three-component versions

Earlier releases mounted three separate package components — `auth`, `email`, and `billing`. They are now one all-in-one `backend` component, and the env vars are renamed **and required**:

- **Set the new env vars before pushing** — `AUTH_SECRET` (was `BETTER_AUTH_SECRET`), `EMAIL_API_KEY` / `EMAIL_FROM` / `EMAIL_TEST_MODE` / `EMAIL_WEBHOOK_SECRET` (were `RESEND_*`), and `BILLING_ACCESS_TOKEN` / `BILLING_WEBHOOK_SECRET` / `BILLING_ENVIRONMENT` (were `POLAR_ORGANIZATION_TOKEN` / `POLAR_WEBHOOK_SECRET` / `POLAR_SERVER`). A deploy fails until all are set.
- **Component data does not migrate** — the rename orphans the old `auth` / `email` / `billing` components' data; the next `convex dev` / `convex deploy` push prompts you to confirm removing those components.
- **Update your webhook URLs** — the billing endpoint moved from `/polar/events` to `/billing/events` and the email endpoint from `/resend-webhook` to `/email/events`; see [Webhooks](/backend-components/webhooks).
- **Function references changed** — `components.auth.adapter.*` → `components.backend.adapter.*`, `components.email.lib.*` → `components.backend.email.*`, `components.billing.lib.*` → `components.backend.billing.*`. `setupBilling(components)` now needs no config (it reads the `BILLING_*` env), and its returned `polar` client is now `provider`.
