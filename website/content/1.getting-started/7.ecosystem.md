`nuxt-backend` is built from community packages, and it works with more of them than it installs. This page says where each one stands. The package's CI reads the tables below: a component that ships without its row, or a row that claims a package the manifest does not have, fails the build.

| Status | Meaning |
|---|---|
| **Shipped** | Installed and wired by this package. You add nothing. |
| **Bundled** | Arrives through a shipped package. It works, but this package exposes no options of its own for it. |
| **Supported** | Works when you add it: the package already sets what it needs. |
| **Planned** | On the roadmap for the release named in the notes. |
| **Recipe** | Works beside the package with a little code of your own. There is no wrapper. |
| **Not planned** | Left out on purpose, for the reason given. |

## Convex tooling

| Package | Status | Surface | Notes |
|---|---|---|---|
| `convex` | Shipped | The peer dependency and the CLI | `npx nuxt-backend dev` runs it for you |
| `convex-helpers` | Shipped | The custom functions behind [`createFunctions`](/platform/authorization#pre-authorized-function-builders), and the triggers behind [aggregates](/platform/aggregates) | |
| `convex-test` | Shipped | [`nuxt-backend/test`](/tooling/testing) registers the component | An optional peer |
| `@convex-dev/eslint-plugin` | Shipped | [`nuxt-backend/eslint`](/tooling/linting) | An optional peer |

The rest of Convex's tooling works as it does anywhere:

- **The dashboard.** The DevTools tab links to it for a cloud deployment.
- **The MCP server.** `npx convex mcp start` lets an agent read the deployment. `init` writes it into `.mcp.json`.
- **The AI guidelines.** `npx convex ai-files install` writes Convex's own rules for agents.
- **Local and self-hosted backends.** An anonymous local deployment is enough for development, and a self-hosted URL works through the Convex CLI's own variables.

## Agent tooling

| Package | Status | Surface | Notes |
|---|---|---|---|
| `skills` | Supported | The [`nuxt-backend` skill](/agents/skills-and-agent-files) | `npx skills add https://nuxt-backend.dev -s nuxt-backend` |

Beyond the skill, `init` writes an `AGENTS.md` section and `.mcp.json` for coding agents, and this site publishes [`llms.txt`](/llms.txt).

## Templates

Apps start from Nuxt's own `create nuxt` with a [template](/getting-started/templates): the starter, the playground or the advanced example. Once the package is listed on [nuxt.com/modules](https://nuxt.com/modules), `create nuxt` and `npx nuxi module add backend` offer it by name.
