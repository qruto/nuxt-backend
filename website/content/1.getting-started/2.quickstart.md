Ten minutes, six steps, nothing to fill in by hand. Every command below is exactly what the module scaffolds and what the `nuxt-backend` CLI does — see [CLI](/tooling/cli) for every flag.

::steps{level="3"}

### Install the module

::code-group
```bash [nuxi]
npx nuxi@latest module add nuxt-backend
npm install convex
```

```bash [pnpm]
pnpm add nuxt-backend convex
```

```bash [npm]
npm install nuxt-backend convex
```
::

`nuxi module add` also adds `'nuxt-backend'` to `modules` in `nuxt.config.ts` (with a plain package-manager install, add it yourself — or run `npx nuxt-backend init`, which does the same wiring). In a fresh `nuxi init` app, `app/app.vue` still renders `<NuxtWelcome />` and no `<NuxtPage />` — the pages this module registers (`/login`, `/pricing`, …) resolve but never render. Replace `<NuxtWelcome />` with `<NuxtPage />` (`npx nuxt-backend init` does it while the file is still the starter; the dev console warns while it is not done). `nuxt-backend` brings the Convex integration and every bundled component as its dependencies; `convex` is its peer and the CLI you run, and has to be in your own `package.json` for `npx convex dev` to start (`init` adds it when missing).

::note
Strict pnpm hides transitive packages from Convex's bundler. Add `publicHoistPattern: ['@convex-dev/*']` to `pnpm-workspace.yaml` first — see [Installation](/getting-started/installation#using-strict-pnpm).
::

### Start Convex and Nuxt

Two terminals, in either order:

```bash
npx convex dev   # terminal 1 — provisions a dev deployment, writes CONVEX_DEPLOYMENT to .env.local, runs codegen
npm run dev      # terminal 2 — scaffolds backend/, derives the Convex URLs, provisions the dev deployment env
```

On the first `npm run dev` the module writes the Convex functions directory — `backend/` with `convex.config.ts`, `auth.ts`, `http.ts`, `functions.ts`, `billing.ts`, `billing.catalog.ts`, `ai.ts`, `email.ts`, `rateLimiter.ts`, `workflows.ts`, `migrations.ts`, `aggregates.ts`, `search.ts` — and, as soon as `CONVEX_DEPLOYMENT` exists, runs the same engine as `npx nuxt-backend env push` against the dev deployment: `AUTH_SECRET` is generated, `SITE_URL` defaults to `http://localhost:3000`, and `NUXT_BACKEND_LOG_OTP=1` is set because no email transport exists yet. There is nothing to copy into `.env`: both Convex URLs derive from the `CONVEX_DEPLOYMENT` slug.

The dev console ends with a preflight summary — `backend preflight: auth ✓`, or the findings to fix.

### Sign in with the console OTP

Open `/login` — the module mounts it. Enter your email (and a name), request a code. With no `EMAIL_API_KEY` configured the one-time code is **printed in the `convex dev` terminal** instead of being emailed. Paste it and you are signed in; the first sign-in creates and activates a personal workspace. Sign-in returns to `/` — a fresh app has no page there yet, so add one first (or open `/settings`, which the module mounts):

```vue [app/pages/index.vue]
<script setup lang="ts">
const { session } = useAuth()
const { current } = useOrganization()
</script>

<template>
  <Authenticated>
    Signed in as {{ session.data?.user.email }} · workspace “{{ current?.name }}”
  </Authenticated>
  <Unauthenticated>
    <NuxtLink to="/login">Sign in</NuxtLink>
  </Unauthenticated>
</template>
```

### Declare a billing catalog and sync it

Billing stays empty until `BILLING_ACCESS_TOKEN` is set. Create an organization access token in the Polar **sandbox** dashboard, add it to `.env.local`, and fill the scaffolded catalog:

```ts [backend/billing.catalog.ts]
import { defineBillingCatalog } from 'nuxt-backend/billing'

export default defineBillingCatalog({
  meters: { credits: {} },
  plans: {
    pro: {
      name: 'Pro', interval: 'month', price: 2900,
      credits: { meter: 'credits', units: 500 },
      features: ['priority_support'],
    },
  },
  packs: {
    credits500: { name: '500 credits', price: 2000, credits: { meter: 'credits', units: 500 } },
  },
  features: {
    priority_support: { description: 'Priority support' },
  },
})
```

Push it, then forward the env to the deployment:

```bash
echo 'BILLING_ACCESS_TOKEN=polar_oat_...' >> .env.local
npx nuxt-backend billing sync   # creates the meter, benefits, products; provisions the /billing/events webhook
npx nuxt-backend env push       # forwards BILLING_ACCESS_TOKEN (and the BILLING_WEBHOOK_SECRET sync printed) to the deployment
npx convex run billing:syncProducts   # once: pull the freshly created products into the reactive products table
```

`billing sync` is find-or-create: every object it makes is tagged `metadata: { managedBy: 'nuxt-backend', key }`, re-running is idempotent, and nothing remote is ever updated or deleted. It writes the id map to `backend/billing.generated.ts` — the only place provider UUIDs live — and, because it derives your `.convex.site` URL from `CONVEX_DEPLOYMENT`, it provisions the `/billing/events` webhook endpoint and prints the secret to store. Details in [Catalog as code](/platform/billing/catalog-as-code).

### Spend credits

The scaffolded `backend/ai.ts` already ships a metered action on the `credits` meter:

```ts [backend/ai.ts]
export const transform = ai.meteredAction({
  meter: 'credits',
  args: { prompt: v.string() },
  handler: async (ctx, { prompt }) => {
    // const completion = await yourModel(prompt)
    return { echo: prompt.toUpperCase(), chargedTo: ctx.usage.entityId }
  },
})
```

Buy the pack (sandbox checkout — use Polar's test card), then call it:

```vue [app/pages/credits.vue]
<script setup lang="ts">
import { api } from '#backend/api'

definePageMeta({ middleware: 'auth' })

const { products } = useBilling()
const credits = useCredits('credits')
const transform = useAction(api.ai.transform)
</script>

<template>
  <p>{{ credits.balance.value ?? '—' }} credits</p>
  <button v-if="products?.credits500" @click="credits.topUp(products.credits500.id)">
    Buy 500 credits
  </button>
  <button @click="transform({ prompt: 'hello' })">Spend one credit</button>
</template>
```

Each call reserves one credit against the cached balance, runs the handler, then settles the spend as an ingested usage event on the provider — a failed run releases the reservation and charges nothing. The balance updates live through the webhook-synced cache. See [Credits & top-ups](/platform/billing/credits-and-top-ups) and [Metered actions](/platform/ai/metered-actions).

### Deploy

```bash
npx nuxt-backend doctor --prod                        # production posture: missing email/billing config is a failure
CONVEX_DEPLOY_KEY=prod:... npx nuxt-backend env push --prod   # forward .env.local to the production deployment; never invents values
npx convex deploy --cmd 'npm run build'               # push the backend, then build the Nuxt app against it
```

`env push --prod` fails on any missing required variable (`AUTH_SECRET`, `SITE_URL`) instead of inventing one, and never forwards the dev-only `AUTH_TRUST_LOCAL_ORIGINS`. The full story — hosts, the env split, previews — is in [Deployment](/production/deployment) and the [checklist](/production/checklist).
