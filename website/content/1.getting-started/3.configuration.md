All options have sensible defaults, and environment variables are picked up automatically. The minimal config is just the module:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
})
```

## Module options

The `backend` options are optional. The module first reads `url` and `siteUrl` from explicit module options, then falls back to the canonical Nuxt app environment variables.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    url: 'https://your-deployment.convex.cloud',
    siteUrl: 'https://your-deployment.convex.site',
    authRoute: '/api/auth',
  },
})
```

::field-group
  :::field{name="url" type="string"}
  Convex deployment URL. Falls back to `NUXT_PUBLIC_CONVEX_URL`.
  :::

  :::field{name="siteUrl" type="string"}
  Convex site URL used by the auth proxy. Falls back to `NUXT_PUBLIC_CONVEX_SITE_URL`.
  :::

  :::field{name="authRoute" type="string" defaultValue="'/api/auth'"}
  Path of the same-origin Better Auth proxy. If you change it, keep `createAuthOptions` and the Convex auth config on the same path.
  :::

  :::field{name="installation" type="'default' | 'local'" defaultValue="'default'"}
  Whether the first scaffold uses the packaged component defaults or creates a local hybrid component for schema ownership. See [Local installation](/backend/local-installation).
  :::

  :::field{name="scaffold" type="'auto' | false" defaultValue="'auto'"}
  Auto-scaffold missing Convex backend files on dev startup. Set `false` when you scaffold explicitly with `npx nuxt-backend init`.
  :::

  :::field{name="pages" type="ModulePagesOptions | false" defaultValue="all pages on"}
  The ready-made pages — `login`, `pricing`, `settings`, `profile`, `security`, `acceptInvitation` — all mounted by default. Per key: `true` (default path), a string (custom path), or `false` (bring your own); `false` disables the whole set. An app page at the same path always wins. See [Default Pages](/guide/default-pages).
  :::

  :::field{name="css" type="boolean" defaultValue="true"}
  Auto-add the neutral `nuxt-backend/ui.css` stylesheet covering every shipped component and page. Set `false` to style the `data-*` hooks yourself. See [Theming](/api-reference/theming).
  :::
::

Auth is always enabled by the module. The only installation choice is whether the first scaffold uses the packaged component defaults or a local hybrid component.

## Runtime config

The module resolves these from module options or env vars and exposes them as typed runtime config:

- `runtimeConfig.public.backend.url`
- `runtimeConfig.public.backend.siteUrl`
- `runtimeConfig.backend.siteUrl`

## Environment variables

### App variables

Minimal app environment file:

```bash [.env.local]
NUXT_PUBLIC_CONVEX_URL=https://your-deployment.convex.cloud
NUXT_PUBLIC_CONVEX_SITE_URL=https://your-deployment.convex.site
```

### Convex deployment variables

The backend reads nine deployment variables — **all required**. The scaffolded `convex.config.ts` **declares** them via Convex's typed [`defineApp({ env })`](https://docs.convex.dev/production/environment-variables), so they're validated at deploy (a push fails until every one is set) and read type-safely through `env` from `_generated/server`. The names are service-neutral on purpose: the package hides its underlying providers behind the general capability.

| Variable | Feature | Description |
|---|---|---|
| `AUTH_SECRET` | Auth | Secret used to sign auth tokens (e.g. `openssl rand -base64 32`) |
| `SITE_URL` | Auth | App URL such as `https://nuxt-backend.localhost` — also the base of emailed invitation links |
| `EMAIL_API_KEY` | Email (powered by Resend) | The provider API key |
| `EMAIL_FROM` | Email | Sender address, e.g. `Acme <hello@yourdomain.com>` |
| `EMAIL_TEST_MODE` | Email | `true` delivers only to the provider's test addresses; set to `false` once your sending domain is verified |
| `EMAIL_WEBHOOK_SECRET` | Email | Verifies delivery-event webhooks at `/email/events` |
| `BILLING_ACCESS_TOKEN` | Billing (powered by Polar) | The provider organization access token |
| `BILLING_WEBHOOK_SECRET` | Billing | Verifies billing webhooks at `/billing/events` |
| `BILLING_ENVIRONMENT` | Billing | `sandbox` or `production` |

#### Required environment

```bash
npx convex env set AUTH_SECRET "$(openssl rand -base64 32)"
npx convex env set SITE_URL https://nuxt-backend.localhost
npx convex env set EMAIL_API_KEY re_...
npx convex env set EMAIL_FROM "Acme <hello@yourdomain.com>"
npx convex env set EMAIL_TEST_MODE true
npx convex env set EMAIL_WEBHOOK_SECRET whsec_...
npx convex env set BILLING_ACCESS_TOKEN ...
npx convex env set BILLING_WEBHOOK_SECRET ...
npx convex env set BILLING_ENVIRONMENT sandbox
```

::note
The `EMAIL_*` vars are forwarded to the `backend` component by reference, since [components can't read the app's env directly](https://docs.convex.dev/components). The scaffolded `convex.config.ts` handles this for you — see [Backend components overview](/backend-components/overview).
::

## Changing the auth route

If you change `backend.authRoute` from `/api/auth`, keep the same path everywhere — the Nuxt proxy route, Better Auth `basePath`, and `defineBackendAuthConfig({ basePath: ... })` must all match. See [Customizing auth](/backend/customizing-auth).
