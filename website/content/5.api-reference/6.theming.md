Every shipped component renders semantic, class-free markup where each element
carries a `data-*` attribute, and every color/radius resolves through custom
properties. Styling is therefore three independent layers you can mix:

1. **`--bk-*` tokens** — one override re-themes every component.
2. **Per-family tokens** (`--auth-*`) — scope a change to one component family.
3. **`data-*` hooks** — style the markup directly (optionally with
   `backend: { css: false }` to drop the neutral stylesheet entirely).

## The `--bk-*` tokens

Defined at zero specificity (`:where(...)`) on every component root, so any
app selector wins:

| Token | Role | Default |
|---|---|---|
| `--bk-accent` | Primary actions, links, focus | `#00dc82` |
| `--bk-on-accent` | Text on accent surfaces | `#04101f` |
| `--bk-ink` | Body text | `inherit` |
| `--bk-muted` | Secondary text | `color-mix(currentColor 55%)` |
| `--bk-edge` | Borders | `color-mix(currentColor 18%)` |
| `--bk-surface` | Card backgrounds | `color-mix(currentColor 5%)` |
| `--bk-error` / `--bk-ok` / `--bk-warn` | Status colors | red / green / amber |
| `--bk-radius` | Corner radius | `8px` |

Because the derived tokens mix from `currentColor`, the components inherit
your app's light/dark scheme automatically.

## `data-*` families

| Family | Component / page | Root |
|---|---|---|
| `data-auth` | `<AuthForm>` + login page | `[data-auth='form']`, `[data-auth='page']` |
| `data-invitation` | `<AcceptInvitation>` + page | state-valued root (`loading`/`ready`/…) |
| `data-gift` | `<GiftClaimBanner>` | `[data-gift='banner']` |
| `data-pricing` | `<PricingTable>` + page | `[data-pricing='table']` |
| `data-settings` | `<WorkspaceSettings>` + page | `[data-settings='root']` |
| `data-profile` | `<ProfileSettings>` + page | `[data-profile='root']` |
| `data-security` | `<SecuritySettings>` + page | `[data-security='root']` |

Families use prefix selectors for groups (`[data-auth^='step-']`,
`[data-settings^='section-']`, `[data-auth^='input-']`) and state attributes
for variants: `[data-pricing='plan'][data-current]`, `[data-current]` on
sessions, `[data-editing]` on passkey rows, `[data-tone='ok'|'error'|'warn']`
on messages and badges, `[data-intent='subscribe'|'switch'|'cancel'|'sign-in']`
on pricing actions.

The exhaustive per-element vocabulary is the stylesheet itself — each family
has one file (`auth.css`, `pricing.css`, `settings.css`, `profile.css`,
`security.css`, `invitation.css`, `gift.css`) barreled into `ui.css`.

## Packaging

- The module auto-adds `nuxt-backend/ui.css` — opt out with
  `backend: { css: false }`.
- `nuxt-backend/auth.css` remains importable alone (just the sign-in form).
- Back-compat: `--auth-*` properties still theme `<AuthForm>` and now derive
  from `--bk-*` (`--auth-accent: var(--bk-accent, #00dc82)`).

## Example: brand re-theme

```css
/* app.css — every nuxt-backend surface picks this up */
:root {
  --brand: #6d5dfc;
}

[data-auth], [data-invitation], [data-gift], [data-pricing],
[data-settings], [data-profile], [data-security] {
  --bk-accent: var(--brand);
  --bk-on-accent: white;
  --bk-radius: 10px;
}
```

The playground demonstrates exactly this: the
[SaaS demo pages](/playground/saas/pricing) are the packaged components under
the site's own palette (one token bridge in its `app.css`), while the
[Vanilla pages](/playground/vanilla/pricing) show the untouched defaults.
