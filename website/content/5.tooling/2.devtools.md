With Nuxt DevTools enabled, the module adds a **Backend** tab — a sibling of `nuxt-convex-module`'s Convex tab (connection, queries, and auth state stay over there). It is dev-only, on whenever DevTools is, and off with `backend: { devtools: false }`.

Two data paths feed it, deliberately separate:

- **Build-time facts** come from the dev server over the DevTools RPC — re-collected on every request so findings stay live. Only **presence booleans** cross for env vars; values (secrets among them) never leave the Node process.
- **Live app state** — identity, billing, credits, workspace, feature grants, webhook deliveries — comes from the inspected page itself: a dev-only client plugin drives the package's own composables (`useAuth`, `useBilling`, `useFeatures`, `useOrganization`, the `getCredits` / `getWebhookDeliveries` queries) and mirrors their state into a plain-JSON bridge on `window.__NUXT_BACKEND_DEVTOOLS__`. If the panel says the bridge is unavailable, reload the inspected page.

## Overview

| Card | Shows |
|---|---|
| Header | Convex connected / disconnected (read from the base module's bridge), the functions dir, and the installed versions of `nuxt-backend`, `nuxt-convex-module`, `convex`, `nuxt` — what a bug report needs |
| Preflight | The same findings the dev-server start prints (`backend-site-url`, `auth-secret`, `site-url`, email/billing transport + webhook secrets, `mcp`): problems first with a **copyable fix command**, then the passing checks as badges |
| Deployment env | Presence per variable, in the two tiers — *required on the deployment* (`AUTH_SECRET`, `SITE_URL`) and *optional (designed degradation)* (`AUTH_TRUST_LOCAL_ORIGINS`, `EMAIL_*`, `BILLING_*`) |
| Pages | Every ready-made page: key, resolved path, whether it sits behind the `auth` middleware, and **mounted** vs **shadowed by app page** — the same detection the module uses to skip its own page |
| Agents (MCP) | Enabled + route + the surviving built-in tools, or "Disabled (`backend.mcp: false`)" |
| Recent webhook deliveries | The last 25 rows of the component's delivery log — service, event type, outcome (`ok` / `duplicate` / `invalid_signature` / …), received time. Needs a signed-in session in the inspected app (the query is identity-gated) |

## Billing

The subscription badge (free / active / trialing / …), the product id and plan ids, every **credit meter** with balance · credited · consumed, and the **catalog as declared in `appConfig.backend.billing`** (the display layer — live prices come from the provider). A tip reminds you which billing environment the app runs against, from `BILLING_ENVIRONMENT`'s presence. Buttons open `billing.ts` and `billing.catalog.ts` in your editor.

## Workspace

Identity (authenticated / unauthenticated, name, email, id), the **active workspace** with member and pending-invitation counts, and the granted **feature keys** — what `useFeatures().has()` will match. A button opens `auth.ts`.

## Open in editor

The panel's file buttons resolve a backend source file (`billing.ts`, `auth.ts`, …) to its path under the functions dir and hand it to DevTools' open-in-editor. Only plain relative names inside the functions dir resolve — path segments like `..` are rejected.

## Options

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  devtools: { enabled: true },   // Nuxt DevTools itself
  backend: {
    devtools: false,             // drop just the Backend tab
  },
})
```

The panel is served at `/__nuxt-backend` from the published package's `dist/devtools-client`; when developing the module itself it is proxied to the `pnpm dev:devtools-client` server on port 3631.
