`nuxt-backend/eslint` applies [Convex's own lint rules](https://docs.convex.dev/eslint) to your functions directory and keeps ESLint out of the generated code.

## Setup

Add `@nuxt/eslint` (the `create nuxt` modules prompt offers it too) and the Convex plugin:

```bash
npx nuxi module add eslint
npm install -D @convex-dev/eslint-plugin
```

Then pass the preset to the config `@nuxt/eslint` generated:

```js [eslint.config.mjs]
import withNuxt from './.nuxt/eslint.config.mjs'
import { backendEslint } from 'nuxt-backend/eslint'

export default withNuxt(backendEslint())
```

`@convex-dev/eslint-plugin` is an optional peer of this package, so an app that does not lint never installs it. Without it, the config fails to load and names the missing package.

## What it adds

`backendEslint()` returns two flat-config entries:

- **`nuxt-backend:convex`** applies the rules below to `backend/**/*.ts`, leaving out test files.
- **`nuxt-backend:generated`** ignores every `_generated` folder under `backend/`, including the component codegen of a [local installation](/tooling/local-installation). Convex's generated files start with `/* eslint-disable */`, which ESLint would otherwise report as an unused directive.

## Rules

| Rule | Level | What it catches |
|---|---|---|
| `@convex-dev/no-old-registered-function-syntax` | error | `query(async (ctx) => …)` instead of `query({ args, handler })` |
| `@convex-dev/require-args-validator` | error | A function without an `args` validator |
| `@convex-dev/explicit-table-ids` | error | `ctx.db.get(id)` instead of `ctx.db.get('table', id)` |
| `@convex-dev/no-filter-in-query` | warn | `.filter()` on a database query, where an index would do |
| `@convex-dev/no-top-of-hour-crons` | warn | A cron at minute 0, when everyone else's run too |
| `@convex-dev/no-schema-import-cycle` | error | The schema value used in a file the schema imports |
| `@convex-dev/no-duplicate-indexes` | error | An index whose fields start another index |
| `@convex-dev/no-process-env` | error | `process.env` instead of the typed `env` from `_generated/server` |

The levels are those of the plugin's own recommended config, and `BACKEND_ESLINT_RULES` exports the table. Three rules stay off, as they do there: `require-access-control`, `import-wrong-runtime` and `no-collect-in-query`. The scaffold's [function builders](/platform/authorization#pre-authorized-function-builders) already check access, so the first one would mostly repeat them.

A scaffolded app passes every rule. The package's test suite lints both scaffolds with this preset on every change.

## Options

```js [eslint.config.mjs]
export default withNuxt(backendEslint({
  // The `functions` entry of convex.json. Default: 'backend'.
  functionsDir: 'convex',
  // Levels that override or extend the table above.
  rules: { '@convex-dev/no-collect-in-query': 'warn' },
}))
```

## Without `@nuxt/eslint`

The rules parse TypeScript. `withNuxt` sets the parser up. A standalone flat config installs ESLint and the parser itself, next to the Convex plugin:

```bash
npm install -D eslint typescript-eslint @convex-dev/eslint-plugin
```

Then it adds the parser before the preset:

```js [eslint.config.mjs]
import tseslint from 'typescript-eslint'
import { backendEslint } from 'nuxt-backend/eslint'

export default [
  { files: ['**/*.ts'], languageOptions: { parser: tseslint.parser } },
  ...backendEslint(),
]
```
