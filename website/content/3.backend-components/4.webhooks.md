`registerBackendRoutes(http, options)` from `nuxt-backend/http` is the whole `http.ts` story: one call mounts every inbound webhook the backend handles on your Convex HTTP router. Signature verification stays where it already lives — the auth routes, the billing component (`BILLING_WEBHOOK_SECRET`), and the email component (`EMAIL_WEBHOOK_SECRET`) — this is composition, not re-implementation.

```ts [backend/http.ts]
import { registerBackendRoutes } from 'nuxt-backend/http'
import { httpRouter } from 'convex/server'
import { authComponent, createAuth } from './auth'
import { provider, webhookEvents } from './billing'
import { email } from './email'

const http = httpRouter()
registerBackendRoutes(http, {
  auth: { authComponent, createAuth },
  billing: { provider, webhookEvents },
  email,
})
export default http
```

## What gets mounted

| Route | What it does | Verified with |
|---|---|---|
| Auth routes | The Better Auth HTTP endpoints (same as `authComponent.registerRoutes`) | Auth's own signing |
| `/billing/events` | Refreshes the reactive entitlement cache (subscriptions, benefit grants, credit balances) and fulfils [gift purchases](/backend-components/billing#gifting) | `BILLING_WEBHOOK_SECRET` |
| `/email/events` | Tracks delivery status (delivered / bounced / complained) behind `useEmailStatus` | `EMAIL_WEBHOOK_SECRET` |

## Point the provider dashboards at them

Webhooks arrive on your Convex **site** URL (`CONVEX_SITE_URL`, the `.convex.site` domain — not `.convex.cloud`):

- **Polar dashboard** → Settings → Webhooks: `https://your-deployment.convex.site/billing/events`, with the same secret as `BILLING_WEBHOOK_SECRET`.
- **Resend dashboard** → Webhooks: `https://your-deployment.convex.site/email/events`, with the signing secret as `EMAIL_WEBHOOK_SECRET`.

## Reacting to events

The built-in handlers keep state fresh; your hooks run on top of them, per event.

Billing hooks go on [`setupBilling`](/backend-components/billing#server-setup), keyed by the provider's own event names. They run **after** the built-in entitlement-cache refresh (and gift fulfilment), so features and credits read fresh inside them — and events outside the built-in refresh set are mounted too:

```ts [backend/billing.ts]
const billing = setupBilling(components, {
  events: {
    'order.paid': async (ctx, payload) => {
      // entitlements are already refreshed here
    },
  },
})
```

Email hooks go on [`setupEmail`](/backend-components/email), and fire after the event is verified and the status recorded:

```ts [backend/email.ts]
export const email = setupEmail(components, {
  events: {
    onDelivered: async (ctx, event) => { /* … */ },
    onBounced: async (ctx, event) => { /* suppress future sends */ },
    onComplained: async (ctx, event) => { /* alert an admin */ },
  },
})
```

## Custom paths

Change where the webhooks mount with `billingPath` / `emailPath` (update the provider dashboards to match):

```ts [backend/http.ts]
registerBackendRoutes(http, {
  auth: { authComponent, createAuth },
  billing: { provider, webhookEvents },
  email,
  billingPath: '/hooks/billing',
  emailPath: '/hooks/email',
})
```

::note
`billing` and `email` are optional — omit one and its route simply isn't mounted. The per-service `registerRoutes` helpers remain available when you need fully custom routing.
