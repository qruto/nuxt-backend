`nuxt-backend` ships one [Convex component](https://www.convex.dev/components) of its own — the all-in-one **`backend`** component — and bundles five upstream `@convex-dev/*` components, all wired into Better Auth and configured by the [required env vars](/getting-started/configuration#convex-deployment-variables).

| Capability | Component | Entrypoint | Setup helper |
|---|---|---|---|
| Auth | `backend` (this package — Better Auth tables + adapter) | `nuxt-backend/auth` | `setupAuth` |
| Email | `backend` (nests [`@convex-dev/resend`](https://www.convex.dev/components/resend)) | `nuxt-backend/email` | `setupEmail` — `components.backend.email.send` |
| Billing | [`@convex-dev/polar`](https://www.convex.dev/components/polar) + `backend` (entitlement/credit cache, gifts) | `nuxt-backend/billing` | `setupBilling` |
| Webhooks | — (HTTP routes over auth + billing + email) | `nuxt-backend/http` | `registerBackendRoutes` |
| Rate limiting | [`@convex-dev/rate-limiter`](https://www.convex.dev/components/rate-limiter) | `nuxt-backend/rate-limit` | `setupRateLimiter` |
| Migrations | [`@convex-dev/migrations`](https://www.convex.dev/components/migrations) | `nuxt-backend/migrations` | `setupMigrations` |
| Aggregates | [`@convex-dev/aggregate`](https://www.convex.dev/components/aggregate) | `nuxt-backend/aggregate` | `TableAggregate`, `withTriggers` |
| Workflows | [`@convex-dev/workflow`](https://www.convex.dev/components/workflow) | `nuxt-backend/workflows` | `setupWorkflows` |
| Search | Convex native full-text search | `nuxt-backend/search` | `search`, `defineSearch` |

## One call mounts everything

`defineBackendApp()` (from `nuxt-backend/app`) is the whole `convex.config.ts` — zero component imports:

```ts [backend/convex.config.ts]
import { defineBackendApp } from 'nuxt-backend/app'

export default defineBackendApp()
```

It mounts the all-in-one `backend` component plus every bundled upstream component, declares the required typed env vars, and forwards the email config to the `backend` component — so you set the `EMAIL_*` vars and auth OTP / verification / invitation email just works.

No `import x from '…/convex.config'` lines are needed: Convex discovers components by intercepting any import whose specifier contains `convex.config` at **any** depth of the bundle graph — including inside the package's own `dist/convex/app.js`, which imports the component configs itself.

::tip
Need to skip an upstream component, add env vars, or swap in your own definition?

```ts
export default defineBackendApp({
  omit: ['aggregate'],                                  // skip mounting (backend is not omittable)
  env: { STRIPE_SECRET_KEY: v.optional(v.string()) },   // extend the declared env
  components: { backend: localBackend },                // swap in a custom definition (local installs)
})
```

`omit` accepts only the upstream names (`'aggregate' | 'migrations' | 'polar' | 'rateLimiter' | 'workflow'`) — the `backend` component is the package's core and cannot be omitted. For total control, build the app yourself with `defineApp` and call `installBackend(app, options)` — both from `nuxt-backend/app`. Hand-written configs must declare `backendEnv` themselves; the env proxy throws on undeclared vars.
::

## One `backend` component — plus the upstream components

The package ships **one Convex component of its own**, with flat function modules split by concern:

- **`adapter`** — the Better Auth tables + adapter (`components.backend.adapter.*`). Better Auth itself is *not* mounted as a component; it runs as app-level code over the component's adapter (the hybrid pattern).
- **`email`** — transactional email, with [`@convex-dev/resend`](https://www.convex.dev/components/resend) nested inside the component: `components.backend.email.send` / `status` / `get` / `cancel` / `handleWebhook`. The component owns the `EMAIL_*` env.
- **`billing`** — the reactive entitlement / credit cache: `components.backend.billing.getByUser` / `upsert` / `userByCustomer` / `clear`.
- **`gifts`** — gift purchases (the `billingGifts` table): `components.backend.gifts.*`, driven by [`setupBilling`](/backend-components/billing#gifting).

Resend is the one component nested **inside** another (it's self-contained, so `backend` re-exposes it through its `email` functions). The upstream components mount at the **app level** — a nested component is sandboxed from the parent app, and polar, rateLimiter, workflow, migrations, and aggregate all operate over **your** tables, functions, auth, and HTTP routes.

The dashboard component tree looks like this:

```text
app
├─ backend
│  └─ backend/resend
├─ polar
├─ rateLimiter
├─ workflow
│  └─ workflow/workpool
├─ migrations
└─ aggregate
```

Because [components are isolated from the app's env](https://docs.convex.dev/components), `installBackend` declares the deployment env vars with typed validators and **forwards** `EMAIL_API_KEY`, `EMAIL_FROM`, `EMAIL_TEST_MODE`, and `EMAIL_WEBHOOK_SECRET` to the `backend` component by reference — you never write that wiring yourself.

## Server helpers vs. composables — two halves, not duplicates

The `nuxt-backend/*` entrypoints are **server** code: you import them *inside your Convex functions* to construct and configure each component client (with sensible defaults baked in — auth rate limits, workflow retries, etc.). The auto-imported `useSearch` / `useCount` / `useBilling` / `useWorkflowStatus` composables are **client** code: thin Vue-reactive wrappers over `useQuery` that subscribe to the queries those functions expose.

You need both — the helper builds the server endpoint; the composable consumes it reactively in your components.

::note
Each helper lives on its **own** entrypoint (rather than one barrel) so a Convex function only bundles the component it actually imports — the same reason the underlying `@convex-dev/*` packages are split, and what keeps `better-auth` out of a file that only does rate limiting.
::
