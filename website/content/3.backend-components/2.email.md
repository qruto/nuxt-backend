The `backend` component ships transactional email powered by [Resend](https://www.convex.dev/components/resend) (**nested inside** it, as `backend/resend` in the dashboard), so email works out of the box once the required `EMAIL_*` env vars are set. Its public functions live in the component's `email` module: `components.backend.email.send` / `status` / `get` / `cancel` / `handleWebhook`. Use `setupEmail(components, options)` from `nuxt-backend/convex/email` for the app-side client — delivery-status tracking, marketing audiences/broadcasts, and delivery-event hooks (`onDelivered`, `onBounced`, `onComplained`).

## Sending mail

Call it from any app function (action, mutation, or a Workflow step):

```ts
await ctx.runMutation(components.backend.email.send, {
  to: 'user@example.com',
  subject: 'Welcome!',
  html: '<p>Hello</p>',
})
```

It enqueues a **durable** email and resolves to the email id.

## Auth emails are automatic

The same path powers auth OTP / verification / reset — and workspace invitation — emails automatically; see [cross-component wiring](/convex-backend/auth-setup#cross-component-wiring). You don't pass an `email` integration.

## Delivery tracking

Delivery-status events arrive on the `/email/events` webhook mounted by [`registerBackendRoutes`](/backend-components/webhooks) (signature-verified with `EMAIL_WEBHOOK_SECRET`) and feed the reactive `useEmailStatus` composable. Per-event hooks go on `setupEmail`:

```ts [backend/email.ts]
import { setupEmail } from 'nuxt-backend/convex/email'
import { components } from './_generated/api'

export const email = setupEmail(components, {
  events: {
    onBounced: async (ctx, event) => { /* pause sends to this address */ },
  },
})
```

## Environment

Email is configured by three of the [required env vars](/getting-started/configuration#convex-deployment-variables) plus the webhook secret:

| Variable | Effect |
|---|---|
| `EMAIL_API_KEY` | The provider API key |
| `EMAIL_FROM` | Sender address, e.g. `Acme <hello@yourdomain.com>` |
| `EMAIL_TEST_MODE` | `true` delivers only to the provider's test addresses; `false` sends to real recipients |
| `EMAIL_WEBHOOK_SECRET` | Verifies delivery events on `/email/events` |

::warning
With `EMAIL_TEST_MODE` set to `true`, only the provider's test addresses receive mail. Set it to `false` once you've verified a sending domain in the Resend dashboard to deliver to real recipients.
::
