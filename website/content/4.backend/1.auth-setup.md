The `nuxt-backend/auth` entrypoint runs in your **Convex backend** (`backend/`), not the Vue app. It exposes the same two client-code patterns described in the Convex component authoring docs — a simple wrapper via `createAuth(ctx, component, options?)` and a ready-made API remount via `makeAuthApi(component, query)` — plus `setupAuth(...)`, a convenience helper that composes both for the common scaffolded case.

## The scaffolded files

If you let the module scaffold the files, you can keep them as generated. If you create them manually, they look like this:

```ts [backend/convex.config.ts]
import { defineBackendApp } from 'nuxt-backend/app'

export default defineBackendApp()
```

```ts [backend/auth.config.ts]
export { default } from 'nuxt-backend/auth.config'
```

```ts [backend/auth.ts]
import { setupAuth } from 'nuxt-backend/auth'
import { components } from './_generated/api'
import { query } from './_generated/server'

export const {
  authComponent,
  createAuthOptions,
  options,
  createAuth,
  getAuthUser,
} = setupAuth(components, query)
```

```ts [backend/http.ts]
import { registerBackendRoutes } from 'nuxt-backend/http'
import { httpRouter } from 'convex/server'
import { authComponent, createAuth } from './auth'
import { provider, webhookEvents } from './billing'
import { email } from './email'

const http = httpRouter()
registerBackendRoutes(http, {
  auth: { authComponent, createAuth },
  billing: { provider, webhookEvents },
  email,
})

export default http
```

That setup mounts the packaged all-in-one `backend` component (plus the upstream components), configures Convex to trust its tokens, registers the auth and [webhook routes](/backend-components/webhooks), and exposes `api.auth.getAuthUser` for app queries. The scaffolded `backend/auth.ts` re-exports `authComponent`, `createAuthOptions`, `options`, `createAuth`, and `getAuthUser` for app Convex functions to import.

## `setupAuth(...)`

```ts
function setupAuth<DM, Schema>(
  components: AuthSetupComponents,  // the whole generated `components` object — uses `auth` + optional `email`
  queryBuilder: QueryBuilder<DM, 'public'>,
  options?: SetupAuthOptions<Schema>,
): {
  authComponent: AuthComponent
  createAuthOptions: (ctx) => BetterAuthOptions
  options: BetterAuthOptions
  createAuth: (ctx) => BetterAuthInstance
  getAuthUser: RegisteredQuery
}
```

The lower-level pieces — `createAuth`, `createAuthOptions`, `makeAuthApi`, `createBetterAuth`, `createBetterAuthOptions` — are also exported from `nuxt-backend/auth` for when you want to compose them yourself.

## Cross-component wiring

OTP / verification / reset — and workspace invitation — emails are routed through the `backend` component (`components.backend.email.send`) **automatically** — you don't pass an `email` integration. `integrations` accepts `{ rateLimiter, onUserCreated, email?, emailTemplates? }`:

- `rateLimiter` throttles OTP sends
- `onUserCreated(ctx, user)` runs on signup (the ctx is a full mutation/action ctx, so it can start a Workflow)
- `email?` is an optional override to bypass the automatic transport
- `emailTemplates?` restyles any of the default auth emails (`welcome` / `otp` / `verify` / `changeEmail` / `deleteAccount` / `invite`) without replacing the transport

```ts [backend/auth.ts]
export const { authComponent, createAuth, getAuthUser } = setupAuth(components, query, {
  integrations: {
    // email is automatic via the `backend` component (the EMAIL_* env vars)
    rateLimiter,
    onUserCreated: async (ctx, user) => {
      await workflow.start(ctx, internal.workflows.onSignup, {
        userId: user.id, email: user.email, name: user.name,
      })
    },
  },
})
```

Billing links provider customers to auth users, and its reactive feature/credit cache lives **inside** the `backend` component — so subscriptions, discounts, feature-gating, prepaid credits, and gifts work out of the box with nothing added to your schema.

::note
Email delivery is configured by the required `EMAIL_*` env vars. During local dev you can set `NUXT_BACKEND_LOG_OTP=1` to echo OTP codes to the console when no transport is wired.
::
