Every email sent through the component is tracked: the provider's delivery events arrive on the **`/email/events`** webhook mounted by [`registerBackendRoutes`](/platform/webhooks), signature-verified with `EMAIL_WEBHOOK_SECRET`, and advance the email's status (`queued` → `sent` → `delivered` / `bounced` / `complained` / `failed`, plus `delivery_delayed`, `opened`, `clicked`). The `useEmailStatus` composable subscribes to it reactively.

## Point the provider at the route

Resend dashboard → Webhooks → add `https://<slug>.convex.site/email/events`, subscribed to the `email.*` events (and the `contact.*` / `domain.*` ones if you use the marketing surface). Store the signing secret:

```bash
echo 'EMAIL_WEBHOOK_SECRET=whsec_...' >> .env.local
npx nuxt-backend env push
```

Until the secret is set the route is mounted but **fail-closed**: every delivery answers `503`, `useEmailStatus` stays at `sent`, and `npx nuxt-backend doctor` reports it (`email-webhook-route`). The secret accepts a comma-separated list (`whsec_new,whsec_old`) for zero-downtime rotation.

## `useEmailStatus()`

```vue
<script setup lang="ts">
import { api } from '#backend/api'

const send = useAction(api.email.send)
const emailId = ref<string>()
const delivery = useEmailStatus(emailId)

async function notify() {
  emailId.value = (await send({ to: 'delivered@resend.dev', subject: 'Hi', text: 'Hello' })) ?? undefined
}
</script>

<template>
  <button @click="notify">Send</button>
  <p v-if="delivery.isLoading.value">Sending…</p>
  <p v-else-if="delivery.isDelivered.value">Delivered ✓</p>
  <p v-else-if="delivery.isError.value">{{ delivery.data.value?.errorMessage ?? delivery.status.value }}</p>
  <p v-else>{{ delivery.status.value }}</p>
</template>
```

::field-group
  :::field{name="data" type="ComputedRef<EmailStatus | null | undefined>"}
  The full record — `status`, `errorMessage`, `bounced`, `complained`, `failed`, `deliveryDelayed`, `opened`, `clicked`. `null` when unknown, `undefined` while loading.
  :::

  :::field{name="status" type="ComputedRef<string | undefined>"}
  The status string.
  :::

  :::field{name="isLoading / isDelivered / isError"}
  Loading until the first status arrives; delivered; or bounced / complained / failed.
  :::
::

Tracking pauses while `emailId` is `undefined`/empty. The composable reads the auto-provided `api.email` namespace (`getEmailStatus`, re-exported by the scaffolded `email.ts`); pass `{ api }` to point it elsewhere.

::note
`getEmailStatus` requires a signed-in caller: delivery records carry recipient and error detail, and email ids leak through return values and logs, so the lookup is never anonymous.
::

## Reacting to events

Per-event hooks go on `setupEmail`, keyed by the provider's event names — the complete catalog (`email.sent`, `email.delivered`, `email.delivery_delayed`, `email.bounced`, `email.complained`, `email.opened`, `email.clicked`, `email.failed`, `email.scheduled`, `email.received`, `email.suppressed`, `contact.created` / `updated` / `deleted`, `domain.created` / `updated` / `deleted`). Handlers run **after** the component has verified the signature and recorded the status, so `useEmailStatus` already reflects the event:

```ts [backend/email.ts]
export const email = setupEmail(components, {
  events: {
    'email.bounced': async (ctx, event) => {
      // event.data: { email_id, to, subject, bounce: { type, subType, message }, … }
      await ctx.runMutation(internal.suppressions.add, { email: event.data.to?.[0] })
    },
    'email.complained': async (ctx, event) => { /* alert an admin */ },
    'contact.created': async (ctx, event) => { /* event.data: { id, audience_id, email, … } */ },
  },
  // A verified event this package's catalog doesn't know (a newer provider) — acknowledged 202 either way.
  onUnknownEvent: async (ctx, { type, payload }) => { /* … */ },
  deliveryLog: true,   // the component's delivery ring buffer (dedupe + doctor + DevTools feed); false disables both
})
```

A handler throw answers `500`, so the provider redelivers — and a redelivery of an already fully-processed delivery id answers `200` without running anything again.

## The delivery log

Every delivery's outcome (`ok`, `invalid_signature`, `unknown_type`, `handler_error`, `duplicate`, `oversized`, `missing_secret`) lands in the component's capped ring buffer. `getWebhookDeliveries` (re-exported by the scaffolded `billing.ts`) serves it to the DevTools [Backend tab](/tooling/devtools) and the playground's webhook feed.
