Every email the package sends on your behalf comes from a template function that returns `{ to, subject, html?, text? }` — an `AuthEmailMessage`. The defaults are minimal, dependency-free HTML + text, exported as `defaultEmailTemplates` from `nuxt-backend/auth` so you can preview them or reuse pieces inside overrides.

## The templates

| Key | Sent when | Data |
|---|---|---|
| `otp` | Sign-in, email-verification, or change-email code | `{ email, otp, type: 'sign-in' \| 'email-verification' \| 'forget-password' \| 'change-email' }` |
| `welcome` | Once, right after a user is created (unless `welcomeEmail: false`) | `{ email, name }` |
| `verify` | Email-verification link (when verification is enabled) | `{ email, url }` |
| `changeEmail` | Confirmation sent to the **current** address when changing email | `{ email, newEmail, url }` |
| `deleteAccount` | Confirmation link for account deletion | `{ email, url }` |
| `invite` | Workspace invitation with an accept link | `{ email, url, inviterName, inviterEmail, organizationName, role }` |

The default `invite`, for reference — the shape every override follows:

```ts
invite: ({ email, url, inviterName, inviterEmail, organizationName, role }) => linkEmail(
  email,
  `Join ${organizationName}`,
  `${inviterName || inviterEmail} invited you to join ${organizationName} as ${role}.`,
  url,
  'Accept invitation',
)
```

## Overriding

Pass any subset as `integrations.emailTemplates` on `setupAuth` — the transport stays the component's, only the message changes:

```ts [backend/auth.ts]
import { defaultEmailTemplates, setupAuth } from 'nuxt-backend/auth'

export const { authComponent, createAuth, getAuthUser, /* … */ } = setupAuth(components, query, {
  integrations: {
    rateLimiter,
    emailTemplates: {
      otp: ({ email, otp, type }) => ({
        to: email,
        subject: type === 'sign-in' ? `${otp} is your Acme sign-in code` : `Your Acme verification code`,
        text: `Your code: ${otp}. It expires in 5 minutes.`,
        html: renderOtpEmail({ otp }),   // your own renderer
      }),
      invite: (data) => ({
        ...defaultEmailTemplates.invite(data),    // keep the default body…
        subject: `${data.inviterName} wants you on ${data.organizationName}`,   // …change the subject
      }),
    },
  },
})
```

Templates run inside the auth flow with the same data the defaults receive; render however you like (a string builder, `@vue-email`, `react-email` — anything returning HTML/text). The [advanced example](/getting-started/examples-and-templates) overrides `otp` and `invite` this way.

### The welcome email

`welcomeEmail` (default `true`) sends `welcome` right after signup. Set it `false` when the app owns onboarding — the scaffold does, because its `onSignup` [email sequence](/platform/workflows) sends the welcome — so new users don't get two.

### Taking over delivery

`integrations.email` replaces the transport for every auth email (`(ctx, message) => Promise<unknown>`); the workspace plugin's own `organization.sendInvitationEmail` replaces just the invitation. Both bypass the component's delivery tracking.

## The gift email

Gift notifications are billing's, restyled through `giftEmail` on `setupBilling` — data `{ recipientEmail, purchaserName, purchaserEmail, message, claimUrl, … }`. See [Gifts](/platform/billing/gifts#the-notification-email).

## Previewing

`defaultEmailTemplates` is a plain object of functions, so a preview page is one call per template — the playground's email-templates page does exactly that:

```ts
import { defaultEmailTemplates } from 'nuxt-backend/auth'

const preview = defaultEmailTemplates.otp({ email: 'you@example.com', otp: '482913', type: 'sign-in' })
// preview.subject, preview.html, preview.text
```
