`registerBackendRoutes(http, options)` from `nuxt-backend/http` is the whole `http.ts` story: one call mounts every inbound route the backend handles on your Convex HTTP router — the auth routes, the two webhooks, the metered AI stream endpoint, and the agent token exchange. Signature verification stays where it already lives — the auth routes, the billing component (`BILLING_WEBHOOK_SECRET`), and the email component (`EMAIL_WEBHOOK_SECRET`) — this is composition, not re-implementation. Each option takes the instance the matching `setup*` helper returns (the scaffolded `http.ts`, shown as generated):

```ts [backend/http.ts]
import { registerBackendRoutes } from 'nuxt-backend/http'
import { httpRouter } from 'convex/server'
import { authComponent, createAuth, mcp } from './auth'
import { billing } from './billing'
import { email } from './email'
import { ai } from './ai'

const http = httpRouter()
registerBackendRoutes(http, {
  auth: { authComponent, createAuth },
  billing,
  email,
  ai,
  mcp,
})

export default http
```

## What gets mounted

| Route | What it does | Verified with |
|---|---|---|
| Auth routes | The Better Auth HTTP endpoints (same as `authComponent.registerRoutes`) | Auth's own signing |
| `/billing/events` (POST) | Refreshes the reactive entitlement cache (subscriptions, benefit grants, credit balances) and fulfils [gift purchases](/platform/billing/gifts) | `BILLING_WEBHOOK_SECRET` |
| `/email/events` (POST) | Tracks delivery status (delivered / bounced / complained) behind `useEmailStatus` | `EMAIL_WEBHOOK_SECRET` |
| `/ai/stream` (POST + OPTIONS) | Runs an `ai.stream(...)` handler and streams its chunks to `useAiStream` — the OPTIONS route answers the browser's CORS preflight for the app origin (`SITE_URL`) | The `streamId` the authenticated `start` action just handed the caller (credits already reserved) |
| `/mcp/exchange` (POST) | The agent token exchange behind the app's `/mcp` endpoint — trades an agent's OAuth bearer for a short-lived Convex JWT | The bearer is looked up in the auth provider's token store (`401` otherwise) |

Both webhooks share one fail-closed policy: missing secret → `503`, invalid signature → `403`, oversized body → `413`, authentic-but-unknown event type → `202`, handler throw → `500` (so the provider retries), redelivery of a processed id → `200`. Every delivery's outcome lands in the component's webhook log (the Backend tab in Nuxt DevTools and the playground feed read it).

## Point the provider dashboards at them

Webhooks arrive on your Convex **site** URL (`CONVEX_SITE_URL`, the `.convex.site` domain — not `.convex.cloud`):

- **Polar dashboard** → Settings → Webhooks: `https://your-deployment.convex.site/billing/events`, with the same secret as `BILLING_WEBHOOK_SECRET`.
- **Resend dashboard** → Webhooks: `https://your-deployment.convex.site/email/events`, with the signing secret as `EMAIL_WEBHOOK_SECRET`.

## Reacting to events

The built-in handlers keep state fresh; your hooks run on top of them, per event.

Billing hooks go on [`setupBilling`](/platform/billing/subscriptions#server-setup), keyed by the provider's own event names. They run **after** the built-in entitlement-cache refresh (and gift fulfilment), so features and credits read fresh inside them — and events outside the built-in refresh set are mounted too:

```ts [backend/billing.ts]
const billing = setupBilling(components, {
  events: {
    'order.paid': async (ctx, payload) => {
      // entitlements are already refreshed here
    },
  },
})
```

Email hooks go on [`setupEmail`](/platform/email/sending), and fire after the event is verified and the status recorded:

```ts [backend/email.ts]
export const email = setupEmail(components, {
  events: {
    onDelivered: async (ctx, event) => { /* … */ },
    onBounced: async (ctx, event) => { /* suppress future sends */ },
    onComplained: async (ctx, event) => { /* alert an admin */ },
  },
})
```

## Custom paths

Change where the routes mount with `billingPath` / `emailPath` / `aiPath` / `mcpExchangePath` (update the provider dashboards to match; the Nuxt side follows `SITE_URL` + the module's `mcp.route`):

```ts [backend/http.ts]
registerBackendRoutes(http, {
  auth: { authComponent, createAuth },
  billing,
  email,
  ai,
  mcp,
  billingPath: '/hooks/billing',
  emailPath: '/hooks/email',
})
```

::note
`billing`, `email`, `ai`, and `mcp` are optional — omit one and its route simply isn't mounted. The per-service `registerRoutes` helpers remain available when you need fully custom routing.
