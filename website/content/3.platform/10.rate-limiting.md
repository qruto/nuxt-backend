`setupRateLimiter(components, limits?)` returns a `RateLimiter` pre-seeded with `DEFAULT_LIMITS` — `emailOtp` (OTP / verification sends, per email — 5/minute, keyed by a SHA-256 of the address), `emailOtpGlobal` (OTP sends across the whole deployment — a fixed window of 300/hour, the backstop against address rotation; raise it for a launch that legitimately signs in more), `billingSync` (entitlement syncs, per billing entity), `ai` (metered AI calls, per billing entity), and `mcp` (agent token exchanges, per client + user). Your `limits` are merged on top and can override any of them.

```ts [backend/rateLimiter.ts]
import { setupRateLimiter } from 'nuxt-backend/rate-limit'
import { components } from './_generated/api'

export const rateLimiter = setupRateLimiter(components, {
  // your own limits, merged over DEFAULT_LIMITS
  sendMessage: { kind: 'token bucket', rate: 10, period: 60_000 },
})
```

Pass the limiter into `setupAuth` to throttle OTP sends — see [cross-component wiring](/platform/auth/setup#cross-component-wiring) — and into `setupAi`, whose metered actions use the `ai` limit unless you name another.

::note
There are no password limits (`signIn`, `signUp`, `passwordReset`): the package is passwordless, and per-code brute force is Better Auth's own `allowedAttempts` guard. `DEFAULT_LIMITS` is also exported from `nuxt-backend/rate-limit` if you want to inspect or extend the defaults directly.
::
