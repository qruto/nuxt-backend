Feature gating reads the entitlement cache the billing webhooks keep fresh: the entity's **active plans** (product ids) and **granted benefits**. Every read is live — a `benefit_grant.*` webhook updates every subscriber.

## Friendly names, not UUIDs

`useFeatures().has(feature)` matches a granted benefit by its benefit id, grant id, `type`, **or any value in the benefit's metadata**. The [catalog](/platform/billing/catalog-as-code) creates each feature benefit tagged `metadata: { managedBy: 'nuxt-backend', key }`, so gating with the catalog key just works:

```ts [backend/billing.catalog.ts]
features: {
  premium: { description: 'Premium features' },
},
plans: {
  pro: { /* … */, features: ['premium'] },
},
```

```vue
<script setup lang="ts">
const { has, hasPlan, plans, benefits, isLoading } = useFeatures()
const { products } = useBilling()   // product ids by catalog key — undefined while loading
</script>

<template>
  <PremiumPanel v-if="has('premium')" />
  <ProBadge v-if="products?.pro && hasPlan(products.pro.id)" />
</template>
```

For benefits managed in the dashboard instead, set a stable key in the benefit's metadata (e.g. `{ key: 'premium' }`) and gate on it the same way. The cache reads benefit metadata **live** (joined at read time and patched by the `benefit.updated` webhook, with a 15-minute snapshot TTL on sync — `benefitMetadataTtlMs`), so renaming a key takes effect without re-granting.

## `<FeatureBoundary>`

Renders its default slot only when the current billing entity has the required feature (any granted-benefit match) or plan (any active-subscription match); `placeholder` while entitlements load, `fallback` when the check fails. The billing counterpart of [`<RoleBoundary>`](/platform/authorization#roleboundary).

```vue
<script setup lang="ts">
const { products } = useBilling()
</script>

<template>
  <FeatureBoundary feature="premium">
    <AdvancedEditor />
    <template #fallback><UpgradePrompt /></template>
    <template #placeholder><Skeleton /></template>
  </FeatureBoundary>

  <FeatureBoundary v-if="products" :plan="[products.pro!.id, products.ultra!.id]">
    <ProDashboard />
  </FeatureBoundary>
</template>
```

## Gating on the server

Client gates are for UI. Enforce in the function: the cache is one query away, and the `authed` tier from [`createFunctions`](/platform/authorization) gives you the caller.

```ts [backend/reports.ts]
import { ConvexError } from 'convex/values'
import { api } from './_generated/api'
import { authed } from './functions'

export const exportReport = authed.action({
  args: {},
  handler: async (ctx) => {
    const features = await ctx.runQuery(api.billing.getFeatures, {})
    const premium = features?.benefits.some(b => Object.values(b.metadata ?? {}).includes('premium'))
    if (!premium) throw new ConvexError('Upgrade to export reports')
    // …
  },
})
```

## Where grants come from

| Source | Cache update |
|---|---|
| Checkout completes | `order.paid` → `subscription.*` / `benefit_grant.created` refresh the entity's plans, benefits, and meters |
| Plan change / cancellation | `subscription.updated` / `subscription.canceled` / `subscription.revoked` |
| Benefit renamed or re-keyed in the dashboard | `benefit.updated` patches the metadata snapshot in place |
| Gift claimed | `claimGift` refreshes the recipient's entitlements |
| Webhooks not configured yet | `syncEntitlements` (`useCredits().refresh()`) on demand |

Fresh grants surface in the DevTools [Backend tab](/tooling/devtools) (Workspace → Feature grants) and the playground.
