`setupBilling(components)` wires subscriptions, discounts, **prepaid credits**, and **gift purchases** via the [Polar](https://www.convex.dev/components/polar) component, linked to your auth users. The reactive **feature + credit cache** and the gift records live inside the all-in-one `backend` component (`components.backend.billing` / `components.backend.gifts`), so **you add nothing to your schema**. This page covers subscriptions; the siblings cover the [catalog](/platform/billing/catalog-as-code), [credits](/platform/billing/credits-and-top-ups), [gifts](/platform/billing/gifts), and [feature gating](/platform/billing/feature-gating).

## Server setup

`setupBilling` needs **no config**: the access token, environment, and webhook secret default to the `BILLING_ACCESS_TOKEN` / `BILLING_ENVIRONMENT` / `BILLING_WEBHOOK_SECRET` env vars, and the billing entity resolves from identity claims — the active workspace by default (`billTo: 'organization'`, so members share the workspace's plan and credits), or the signed-in user with `billTo: 'user'` for B2C apps. The scaffolded `billing.ts`, as generated:

```ts [backend/billing.ts]
import { setupBilling, type DiscountInput } from 'nuxt-backend/billing'
import { v } from 'convex/values'
import { components } from './_generated/api'
import { internalAction } from './_generated/server'
import { catalog } from './billing.generated'

// The catalog id map (plans, packs, credit meters) comes from billing.generated.ts,
// written by `npx nuxt-backend billing sync`. Exported for ai.ts (metered actions spend through it).
export const billing = setupBilling(components, { catalog })

export const { provider } = billing
export const {
  generateCheckoutLink,
  generateCustomerPortalUrl,
  getConfiguredProducts,
  listAllProducts,
  listAllSubscriptions,
  changeCurrentSubscription,
  cancelCurrentSubscription,
  giftCheckout,
} = billing.api
export const {
  getCurrentSubscription,
  getFeatures,
  getCredits,
  syncEntitlements,
  syncProducts,
  getReceivedGifts,
  claimGift,
  getWebhookDeliveries,
  // Subscription lifecycle — each resolves the caller's own billing entity,
  // so a client can only ever act on its own subscription.
  updateSubscription,
  cancelSubscription,
  uncancelSubscription,
  pauseSubscription,
  resumeSubscription,
  // Order history, invoices and metered usage, read live from the provider —
  // this package keeps no local order or usage table.
  getOrders,
  getInvoiceUrl,
  getUsageHistory,
  // Admin-tier: gated by `setupBilling({ requireAdmin })`, which defaults to
  // an `admin` role claim on the caller's identity.
  refundOrder,
} = billing.functions
export const { webhookEvents } = billing

// Discounts are privileged — an internalAction, run from ops:
//   npx convex run billing:createDiscount '{"name":"Launch","percent":20}'
export const createDiscount = internalAction({
  args: { name: v.string(), percent: v.number(), code: v.optional(v.string()) },
  handler: async (ctx, { name, percent, code }) => {
    const basisPoints = Math.round(Math.min(Math.max(percent, 0), 100) * 100)
    const discount: DiscountInput = { type: 'percentage', name, code, duration: 'once', basisPoints }
    return billing.discounts.create(discount)
  },
})
```

::warning
Keep these exports. The composables bind to them by name (`useBilling` → `getConfiguredProducts` / `listAllSubscriptions` / `getCurrentSubscription` / `generateCheckoutLink` / …), and `npx nuxt-backend doctor` verifies the contract against the deployment — a trimmed export degrades the matching composable to `undefined`s.
::

Config is optional — pass it to override the env-var defaults (`accessToken`, `environment`, `webhookSecret`), switch `billTo`, throttle syncs (`rateLimiter` — the `billingSync` limit, 10/min per entity), hook webhook events (`events`), restyle the gift email (`giftEmail`), name credit meters explicitly (`credits`), tune `benefitMetadataTtlMs`, or override entity resolution (`getUserInfo` / `currentUserId`, consulted only with `billTo: 'user'`).

`setupBilling(...)` returns:

::field-group
  :::field{name="api"}
  Checkout / portal / product / subscription functions to re-export, plus `giftCheckout` (a checkout billed to someone else's email). `listAllSubscriptions` is wrapped to return `null` instead of throwing for claimless callers.
  :::

  :::field{name="functions"}
  Reactive functions to re-export so the composables work with zero wiring: `getCurrentSubscription` (→ `useBilling`), `getFeatures` (→ `useFeatures`), `getCredits` (→ `useCredits`), `getReceivedGifts` / `claimGift` (→ `useGifts`), `syncEntitlements` (refresh the cache on demand), `syncProducts` (pull the provider's product catalog into the reactive products table — fresh deployments render empty pricing until it runs once; webhooks keep it fresh afterwards), `getWebhookDeliveries` (the delivery feed behind DevTools and the playground), the subscription lifecycle actions `updateSubscription` / `cancelSubscription` / `uncancelSubscription` / `pauseSubscription` / `resumeSubscription`, the live provider reads `getOrders` / `getInvoiceUrl` (→ `useOrders`, `<BillingHistory>`) and `getUsageHistory` (→ `useUsage`, `<UsageHistory>`), and the admin-tier `refundOrder`.
  :::

  :::field{name="webhookEvents / webhookHandler"}
  Typed handlers over the provider's full event catalog that keep the cache fresh (subscriptions, benefit grants, credit balances), patch benefit metadata, and fulfil gifts — and the guarded endpoint [`registerBackendRoutes`](/platform/webhooks) mounts at `/billing/events`.
  :::

  :::field{name="spendCredits · reserveCredits · settleSpend · releaseSpend · refundCredits"}
  The prepaid-credit primitives — see [Credits & top-ups](/platform/billing/credits-and-top-ups).
  :::

  :::field{name="updateSubscription · cancelSubscription · uncancelSubscription · pauseSubscription · resumeSubscription"}
  The same lifecycle operations as server-side methods, for your own actions. These accept the full `proration` set (`invoice`, `prorate`, `next_period`, `reset`); the registered action deliberately accepts only `invoice` / `prorate` from a client, because `next_period` and `reset` hand over a new plan immediately while deferring or waiving the charge.
  :::

  :::field{name="getOrders · getInvoiceUrl · getUsageHistory · refundOrder"}
  Order history, invoice URLs and metered consumption, read live from the provider — there is no local order or usage table, because the provider already is the ledger. Each returns `null` when no access token is configured. `refundOrder` is admin-tier (`requireAdmin`).
  :::

  :::field{name="getCustomerState · resolveEntity · discounts · provider"}
  Live customer state, entity resolution from claims, discount management (`discounts.create` / `.list` / `.remove` — privileged, so server-side methods rather than registered functions), and the underlying billing-provider client (an advanced escape hatch — `provider.polar` is the raw SDK).
  :::
::

## Reading subscription state

```vue
<script setup lang="ts">
const billing = useBilling()
// billing.products      — configured products keyed by catalog key (name, id, prices live from the provider)
// billing.subscription  — the active subscription, null on the free plan, undefined while loading
// billing.subscriptions — every subscription incl. ended/expired trials
// billing.isSubscribed / billing.isFree / billing.isLoading
// billing.status        — the provider status (active, trialing, past_due, paused, …)
// billing.cancelAtPeriodEnd / billing.trialEnd / billing.isTrialing / billing.isPaused
</script>

<template>
  <p v-if="billing.isSubscribed.value">On {{ billing.subscription.value?.productId }}</p>
</template>
```

Signed-out visitors are simply on the free plan: the user-scoped queries are skipped and `subscription` resolves to `null`.

## Checkout, portal, plan changes

```vue
<script setup lang="ts">
const { products, checkout, portal, changePlan, cancel } = useBilling()

// Subscribe (opens checkout in a new tab; `redirect: true` for same-tab)
await checkout(products.value!.pro!.id, { trialInterval: 'day', trialIntervalCount: 7 })

// Manage payment methods, invoices, the subscription
await portal({ returnUrl: window.location.href })

// Upgrade / downgrade the active subscription
await changePlan(products.value!.ultra!.id, { proration: 'invoice' })

// Cancel at the end of the paid period (the default) — `atPeriodEnd: false`
// revokes on the spot, with no refund implied either way.
await cancel({ atPeriodEnd: true, reason: 'too_expensive' })
</script>
```

The rest of the lifecycle sits on the same composable: `uncancel()` undoes a scheduled cancellation, `pause({ resumesAt })` pauses at the end of the period, and `resume()` restarts a paused subscription immediately. Each takes an optional `subscriptionId` — needed only when the backend runs with `multipleSubscriptions` and one account can hold several at once (the ids are on `billing.subscriptions`).

`checkout(productIds, options)` accepts `subscriptionId`, `metadata`, `trialInterval` / `trialIntervalCount`, `locale`, `successUrl` (defaults to the current URL), `redirect`, and the checkout-form options `prefill`, `customFields`, `requireBillingAddress`, `allowDiscountCodes` and `discountId`. Discount **codes** are typed by the customer into the provider's own checkout (`allowDiscountCodes`, on by default): the provider's payload takes ids only and its API has no code→id lookup, so a campaign resolves its code once with `billing.discounts.list()` and stores the id. After checkout returns, the `subscription.*` / `order.paid` webhooks refresh the cache — or call `syncEntitlements` (`useCredits().refresh()`) to pull immediately.

## Order history and invoices

`useOrders()` pages the entity's past charges straight from the provider (no local order table), and `<BillingHistory>` renders them with invoice links:

```vue
<script setup lang="ts">
const { orders, invoiceUrl, next, previous, hasMore } = useOrders({ limit: 10 })
// invoiceUrl(orderId) returns null while the provider is still generating the
// PDF — the next call returns the URL.
</script>

<template>
  <BillingHistory :limit="10" />
</template>
```

There is also a `<CheckoutLink>` component for launching checkouts and the `<PricingTable>` component behind the `/pricing` page, which renders the plan catalog from `appConfig.backend.billing.plans` with names and prices resolved live (see [Customization](/guide/customization#_2-appconfig-content)).

## Environment

| Variable | Purpose |
|---|---|
| `BILLING_ACCESS_TOKEN` | The provider organization access token — unset, billing queries return empty and checkout actions fail on invocation |
| `BILLING_WEBHOOK_SECRET` | Verifies webhooks on `/billing/events` — unset, events are rejected (503) and entitlements refresh only on demand |
| `BILLING_ENVIRONMENT` | `sandbox` (the default) or `production` |

All three are optional at deploy time and forwarded from `.env.local` by `npx nuxt-backend env push`; see the [configuration reference](/getting-started/configuration#convex-deployment-variables).
