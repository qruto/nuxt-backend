A signed-in user can buy credits or a plan **for someone else**, identified only by email. The purchaser pays; the recipient owns the entitlements. Gift records live in the `backend` component's `billingGifts` table — nothing to add to your schema.

## Sending a gift

```vue
<script setup lang="ts">
const { products } = useBilling()
const { gift } = useCredits()

async function sendGift() {
  await gift(products.value!.credits500!.id, {
    recipientEmail: 'friend@example.com',
    message: 'Happy birthday!',
  })
}
</script>
```

`useBilling().gift(productIds, { recipientEmail, message?, metadata?, successUrl?, redirect? })` and `useCredits().gift(...)` both call the `giftCheckout` action: a checkout billed to a provider customer keyed by the **recipient's** email. On the `order.paid` webhook the package marks the gift paid and:

- **Recipient already has an account** — the gift attaches automatically (in workspace mode, to their personal workspace), and they're notified by email.
- **No account yet** — the recipient gets an email linking to `SITE_URL`; on their first sign-in `useGifts()` claims every paid gift automatically.

## Receiving gifts

```vue
<script setup lang="ts">
// Auto-claim is the default: the first authenticated load holding paid-but-unclaimed
// gifts claims them all. Disable it to show an explicit "receive" action instead.
const gifts = useGifts({ autoClaim: false })
</script>

<template>
  <GiftClaimBanner />  <!-- or your own UI over gifts.unclaimed / gifts.claim() -->

  <div v-for="g in gifts.unclaimed.value" :key="g.id">
    🎁 from {{ g.purchaserName ?? 'someone' }}: {{ g.message }}
    <button :disabled="gifts.isClaiming.value" @click="gifts.claim(g.id)">Receive</button>
  </div>
</template>
```

::field-group
  :::field{name="received" type="ComputedRef<ReceivedGift[] | undefined>"}
  Every gift addressed to the signed-in user's email — `id`, `recipientEmail`, `purchaserUserId` / `purchaserEmail` / `purchaserName`, `productIds`, `message`, `status` (`'pending'` → `'paid'` → `'claimed'`), `createdAt`, `paidAt`, `claimedAt`.
  :::

  :::field{name="unclaimed" type="ComputedRef<ReceivedGift[]>"}
  The `paid` ones — claimable now.
  :::

  :::field{name="isLoading / isClaiming" type="ComputedRef<boolean>"}
  `isLoading` is `true` until the gift list has loaded (always `false` when signed out); `isClaiming` while an auto- or manual claim is in flight.
  :::

  :::field{name="claim(giftId?)" type="Promise<number>"}
  Claim one gift or every claimable gift; resolves with the number attached. Entitlements and credits refresh reactively right after. The server checks the gift is addressed to the signed-in identity's email.
  :::
::

## The notification email

Restylable via `giftEmail` in the `setupBilling` config; the default is a minimal, dependency-free template linking to `SITE_URL`:

```ts [backend/billing.ts]
export const billing = setupBilling(components, {
  catalog,
  giftEmail: ({ recipientEmail, purchaserName, message, claimUrl }) => ({
    to: recipientEmail,
    subject: `${purchaserName ?? 'Someone'} sent you a gift 🎁`,
    html: `…<a href="${claimUrl}">Receive it</a>`,
  }),
})
```

::warning
If the recipient's account already bills through a provider customer under a **different** email, the gift can't attach — entitlements can't move between provider customers. The sender should re-gift to the email the recipient's billing runs under.
