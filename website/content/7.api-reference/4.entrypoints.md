Two ways to consume the surface:

- **Explicit imports** — `import { … } from 'nuxt-backend/…'`, declared in the package `exports` map. The `nuxt-backend/auth*` subpaths run in your **Convex backend** (`backend/`), not the Vue app.
- **Auto-imports** — registered by the module, no `import` needed. Vue composables/components in app code; server utilities in `server/` (Nitro).

## Import tree

```text
nuxt-backend
├─ "nuxt-backend" ............................ Nuxt module (default) + type ModuleOptions
├─ "nuxt-backend/app" ............... backendEnv — the typed deployment env contract for convex.config.ts
├─ "nuxt-backend/auth" .................... setupAuth · createAuth · createAuthOptions
│                                             makeAuthApi · createBetterAuth · createBetterAuthOptions
│                                             + types CreateBetterAuthOptions · SetupAuthOptions
├─ "nuxt-backend/{billing,email,rate-limit,migrations,aggregate,search,workflows}" .. per-component setup helpers
├─ "nuxt-backend/ai" ................ setupAi — metered actions + persisted token streams over billing
├─ "nuxt-backend/http" .............. registerBackendRoutes — auth routes + /billing/events + /email/events
│                                             + /ai/stream + /mcp/exchange in one call
├─ "nuxt-backend/functions" ......... createFunctions — pre-authorized function builders
├─ "nuxt-backend/authorization" ..... setupAuthorization — roles & permissions
├─ "nuxt-backend/mcp" ............... defineBackendMcpTool · useBackendMcp — custom agent tools (Nitro side)
├─ "nuxt-backend/component/convex.config" ... default: the all-in-one `backend` component
├─ "nuxt-backend/component/schema" .. tables · billingTables · aiTables · webhookTables · authSchema
│                                             vEntitlementBenefit · vEntitlementMeter · vGift · vPendingSpend · default
├─ "nuxt-backend/component/{email,billing,gifts,ai,webhooks}" .. the component's function modules
├─ "nuxt-backend/component/_generated/component" .. type ComponentApi  (types only)
├─ "nuxt-backend/auth.config" ....... defineBackendAuthConfig · default · type DefineBackendAuthConfigOptions
└─ "nuxt-backend/test" .............. register · default ({ register, modules })

auto-imports (no import statement)
├─ Vue composables ......... useConvex · useQuery (+ useConvexQuery, useQuery_experimental)
│                            useQueries (+ useQueries) · useMutation (+ useConvexMutation)
│                            useAction (+ useConvexAction) · usePaginatedQuery (+ usePaginatedQuery_experimental)
│                            usePreloadedQuery · usePreloadedAuthQuery · useConnectionState
│                            useUpload · useUploadQueue · useStorageUrl (+ uploadFile)
│                            useAuthState · provideConvexAuth · useAuth · useOrganization
│                            useSearch · useAggregate (+ useCount) · useBilling · useFeatures
│                            useCredits · useGifts · useEmailStatus · useWorkflowStatus · useAiStream
├─ Vue components .......... <Authenticated> · <Unauthenticated> · <AuthLoading>
│                            <RoleBoundary> · <FeatureBoundary> · <AcceptInvitation> · <GiftClaimBanner>
├─ Injection ............... useNuxtApp().$convex : ConvexVueClient
└─ Server utils (Nitro) .... fetchQuery · fetchMutation · fetchAction
                             preloadQuery · preloadedQueryResult · backendAuth

aliases ...................... #backend · #backend/api · #backend/server
                             #backend/dataModel · #backend/_generated  (Vite + Nitro)
```

## Exports map

| Export | Use for |
|---|---|
| `nuxt-backend` | The Nuxt module used in `modules: ['nuxt-backend']` |
| `nuxt-backend/app` | `backendEnv` — the typed deployment env contract the scaffolded `convex.config.ts` passes to `defineApp` |
| `nuxt-backend/auth` | App-side helper bridge (`setupAuth`, `createAuth`, `makeAuthApi`, …) |
| `nuxt-backend/http` | `registerBackendRoutes(http, options)` — auth routes, the [webhooks](/platform/webhooks), `/ai/stream`, and the [agent token exchange](/agents/oauth-and-consent) `/mcp/exchange` in one call |
| `nuxt-backend/functions` | `createFunctions(...)` — pre-authorized `authed` / `org` / `admin` / `withRole` builders |
| `nuxt-backend/authorization` | `setupAuthorization(...)` — roles & permissions over the admin plugin |
| `nuxt-backend/ai` | `setupAi(...)` — metered actions and persisted token streams: rate-limited, credit-metered (reserve → run → settle) |
| `nuxt-backend/mcp` | [`defineBackendMcpTool(...)` / `useBackendMcp(event)`](/agents/custom-tools) — custom tools on the [OAuth-protected agent endpoint](/agents/mcp-server) (Nitro) |
| `nuxt-backend/component/convex.config` | Mounting the packaged all-in-one `backend` component |
| `nuxt-backend/component/schema` | The auth, billing/gift, AI, and webhook-log tables and validators for local hybrid schema scaffolding |
| `nuxt-backend/component/{email,billing,gifts,ai,webhooks}` | The component's function modules, re-exported by local installs |
| `nuxt-backend/auth.config` | Creating `auth.config.ts` with `defineBackendAuthConfig(...)` |
| `nuxt-backend/test` | Registering the packaged `backend` component in `convex-test` |
| `nuxt-backend/billing` | `setupBilling(...)` — subscriptions, discounts, prepaid credits & gifts |
| `nuxt-backend/email` | `setupEmail(...)` — transactional email over the `backend` component |
| `nuxt-backend/rate-limit` | `setupRateLimiter(...)` + `DEFAULT_LIMITS` (`emailOtp`, `billingSync`, `ai`, `mcp`) |
| `nuxt-backend/migrations` | `setupMigrations(...)` — online schema migrations |
| `nuxt-backend/aggregate` | `TableAggregate`, `withTriggers`, `Triggers` — denormalized counts/sums |
| `nuxt-backend/workflows` | `setupWorkflows(...)` — durable multi-step functions |
| `nuxt-backend/search` | `search(...)` (fluent) + `defineSearch(...)` over native full-text search |

## Selected entrypoint signatures

### `nuxt-backend/auth.config`

```ts
import defineBackendAuthConfig, {
  type DefineBackendAuthConfigOptions,
} from 'nuxt-backend/auth.config'

function defineBackendAuthConfig(options?: DefineBackendAuthConfigOptions): AuthConfig
interface DefineBackendAuthConfigOptions {
  basePath?: string  // default '/api/auth'
  jwks?: string
}
```

### `nuxt-backend/component/schema`

```ts
import {
  tables, billingTables, aiTables, webhookTables, authSchema,
  vEntitlementBenefit, vEntitlementMeter, vGift, vPendingSpend,
} from 'nuxt-backend/component/schema'
// tables:        the Better Auth tables (user, session, account, …)
// billingTables: the entitlement cache + billingGifts tables
// aiTables:      metered AI requests (the reserve → settle ledger behind streams)
// webhookTables: the webhook delivery log (dedupe + outcomes)
// default:       the component's full schema (auth + billing/gift + ai + webhook tables)
```

### `nuxt-backend/auth` — option types

```ts
interface CreateBetterAuthOptions {
  authConfig?: AuthConfig          // override the default Convex auth config
  authOptions?: BetterAuthOptions  // merged with package defaults
  basePath?: string                // default '/api/auth'
  admin?: AdminPluginOptions | false           // roles/ban/impersonation — on by default
  organization?: OrganizationPluginOptions | false
  // workspaces — on by default, plus `personal` (auto personal workspace)
  // and `invitationPath` (default '/accept-invitation')
}
interface SetupAuthOptions<DM, Schema> extends CreateBetterAuthOptions {
  schema?: Schema                  // local Better Auth schema for hybrid/local installs
  verbose?: boolean                // verbose component client logs
  integrations?: AuthIntegrations  // { email?, rateLimiter?, onUserCreated?, emailTemplates?, welcomeEmail? }
}
```
