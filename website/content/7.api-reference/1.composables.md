These are auto-imported in app code — no `import` needed. Generic helpers in the signatures (`FunctionReference`, `FunctionArgs`, `FunctionReturnType`, `OptionalRestArgs`, `ConnectionState`, `Value`) come from `convex`; the paginated result types are re-exported from `convex/react` for parity.

## Queries

```ts
// Returns undefined while loading; throws query errors.
function useQuery<Q extends FunctionReference<'query'>>(
  query: Q,
  ...args: OptionalRestArgsOrSkip<Q>   // reactive args; pass 'skip' to pause
): ShallowRef<FunctionReturnType<Q> | undefined>
const useConvexQuery = useQuery

// Experimental object form — errors returned in result unless throwOnError.
function useQuery_experimental<Q extends FunctionReference<'query'>, ThrowOnError extends boolean = false>(
  options: { query: Q, args: MaybeRefOrGetter<FunctionArgs<Q> | 'skip'>, throwOnError?: ThrowOnError },
): ShallowRef<UseQueryResult<FunctionReturnType<Q>, ThrowOnError>>
// → { status: 'pending' | 'success' | 'error', data?, error? }

// Dynamic set of queries.
function useQueries(queries: MaybeRefOrGetter<RequestForQueries>): ShallowRef<QueriesResults>
const useConvexQueries = useQueries
// RequestForQueries: Record<string, { query: FunctionReference<'query'>, args: Record<string, Value> }>
// QueriesResults:    Record<string, Value | undefined | Error>
```

## Backend-component composables

The billing and email composables bind to the `api.billing` / `api.email`
namespaces the module provides from your scaffolded `backend/` files; every
one of them takes an `api` option to point at a different namespace.

```ts
// Debounced reactive full-text search over a `defineSearch` query (or any
// query taking `{ query: string }`); pauses while the term is blank.
function useSearch<Q extends FunctionReference<'query'>>(
  query: Q,
  term: MaybeRefOrGetter<string>,
  options?: {
    debounce?: number                                        // ms, default 200
    args?: MaybeRefOrGetter<Omit<FunctionArgs<Q>, 'query'>>  // merged with { query } — a limit, filter fields
  },
): {
  results: ComputedRef<FunctionReturnType<Q>>   // [] while loading or while the term is blank
  isLoading: ComputedRef<boolean>
  term: ComputedRef<string>                     // the debounced term driving the query
}

// Live aggregate count (coerces loading/null to 0). useCount is an alias.
function useAggregate<Q extends FunctionReference<'query'>>(query: Q, ...args: OptionalRestArgsOrSkip<Q>): ComputedRef<number>
const useCount = useAggregate

// Billing. `gift` opens a checkout billed to someone else's email. Every
// lifecycle action takes an optional `subscriptionId` — needed only once the
// backend runs with `multipleSubscriptions` and one account holds several.
function useBilling(options?: { api? }): {
  products, subscription, subscriptions, isSubscribed, isFree, isLoading,
  // Lifecycle state, read off the synced subscription row.
  status, cancelAtPeriodEnd, trialEnd, isTrialing, isPaused,
  // Reserved: the synced subscription table has no columns for these yet, so
  // they read `null` until the provider component adds them.
  pausedAt, resumesAt, pendingUpdate,
  checkout, gift, portal,
  changePlan,  // (productId, { proration?: 'invoice' | 'prorate', subscriptionId? })
  cancel,      // ({ atPeriodEnd?, reason?, comment?, subscriptionId? })
  uncancel, pause, resume,
}

// Feature gating off the webhook-synced entitlement cache.
function useFeatures(options?: { api? }): {
  plans,      // ComputedRef<string[] | undefined> — active product ids
  benefits,   // ComputedRef<EntitlementBenefit[] | undefined> — granted benefits
  isLoading,  // true until the cache has loaded — gate on it to avoid a first-paint flicker
  has: (feature: string) => boolean,       // matched by benefitId, grant id, type, or any metadata value
  hasPlan: (productId: string) => boolean,
}

// Prepaid credits: the balance cache, the cycle it belongs to, and top-ups.
// `cycle` is `null` for credits bought as a one-time pack (they have no
// billing period); `expiresAtCycleEnd` is only `true` when the granting
// benefit is known not to roll over.
function useCredits(meterId?: MaybeRefOrGetter<string>, options?: { api? }): {
  balance, credited, consumed, overage, cycle, expiresAtCycleEnd,
  meterId, isLoading, topUp, gift, refresh,
}

// Past charges, read live from the provider (no local order table). Paged by
// provider page number. `invoice(orderId)` fetches the invoice link and opens
// it, resolving with the URL — `null` while the provider has no invoice PDF
// for that order yet; pass `{ open: false }` to get the URL without opening it.
function useOrders(options?: { limit?, immediate?, api? }): {
  orders, page, total, pageCount, hasMore, hasPrevious, isLoading, error,
  refresh, next, previous, goTo,
  invoice: (orderId: string, options?: { redirect?: boolean, open?: boolean }) => Promise<string | null>,
}

// Metered consumption for one credit meter, read live from the provider's
// events API — the events your server ingested when it spent credits.
function useUsage(options?: { meter?, limit?, immediate?, api? }): {
  events, page, total, pageCount, units, hasMore, hasPrevious,
  isLoading, error, refresh, next, previous, goTo,
}

// Gifts addressed to the signed-in user. Auto-claims paid gifts on first
// authenticated load unless autoClaim: false.
function useGifts(options?: { autoClaim?: boolean, api? }): {
  received,    // every gift addressed to the user's email, undefined while loading
  unclaimed,   // the paid-but-unclaimed subset
  isLoading,   // true until the list has loaded (always false when signed out)
  isClaiming,  // true while an auto- or manual claim is in flight
  claim: (giftId?: string) => Promise<number>,   // one gift, or every claimable one; resolves with the count
}

// Workspaces + the full invitation flow.
function useOrganization(): {
  organizations, current, member, role, members, isLoading,
  setActive, create, invite, leave,
  acceptInvitation, declineInvitation, cancelInvitation,
  getInvitation, listReceivedInvitations,
}

// Live email delivery status (advances as /email/events webhooks land);
// pauses while the id is undefined or empty.
function useEmailStatus(emailId: MaybeRefOrGetter<string | undefined>, options?: { api? }): {
  data,       // the full status record — null if unknown, undefined while loading
  status,     // 'queued' | 'sent' | 'delivered' | 'bounced' | … | undefined
  isLoading, isDelivered, isError,
}

// Live durable-workflow status; pauses while the id is null/undefined.
function useWorkflowStatus<Q extends FunctionReference<'query'>>(
  query: Q,   // a query taking { workflowId } that wraps workflow.status
  workflowId: MaybeRefOrGetter<string | null | undefined>,
): ComputedRef<FunctionReturnType<Q> | undefined>

// Drive a metered, persisted AI token stream (an `ai.stream(...)` definition
// from `nuxt-backend/ai`): `start` reserves credits + drives /ai/stream, the
// text also persists server-side — reload (or pass `streamId`) and it continues.
function useAiStream(
  stream: { start, body },
  options?: { streamId?, url?, headers? },
): { text, status, isStreaming, streamId, start: (args?) => Promise<string>, stop }
```

## Better Auth

```ts
function useAuth(initialToken?: string | null): UseBackendAuthService
interface UseBackendAuthService {
  // The base service
  client: AuthClient                       // the Better Auth client — every plugin flow lives here
  session: BetterAuthSession               // Better Auth's own useSession() ref: { data, isPending, error }
  user: ComputedRef<BetterAuthUser | null>
  isAuthenticated: ComputedRef<boolean>
  isLoading: ComputedRef<boolean>
  fetchAccessToken: AuthTokenFetcher
  authVersion: ComputedRef<string | null>
  // Passwordless flows (OTP + passkeys)
  signOut(): Promise<unknown>
  sendOtp(email: string, type?: 'sign-in' | 'email-verification' | 'forget-password'): Promise<unknown>
  signInWithOtp(args: { email: string, otp: string, name?: string }): Promise<unknown>
  signInWithPasskey(): Promise<unknown>
  registerPasskey(context?: string): Promise<unknown>
  // Account management
  updateUser(args: { name?: string, image?: string | null }): Promise<unknown>
  changeEmail(newEmail: string, callbackURL?: string): Promise<unknown>
  sendVerificationEmail(callbackURL?: string): Promise<unknown>   // throws for already-verified users
  deleteAccount(): Promise<unknown>
  // Authorization (admin plugin)
  role: ComputedRef<string>                // 'user' when signed out or unset
  hasRole(role: string | string[]): boolean
  can(permissions: Record<string, string[]>): boolean   // e.g. { user: ['ban'] } — sync and local
  banned: ComputedRef<boolean>
}

// The headless state machine behind <AuthForm>: choose → request-code →
// verify-code → add-passkey (email OTP), or choose → signInWithPasskey.
function useLoginFlow(options?: {
  requireName?: boolean                                  // default true — a name field on the email step
  validateEmail?: (email: string) => boolean | string    // false = the default message, a string = your own
  offerPasskey?: boolean                                 // default true — the post-OTP "save a passkey" step
  onSuccess?: () => unknown | Promise<unknown>           // signed in and done (e.g. navigateTo)
}): {
  step: Ref<'choose' | 'request-code' | 'verify-code' | 'add-passkey'>
  email: Ref<string>; name: Ref<string>; otp: Ref<string>
  pending: Ref<boolean>; error: Ref<string | null>
  emailValid: ComputedRef<boolean>
  signInWithPasskey: () => Promise<void>
  sendCode: () => Promise<void>       // → 'verify-code'
  verifyCode: () => Promise<void>     // signs in / signs up → 'add-passkey' or done
  addPasskey: () => Promise<void>     // → done
  skipPasskey: () => Promise<void>    // → done
  goTo: (step: LoginStep) => void
  reset: () => void
}

// Passkey management over the auth client. The list loads in the browser
// only (`undefined` during SSR); every method throws a plain Error on
// failure, mirrored into `error`.
function usePasskeys(options?: { immediate?: boolean }): {   // immediate: load on mount, default true
  passkeys: Ref<Passkey[] | undefined>
  isLoading: ComputedRef<boolean>
  error: Ref<string | null>
  refresh: () => Promise<void>
  add: () => Promise<void>
  rename: (id: string, name: string) => Promise<void>
  remove: (id: string) => Promise<void>
}

// Device sessions — list, revoke one, revoke the rest. Same loading and
// error contract as usePasskeys.
function useSessions(options?: { immediate?: boolean }): {
  sessions: Ref<SessionInfo[] | undefined>
  current: ComputedRef<SessionInfo | undefined>   // the session belonging to this browser
  isLoading: ComputedRef<boolean>
  error: Ref<string | null>
  refresh: () => Promise<void>
  revoke: (token: string) => Promise<void>
  revokeOthers: () => Promise<void>
}

// 'Chrome · macOS'-style label from a session's userAgent ('unknown device' when empty).
function describeUserAgent(userAgent?: string | null): string

// Unwrap an auth-client `{ data, error }` envelope: returns `data`, or throws
// a plain Error carrying the message when `error` is set.
function unwrapAuth<T>(result: unknown): T
```

## Auto-registered components

`<Authenticated>`, `<Unauthenticated>` and `<AuthLoading>` come from the base module and render their slot by auth state. The package registers the rest:

| Component | Props (default) | Emits | Slots |
|---|---|---|---|
| `<AuthForm>` | `title` (`'Sign in'`), `passkeys` (`true`), `otp` (`true`), `requireName` (`true`), `validateEmail` | `success`, `error(message)`, `step(step)` | `header`, `error`, `footer`, and one per step — `choose`, `request-code`, `verify-code`, `add-passkey`; each receives the `useLoginFlow()` object |
| `<RoleBoundary>` | `role` (string or array — any match), `permission` (`{ user: ['ban'] }`) | — | `default`, `fallback` (not allowed), `placeholder` (session loading) |
| `<FeatureBoundary>` | `feature` (string or array), `plan` (product id or array) | — | `default`, `fallback`, `placeholder` |
| `<OrganizationBoundary>` | — | — | `default` (`{ workspace }`), `fallback` (no active workspace), `placeholder` |
| `<AcceptInvitation>` | `invitationId` (the `?id=` query parameter), `activate` (`true`) | `accepted(invitation)`, `declined(invitation)`, `error(message)` | one per state — `loading`, `ready`, `accepted`, `declined`, `missing`, `error`; each receives `{ invitation, accept, decline, pending, error }` |
| `<GiftClaimBanner>` | `autoClaim` (`false`) | `claimed(count)`, `error(message)` | `default` (`{ gifts, claim, isClaiming }`) |
| `<PricingTable>` | `plans`, `packs` (`appConfig.backend.billing.*`), `title`, `period` (`'/mo'`), `showPacks` (`true`), `showPortal` (`true`), `redirect` (`true`) | `checkout(url)`, `plan-changed(key)`, `canceled`, `uncanceled`, `topped-up(key)`, `error(message)` | `header`, `plan`, `plan-action`, `packs`, `pack`, `portal`, `empty`, `error`, `footer` |
| `<BillingHistory>` | `title`, `limit` (the provider's page size), `invoices` (`true`), `redirect` (`false`) | `invoice(url)`, `error(message)` | `header`, `order`, `loading`, `empty`, `error`, `pager`, `footer` |
| `<UsageHistory>` | `meter` (every metered event), `title`, `limit` | — | `header`, `event`, `loading`, `empty`, `error`, `pager`, `footer` |
| `<CreditsLowBanner>` | `meter` (the primary meter), `threshold` (`appConfig.backend.billing.lowCreditsThreshold`), `pack`, `dismissible` (`true`), `redirect` (`true`) | `dismissed`, `topped-up(url)`, `error(message)` | `default`, `message`, `action`, `dismiss` |
| `<WorkspaceSettings>` | `sections` (`['workspaces', 'billing', 'credits']`), `pricingPath` (the resolved pricing page) | `workspace-created(workspace)`, `workspace-switched(id)`, `plan-canceled`, `topped-up(key)`, `error(message)` | `workspaces`, `workspace`, `create`, `billing`, `credits`, `footer` |
| `<ProfileSettings>` | `validateEmail`, `callbackPath` (the current path), `showIdentity` (`true`) | `name-saved(name)`, `email-change-requested(email)`, `error(message)` | `identity`, `name`, `email`, `footer` |
| `<SecuritySettings>` | `sections` (`['verification', 'passkeys', 'sessions', 'danger']`), `confirm` (`window.confirm`), `callbackPath` (the current path) | `verification-sent`, `passkey-added`, `passkey-removed(id)`, `session-revoked(token)`, `sessions-revoked`, `delete-requested`, `signed-out`, `error(message)` | `verification`, `passkeys`, `passkey`, `sessions`, `session`, `danger`, `footer` |

Every slot of the pricing, history, banner and settings components receives the component's full slot context — the composables it runs on plus its pending and error state; [Customization › Slots](/guide/customization#_3-slots) has a worked example.

The module also mounts the [ready-made pages](/guide/default-pages) on these components — `/accept-invitation` (module option `pages.acceptInvitation`), for one, renders `<AcceptInvitation>` behind the `auth` middleware.
