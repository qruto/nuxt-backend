Auth is always installed. Use **local** installation mode when you want to own the component's schema or functions — add custom indexes or component tables, regenerate the auth schema after adding Better Auth plugins, or inline a function module to customize it:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-backend'],
  backend: {
    installation: 'local',
  },
})
```

(or scaffold explicitly with `npx nuxt-backend init --installation local`).

The first run scaffolds the **whole** `backend` component into `backend/components/backend/`:

```text
backend/components/backend/
├── convex.config.ts       # defineComponent('backend') — nests the email provider, declares EMAIL_* env
├── generated-schema.ts    # re-exports the packaged tables + validators
├── schema.ts              # authSchema + the component's full default schema
├── adapter.ts             # createApi(authSchema, createAuthOptions)
├── email.ts               # thin re-export of the packaged email module
├── billing.ts             # thin re-export of the packaged entitlement cache
├── gifts.ts               # thin re-export of the packaged gift module
└── auth.ts                # schema-generation probe for `npx auth generate`
```

- `convex.config.ts` — `defineComponent('backend', { env: { EMAIL_API_KEY, EMAIL_FROM, EMAIL_TEST_MODE, EMAIL_WEBHOOK_SECRET } })` with the provider component nested via `component.use(resend)`. The env vars are **required**; the app forwards the deployment's values (`defineBackendApp` does this for you).
- `generated-schema.ts` — re-exports `tables`, `billingTables`, `vEntitlementBenefit`, `vEntitlementMeter`, and `vGift` from `nuxt-backend/convex/components/backend/schema`.
- `schema.ts` — builds `authSchema` from the auth `tables` (customize here) and default-exports the full component schema (`...tables, ...billingTables`).
- `adapter.ts` — the Better Auth adapter over your local schema: `createApi(authSchema, createAuthOptions)`.
- `email.ts` / `billing.ts` / `gifts.ts` — one-line re-exports from `nuxt-backend/convex/components/backend/{email,billing,gifts}`; inline any of them to customize the implementation.

The app config swaps in your local definition with a single relative import:

```ts [backend/convex.config.ts]
import { defineBackendApp } from 'nuxt-backend/convex/app'
import backend from './components/backend/convex.config'

export default defineBackendApp({ components: { backend } })
```

The app-facing `backend/auth.ts` passes your local schema to `setupAuth(components, query, { schema: authSchema, … })` and still exports `authComponent`, `createAuthOptions`, `options`, and `createAuth`, matching the official Better Auth Convex API while hiding the installation details behind the Nuxt module.

::warning
Under **pnpm**, the local component's `convex.config.ts` imports `@convex-dev/resend` directly, so add it as a direct dependency: `pnpm add @convex-dev/resend`.
::

## Regenerating the schema

After changing Better Auth plugins or schema-affecting options, regenerate the local schema:

```bash
npx auth generate \
  --config ./backend/components/backend/auth.ts \
  --output ./backend/components/backend/generated-schema.ts
```

::tip
Keep hand-written indexes and schema customizations in `backend/components/backend/schema.ts`; it imports and spreads the generated tables, so regeneration does not overwrite your local edits.
::

## When to use local mode

The packaged component is intentionally opinionated for zero setup. Reach for local mode only when you need full ownership beyond route wiring — custom indexes, schema ownership, extra component-owned tables, plugins that change the schema, or inlining a packaged function module. The [advanced example](https://github.com/qruto/nuxt-backend/tree/main/examples/advanced) exercises all of it.
