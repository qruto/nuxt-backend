# Testing nuxt-backend end-to-end

## Local, on the sandboxes (start here)

`pnpm try` runs the docs and the whole playground on this machine: the local deployment `website/.env.local` names (provisioned with no account when there is none; never a cloud one), with every provider in its own test mode: billing in Polar's sandbox, email to Resend's test addresses (read back through the dev inbox), models through the AI gateway. Nothing is simulated. It forwards the sandbox keys of the root `.env.local` (`BILLING_ACCESS_TOKEN`, `EMAIL_API_KEY`, `EMAIL_FROM`, `AI_GATEWAY_API_KEY`) to the deployment and syncs the catalog to Polar's sandbox; without a key the capability reads `missing` and its pages show empty states. It serves **https://nuxt-backend.localhost** (it prints the origin portless gives it) and seeds a persona per kind of account.

- **Personas** (`scripts/try/personas.mjs` holds them): admin `delivered+tryplaygroundadmin@resend.dev`; owner of Acme `delivered+tryworkspaceowner@resend.dev`; member of Acme `delivered+tryworkspacemember@resend.dev`; free user `delivered+tryfreeplanpersona@resend.dev`; gift purchaser `delivered+trygiftpurchaser@resend.dev`; unclaimed gift recipient `delivered+trygiftrecipient@resend.dev`. Sign in on `/login` by typing the address: the code shows under the form.
- **Paid states are bought once, with the test card.** Polar's sandbox takes a payment at its checkout only, so the seeding pays for nobody: it starts every workspace on the free plan and prints which persona needs which purchase. As the owner, subscribe Acme to Pro on `/pricing`; as the purchaser, buy 100 credits and give one to the recipient on `/playground/platform/credits`. Card `4242 4242 4242 4242`, any future expiry, any CVC. A local deployment gets no webhooks from Polar: the return from checkout refreshes the state once.
- **The checklist** is the [Try everything](https://nuxt-backend.dev/docs/start/playground/try-everything) guide: one row per playground page, the persona to sign in as and what should happen.
- **Between runs:** `pnpm try:reset` empties every table of the local deployment and seeds the personas again (about two minutes). Polar's sandbox keeps its customers and orders: archive them in its dashboard for a clean slate.
- **Findings:** press N on a page to note the element under the pointer; `pnpm try:notes` prints them as Markdown by page.
- **Checkout** opens Polar's sandbox checkout: pay with the test card, or add a 100% discount code for a card-free pass (see Card-free checkout below). Polar renews subscriptions and ends trials on its own schedule; its dashboard moves a subscription through each state.
- **The starter as a new user gets it:** `pnpm try:starter` (the packed package in a fresh `templates/starter`, at https://starter.localhost; it prints the one `billing sync` left to run in the copy).

The sections below are the live-provider path: run them once the local pass is green, for what only the real services show (the provider's own checkout and emails, webhooks over the internet).

Everything runs against **testing environments only**: Polar **sandbox** and Resend **test mode** (both follow the deployment's `BACKEND_ENVIRONMENT`, `development` on a dev deployment; only `*@resend.dev` inboxes, read back with `nuxt-backend inbox`), Convex **dev** deployment (the `CONVEX_DEPLOYMENT` in the root `.env.local`). The dev server is `pnpm dev` from the repo root → **https://nuxt-backend.localhost** (portless proxy, Nuxt serves `website/`); `pnpm dev:lan` serves the same stack at **https://nuxt-backend.local** for phones on the network. Watch for origin drift: the deployment's `SITE_URL` must equal the origin you test through (`npx convex env get SITE_URL`) — emailed links and sign-in break until they match. Always test through the portless origin, not `127.0.0.1:<port>` (client auth state needs the canonical origin).

## Environment cheatsheet

- Secrets live **on the Convex deployment**, not in dotenv files: `npx convex env get <NAME>` (from repo root). Names: `BACKEND_ENVIRONMENT`, `BILLING_ACCESS_TOKEN`, `BILLING_WEBHOOK_SECRET`, `EMAIL_API_KEY`, `EMAIL_WEBHOOK_SECRET`, `AUTH_SECRET`, `SITE_URL`.
- The Polar/Resend **MCP servers have under-scoped or dead tokens** — use `curl` with deployment tokens instead:
  - Polar sandbox API: `https://sandbox-api.polar.sh/v1/...` with `Authorization: Bearer $(npx convex env get BILLING_ACCESS_TOKEN)`. **Trailing slash required** on collection endpoints (`/products/`, `/benefits/`) — without it you get an empty 307 body.
  - Resend API: `https://api.resend.com/emails` with `Bearer $(npx convex env get EMAIL_API_KEY)` — list, then `GET /emails/{id}` for html.
- Polar org `qruto` (sandbox). The catalog is **code**: `website/backend/billing.catalog.ts` (plans, packs, the `credits` meter, feature benefits); `npx nuxt-backend billing sync --env sandbox` finds-or-creates it on the org and writes the product/meter ids into `website/backend/billing.generated.ts` — the only place UUIDs live (commit it when it changes). The paid plans and packs are priced in EUR (the org's default currency, which the free plan is priced in) and USD; `free` is the free plan.
- Catalog: starter €5/50cr, pro €9/200cr+premium, ultra €19/500cr+premium+ultra, each also yearly at ten months' price (€50/€90/€190, twelve months of credits a year; products `<plan>:year`), credits100 €10 (no rollover), credits500 €40, credits1000 €70. Feature benefits match `useFeatures().has()` via benefit `metadata: { key: '<feature>' }`.
- Before a pass: `npx nuxt-backend doctor` must be fully green — it probes the deployment env, both webhook routes, the function contract and the catalog against the org (an expired token shows as `billing-organization`).
- Webhooks (verify if entitlements "never arrive"): Polar → `https://<deployment>.convex.site/billing/events`; Resend → `https://<deployment>.convex.site/email/events`.

## Reset & prep

```sh
pnpm run db:reset        # empties every scope: app tables, the backend component, email, and the Polar component's cache
npx convex run billing:syncProducts '{}'   # refill the plan catalog the reset emptied (Polar itself is untouched)
npx convex run discounts:createDiscount '{"name":"E2E","percent":100,"code":"E2E100","duration":"forever"}'
```

`duration: "forever"` keeps recurring checkouts card-free. `discounts:createDiscount` is an `internalAction` (ops only) — the playground's billing page mints through `createDiscountAsAdmin`, which needs the admin role: `npx convex run functions:setUserRole '{"email":"delivered+LABEL@resend.dev","role":"admin"}'` after that sandbox identity signs up (the marketing actions on the Email page need it too). Products come from `billing sync` (above), not from a seed.

## Sign-in: sandbox identities and the dev inbox

The playground admits **sandbox identities only**: `delivered+LABEL@resend.dev` with a label of 16+ lower-case letters and digits (`canSignIn` in `website/backend/auth.ts`; email changes, invitations and gift recipients follow the same rule). Any other address is refused, `delivered@resend.dev` and short labels included.

On `/login`, "Create a sandbox identity" generates one (remembered in localStorage), or type your own (e.g. `delivered+e2e$(date +%s)run@resend.dev`; one label per run, OTP limit 5/min/address). After "Send code", the dev inbox under the form shows the code; "Fill the code" enters it. `/playground/platform/email` → "Dev inbox" lists any sandbox address's mail from the last hour as text: the sign-in and email-change codes, the welcome, the delete-account link, invitations.

From a shell, the same inbox, read back from Resend's own log of sent email:

```sh
npx nuxt-backend inbox delivered+LABEL@resend.dev --json   # { address, deployment, messages, code }, newest first; never a body
npx convex run email:getSandboxInbox '{"address":"delivered+LABEL@resend.dev"}'   # an action: code or links in .text of the newest three
```

The inbox needs test mode (the default) and `EMAIL_API_KEY` on the deployment with full access (a key restricted to sending cannot read sent mail), and reads the last hour. For anything older, list through the Resend API with `EMAIL_API_KEY` (`GET https://api.resend.com/emails`, then `/emails/{id}`; decode `&amp;` → `&` in links).

## Card-free checkout

SaaS pages use redirect checkout (`billing.checkout(id, { redirect: true })`) — automation-friendly, unlike the embed iframe. On the Polar page: "Add discount code" → `E2E100` → Enter → "Get for free". Redirects back to the app; webhooks land within seconds (watch the Billing activity feed on `/playground/saas/pricing`).

## The full pass (what to verify)

1. **Register via OTP** → user chip; exactly **one** "Welcome aboard" email; `auth · user.created` in the feed.
2. **Subscribe Starter** → feed `subscription.active`/`order.paid`; plan pill + credits 50. The return from checkout lands with no `checkout_return` left on the address and reads "Finishing your purchase…" until the new plan shows (`useBilling().isFinishingCheckout`); a reload refreshes nothing more. Plan resolution can lag credits by seconds — the UI self-heals; "Refresh entitlements" forces it.
3. **Spend credit** (settings) → balance decrements reactively. Blocked at 0 (prepaid).
4. **Top-up packs** → balance += pack units.
5. **Switch plan** (`changePlan`, no checkout) → old plan's monthly grant revoked, new granted (e.g. 148−50+200=298).
6. **Change email** (profile, to another sandbox identity) → a code to the OLD address, entered on the profile page → a code to the NEW address, entered too (read both on the Email page's dev inbox) → the account moves, and the identity shows the new address. A wrong code stays on its step with the reason; a non-sandbox address is refused before any code goes out. No email in either inbox carries a link. Covers `useEmailChange` and the `otp` template's `email-verification` and `change-email` purposes.
7. **Security page** → sessions list (current marked), passkey list/add/rename/remove. Sign in on a second browser, revoke it from the first → its row drops off live and the second browser is signed out, then lands on `/login?redirect=/playground/saas/security` once its session reloads (focus the tab); signing back in returns to the security page. Sign out from the danger zone → `/login` with no `?redirect=`. The list must also load for a session over a day old (Better Auth's `/list-sessions` refuses those with `SESSION_NOT_FRESH`; ours reads the session table).
8. **Email outcomes** (platform/email) → bounced flips status; **complained is a flag on top of `delivered`** (shown as a warn pill), events may arrive out of order.
9. **Cancel** (settings) → "Cancel plan" opens one group: the end date and one "Confirm cancellation" button, nothing else (no field, no offer). Confirm → the plan reads "Cancels at period end · ends …", focus on it, and no "Cancel plan" is left to press twice. "Keep plan" undoes it. The same on `/pricing`: the current plan's "Cancel plan" opens the same group. `/playground/platform/plan` shows each state's line and action (trial, past due, paused, set to cancel, change scheduled); on a local deployment the billing simulator's home page renews, ends trials and fails a payment to walk through them. **Delete account** → confirmation link → user row gone (`npx convex data user --component backend`).
10. **Workspaces** (settings) → create auto-activates → billing shows Free with its 10 credits for the new workspace (the free plan, queued on the workpool as the workspace was made: give it a few seconds); switch back → plan/credits return. Billing entity = active workspace (`billTo: 'organization'`).
11. **Off-catalog checkout refused** → from the browser console on a signed-in page, call `billing:generateCheckoutLink` with a product id outside `billing.generated.ts`, then a catalog id with `successUrl: 'https://example.com'`, then with `trialInterval: 'day'`, then with `metadata: { userId: 'x' }`: each rejects with `invalid_input` naming the field (`productIds`, `successUrl`, `trialInterval`, `metadata`), and no checkout appears in the Polar sandbox. A gift by a plan's key (`giftCheckout` with `pack: 'pro'`) rejects with field `pack`. A campaign link's `utm` lands on the order as `utm_*` metadata (Polar dashboard → the order).

### Yearly prices, campaigns and the pricing page

- **Yearly toggle** (`/playground/saas/pricing`): the **Monthly / Yearly** radio group switches every card; yearly shows the year price, "/yr", "Save 16%" and twelve months of credits. Arrow keys move between the two options. The panel under the table follows `v-model:interval`. Subscribe to Pro yearly: Starter reads Downgrade and Ultra Upgrade, by price per month. Flip to Monthly: Pro's card reads "Switch to monthly billing"; pressing it schedules the switch for the paid year's end (`next_period`), so the card then reads "Starts on <date>", `/settings` shows the change scheduled, and the balance keeps the year's credits with nothing refunded.
- **Server-rendered**: `curl -s https://nuxt-backend.localhost/playground/vanilla/pricing | grep -c 'data-pricing="plan"'` counts the plans in the HTML, before any JavaScript.
- **Packs**: credits500 and credits1000 show a price per credit, credits1000 "Best value" and "12% less per credit"; credits100 (no rollover) shows no comparison.
- **Campaign link**: open `/playground/vanilla/pricing?utm_source=newsletter&utm_campaign=autumn&discount=EXPIRED1` signed out (a public page; the saas one sends a visitor to sign in first): each card's `data-intent="sign-in"` link carries the whole query in its `redirect`, and signing in from it lands back on the same address. Signed in, check out from `/playground/saas/pricing?utm_source=newsletter&utm_campaign=autumn&discount=EXPIRED1`: a code the provider refuses still opens the checkout, without the discount and with no error, and the order's metadata on the Polar sandbox (or the simulator) carries `utm_source` and `utm_campaign`.
- **Promotion** (`/playground/saas/pricing`): the catalog's `launch` discount (`billing sync` on the sandbox creates it: `created discount launch`, then `at most 1 per customer`). The monthly cards read "Launch offer 20% off for 3 months, then …/mo" and "Offer ends Jun 30, 2027"; the yearly cards and the packs carry none. Subscribe Pro monthly: Polar's checkout shows the discount applied, and the order's `discountId` is the one `billing.generated.ts` names. A second checkout by the same customer is refused by Polar (per-customer limit) and the table reopens it at the regular price with no error. `generateCheckoutLink` with `discount: 'nope'`, or with `discount` beside `discountCode`, rejects `invalid_input` field `discount`. `npx nuxt-backend doctor` passes `billing-promotion-limits`. Hardening: a client names only a promotion with a code; a code-free one is the server's (`billing.checkout`, `checkoutDiscount`, `applyDiscount`), and the probe suite's `input:discount` run holds it.
- **Free plan** (`/playground/saas/pricing`): a new sandbox identity's workspace is on **Free** within seconds of signing in: its card is marked current with no button, the current-plan card reads `free` / "the free plan", and the balance is 10. Polar shows a $0 subscription on the workspace's team customer (no order). **Subscribe Pro** → the checkout upgrades that same subscription (Polar: one subscription, now Pro, trialing when Pro has a trial and the owner never had one); credits 200. Cancel at period end, then end it in the Polar dashboard (revoke): the workspace is back on Free a moment later (a new $0 subscription). `billing:cancelSubscription`, `pauseSubscription` and `updateSubscription` on the free plan, and `generateCheckoutLink` with the free product, reject `invalid_input` reason `free_plan`. Existing workspaces: `npx convex run billing:startFreePlan '{}'` once after the sync that adds the plan. Hardening: `startFreePlan` is internal; a client can't start, upgrade or cancel another workspace's free plan.
- **Currencies** (`/playground/saas/pricing?currency=usd`): every price in USD and the **Currency** select on EUR/USD; switching re-reads the prices, and a checkout opens at the price in the currency shown (Polar's checkout page shows it). Without the parameter the page starts in the country of the request (Vercel's geo header), else the browser language's region. `generateCheckoutLink` with `currency: 'gbp'` rejects `invalid_input` field `currency`. `billing sync` on the sandbox adds the USD prices to the existing products (`adds its price in usd`) and moves each gift twin to both. **Sandbox check before merge — a currency change on upgrade:** from a workspace on Free (its $0 subscription is in EUR), switch to USD and subscribe Pro: Polar must move the EUR free subscription to USD Pro (one subscription, now USD). If Polar refuses the change, record it: the package must then check out in the free subscription's currency, or say the limit. A gift from the pricing page in USD (`useCredits().gift(pack, { currency: 'usd' })`) opens at the twin's USD price.
- **Retired plan**: in a scratch catalog, mark a plan `retired: true` and `billing sync --dry-run`: it reads `would-archive`. A retired plan's card shows only to its subscribers ("No longer offered"); `generateCheckoutLink` with its product id rejects `invalid_input` reason `retired`.
- **Benefit edit**: change credits1000's units in the Polar dashboard: `benefit.updated` arrives, the products table re-syncs, and the pricing page shows the new units within seconds.

## Production (nuxt-backend.dev)

The live playground runs on the production deployment `determined-horse-300`, deployed by Vercel's production build (`website/vercel-build.sh`). A pass there differs from a dev pass:

- Every `npx convex …` needs the production deploy key, **prefixed per command** (`CONVEX_DEPLOY_KEY=… npx convex …`) — never exported into the shell you test from. Check it first: `echo "${CONVEX_DEPLOY_KEY%%|*}"` prints `prod:determined-horse-300`.
- **Never run `pnpm db:reset` or `db:seed` against it for a test.** Without `--prod` they drop the key and refuse one kept in `.env.local`, so they reach the dev deployment. `pnpm db:reset --prod --yes <scopes>` is the maintainer's step before merging a pull request that names a reset (CONTRIBUTING, the playground deploy rule), never part of a test pass.
- Test through `https://nuxt-backend.dev` with a sandbox identity (see Sign-in above): the code shows up in the dev inbox on `/login`, as on dev.
- Admin checks need `functions:setUserRole` run against production, from the Convex dashboard or with the key, on a sandbox identity. Keep that address private: whoever knows it can read its codes.
- `pnpm cli doctor --prod` (after `pnpm build`) checks production: env names, the function contract, and the webhook routes on the deployment's own site URL.

## Known limitations & gotchas

- **Passkeys can't be automated here** — chrome-devtools MCP has no WebAuthn virtual authenticator; the ceremony fails with a focus/NotAllowed error (the UI must surface it). Manual test: real DevTools → WebAuthn panel → virtual authenticator (ctap2/internal/resident-key) → add passkey → rename/remove → passkey sign-in from `/login`. Passkey autofill runs in CI instead (`test/e2e/passkey-autofill.test.ts`, Playwright's CDP virtual authenticator); WebKit has none, so Safari and iOS stay manual.
- **Raw Better Auth client calls do NOT throw** — `client.…` resolves `{ data, error }`; demo pages wrap those in `unwrapAuth()`. The composables' actions (`useAuth`, `useOrganization`, `usePasskeys`) already resolve data and reject — never wrap them.
- **Marketing broadcasts** require a verified domain — Resend rejects broadcasts from `resend.dev` senders. Expect the surfaced error in test mode. The marketing actions are admin-only, and contacts must be Resend test inboxes.
- **Playground throttles** (`website/backend/rateLimiter.ts`): the test email and the demo workflow share 5 sends a minute per user and 100 an hour for the deployment; the log seeder runs 3 times a minute; upload URLs 10 a minute and the demo action 20 a minute per user. Uploads stop at 5 MB and 50 files (a full library gets no upload URL). Todos are capped at 200 characters and 200 per account, log messages and the echo text at 500. A visitor has two counters, `demo` and `server`, with steps up to ±1000. The demo action needs a sign-in, and a migration backfill needs the `admin` role. Crons (`website/backend/crons.ts`) prune email records and the event feed after a week, remove uploads nobody saved (daily, once an hour old), and clear the app data of sandbox accounts idle for a week: no session, sign-in or new row in that time (admins skipped; the accounts themselves stay).
- **Resetting data**: `pnpm db:reset [app|backend|email|polar]` empties the dev deployment table by table from the schemas; `pnpm db:seed` refills it. On production only with `--prod --yes`, and only when a pull request names the reset (CONTRIBUTING, the playground deploy rule).
- **`spendCredits`**: omit `userId` so the billing entity resolves from identity claims (org mode); passing the auth user id breaks the Polar customer lookup.
- **Session-dependent UI needs `<ClientOnly>`** — SSR has no session while hydration does; class mismatches silently persist (Vue hydration is check-only for classes).
- `website/backend/**` edits hot-sync via the running `convex dev`; `src/**` module/runtime edits need a `pnpm dev` restart to be safe (runtime stubs sometimes HMR, module.ts never does).
- `billing.api.listAllSubscriptions` is wrapped by `setupBilling` to return `null` for claimless callers (auth handshake / WS reconnect windows) instead of throwing — if "needs an active workspace" errors spam the Convex logs, that wrapper regressed.

## New surfaces to verify (all-in-one alignment)

- **Default pages**: `/playground/vanilla/{pricing,settings,profile,security}` show the untouched `ui.css` look; `/playground/saas/*` are the same components site-styled. `/login` is the app page shadowing the module page (`<AuthForm>` inside); `/accept-invitation` stays module-mounted.
- **Counter**: `/playground/client/mutations` — +1, +5, +10 and Reset move the gauge, optimistic or not, and a burst of clicks never errors: the counter is a `setupCounter` count over the sharded counter component (`npx convex data counters --component shardedCounter`, one row per shard). `/playground/client/ssr` bumps the separate `server` counter. Clearing an account's data (or the idle sweep) resets both.
- **Migrations**: `/playground/platform/migrations` — run + dry-run both backfills, watch the live status table and the two aggregate metric cards.
- **Monitoring**: `/playground/platform/monitoring` — the health card reads `GET /api/backend/health`: states only when signed in as a plain user, with each layer's reason as an admin or on a dev deployment (`env push` names it `development`; `curl` it signed out on production: no env names). **Fail the action** errors with "Action failed (simulated)"; in dev without a DSN, DevTools › Monitoring lists it (browser, `demo:echo`); with `MONITORING_DSN` pushed, the backend's report lands in Sentry too, tagged `backend.source: backend`. `npx nuxt-backend status` shows `monitoring` simulated locally.
- **Webhooks**: `/playground/platform/webhooks` — send a test email, expect an `email.delivered` row in the unified feed (billing rows come from checkout flows). The feed is for signed-in visitors, and its rows name ids, never addresses.
- **Gifts**: `/playground/platform/credits` — the "Received gifts" panel lists and manually claims (`useGifts({ autoClaim: false })`).
- **Server guards**: `/playground/platform/authorization` — the four guard buttons show real allow/deny per role; the admin panel bans/unbans (admin role required).
- **Feature gates (server)**: `/playground/platform/features` — as the owner on Pro, `withFeature('premium')` answers and `withFeature('ultra')` is refused `feature_required`; the `<UpgradePrompt>` under it reads "Available on Ultra." and links to `/playground/vanilla/pricing?plan=ultra` (the module's pricing page on this site), where Ultra's card carries `data-requested`. Hardening: both demo functions read and write nothing, and answer only the caller's own workspace.

As a non-admin, open **Admins only** from the nav: the site's error page shows `<AccessDenied>` (role reason, "Go to the home page" → `/playground`), and a reload of `/playground/platform/admins-only` answers **403** (network panel). - **Plan quotas**: `/playground/platform/features`, the boards panel — run `npx nuxt-backend billing sync` first (it creates each plan's `<plan>-quotas` benefit and attaches it to the plan's products, the ones people already subscribe to included). As the free user the panel reads `0 / 0` and `<QuotaBoundary>` says "Your plan includes no boards.
